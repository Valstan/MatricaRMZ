# Ииваныч только с прод-сервера: локальный движок снят с клиентов

> **Тип:** plan · **Статус:** done · **Создан:** 2026-10-23 · **Релиз:** 3.89.0
> Отменяет [`neural-auto-engine-2026-10.md`](neural-auto-engine-2026-10.md) (решение 21.10 о
> «сначала этот ПК»). Контур A — [`neural-contour-a-in-product-2026-10.md`](neural-contour-a-in-product-2026-10.md).

## Решение владельца (23.10.2026)

С клиентских машин локальный движок (opencode на ПК) **убрать целиком** — не выключать, а снять:
ни бинаря, ни каталога, ни настроек, ни кнопок в интерфейсе. Вся работа Ииваныча идёт
**через серверный движок на проде** (`AI_SERVER_ENGINE_*`, opencode на `127.0.0.1:49374`):
клиент кладёт вопрос в очередь, сервер считает движком завода, DeepSeek остаётся последним
звеном цепочки на сервере.

Причина — не «локальный плохой», а цена сопровождения: движок на каждой машине ставится,
обновляется, ломается и диагностируется по одной (случай Сапегина 21.10 так и не разобран),
а прод-движок уже отвечает по реальной базе (приёмка 21–22.10).

## Что сделано

Клиент (`electron-app`):

- удалены `localAiEngine`, `localEngineSession`, `aiEngineAuto`, `localAiChat`,
  `localEngineDiagnostics`, `aiLocalTools`, `aiMcpProxy` — вместе с тестами; ни одного
  локального процесса/порта/MCP-моста в клиенте не осталось;
- `aiChatService.aiChatCreate` всегда кладёт строку в очередь как `pending` и пинает синк:
  вопрос уходит на сервер, ответ приезжает pull'ом (был режим `prod`, стал единственным);
- IPC-поверхность `aiEngine:*` (status/setMode/diagnose/resetBreaker/answerSource) снята
  из `main`, `preload` и `shared/ipc/types.ts`; настройка `ai.engineMode` больше не читается;
- `AiAgentChat` больше не показывает переключатель «Авто / Этот ПК / Сервер» и кнопку
  «Проверить движок»: только состояние сервера («на связи» / «недоступен»);
- `shared/domain/aiEngineMode.ts` удалён; источник ответа оператору теперь один —
  серверный `answer_source` (`считал движок завода` / `считал резервный движок`);
- разовая подчистка при старте (`opencodeTracesCleanup`): гасит живой `opencode.exe`,
  поднятый прежней версией (PID из `serve.pid`, сверка имени образа), и удаляет
  `%LOCALAPPDATA%\Programs\MatricaRMZ\engine`, `<userData>\engine`, `%TEMP%\matricarmz-engine`;
  деинсталлятор снимает тот же каталог.

Сервер (`backend-api`):

- `/updates/engine/manifest` и `/updates/engine/file/:name` удалены вместе с
  `engineArtifactService` — раздавать клиентам движок больше некому и незачем;
- цепочка ответа не менялась: движок прода первым, DeepSeek последним.

## Последствия (владельцу знать)

- Пока прод-движок отвечает — ничего не меняется, только чуть медленнее, чем локально
  (48–240 с на free-тире).
- Если прод-движок в паузе после сбоя, а баланс DeepSeek нулевой (на 21.10 было 0, `402`),
  оператор ответа не получит вовсе. Это вопрос к балансу ключа, а не к коду.
- Старые клиенты (3.86–3.88) живут со своим локальным движком до автообновления на 3.89.0;
  манифест движка у них перестанет находиться — их движок просто не будет обновляться.

## Гейты

`build shared` + `-r typecheck` + `typecheck:test` + `lint` + `-r test`; CDP-смоук окна Ииваныча
(статус сервера, вопрос → ответ, отсутствие переключателя режимов).

Заводская линза: участок — нет (ассистент, не поток двигателя); затор — не кормит;
инвариант потока — не ломает.
