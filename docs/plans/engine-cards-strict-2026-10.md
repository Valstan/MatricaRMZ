# Двигатели: EAV → строгие таблицы (B4 трека B)

**Статус:** ACTIVE (2026-10-04, ветка `feat/engine-cards-e3a`, фаза 1)
**Контекст:** план [matrica-v4-kickoff-2026-08.md](matrica-v4-kickoff-2026-08.md), этап B4. Разведка писателей — 7 семейств (см. ниже).

## Семейства писателей (разведка 2026-10-03)

1. **Карточка двигателя (renderer)**: `saveAllAndClose` (~40 кодов: номера, клеймо, бренд, даты, заказчик/договор/секция/цех, рекламации 8, scrap, флаги, ENGINE_FLAT_FIELDS) + `saveAttr` (вложения) + `copyToNew` — всё sync-EAV.
2. **engineService.setEngineAttribute (main)**: единственный `engine:setAttr`, гейты дублей (заводской номер с обходом флагами; клеймо без обхода), дедуп строк, deferred-материализация.
3. **Резерв `engine_reservation`**: уже server-managed (REST + прямой PG + ledger), sync-push зарезан backstop'ом — не трогаем.
4. **adminMasterdataService.setEntityAttribute + engineNumberGuard (server)**: те же гейты + аудит статусов.
5. **enginePhaseService**: `engine_phase` уже strict-писатель (сервер) — не трогаем.
6. **applyPushBatch**: generic EAV-транспорт.
7. **Скрипты**: импорты, canonicalize, dedupe/merge (`merged_into`), backfill этапов (читают EAV, пишут operations — не трогаем).

## Решение

Одна широкая таблица `erp_engine_cards` (id = entities.id, колонка на поле карточки — номера, клеймо+год, бренд, даты, ссылки, рекламации, флаги, FLAT-поля), по образцу договоров: триггерное зеркало EAV→strict на переходный период, затем двери + freeze. Отдельных таблиц под рекламации/фазы не заводим (фазы уже в operations).

Поля-ссылки (contract_id, customer_id, engine_brand_id, workshop_id): uuid без жёстких FK (как слоты платежей — legacy-данные с битыми ссылками не должны ронять зеркало).

## Шаги

- **E1 (зеркало):** миграция (таблица + sync-колонки + `rebuild_erp_engine_card()` + триггеры + бэкфилл) + `engines:parity` (EAV↔strict). Без смены поведения: писатели и читатели не тронуты.
- **E2 (двери):** ✅ **готов 2026-10-04** — `engineStrictService` (полевой патч 57 полей + get, whitelist с громким отказом) + маршруты `GET/POST /engines/cards/:id(/patch)` (view/edit) + `engineStrict.test.ts` (13 кейсов) + живая проверка на PG (двери + след + оба гейта + parity зелёный). Dual-write EAV-следом через те же гейты; ссылки проверяются существованием в entities. Найдено вживую: след обязан писать флаги раньше номера и дверь обязана возвращать перечитанную строку — иначе триггер зеркала откатывает strict к EAV, а ответ врёт (гейт следа видел БД без флага из того же патча). Гейт номера — merged-взгляд (явное снятие флага в патче возвращает запрет).
- **E3 (клиент):** разбит на E3a (контракт+сервер+реплика/чтение) и E3b (запись/push) — одним PR не ревьюится.
  - **E3a (контракт + сервер + реплика/чтение):** ✅ **готов 2026-10-04** — `ErpEngineCards` в SyncTableName/LedgerTableName/DTO/registry/`permission+engines.edit`, waiver снят, pre-sign гейты (`engineCardPushGuard`: номер/пара, per-row skip), ветка apply (parse→LWW→upsert→diff-след), паблишер, `engines:card:get` IPC + прелоад + секция, реплика 0032 + parity + android, тесты (гейты/diff/паблишер/IPC/реестр). Живая проверка на PG: дверь→паблишер→seq, полный push-путь, гейт до подписи, authz-запрет, parity зелёный. Карточка грузится и пишется по-старому (EAV) — переключение чтения/записи в E3b одним касанием.
  - **E3b (запись):** ✅ **готов 2026-10-04** — клиент SAVE → реплика pending (EAV-подложка при отсутствии реплики) + push + heal (error + баннер) + клиентские гейты + deferred-create через ensureEngineRow; `EngineDetailsPage` LOAD (реплика + EAV-фолбэк, без затирания набранного) и SAVE одним патчем + CDP-смоук зелёный. Write-through серверной строкой УБРАН (гонка: GET возвращал досейвовое и гасил собственную правку). Найдено смоуком: push везёт полную строку — недостающее поле уехало бы null'ом (EAV-подложка закрывает); parity: тумстоун без живой сущности — не расхождение.
- **E4 (хвосты):** ✅ **готов 2026-10-04** — все писатели карточки переведены на strict-путь: `copyToNew` ×2 и привязки/переносы/создание из карточки договора → `card.save`; импортёр completeness-CSV — дверью с фолбэком на legacy (прод без 0105); merge/dedupe — без изменений (EAV+зеркало, пометка на E5); сиды — dev-only, осознанно на EAV. `engines:parity` на проде ЗАБЛОКИРОВАН до релиза с 0104/0105 (прод на v3.60.0 без strict-таблиц) — едет релизным шагом, не E4.
- **E5 (freeze, после обновления парка):** гейт кодов engine в setAttr + push-backstop, снос триггеров.

## Вне скоупа

- `engine_reservation`, `engine_phase`, этапы/листы (уже strict) — не трогаем.
- `erp_engine_instances` (складской регистр) — связь карточка↔инстанс решается на E4.
- Уникальность заводского `engine_number`: действующий гейт с флагами обхода — переносится как есть.
