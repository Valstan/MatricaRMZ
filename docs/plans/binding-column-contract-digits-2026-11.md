# Колонка «Привязка»: три цифры договора вместо слова «договор», номер ДС, колонка выключена по умолчанию

> План по живым промтам КАРМАНА **#8** (текст владельца) и **#12** (план из библиотеки), прочитанным 12.11.2026. Библиотечный план сверен с нашим кодом (база `17c189db`, v3.121.0) и **уточнён под него** — расхождения перечислены в §«Расхождения с библиотечным планом».

**Статус:** в работе. **Дата:** 2026-11-12. **Ника:** список двигателей, договоры и ДС.

## Цель

В списке двигателей колонка «Привязка» показывает не слово «договор», а **рабочий номер договора** — последние три цифры части номера ДО первого «/» — а для привязки к дополнительному соглашению ещё и «/N» (номер ДС, без слова «ДС»). Если ничего не привязано — только красный кружок, без текста. Колонка при этом **выключена по умолчанию** и остаётся в «Колонках списка».

## Заводская линза (три строки)

- **Участок:** приёмка и учёт двигателей — привязка карточки к договору и ДС видна оператору в списке.
- **Кормит ли затор:** не кормит. Главный затор модели — «начало сборки: ручной подбор совместимых деталей из обезличенного фонда»; подпись привязки его не касается.
- **Инвариант потока:** не ломает. Привязка двигателя к договору/ДС не меняется и не переносится — меняется только **подпись** в одном списке. Сортировка колонки, печать и кружки остаются как есть.

## Расхождения с библиотечным планом (важно)

1. **В строке списка нет поля `contractNumber` — и переименовывать не надо.** Поле называется `contractName`, но по факту это **номер договора**: у сущности «договор» в EAV нет атрибута `name`, подпись берётся по `number` (`entityService.listEntitiesByType`: метка по ключам `name` → `number` → …). Проверено на проде: 76 договоров, атрибут `number` заполнен у всех; `contractName` в строке списка — это он. Схему и тип не трогаем: переименование `contractName` → `contractNumber` тянет за собой восемь экранов и не входит в задачу владельца. В доменной функции параметр называется `contractNumber` — по смыслу, а не по имени поля строки.
2. **Колонку надо спрятать не только «по умолчанию», но и у тех, у кого она уже видна.** Влалелец попросил «выключить, чтобы не мешалась», а колонка была видимой по умолчанию — то есть у него и у всего парка она на экране. Одного `ENGINE_LIST_HIDDEN_BY_DEFAULT` мало: `layoutFromPersisted` прячет только колонки, которых в сохранённой раскладке **не было** (`useColumnLayout.ts:46`). Поэтому — `HIDE_ONCE` (разово, как «Дата изменения»): включил обратно в «Колонках списка» — значит, так и надо.

   **⚠️ Найдено смоуком: `HIDE_ONCE` был помечен на пользователя, а не на колонку.** Отметка `matrica:columnLayout:hideOnce:<user>:<layout>` ставилась целиком: «это умолчание уже применялось». У парка отметка уже стояла (с 19.10.2026 — для «Даты изменения»), значит, колонка «Привязка», добавленная в `HIDE_ONCE` позже, **никогда бы не спряталась**: механизм видел «уже применяли» и выходил. Смоук это показал — плашка оставалась включённой при сохранённой раскладке.
   **Починка:** отметка стала **по колонкам** (в значении — список id через запятую), старое значение «1» читается как «updatedAt» — единственная колонка, что тогда была в списке. Теперь новая колонка прячется один раз у всех, а включил оператор — больше не трогаем.
3. **Подпись «/N» даём только по канону `isContractAddonToken` («ДС N»).** В данных продa `contract_section_number` встречается в четырёх видах: «ДС N» (199 двигателей), «primary» (276), пусто (40) и **голые числа «1»–«4» (55)** — наследие старого импорта; ещё 8 строк держат в поле раздела номер договора (мусор). Приложение голые числа ДС-ами не считает (кружок один зелёный, сортировка — «договор»), и подпись обязана agrees с кружком в той же ячейке: «🟢 239/3» противоречила бы легенде «два зелёных — привязан к ДС». Значит, `/N` — только по канону. Расхождение данных вынесено в PENDING (см. ниже), это работа по данным, а не по UI.
4. **Печать не трогаем** — `printValue: (e) => bindingTextLabel(e)` печатает по своей метке («Договор» / «ДС 3» / «Не привязан»). Владелец про печать не говорил; если короткий номер нужен и на бумаге — это отдельное решение владельца.
5. **Номер РМЗ не трогаем** — колонка `rmzNumber` остаётся как есть (владелец: «пусть он есть, остаётся»).

## Реализация

### 1. Домен (`shared/src/domain/contract.ts`)

`engineBindingLabel({ contractId, contractNumber, contractSectionNumber })`:

- привязки нет (`contractId` пуст) → **пустая строка** (в ячейке — только красный кружок, без букв);
- цифры — из `shortContractSuffix` (одно правило на список, карточку и печать), без звёздочки: `239`;
- цифры выделить нельзя (номер другого вида или его нет) → `Договор`;
- ДС есть (по `isContractAddonToken`) → `239/2` (слэш + номер ДС без слова «ДС»); ДС нет → `239`;
- ДС без договора → пусто (привязки к договору нет — показывать не к чему).

### 2. Ячейка (`EnginesPage.tsx`)

`renderBindingCell` берёт текст из `engineBindingLabel`; **кружки остаются как есть** (зелёный / два зелёных / красный / синий). Пустая подпись + красный кружок = «ничего не привязано» — слово «Не привязан» из ячейки уходит. Подсказка (title) сохраняет полный номер договора и токен ДС.

### 3. Колонка выключена по умолчанию

- `ENGINE_LIST_HIDDEN_BY_DEFAULT` += `binding` — для новых раскладок;
- `HIDE_ONCE['list:engines:columns']` += `binding` — разово у тех, у кого колонка уже видна (см. расхождение 2);
- **отметка `HIDE_ONCE` — по колонкам** (`columnLayoutStore.ts`): иначе новая колонка у парка не спряталась бы никогда.

## Что НЕ входит

- **Переименование `contractName` → `contractNumber`** в типах строки (расхождение 1) — отдельная работа.
- **Чистка данных привязки**: 55 движков с разделом в старом формате («1»–«4») и 8 с номером договора в поле раздела. Правится данными (expand-contract + миграция по согласованию с владельцем), не кодом списка. → PENDING.
- **Короткий номер договора на печатных формах** — решение владельца (расхождение 4).
- **Сортировка колонки** (`bindingRank`) — не трогаем: она по типу привязки, а не по подписи.
