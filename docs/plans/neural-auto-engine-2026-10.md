# Ииваныч «Авто»: локальный движок по умолчанию, откат на сервер, тихая установка и автообновление движка

> **Тип:** plan · **Статус:** active · **Создан:** 2026-10-21 · **Релиз:** 3.86.0
> Продолжение [`neural-contours-2026-10.md`](neural-contours-2026-10.md) (контур B собран 20.10,
> ветка `feat/neural-contours`), письмо brain 19.10 `2026-10-19-neural-selfhost-and-client-contour`.
> Отдельная нитка «контур A в продукте» — [`neural-contour-a-in-product-2026-10.md`](neural-contour-a-in-product-2026-10.md).

## Ситуация на 21.10.2026

- На машине **Фатыхова** локальный движок работает: отвечает, отвечает по делу.
- На машине **Сапегина** — не заработал. Причина не установлена: у нас нет ни версии клиента,
  ни лога движка, ни содержимого каталога установки. Достоверных выводов из «у одного работает,
  у другого нет» делать нельзя.
- Режим сейчас **ручной**: переключатель «Сервер / Этот ПК», по умолчанию «Сервер», движок
  качается только при переключении, автозапуска при старте нет, отката нет.

## Решение владельца

Ииваныч должен **всегда** пытаться считать локально, а на сервер уходить только когда локальный
не справился. Цепочка:

**локальный движок → opencode на проде → DeepSeek (аварийное звено)**

Третье звено нужно, потому что free-тир прод-движка может ответить `limit` — без страховки
Ииваныч просто промолчит. Пока контур A не в продукте (отдельная нитка), второе звено —
текущий серверный Ииваныч; после его готовности порядок не меняется, меняется только адресат.

## Что делаем

### 1. Режим «Авто» и дефолт

- Новое значение `ai.engineMode = 'auto'`, **дефолт для всех**, в том числе для уже
  установленных клиентов (миграция настройки: `prod`/`local`, выставленные вручную, уважаем —
  но на чистой установке и при отсутствии значения ставим `auto`).
- В окне Ииваныча — не переключатель «Сервер/Этот ПК», а состояние и ручной выбор:
  «Авто (этот ПК, иначе сервер)» / «Только этот ПК» / «Только сервер».

### 2. Автозапуск движка

- После старта клиента (когда интерфейс уже показан, не на критическом пути) — `ensureLocalEngine()`:
  проверка установленной версии, при отсутствии/устаревании — тихая загрузка, запуск скрыто,
  health-опрос.
- Пока движок не готов, Ииваныч работает от сервера без ошибок для оператора; в окне — строка
  «Готовлю движок на этом компьютере…» с процентом.
- Ошибка запуска — не молчит: в окне кнопка **«Проверить движок»**, отчёт (версия клиента,
  версия и путь движка, свободное место, код ошибки, последние строки лога движка) копируется
  в буфер одним нажатием. Это и есть диагностика Сапегина: просим его нажать и прислать.

### 3. Откат на сервер и возврат к локальному

- Попытка локального ответа — с коротким таймаутом (10–15 с) и health-проверкой перед отправкой.
- Неудача → **одна** попытка серверного ответа, строка помечается «считал сервер» (оператор
  видит, где считалось).
- **Circuit breaker:** после N подряд неудач локальный движок не пробуем 10–30 минут, потом
  снова пробуем. Иначе каждый вопрос ждёт таймаут — это раздражает сильнее, чем ответ с сервера.
- Причина неудачи видна в статусе (нет сети/лимит/не запустился/таймаут).

### 4. Раздача движка с нашего сервера + LAN

Сейчас движок качается с `registry.npmjs.org` — внешний интернет, 210 МБ. На заводской машине
это первая причина «не заработало». Меняем:

- архив движка публикуется на нашем сервере рядом с обновлениями клиента;
- клиент качает с сервера (HTTPS), при недоступности — берёт у соседа по LAN (тот же принцип,
  что у `lanUpdateService`, но отдельным каналом: текущий отдаёт **один** файл — установщик
  клиента);
- sha512 сверяется как сейчас, подпись/целостность не ослабляем.

### 5. Автообновление движка (чужой продукт, выходит независимо)

Ключевое ограничение: **ставим не «любую свежую», а рекомендованную нами версию**. Иначе чужой
релиз с изменённым API положит Ииваныча у всего парка в один день.

- На нашем сервере — **манифест рекомендованной версии** (по образцу `latest.yml` клиента):
  версия, URL архива, sha512, минимальная версия клиента.
- Клиент проверяет манифест **раз в сутки** (в простое, не во время работы оператора).
- Есть новая рекомендованная → качаем в **отдельный каталог**, не трогая рабочую версию.
- Запускаем и проверяем: health + пробный вызов модели (короткий промпт, дешёвый).
- Прошло — переключаемся на новую, прежнюю **оставляем как откат**; удаляем старую только
  после успешного запуска новой (на диске живут одна рабочая + одна предыдущая).
- Не прошло — откат на прежнюю, событие в критичные события (владельцу видно).
- Обновление **серверного** opencode на проде — **вручную, нами, по чек-листу** (проверка
  ответа модели после рестарта). Автообновление прода не делаем: это единственный серверный
  fallback парка.

## Код (ожидаемые точки)

- `electron-app/src/main/services/localAiEngine.ts` — источник архива, каталоги версий,
  проверка/переключение, откат, суточный планировщик.
- `electron-app/src/main/services/localEngineSession.ts`, `aiChatService.ts` — цепочка
  «локальный → сервер», таймауты, circuit breaker, признак «считал сервер».
- `electron-app/src/main/ipc/register/aiChat.ts` — режим `auto`, статус, диагностика.
- `electron-app/src/renderer/src/ui/components/AiAgentChat.tsx` — состояние, «Проверить движок»,
  отчёт в буфер.
- `shared/src/ipc/types.ts` — новые типы статуса/режима.
- Тесты: домен «когда пробуем локальный, когда нет» (circuit breaker), сервис версий
  (новая/прежняя/откат), guard «режим по умолчанию auto», guard «в локальном режиме вопрос
  не уезжает на сервер».
- CDP-смоук: окно Ииваныча на стенде, строка состояния движка, отчёт диагностики.

## Безопасность и границы

- Движок слушает только loopback; прав администратора не требует (`%LOCALAPPDATA%`).
- В локальном ответе вопрос и ответ на сервер **не уходят** (как сейчас). При откате на сервер
  вопрос уходит — это и есть смысл отката; границы данных владелец снял 19.10.
- Секретов в репо нет; токен движка — на запуск, живёт в памяти/каталоге движка.

## Гейты и выпуск

Обычные гейты + CDP-смоук. Релиз 3.86.0. Приёмка на живой машине обязательна (стенд PC79 +
одна машина парка, желательно Сапегин — с отчётом диагностики до и после).

## Сделано (код) — 21.10.2026

Вошло в первый PR релиза 3.86.0:

- **Режим «Авто» — дефолт для всех** (`shared/src/domain/aiEngineMode.ts`): `resolveAiEngineMode`
  (пустое/неизвестное → `auto`, ручной выбор `local`/`prod` уважаем), `shouldTryLocalEngine`,
  circuit breaker (`recordLocalEngineFailure/Success`, 3 неудачи → пауза 15 минут).
- **Цепочка «локальный → сервер»** (`main/services/aiEngineAuto.ts`, `localAiChat.ts`,
  `aiChatService.ts`): в «Авто» строка создаётся локальной (`syncStatus: 'synced'` — на сервер
  не уезжает); при неудаче движка она возвращается в `pending`, вопрос уходит на сервер, ответ
  приезжает оттуда. Пока движок не поднят, в «Авто» **не ждём** его — отвечает сервер
  (в строгом «Только этот ПК» ждём: оператор сам выбрал этот компьютер). Оператор видит
  «считал сервер» — источник ответа едет вместе со строкой (`answerSource`).
- **Тихая подготовка движка** (`main/index.ts` → `prepareLocalEngineInBackground`): после
  показа окна, не на критическом пути; режим читается из `ai.engineMode`.
- **Диагностика «Проверить движок»** (`localEngineDiagnostics.ts` + IPC `aiEngine:diagnose`):
  версия клиента, режим, состояние, версия и каталог движка, свободное место, рекомендованная
  версия, breaker, последние строки лога движка — отчёт копируется в буфер одним нажатием.
  Это и есть ответ на «у Сапегина не заработало».
- **Версии движка в подкаталогах** (`localAiEngine.ts`): `engine/versions/<версия>/` + указатель
  `engine/active.json`; новая версия ставится рядом со старой и переключается только после
  успешного health, прежняя остаётся как откат. Старая плоская установка (движок до 3.86.0)
  распознаётся и продолжает работать.
- **Раздача движка с нашего сервера**: `GET /updates/engine/manifest` (рекомендованная версия,
  url, sha512, размер, минимальная версия клиента) и `GET /updates/engine/file/:name` (Range,
  публично — как остальные маршруты обновлений); манифест лежит в `<updatesDir>/engine/manifest.json`.
  Клиент берёт движок сначала с нашего сервера, а если сервер недоступен — из npm-реестра
  (фолбэк, чтобы машины без доступа к серверу не остались без Ииваныча).
- **Суточная проверка рекомендованной версии** (`runEngineMaintenance` + `scheduleEngineMaintenance`):
  раз в сутки, в простое; новая версия скачивается в отдельный каталог, запускается, проверяется
  health'ом, и только потом переключение; не поднялась — откат на прежнюю.
