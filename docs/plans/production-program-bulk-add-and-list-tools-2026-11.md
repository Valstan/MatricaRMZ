# План: ПП — добавление двигателей списком, блок «без договора» с автопереездом, клик в карточку и контекстное меню

**Источник.** Промты КАРМАНА (раздел проекта `MatricaRMZ`): **#64** — задание владельца, **#65** — план из библиотеки, **#66** — ответы владельца (зафиксированы как **D-246** в журнале решений Мозга).

**Задача владельца (#64, дословно).** В модуле производственной программы — вариант добавления двигателей **списком номеров**: двигатели «нашлись, не нашлись, у таких нет договора или контрагента»; по каждому номеру видно проблему («нет в базе», «нет истории ремонта»); оператор ставит галочки и одной кнопкой внизу добавляет выбранное. Проблемные двигатели попадают **отдельным блоком** у программы — пока временно — и **сами** переезжают в свой договор, когда их починят (проверка при открытии программы). Плюс: клик по двигателю открывает его карточку, двигатели можно выделять **множественным выбором**, и по правой кнопке с выделенным — печать / копировать / почта.

## Заводская линза (три строки)

- **Участок:** планирование производства (ПП) — плашка программы, добор двигателей, разбор проблемных номеров.
- **Кормит ли затор:** косвенно — главный затор завода это **начало сборки** (ручной подбор деталей из ремфонда). ПП — не сборка, но это **вход**: чем быстрее двигатель попадает в программу со своим договором, тем раньше он виден плановой службе. Напрямую затор не кормит; косвенно — снимает ручную переписку номеров и ручной переезд строк.
- **Не ломает ли инвариант потока:** нет. Поток ремонта (приёмка → разборка → дефектовка → комплектование → сборка → отгрузка) не трогаем: пишем только строку плана и примечание; этапы, история ремонта, наряды и склад не затрагиваются. Инвариант «строка плана без договора не имеет группы» сохраняется: проблемные строки живут **внутри** программы отдельной группой «Требует данных», а не в чужих договорах.

## Уточнения плана #65 под наш код (решения сессии)

1. **Проблемные строки — не отдельная сущность, а группа «Требует данных» внутри программы** (D-246 ①). Новая группа с подписью словами: она и есть «блок без договора» в терминах владельца. Ключ группы = `без-договора:Требует данных` — совпадает с существующей механикой, новых таблиц и атрибутов нет.
2. **Причина проблемы едет в `note` строки** (D-246 ②) ⇒ сама едет в печать (колонка «Примечание» уже есть), в Word/Excel и в чат. Правок печатной формы не требуется.
3. **Перепроверка — и при открытии программы, и кнопкой «Перепроверить»** (D-246 ③). Проход один и тот же; запись — **только** через `applyRows`; **только при реальном изменении**, иначе каждое открытие писало бы в сервер.
4. **Галочка у проблемной строки разрешена**, но по умолчанию снята: оператор решает сам («этот добавить, а этот пока не добавлять»). Заблокирована строка, взять которую **нельзя**: отгруженный двигатель (`productionProgramEngineHint` → `block`).
5. **Карточка из ПП не заводится**: строка без карточки ждёт карточку в блоке и получит ссылку, когда карточка появится. Создание карточки — другой уже существующий путь (пакетный приём), в ПП второй путь не заводим.
6. **«Нет контрагента» и «нет истории ремонта» — предупреждения, а не блок.** Переезд вызывается появлением **договора** (так и в ответе владельца: «строка … сама меняет группу, когда договор появится»): шапка группы складывается и из одного номера договора, без контрагента. Блокируют остаться в блоке только «нет карточки в базе» и «нет договора» — до них строке группы не из чего собрать. Предупреждения видны в отчёте добавления.
7. **Поиск карточки по номеру** — нормализованно (`normalizeLookupCompact`, тот же ключ, что у гейта дублей и пакетного приёма). Номер дублей в базе не уникален ⇒ при нескольких совпадениях строка **остаётся в блоке** (молча выбрать одну карточку нельзя).
8. **Контекстное меню ПП собираем своё** (в ките нет «почты», а «Удалить» завязан на отдельный `onDelete`): печать / копировать / почта по **выделению**, для одной строки — «открыть карточку», для пачки — «убрать из программы» (через `applyRows`, право `production_program.edit`).

## Шаги

### A. Домен (`shared/src/domain/productionProgram.ts`)

1. `PRODUCTION_PROGRAM_PENDING_GROUP_LABEL` — подпись группы проблемных строк («Требует данных»): словами, не идентификатором (сервер такое не принимает — `productionProgramService.ts:344-346`).
2. `productionProgramEngineByNumber(engines, number)` — карточка по номеру + признак неоднозначности.
3. `productionProgramEngineProblem(engine, number)` — причина проблемы строкой («Нет карточки в базе», «Нет договора», «Нет контрагента», «Нет истории ремонта», «Уже отгружен — в план не берём»).
4. `productionProgramResolvePendingRows(rows, engines, {contractLabelOf, contractKindOf})` — проход перепроверки: строки без `contractId` получают найденную карточку и, если у карточки есть договор и контрагент, **уезжают в группу договора**. Возвращает `{rows, changed, moved, unresolved}`.

### B. Диалог «Добавить двигатели списком» (новый компонент)

- Поле ввода номеров (разбор — `parseEngineBulkIntake`).
- Отчёт по каждому номеру: найден / нет в базе / нет договора / нет контрагента / нет истории ремонта / отгружен.
- Галочка у каждой строки; заблокированная строка (отгружен) галочкой не отмечается, причина видна рядом.
- Одна кнопка внизу «Добавить в производственную программу» — добавляет **только отмеченные**.
- Годные → обычная строка (`productionProgramRowFromEngine`); проблемные → строка с `contractId = null`, `groupLabel = PRODUCTION_PROGRAM_PENDING_GROUP_LABEL`, причина в `note`, `engineId = null`, если карточки нет.
- Перед записью строки плана читаются **с сервера** (`productionProgram.get`), дополняются и уходят одним набором.

### C. Страница ПП (`ProductionProgramPage.tsx`)

- Проп `onOpenEngine` + клик по номеру двигателя в карточку (в `App.tsx` — `openEngine`).
- Кнопка «Перепроверить» в ряду программы; автопереезд при открытии программы (тот же проход).
- Выделение строк (`useListSelection`, свой `persistKey`), чекбокс в шапке и в строке, `data-list-root="true"` на контейнере таблицы.
- Контекстное меню: печать / копировать / почта по выделению, «открыть карточку», «убрать из программы».

## Приёмка

1. Смоук CDP: список из 5 номеров (нормальный · нет в базе · без договора · без истории ремонта · отгруженный) — по каждому видна причина, галочка только у годного, кнопка добавляет только его.
2. Проблемный двигатель в блоке «Требует данных»; после правки карточки (добавлен договор) и **переоткрытия** программы он **сам** переехал в группу договора; кнопка «Перепроверить» даёт тот же результат без переоткрытия.
3. Клик по двигателю открывает карточку.
4. Выделение нескольких строк → ПКМ → печать / копировать / почта.
5. Юнит-тесты домена (разбор номера, причины, проход перепроверки) + сторож страницы.

## Осторожности

- **Одна дверь записи строк.** Любая правка строк — только `applyRows`. Вторая дверь вернёт пару «удалить + вставить» (чинили 10.11).
- **Зеркало отстаёт на минуту** ⇒ перед записью читать строки с сервера; перепроверка — по **живой** реплике карточек (карточки едут отдельно).
- **Переезд только при реальном изменении** — иначе каждое открытие программы пишет в сервер и может перебить правку оператора (канон #1240).
- **`groupLabel` обязателен** и не должен быть «техническим идентификатором» ⇒ подпись блока словами.
- **Нумерация пересчитывается** по позиции: переезд меняет порядок групп ⇒ `orderNo` шлётся по индексу (уже так в `persistRows`).
- **Чужие строки не снимаем**: замена набора полная ⇒ строки из реплики, которых мы не знали, добавляются в набор (уже сделано в `persistRows`).
- **Печать блока «Требует данных»** — печатается (D-246 ②), причина видна в колонке «Примечание».
