# Пакет владельца 2026-08-11

Восемь ниток из одного сообщения владельца 11.08. Статусы обновляются по мере мержей.

## Контекст

Владелец надиктовал пакет: планшет не грузит наряды; довести D-024 до пользователей; чат ИИваныча — обычной вкладкой; меню — оверлеем; перенос двигателя между секциями контракта; гейт «отгружено заказчику» против незакрытого наряда; очеловечить еженедельный дайджест; разобраться, почему на его машине программа исчезла целиком и watchdog не помог. Разведка — workflow `owner-batch-understand` (7 карт, 2026-08-11).

## Нитки и решения

### 1. Планшет: наряды не грузятся — OOM Java-кучи в Capacitor-мосте ✅ диагноз

**Корень (подтверждён logcat 10.08 15:38 и 11.08 09:45):** `java.lang.OutOfMemoryError` (лимит кучи 256 МБ) в `org.json.JSONTokener` ← `MessageHandler.postMessage` — разбор гигантского JSON-сообщения JS→native. Источник: `upsertPulledRowsInChunks` в `syncService.ts` шлёт до 2000 строк одним INSERT (десктопные `SQLITE_BIND_PARAM_LIMIT=32000`, `MAX_UPSERT_CHUNK_ROWS=2000`); на жирных таблицах фолбэк «too many variables»→900 не успевает — Java-парсер умирает раньше SQLite. Первый полный pull детерминированно гибнет на середине: двигатели доезжают (1804), наряды — нет. Sync рестартует и гибнет там же.

**Фикс (PR-1):** инжектируемые лимиты `setSyncSqlLimits({maxBindParams, maxChunkBytes})` из android-обвязки (`wireSyncForAndroid`: 900 параметров + байтовый кап на пачку); чанкование по размеру строк; `android:largeHeap="true"` как страховка. Приёмка — живой полный pull на DIGMA до появления нарядов.

**Сопутствующее (в PENDING):** экран гаснет → DuraSpeed режет сеть → sync `Failed to fetch` (первый pull лучше гнать с включённым экраном; вайтлист DuraSpeed/батареи на планшете); прерванный холодный pull начинается с нуля (нет per-table чекпойнта); прогресс первой загрузки почти невидим оператору (маленький индикатор вместо полноэкранного оверлея).

### 2. Watchdog: почему не помог + самовосстановление ⏳

Движок self-heal **уже есть** (`watchdog/main.go`: appPresent → скачать установщик → `/S` → отчёт в критические события). Отказала обвязка. Живые находки PC40: (а) dev-стенд **перезаписывает боевой handshake** (`watchdog.json` смотрит на dev-`electron.exe` и localhost) — нет защиты от чужого handshake; (б) fallback-путь `standardInstallExe` устарел (смотрит `Programs\@matricarmzelectron-app\`, а preInit ставит в `Programs\MatricaRMZ`).

**PR-6:** `--repair` флаг + ярлык «Восстановить Матрицу РМЗ.lnk» (NSIS + поддержка в `restoreShortcutsHeadless`); взаимное лечение: клиент на старте восстанавливает watchdog (exe из resources + schtasks), watchdog лечит клиента; MZ-проверка exe клиента; новый kind `app_missing` в `/client/watchdog/report` (backend раскатать раньше клиента); lock от параллельных проходов; фикс fallback-пути; защита handshake от dev-инстансов (dev/CDP-клиент не пишет handshake). Приёмка по ADR-0002 — живая установка на одной машине.

**Форензика машины владельца — закрыто 2026-08-13** решением владельца: расследовать конкретный случай «программа исчезла целиком» не нужно, hostname не разыскиваем. Сам PR-6 (самовосстановление, `--repair`, взаимное лечение, kind `app_missing`) остаётся в силе — он чинит класс проблемы, а не тот единичный случай.

### 3. Чат ИИваныча — обычной вкладкой ⏳ (PR-5, вручную)

Все точки входа (кнопка меню, плавающая кнопка, deep-link) открывают вкладку v3 (kind `ai_chat` уже существует в keep-alive); старая боковая панель выводится. Сохранить D-024-фичи (плашка «думает», быстрый опрос). Карта: `maps/ai-chat-tab.json` (скретчпад сессии).

### 4. Меню-оверлей ⏳ (PR-5, вручную)

Сейчас меню — вечная вкладка `menu` (tabs[0], `V3TabShell` → `ButtonPanel`, `.v3-tab-content-menu` max-width:320px). Целевое: узкий оверлей поверх активной вкладки (`.v3-tab-body` position:relative — якорь), автозакрытие после выбора; аккордеон секций (развёрнута максимум одна); блок «Закреплённые» - вне скролла, всегда сверху; заголовки секций — отличимый цвет. Класс-префикс `v2-`/`v3-` заморожен для CDP-смоуков (`chromeContract.test.ts`) — не переименовывать. Планшетный режим прячет tab strip — оверлею нужен свой триггер на планшете.

### 5. Контракт: перенос двигателя между секциями ⏳ (агент)

Дроп-даун секции в строке двигателя карточки контракта. Реюз `attachEngineToSection` (уже двусторонний: `contract_payments` через `mutateContractPayments` + `engines.setAttr(contract_section_number)`). Решения: строгое размещение в выбранную секцию (`planSlotForEngine` со strict-флагом, over-plan с confirm — фолбэк в чужую секцию для явного переноса запрещён); дроп-даун также в блоке «Двигатели без секции»; деньги остаются на старом слоте (подсказка в UI); заблокировать перенос, если двигатель занят другим оператором (reservedByUserId). Карта: `maps/contract-sections.json`.

### 6. «Отгружено заказчику» ↔ открытый сборочный наряд ⏳ (агент)

Решение владельца: модалка «наряд не закрыт — закрыть сегодняшним числом?» [Закрыть наряд / Отмена]; отмена = галка не ставится. Реализация: shared-хелпер рядом с гейтом дублей (`isAssemblyWorkOrderBlocking`), клиентский `shipmentAssemblyGate.ts` по образцу `assemblyDuplicateGate.ts`, врезка в `applyStatusCheckboxChange` (`EngineDetailsPage`). Подтверждение → `sync.run()` → `workOrders.close()` на каждый blocking-наряд (`closedTs=now` даёт сегодняшнюю дату; `workOrders.update` не звать — сбрасывает статус в draft), `status_repaired` ставится локальным state карточки (не `advanceStatus` — разойдётся с несохранённым state). Нет права `work_orders.close` → галка не ставится, показать причину (строгий блок, предпочтение владельца data-integrity). Серверный guard не в этом PR (единственный UI-вход перекрыт) — отметить в PENDING. Карта: `maps/ship-trigger.json`.

### 7. Еженедельный дайджест по-человечески ⏳ (агент)

Дайджест умер вместе с облачной рутиной (D-024); пересобрать на прямом движке. Решения: реестр русских названий разделов переезжает в `shared/src/domain/uiSections.ts` (renderer реимпортирует — вторую копию канона не заводить); `aiUsageDigestService` по паттерну `aiAgentReportsService` (тик + понедельник, dedupe по ISO-неделе, персистентно); статистика из `audit_log`/`statistics_audit_daily` + ИИваныч-статы; очеловечивание ДО промпта (ФИО через `resolveLoginsToFullNames`/`listEmployeesAuth`, разделы через shared-реестр, отчёты через `REPORT_PRESET_DEFINITIONS`); нарратив через `callLlm` (AI_MODEL_ANALYTICS) с детерминированным фолбэком — дайджест не молчит при отказе LLM; доставка — answered-строка `ai_chat_requests` суперадмину (как старая рутина); заодно чинятся утечки логинов/ключей в `aiAgentReportsService.buildReportText`, `notifySuperadminEscalation`, `aiChatAnswerService.userMessage`. Двухразовый ops-отчёт остаётся (другой жанр). Карта: `maps/digest.json`.
