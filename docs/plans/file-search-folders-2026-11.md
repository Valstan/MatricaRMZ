## Заводская линза (три строки)

- **Участок:** приёмка и дефектовка — оператор находит фотографии двигателя в своей папке и печатает их для разбира.
- **Кормит ли затор:** не кормит. Главный затор модели — «начало сборки: ручной подбор совместимых деталей из обезличенного фонда»; модуль ищет фото по номеру двигателя, а не детали в фонде. Косвенно помогает приёмке (быстрее находит «что известно про этот движок» в бумажном виде).
- **Инвариант потока:** не ломает. Модуль читает папки и ничего в них не пишет; записи в карточку двигателя не касается. Обезличивание деталей, партия/экземпляр (`stamped_number`), подпись и ответственный, маршрутный лист, сдельщина против нормо-часов не затрагиваются.

## Решения (уточнения плана библиотеки под наш код)

1. **Модуль остаётся читающим.** Поиск по названию — тоже чтение; ничего не пишем ни в папки, ни в файлы.
2. **Диск целиком не индексируем** — только явно выбранные оператором папки, как и сейчас (правило плана модуля).
3. **Превью — data-URL, не `file://`:** renderer не читает диск (сторож `ListChrome.guard.test.ts:487-491`).
4. **Картинка получает `id`, а не путь.** Renderer знает только `id`, который выдал main при поиске; путь на диск в renderer не уходит. Превью и печать берут путь из реестра main по этому `id`. Тот же класс защиты, что `consumeIssuedPath` для загрузки файлов: иначе канал «покажи картинку» стал бы «прочитай любой файл с диска».
5. **Папки для поиска берутся из машинно-локального хранилища, а не из аргументов renderer** — иначе `searchFolders` стал бы каналом «обойди любую папку на диске». Оператор добавляет папки кнопкой (штатный диалог выбора), они сохраняются в `sync_state` (per-user), и поиск идёт по ним.
6. **Печать — существующий путь печати фотографий.** `photosPrintLocalPaths` (`fileService.ts`) переиспользует `buildPhotosHtml` + `renderPhotosWindow` + `webContents.print` без `silent`; окно скрытое, но **не offscreen** (грабли из `:761-763`). Оператор в системном диалоге правит масштаб и ориентацию и сам отправляет на печать.
7. **Потолки обязательны:** глубина вложенности, число папок, число файлов, число находок, картинок в находке, время обхода, размер картинки. При превышении — замечание оператору, а не зависание (прецедент `MAX_SHEET_ROWS` / `READ_TIMEOUT_MS`).
8. **Не-изображения не печатаются картинкой** — перечисляются списком (как в `photosPrint:1013-1018`).
9. **Права и раздел:** каналы `fileSearch:` гейтятся разделом «Производство» автоматически (префиксное правило `sectionGate.ts:33`) — новые каналы попадают под то же правило без новой записи.

### Развилки, которые решает владелец

План #89 перечислил три развилки. Две взяты по умолчанию из самого плана, одна — по существу:

1. **«Microsoft Picture Manager»** — по умолчанию (а) системный диалог печати Chromium: тот же набор, что у Picture Manager (принтер, масштаб, ориентация), и работает на любой машине парка без внешних программ. Развилка (б) — внешний диспетчер фото ОС — это отдельная работа (поиск приложения на машине, вызов с аргументами, свой сценарий приёмки). **Вопрос владельцу задан 24.11.2026.**
2. **Глубина обхода папок** — по умолчанию разумный потолок: 3 уровня вложенности (`MAX_FOLDER_DEPTH`). **Вопрос владельцу задан 24.11.2026.**
3. **Совпадение по названию** — и имя папки, **и** имя файла: владелец сказал прямо «по названию файлов, по названию папок» ⇒ решено текстом промта, не угадыванием.

## Приёмка (критерии промта #88 → чем проверяем)

| # | Критерий | Проверка |
|---|---|---|
| 1 | Оператор добавляет одну и несколько папок, они сохраняются между запусками | юнит-тест main (per-user) |
| 2 | Поиск по номеру находит папку с этим номером в названии | юнит-тест main: папка «Э06АТ0889» ⇒ совпадение |
| 3 | Совпадение по названию файла тоже работает | юнит-тест main |
| 4 | Картинки найденной папки видны крупным превью | смоук: превью открывается, видно изображение |
| 5 | Галочки отбирают несколько картинок | смоук: отметка N картинок |
| 6 | Отобранные уходят на печать, оператор правит размер и печатает сам | смоук: системный диалог открылся, печать пошла (как в `photosPrint`) |
| 7 | Диск целиком не индексируется, модуль ничего не пишет | сторож страницы + тест main |
| 8 | Недоступная папка — сообщение с путём, остальные ищутся дальше | юнит-тест main |

## Границы (что сознательно не входит)

- Поиск по PDF и OCR картинок — не входит: промт говорит про папки с фотографиями и поиск по названию.
- Индексирование диска целиком и сетевых каталогов без явного выбора — не входит.
- Перенос найденного в карточку двигателя — не трогаем: поиск по названию даёт фото, а не поля карточки.
- Открытие картинок во внешнем диспетчере фото ОС (Picture Manager / Photos) — отдельная развилка, не в этой нитке.
- Раздел на планшете — не входит: раздел `file_search` не входит в `ANDROID_TABS`/`TABLET_OPERATOR_TABS`, каналы `fileSearch:` на планшете не регистрируются.
