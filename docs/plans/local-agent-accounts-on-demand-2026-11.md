## Разрез 1 (этот PR) — аккаунты по надобности и тишина

**Решение совета** ([`council/2026-11-27-local-agent-accounts/99-verdict.md`](council/2026-11-27-local-agent-accounts/99-verdict.md)):
правило «что видит оператор» живёт в домене; причина едет **машинным кодом**; перебор ограничен.

**Правится:** `shared/src/domain/aiChatSchedule.ts` (домен статусов — причина, слова, строка),
`electron-app/src/main/services/localMiniMax/localMiniMaxEngine.ts` (перебор, лимиты, чистка),
`electron-app/src/main/services/localMiniMax/karmanPool.ts` (написание причин — как у сервера),
`electron-app/src/renderer/src/ui/components/AiAgentChat.tsx` (строка — из дома),
`android-app/src/shims/localMiniMaxService.ts` (новый формат статуса),
сторож `localAiChatBoundary.guard.test.ts`, тесты домена и движка.

1. **Доказательство простоя.** Тест: движок поднят, статус опрошен (панель так делает при
   монтировании и по таймеру) — счётчик запросов пула равен нулю; первый запрос уходит только
   после задания. Сторож: `runLocalAnswer` зовётся ровно из `aiChat:create`, `answerQuestionLocally` —
   ровно из клея.
2. **Перебор аккаунтов.** Отказ аккаунта (маркеры `AUTH_FAILURE_MARKERS`) ⇒ продление **своего**
   аккаунта (не съедает ёмкость пула) ⇒ если не помогло — **свежий** аккаунт у пула и повтор
   задания. Ограничители: не больше одного свежиго аккаунта; пул, вернувший тот же id, второй раз
   не берём; бюджет ожидания 5 минут (дальше вопрос считает сервер); отказавший вход чистится из
   профиля, иначе следующий вопрос переиспользовал бы мёртвый токен.
3. **Честная пустота.** Причина пустоты пула доезжает до оператора **различимой** — «нет свободных»,
   «нет готовых», «нет пригодных» — и только когда работать нечем. Написание кодов — как у сервера
   (`no_handable_accounts`): своя копия словаря расходится молча, и третья причина тогда не
   сойдётся никогда (ADR-0011).
4. **Тишина.** В статусе — **код причины**, не свободный текст: слова собирает домен
   (`aiChatLocalStatusLine`), служебные подробности уходят в лог клиента. Красный остался только
   у «не отвечает никто»; отказ локального звена — синяя строка «считает сервер» с причиной.
5. **Давний отказ протухает** (15 минут): причина теряется, строка перестаёт врать, а локальный
   claim оживает без перезапуска клиента.

**Проверка:** `corepack pnpm -F @matricarmz/electron-app test` (движок + домен + сторож),
`corepack pnpm -F @matricarmz/shared test`, `typecheck`, `typecheck:test`, `lint` — зелёные.
Живая проверка на стенде `lane1` (CDP): строка статуса в панели ИИваныча рисуется и не содержит
ни кодов, ни служебных слов — **6/6 PASS**, доказательства —

Локальная ветка статуса на стенде не наблюдаема (движок ИИваныча там выключен, `aiEnabled: false`)
— она закрыта юнит-тестами; живая приёмка локального звена — на машине с настроенным рантаймом.

## Разрез 2 — общий реестр клиентских инструментов (решение совета)

**Совет:** тройка (Хранитель прав · Производственник · Оболочщик) —
[`council/2026-11-27-local-agent-tools/`](council/2026-11-27-local-agent-tools/99-verdict.md).

**Решения совета (коротко):**
- слой «право + текст отказа» **не заводим** — он уже есть (`ipcContext.ts` + `sectionGate.ts`),
  инструмент зовёт существующие двери и возвращает их отказы как есть;
- реестр живёт **в main** (`services/localMiniMax/agentTools/`): гейт раздела есть только в main;
- гейт раздела надо **взять с собой**: он накрывает только `ipcMain.handle`, а действие из канала
  прошло бы мимо него ⇒ инструмент оборачивается тем же гейтом под тем же именем канала;
- мост «реплика → агент» остаётся **read-only**, действия идут **отдельным каналом** (агент —
  отдельный процесс, IPC ему недоступен: единственный путь — именованный канал + MCP поверх stdio,
  второй MCP-сервер в том же `.mcp.json`);
- первый инструмент — **«подготовить номера»**, он **не пишет**: разбирает данные и открывает
  существующую модалку «Добавить списком» с готовым списком; добавляет оператор, как сегодня.
  Причина: `productionProgram:saveRows` — **полная замена** набора строк на сервере, а слияние с
  сервером живёт в renderer ⇒ запись из main **стёрла бы несохранённую правку оператора**;
- тело «Добавить списком» (разбор → отчёт → строки) выносится из модалки в **домен**: пока оно в
  компоненте, любой второй вызовчик = вторая копия правила дублей;
- агент **не заводит карточки** двигателей;
- аудит — **до** записи, семейство `agent.<домен>.<операция>`, `actor` = оператор.

**Шаги:**

1. **Домен** (`shared/src/domain/productionProgramAddByNumbers.ts`, новый): чистая функция
   «разобрать номера → отчёт по каждому → строки + причины отказов» (переезд из
   `ProductionProgramAddEnginesByNumbersDialog.tsx`). Сторож страницы ПП продолжает проверять, что
   правка строк идёт только через `applyRows`.
2. **Реестр** (`electron-app/src/main/services/localMiniMax/agentTools/registry.ts`, новый):
   `{id, titleRu, requires: PermissionCode[], section, level, handler}`; обработчик зовёт те же
   сервисные функции, что и интерфейс, и оборачивается **тем же гейтом раздела**.
3. **Гейт инструмента** (`.../agentTools/gate.ts`, новый): право → раздел → режим просмотра; отказ —
   текстом гейта. В `sectionGate.ts` — один экспорт наружу (доступ к разделу вне IPC).
4. **Канал действий** (`.../localMiniMax/actionBridge.ts`, новый): отдельный именованный канал,
   свой токен, только зарегистрированные инструменты. «Универсального канала вызова любого IPC» не
   делаем — гейт разделов работает по префиксам каналов.
5. **MCP-сервер действий** (`electron-app/resources/local-minimax/matrica-actions-mcp.mjs`, новый) +
   второй сервер в `.mcp.json`: чтение (`matrica-db`) и действия — разделены.
6. **Первый инструмент — «подготовить номера»**: разбирает данные (список / Excel / Word) в номера
   и открывает существующую модалку «Добавить списком» с готовым списком. Разбор Excel/Word
   выносится из приватных функций `fileSearchService.ts` в общий модуль — второй ридер не заводим.
7. **Аудит**: префикс `agent.` в `shared/src/domain/auditObject.ts`, подпись действия в
   `shared/src/labels/auditAction.ts`, запись — **до** записи (как в `engine:delete`).
8. **Сторож** (`agentTools.guard.test.ts`): инструмент объявлен только в общем реестре; у каждого
   есть право и раздел; агент не пишет в реплику мимо моста; канал БД не умеет действий; в реестре
   нет ни одного **собственного** текста отказа.
9. **Тесты**: домен (неоднозначный → ничего; повтор → одна строка; отгруженный → не берётся),
   реестр (гейты и отказы), канал действий (токен, неизвестный инструмент).

**Кнопка нейросети в ПП (разрез 3, по советам):** рядом с «Добавить списком» — **не** в
`v2ButtonCatalog`/`menuActions`/`PageToolbar` (это каталог кнопок меню и вёрстка ряда). Кнопка
открывает **ту же** вкладку «ИИваныч» (второго чата не заводим) и префиллит композер; контекст
раздела едет **в тексте вопроса** — единственное поле, которое доезжает и до сервера, и до
локального агента; формат контекста собирает домен. На планшете кнопка прячется (канала действий
там нет).

## Разрез 3 — производственная программа (первый раздел внедрения)

стать **записью в реестре действий приложения** (разрез 2) — тогда агент зовёт её, а не кликает по DOM.

Разбор Excel/Word в чате тоже нужен (сейчас разбор есть только в поиске по файлам,
`fileSearchService.ts:334-339`).

### Приёмка 28.11.2026 — машина с локальным рантаймом MiniMax

Раздел 4 закрыт по коду; дальше нужна была **живая приёмка** — машина, где настроен локальный
рантайм MiniMax. Стенд lane1 на PC79 (backend 3002, БД `matricarmz_dev_lane1`, renderer 5174,
CDP 9223) с рантаймом MiniMax Code 0.7.4 и настоящим пулом «Кармана».

**Интерфейс принят:** кнопка на месте в разделах и несёт свой раздел; клик открывает ту же
вкладку «ИИваныча» с вопросом, в котором едет контекст раздела (домен, не страница); строка
статуса переключилась на ветку локального звена.

**Звено было сломано в трёх местах — все три починены (подробности и факты в
[`pending/lokalnyy-minimax-na-kliente-privyka-i-runtaym.md`](../pending/lokalnyy-minimax-na-kliente-privyka-i-runtaym.md) §0.1):**

1. `spawn EINVAL` — npm-шим ссылается на пакет путём `%dp0%`, разбор знал только `%~dp0`.
2. «Sign in to MiniMax» — рантайм читает ещё и `auth-state.json`, а в записи не хватало
   `tokenType` и строкового `accountId`.
3. `MCODE_REGION` стоял `'prod'` — рантайм брал свой регион, а вход лежал в другом.

Плюс признак отказа во входе теперь ищется и в stderr прогона (иначе правило «при отказе
аккаунта берём свежий» не срабатывало).

**Что осталось за владельцем:** баланс на аккаунтах пула (модель отвечает «insufficient balance
(1008)» — цепочка до запроса доходит целиком) и рантайм в сборке парка (в CI нет шага, который
готовит `electron-app/build/local-minimax/`).

**Глобальная линза (три строки):**
> Глобальная линза: кандидат — модуль локального звена (`electron-app/src/main/services/localMiniMax/`) ·
> дубль: нет (своей копии запуска MiniMax Code в проекте нет) · действие: доработать существующий
> модуль — правки в `agentProfile.ts` (формат входа + файл состояния), `agentRunner.ts` (разбор
> npm-шима и регион) и `localMiniMaxEngine.ts` (признак отказа во входе).

**Заводская линза (три строки):**
> Заводская линза: кнопка в разделах производства · затор: не кормит (главный затор — ручной
> подбор деталей из фонда при сборке; кнопка лишь открывает чат) · поток: не ломает (кнопка ничего

## Границы нитки

- Прод не трогаем: клиентский контур, тесты на стенде.
- Секреты (токен комнаты, токены аккаунтов) — только в профиле на диске, не в коде и не в логах.
- Реестр глобальных модулей: локальный агент в него **не внесён** — это находка; правку реестра
  вносим отдельным коммитом рядом с кодом (курируемый документ — его правку должно быть видно).
