## Дыры против критериев приёмки промта #176

| Критерий промта | Состояние | Дыра |
|---|---|---|
| 1. При простое запросов к пулу нет | **выполнено по коду**, но без доказательства | нет теста «счётчик запросов пула = 0 при простое» |
| 2. Аккаунт берётся только при появлении задания | выполнено | доказательства нет (тот же тест) |
| 3. При отказе — свежий аккаунт, задание доводится | **не выполнено** | берётся только продление своего аккаунта; свежий — нет |

| 5. «Аккаунтов нет» ≠ «сервис сломался» | **не выполнено** | причина пустоты пула сворачивается в одну |

## Разрез 1 (этот PR) — аккаунты по надобности и тишина

**Решение совета** ([`council/2026-11-27-local-agent-accounts/99-verdict.md`](council/2026-11-27-local-agent-accounts/99-verdict.md)):
правило «что видит оператор» живёт в домене; причина едет **машинным кодом**; перебор ограничен.

**Правится:** `shared/src/domain/aiChatSchedule.ts` (домен статусов — причина, слова, строка),
`electron-app/src/main/services/localMiniMax/localMiniMaxEngine.ts` (перебор, лимиты, чистка),
`electron-app/src/main/services/localMiniMax/karmanPool.ts` (написание причин — как у сервера),
`electron-app/src/renderer/src/ui/components/AiAgentChat.tsx` (строка — из дома),
`android-app/src/shims/localMiniMaxService.ts` (новый формат статуса),
сторож `localAiChatBoundary.guard.test.ts`, тесты домена и движка.

1. **Доказательство простоя.** Тест: движок поднят, статус опрошен (панель так делает при
   монтировании и по таймеру) — счётчик запросов пула равен нулю; первый запрос уходит только
   после задания. Сторож: `runLocalAnswer` зовётся ровно из `aiChat:create`, `answerQuestionLocally` —
   ровно из клея.
2. **Перебор аккаунтов.** Отказ аккаунта (маркеры `AUTH_FAILURE_MARKERS`) ⇒ продление **своего**
   аккаунта (не съедает ёмкость пула) ⇒ если не помогло — **свежий** аккаунт у пула и повтор
   задания. Ограничители: не больше одного свежиго аккаунта; пул, вернувший тот же id, второй раз
   не берём; бюджет ожидания 5 минут (дальше вопрос считает сервер); отказавший вход чистится из
   профиля, иначе следующий вопрос переиспользовал бы мёртвый токен.
3. **Честная пустота.** Причина пустоты пула доезжает до оператора **различимой** — «нет свободных»,
   «нет готовых», «нет пригодных» — и только когда работать нечем. Написание кодов — как у сервера
   (`no_handable_accounts`): своя копия словаря расходится молча, и третья причина тогда не
   сойдётся никогда (ADR-0011).
4. **Тишина.** В статусе — **код причины**, не свободный текст: слова собирает домен
   (`aiChatLocalStatusLine`), служебные подробности уходят в лог клиента. Красный остался только
   у «не отвечает никто»; отказ локального звена — синяя строка «считает сервер» с причиной.
5. **Давний отказ протухает** (15 минут): причина теряется, строка перестаёт врать, а локальный
   claim оживает без перезапуска клиента.

**Проверка:** `corepack pnpm -F @matricarmz/electron-app test` (движок + домен + сторож),
`corepack pnpm -F @matricarmz/shared test`, `typecheck`, `typecheck:test`, `lint`; живая проверка —
стенд `lane1` (CDP): панель ИИваныча при отказе пула показывает человеческое сообщение, а не
«Карман ответил 500».

## Разрез 2 (следующий PR) — общий реестр клиентских инструментов

Мост «реплика → агент» — read-only **намерно** (база завода под защитой), поэтому действие агента —
это команда приложения, выполненная приложением от имени оператора, с его правами и в его аудите.

- Реестр инструментов клиента: чтение данных (уже есть — MCP-мост `dbBridge.ts`) + действия
  приложения (каждое действие — с проверкой права и своим текстом отказа).
- Образец — серверный `backend-api/src/services/ai/llmTools.ts` (реестр + проверка прав + отказ
  при недостаточном праве + предел выборки строк).
- Нужен **один** реестр на программу (п. 11 промта), а не по реестру на раздел.

## Разрез 3 — производственная программа (первый раздел внедрения)

П. 8 и 12 промта: кнопка нейросети рядом с «Добавить списком»; оператор закидывает номера списком /
Excel / Word; нейросеть сама проверяет, что уже есть, и **вызывает существующую функцию**
«Добавить списком» (дубли не создаются).

Найденное препятствие: «Добавить списком» — локальная модалка страницы
(`ProductionProgramAddEnginesByNumbersDialog.tsx`), публичного IPC нет, программно её можно открыть
только кликом по `data-pp-action="add-by-numbers"`. Значит, действие «добавить списком» должно
стать **записью в реестре действий приложения** (разрез 2) — тогда агент зовёт её, а не кликает по DOM.

Разбор Excel/Word в чате тоже нужен (сейчас разбор есть только в поиске по файлам,
`fileSearchService.ts:334-339`).

## Разрез 4 — кнопки нейросети по разделам

П. 6 промта: в каждом разделе кнопка, открывающая чат **с контекстом раздела**. Найдено: пропс
`context` у `AiAgentChat` объявлен, но **не используется** (`AiAgentChat.tsx:116`) — в запрос уходят
только `{questionText, filePath}` (`:310`). Значит, контекст раздела надо довести до запроса.

Порядок внедрения (п. 12): производственная программа и добавление двигателей списком — первыми
(там проверка дублей однозначна), дальше — по очереди. Порядок разделов — за владельцем (закрыт по
умолчанию: ПП → двигатели → дефектовка → склад → заказы/контракты → производство/наряды).

## Границы нитки

- Прод не трогаем: клиентский контур, тесты на стенде.
- Секреты (токен комнаты, токены аккаунтов) — только в профиле на диске, не в коде и не в логах.
- Реестр глобальных модулей: локальный агент в него **не внесён** — это находка; правку реестра
  вносим отдельным коммитом рядом с кодом (курируемый документ — его правку должно быть видно).
