# Скрипты обслуживания: плитка на Верстаке запускает окно сразу, инструкция при старте не лезет

**Заказ владельца:** 2026-11-19 (в сессии) — «убери запуск окна инструкции для сисадмина в начале запуске программы после обновления» и «при щелчке по ярлыку Скрипты обслуживания на Верстаке, сразу запускалось окно скрипта обслуживания, без запроса прав администратора … автоматически распаковывался архив со скриптами и запускался главный скрипт с графическим окном … сбор инфы о компе и программе и создание ссылок для вставки в Касперский».
**Связано:** [`kaspersky-exclusions-no-elevation-2026-11.md`](kaspersky-exclusions-no-elevation-2026-11.md) (PR3: автопоказ и кнопка), [`docs/gotchas/M200.md`](../gotchas/M200.md), [`docs/gotchas/M201.md`](../gotchas/M201.md), ADR-0003.

## Что было

1. **Автопоказ инструкции.** Установщик писал метку `kaspersky-setup-needed.flag` при установке с нуля (`${ifNot} ${isUpdated}`), клиент при входе её читал и показывал окно `KasperskySetupDialog`. Метка снималась только после нажатия «Готово» — не закрыли окно крестиком, и **инструкция лезла при каждом запуске**, в том числе после обновления. Это и есть жалоба владельца.
2. **Плитка «Скрипты обслуживания» на Верстаке** открывала **внутрипрограммное справочное окно** (`ClientOpsDialog`), а уже из него кнопка «Открыть окно обслуживания» распаковывала архив и поднимала `matrica-ops.ps1`. Лишний щелчок и лишнее окно на пути к нужному.

## Решение

### 1. Автопоказ — долой (инструкция остаётся доступна по кнопке)

- Клиент больше **не читает метку и не показывает окно при старте**.
- Установщик **не пишет метку**: макрос `MarkFreshInstall` убран целиком — он больше ни на что не влияет, а оставленная метка вводила бы в заблуждение следующего читателя.
- IPC-двери `clientOps:freshInstallPending` / `clientOps:freshInstallAck` и их проводка (preload, типы) — сняты.
- **Инструкция не пропала:** она по-прежнему открывается кнопкой «Инструкция для администратора» в справочном окне (пункт МЕНЮ «Сервис» → «Скрипты обслуживания»).

### 2. Плитка на Верстаке → сразу окно скрипта

- Щелчок по плитке **распаковывает архив и запускает главный скрипт** `matrica-ops.ps1` (окно с вкладками; по умолчанию — вкладка «Касперский», где и собирается информация о компьютере и готовятся списки исключений и доверенных программ).
- **Прав администратора не спрашиваем:** сам скрипт права не поднимает (это сделано в PR1 плана по Касперскому) и работает в учётке пользователя.
- **Если запуск не удался** (нет PowerShell, политика запуска, нет архива в сборке) — открывается **справочное окно**: там архив в проводнике, копия в «Загрузки» и пароль, то есть запасной путь не теряется.
- Пункт МЕНЮ «Скрипты обслуживания» остаётся **справочным окном** (инструкция для администратора + запасные пути) — это единственный вход к инструкции после снятия автопоказа.

## Что не делаем

- Не поднимаем права и не добавляем новых запросов UAC: окно обслуживания по замыслу работает без администратора.
- Не убираем инструкцию для сисадмина — убираем только её **автоматический** показ при старте.
- Не меняем содержимое архива скриптов и сам `matrica-ops.ps1` (он уже без прав администратора).

## Что нашлось по пути (и почему окно не открывалось НИКОГДА)

Плитка запускала окно «по правилам» — архив распаковывался, `spawn` возвращал успех, оператор
получал уведомление «Открываю окно обслуживания», **а окна не было**. Причина — флаги запуска в
Node: `detached: true` (DETACHED_PROCESS) и `windowsHide: true` (CREATE_NO_WINDOW) оставляют
процесс **без консоли**, и графическое окно WinForms при этом не показывается (при `detached`
процесс к тому же уходит сразу, код 0).

Проверено перебором вариантов на живом клиенте (19.11.2026):

| Запуск | Процесс | Окно «Матрица РМЗ — обслуживание машины» |
|---|---|---|
| `detached: true`, `windowsHide: true` | умер, код 0 | нет |
| `detached: false`, `windowsHide: true` | жив | **нет** |
| `detached: false`, `windowsHide: false` | жив | **есть** |
| `detached: false`, `windowsHide: false`, `-WindowStyle Hidden` | жив | **есть** (консоль спрятана) |

Лечение: консоль прячет **сам PowerShell** (`-WindowStyle Hidden`), а `spawn` идёт без `detached`
и без `windowsHide`. Грабля — [M214](../gotchas/M214.md).

То есть требование владельца «по щелчку сразу запускалось окно» выполнено не только новым
маршрутом, но и починкой самого запуска: старый путь («Открыть окно обслуживания» в справочном
окне) был сломан так же — окно обслуживания не открывалось с момента своего появления.

## Стражи

- `kasperskySetup.guard.test.ts` — переписан: автопоказа быть НЕ должно (ни в App, ни в preload/IPC/типах, ни метки в установщике), а инструкция по кнопке — обязана.
- `ClientOpsShortcut.guard.test.ts` — плитка ведёт на запуск окна, а не в справочное окно; запасной путь при отказе — есть; запуск не должен использовать `detached`/`windowsHide` (M214).
- CDP-смоук `.claude/skills/verifier-electron/scripts/cdp-client-ops-launch.mjs` — **7/7 PASS** на живом клиенте: окно инструкции при старте не вылезло, щелчок по плитке поднял живой процесс `matrica-ops.ps1`, справочное окно не открылось, окно скрипта закрыто за собой.
