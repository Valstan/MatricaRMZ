# План: темы оформления («Строго/Красиво») + эргономика интерфейса

**Status:** DRAFT (не начат). Делать ПОСЛЕ вкладочной оболочки (tabs-window-shell-2026-07.md) — иначе украшать придётся дважды.
**Заказ владельца:** 2026-07-27.

## Требования владельца

1. **Переключатель оформления «Строго / Красиво»** (строгое и украшенное).
2. **Украшенное:** разнообразие цвета, завитушки, даже цветочки — колорит, привлекательно для глаз, проявить фантазию.
3. **По ~5 цветовых гамм у каждого варианта** (на разный вкус).
4. **Строгое тоже улучшить:** данные в строках/блоках не должны сливаться в трудноразличимую массу (зебра, разделители, контраст, воздух).
5. **Эргономика:** перегруженные информацией места разгрузить — разделить на блоки или на разделы-вкладки со взаимосвязанным редактированием.

## Подход

**Сначала концепция, потом реализация** (так просил владелец).

### Фаза A — концепция — ✅ 2026-07-27 (превью у владельца)
**Инвентаризация:** система токенов УЖЕ есть и полная — `global.css` :root держит ~100 CSS-переменных (surface/border/text, кнопки, списки-зебра, карточки, tone-бейджи), темы `light`/`dark`/`warm` переключаются `data-theme` на :root, персист per-user (`uiPrefs.theme`). Новых «--mx-*» токенов не нужно — надстраиваемся на существующие.

**Принятая модель** (2 ортогональных настройки поверх существующей темы яркости):
- `uiPrefs.decor: 'strict' | 'fancy'` → `data-decor` на :root. Strict = текущий вид + улучшения читаемости; fancy = декоративный слой (градиентные шапки, орнаментальная кайма SVG data-URI, цветочные акценты в заголовках) — только на контейнерах, НЕ в строках гридов (перф).
- `uiPrefs.palette: 'classic' | 'emerald' | 'terracotta' | 'lilac' | 'graphite'` → `data-palette` на :root; каждая — компактный оверрайд акцентных токенов (`--button-primary-bg`, `--input-border-focus`, `--card-panel-*`, `--app-bg-*`). Классика = текущая синяя (дефолт, оверрайд пустой).
- Существующий переключатель Авто/Светлая/Тёмная/Тёплая остаётся как есть (яркость ⊥ гамма ⊥ декор).

**Превью для выбора:** `ui-themes-preview.html` (отправлен владельцу 2026-07-27) — мини-макеты интерфейса в 5 гаммах × Строго/Красиво. Ждём выбора направлений/правок гамм.

### Фаза B — фундамент переключателей — ✅ 2026-07-27
- Сквозная цепочка: `SettingsKey.UiDecor/UiPalette` (sysDb) → `ui:prefs:get/set` → preload/shared-типы → `uiPrefs.decor/palette` в App → `data-decor`/`data-palette` на :root. Дефолты strict/classic = текущий вид, ничего не меняется без явного клика.
- Управление в шапке: кнопка «▦ Строго / ❀ Красиво» + селект «🎨 Гамма» (5 вариантов), применение мгновенное, персист per-workstation.
- CSS: 4 гаммы-оверрайда акцентных токенов (emerald/terracotta/lilac/graphite; classic = базовые) + декоративный слой fancy (кайма-градиент заголовков секций, ❀/❦-акценты, подцветка шапок панелей/таблиц) — только контейнеры, не строки гридов.
- Живой смоук: переключение fancy+emerald применяет атрибуты и токен (#059669), после рестарта main персист подтверждён.
- **Гаммы черновые** — цвета правим по выбору владельца из превью (фаза A). Fancy-декор пока минимальный, фаза D его насыщает.

### Фаза C — строгий режим: читаемость — ✅ 2026-07-27
- **Зебра заметнее** во всех трёх темах яркости: light alt `#eef2f7 → #e7edf5` (hover углублён, порядок base<alt<hover сохранён), dark alt `rgba(30,41,59,.88) → rgba(51,65,85,.85)`, warm alt/hover углублены.
- **Зебра для ad-hoc таблиц в карточках** (вложения, чек-листы, составы, строки документов): `color-mix`-оверлей по чётным строкам + границы строк — тема-независимо; цветные строки со своим inline-фоном не перекрываются. Проверено скриншотом (строки документа импорта 1С).
- **Границы**: `--border .18 → .22`, `--border-strong .28 → .34`, `--list-row-border .14 → .2` (light), рамка card-panel `.28 → .4`; dark row-border `.28 → .38`.
- **Контраст второстепенного текста**: `--subtle #64748b → #56657b`.
- Попутный фикс этапа 3 вкладок: заголовок вкладки складского документа читал не тот путь ответа — теперь `📦 <docNo>`.

### Фаза D — украшенный режим — ✅ 2026-07-27
**Решение владельца:** все 5 гамм остаются как есть — каждый оператор выбирает свою.
- Декор fancy насыщен (всё от `--input-border-focus` → следует гамме): градиентно-радиальный фон приложения с мягкими цветными пятнами, акцентная «прошивка» сверху панелей, завиток ⸙ у заголовков секций, скруглённые вкладки v3 с градиентной подложкой и ✿-маркером активной закреплённой, hover-подсветка меню, цветочный мотив пустых состояний, скроллбар и разделитель сплита в цвет гаммы.
- Всё на контейнерах, в строках гридов декора нет (перф). Проверено скриншотом (fancy + Сирень).

### Фаза E — эргономика перегруженных экранов — ✅ 2026-07-27 (первый проход)
Список владельца: карточка двигателя (дефектовка), карточка наряда, BOM.
- **Карточка двигателя:** статусные строки (7 шт: принят/начат ремонт/отремонтирован/отгрузка/…) вынесены из общего списка полей в сворачиваемый блок «Статусы ремонта» с бейджем числа активных (раскрыт, если есть активные). Основные реквизиты больше не тонут среди чекбоксов. Drag-порядок базовых полей сохранён (статус-коды дописываются в конец при персисте).
- **Карточка наряда:** блок «Подписи» свёрнут по умолчанию (заполняется при закрытии наряда, в повседневной работе загромождал).
- **BOM:** длинные предупреждения (рассинхрон типов, предупреждения сохранения) — `<details>`: заголовок с количеством виден всегда, список строк по клику.
- Проверено живьём (скриншот карточки TEST-001). Дальнейшая разгрузка — по жалобам после приёмки.

## Риски
- Декор × производительность больших гридов — декор только на уровне контейнеров, не строк.
- 10 комбинаций тем × все экраны = комбинаторика проверки: смоук прогонять на 2 крайних (строгая №1, красивая №1), остальные — точечно.
- Пересечение с планшетным режимом (крупные кнопки) — токены должны работать в обоих.
