# План: подписи печатных форм — редактируемый блок (добавление, правка, удаление)

**Основание:** заказ владельца 23.11.2026 (через Управляющего, meta-репо `brain_matrica`, область
`p-matricarmz3`): «В печатной форме блок подписей нужно сделать редактируемый, чтобы можно было
добавлять другие подписи, с другими людьми, с другими профессиями, должностями. Добавлять и удалять
подписи. А то сейчас вот производственную программу открыли на печать, и там надо добавить ещё одну
подпись, а мы не можем, никак».

**Порядок работ (по заданию):** сначала текущая нитка линии (шов с ПП) — она закрыта и смержена
(PR #1929), хвост (клавиатурное перемещение по ручке в ПП) ждёт кита другой линии; потом эта задача.

**Зона линии:** `shared/src/domain/productionProgram.ts`, `shared/src/domain/printSignatures.ts`
(новый общий слой), `pages/ProductionProgramPage.tsx`, `components/ProductionProgramPrintPreview.tsx`,
`components/PrintSignatureBlockEditor.tsx` (новый общий редактор), `utils/productionProgramPrintHtml.ts`.

## Что показала разведка по коду (23.11.2026)

1. **Корень — в домене:** `resolveProductionProgramSignatureSlots(saved)` возвращал **только** роли по
   умолчанию (`PRODUCTION_PROGRAM_SIGNATURE_SLOTS`), а сохранённые слоты, которых в этом списке нет,
   **отбрасывались**. Добавленная подпись исчезала из печати — ровно то, что описал владелец.
2. **Хранилище уже есть:** слоты лежат в программе строкой `signatureSlots` (JSON), ездят по
   `shared/src/sync/registry.ts` (`db: 'signatureSlots'` ↔ `dto: 'signature_slots'`) и пишутся
   серверной дверью `productionProgram.update` ✔ — хранить новый набор не нужно.
3. **Редактировать было негде:** в превью ПП (`ProductionProgramPrintPreview.tsx`) у подписей были
   только галочки «снять подпись»; в самой странице программы редактора слотов нет вовсе.
4. **Образец уже есть:** в наряде (`WorkOrderDetailsPage.tsx`) блок подписей редактируемый — «+
   Добавить подписанта», «+ Добавить пустую подпись», «Удалить», выбор сотрудника. Паттерн взят
   оттуда; **перетаскиваемость подписей не делалась** — задание прямо говорит «вообще без неё».
5. **Механизм шаблонов печати — отдельный и живой:** `shared/src/domain/printTemplate.ts` (`PrintTemplateField`
   с `source: 'signature_role'`, поля `role` и `requireDepartment`) + `PrintTemplateEditorDialog.tsx`
   умеют добавлять и править подписи по шаблонам. Этот механизм **не трогаем** и не дублируем.

## Какие формы печатаются мимо шаблона (ответ на вопрос задания)

| Форма | Как печатается | Блок подписей | Что сделано |
|---|---|---|---|
| Формы по шаблону (`printForms`: бланки СИЗ, карточки, списки) | шаблон + поля `signature_role` | в шаблоне, редактируется в редакторе шаблона | не трогаем — свой механизм, работает |
| **Производственная программа** | своё превью + своя модель печати (`productionProgramPrintHtml.ts`) | был только на галочках | **сделано** (общий слой) |
| Наряд | свой блок `signatureBlocks` в payload, свой лист | уже редактируемый | не трогаем (зона линии 1) |
| Списки (контрагенты, договоры, сотрудники, наряды, детали, свойства) | `printRowsPreview` | подписей нет | не трогаем |
| Прочие бланки (бирки, QR, инвентарь деталей) | свой HTML | подписей нет | не трогаем |

Итог: **мимо шаблона печатаются две формы — ПП и наряд**; наряд уже редактируемый, ПП — теперь тоже.

## Решение

1. **Общий слой подписей — `shared/src/domain/printSignatures.ts`:**
   - слот = должность + человек (`employeeId` из базы **или** ФИО, вписанное от руки);
   - `resolvePrintSignatureSlots(saved, defaults)`: сохранённое — **как есть** (добавленная подпись
     не теряется, удалённая — не возвращается); `null` — роли по умолчанию; пустой массив — «снял всё»;
   - `parse/serialize` — разбор и запись JSON в документ (мусор не роняет разбор, пустая подпись
     сохраняется: под неё подписывают от руки);
   - правки: `add/update/removePrintSignatureSlot`.
2. **Общий редактор — `components/PrintSignatureBlockEditor.tsx`:** строка подписи = должность
   (подсказки из ролей по умолчанию, можно вписать свою) + подписант из базы + ФИО от руки +
   «Удалить»; внизу «+ Добавить подпись»; галочка «печатать» — снимает подпись **только с этой
   печати** (правка печати), а не из документа.
3. **ПП подключает общий слой:** домен ПП делегирует общее правило (корень закрыт), превью печати
   показывает общий редактор, а правка состава **уходит в программу** (`onSignatureSlotsChange` →
   `setHeader({ signatureSlots })` → автосейв → сервер). Потому подпись печатается не только в
   превью, но и на бумаге (лист ПП). Выгрузка Word/Excel и буфер обмена несут только строки —
   подписей в них нет и раньше, это отдельный вопрос.
4. **Фильтр печати — по слотам, а не по должности:** должность теперь меняется, и две подписи могут
   оказаться с одинаковой должностью — фильтр по названию печатал бы не то.

## Доводка (отдельный PR, после мержа #1936)

Три правки в общем редакторе подписей и превью ПП — то, что ломало собственный сценарий приёмки
(см. [`docs/pending/print-signature-slots-acceptance.md`](../pending/print-signature-slots-acceptance.md)):

1. **Ключ строки React не должен содержать редактируемые поля.** Было `` `${caption}-${index}` ``
   ⇒ строка пересоздавалась на каждом нажатии клавиши, поле теряло фокус после первого символа.
   Теперь ключ по позиции строки.
2. **Снятые подписи — по содержанию слота, а не по индексу:** индекс сдвигается при любой правке
   состава, и снятая подпись возвращалась сама.
3. **Блок подписей ПП переведён на общий кит списков** (ручка «⠿», маркеры строк, граница списка) —
   **это меняет границу «общий кит не трогаем» из шага выше.** Основание: блок подписей **наряда**
   после фазы «карточек» (PR #1934) уже на ките, и два одинаковых по смыслу блока подписей в двух
   формах вели себя по-разному (D-248 — «везде одинаково»). Файлы кита при этом **не меняются**:
   подключается существующий `useListReorder` + `ListReorderHandle`. Своей перетаскиваемости
   (отдельного механизма) не вводится — ровно то, чего требовало задание линии 3.
