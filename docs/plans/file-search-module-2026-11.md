## Заводская линза (три строки)

- **Участок:** карточка двигателя и приёмка — оператор ищет сведения по конкретному двигателю в своих файлах (Excel/Word) и переносит их в карточку.
- **Кормит ли затор:** не кормит. Главный затор модели — «начало сборки: ручной подбор совместимых деталей из обезличенного фонда»; модуль ищет сведения по одному двигателю, а не детали в фонде. Косвенно помогает приёмке и дефектовке (быстрее находит «что известно про этот движок» в бумажном виде).
- **Инвариант потока:** не ломает. Обезличивание деталей, партия/экземпляр (`stamped_number`), подпись и ответственный, маршрутный лист, сдельщина против нормо-часов не затрагиваются: модуль пишет только атрибуты карточки двигателя и только через единственную дверь `saveEngineCardGated` (с гейтами дублей и авто-этапами).

## Что уже есть (сверено с кодом, а не по памяти)

- **Чтение Word у нас уже есть.** `shared/src/domain/docxText.ts` — чистая функция `docxXmlToText(xml)`: `<w:p>` → строки, `w:tab`/`w:br` → разделители, XML-сущности раскодируются. `electron-app/src/main/services/fileService.ts:857` (`filesReadPastableText`) читает `.docx` как zip (JSZip) и отдаёт текст. **Переиспользуем, не пишем вторым reader'ом.**
- **Чтения Excel в клиенте нет.** `exceljs` в `electron-app` есть (`package.json:37`), но он используется только для **выгрузки** (`main/services/listExportService.ts:19`, `main/services/ppeOneCExportService.ts:15`). Ридера xlsx в клиенте не существует — пишем свой, на том же `exceljs`.
- **Сборщики (exceljs/docx/jszip) живут в main — их место у файловой системы, а не в окне.** Это зафиксировано сторожем `electron-app/src/renderer/src/ui/components/ListChrome.guard.test.ts:487-491`. Renderer в нашем модуле файлы не читает и путей «из воздуха» не подделывает.
- **Диалог выбора файлов уже есть.** `files:pick` (`main/ipc/register/files.ts:47`) — мультивыбор с `rememberIssuedPath` (allowlist путей, TTL 30 мин). Наш диалог будет свой (фильтры xlsx/docx/txt/csv), но по этому же образцу.
- **Единственная дверь записи карточки.** `saveEngineCardGated` (`main/services/engineCardWrite.ts:33`) ← IPC `engines:card:save` (`main/ipc/register/engineCards.ts:52`): белый список кодов (`isKnownEngineCardCode`, 58 кодов — `engineCardsReplica.ts:17-75`), гейт дубля по `engine_number`, гейт дубля по паре (внутренний номер, год), deferred-create, авто-этапы из дат. Право — `engines.edit`.
- **Готового «найди двигатель по номеру и отдай карточку» API нет.** `findEngineDuplicateByNumber` (`engineService.ts:1727`) — строгое совпадение по канон-ключу, но наружу не выведен; `engine:findDuplicateCandidates` (`engineService.ts:1906`) отдаёт `exact`+`similar` и отключается при длине ключа < 3. Точный поиск — новый канал, без `similar`.
- **Три разных номера у двигателя**, «внешнего» нет: документный `engine_number` (уникален по канон-ключу `normalizeLookupCompact`), внутренний клеймо `engine_internal_number` + `engine_internal_number_year` («41/26»), сквозной `rmzCode`. Ищем по обоим — оба **точно**.
- **Характеристики карточки — динамические**: `attribute_defs` типа «Двигатель» (`getEngineAttrDefs`, `engineService.ts:104`). Статического каталога «всех характеристик движка» в коде нет; перечень дефов читаем из БД, а не выдумываем.
- **Разделы и каналы — по реестрам, а не «куда влезет».** Реестр разделов — `shared/src/domain/uiSections.ts` (`TabId`, `menuTabSet`, `MENU_TAB_LABELS`, `DEFAULT_GROUP_TABS`), картинки — `renderer/.../layout/Tabs.tsx` (`TAB_VISUALS`), доступ по разделам — `shared/src/domain/sectionAccess.ts`, гейт каналов в main — `main/ipc/sectionGate.ts` (`PREFIX_RULES`, `WRITE_CHANNELS`). Страница, на которую не ссылается ни один модуль `ui/`, валит гейт `scripts/check-dead-pages.mjs`.
- **Машинно-локальное хранилище настроек** — `sync_state` (key/value) через `main/services/settingsStore.ts` (`SettingsKey`). Прецедент: `files.downloadDir` — папка выбирается один раз и запоминается локально.

## Решения (уточнения плана библиотеки под наш код)

1. **Модуль живёт в клиенте, читает файлы в main.** Файлы оператора лежат на его диске и в его сети — сервер их не видит и не должен. Чтение — `main/services/fileSearchService.ts` (`exceljs` для xlsx, `JSZip`+`docxXmlToText` для docx, plain-текст для txt/csv). Renderer получает только результаты.
2. **Пути к источникам храним машинно-локально, в `sync_state` (`SettingsKey.FileSearchSources`), per-user.** Не в `ui_profile_json`: профиль **роумится** (сервер, `user_settings`), а путь к файлу на другой машине невалиден — такой «роум» приносил бы только недоступные файлы. Прецедент — `files.downloadDir`. Санитайзер профиля не трогаем, чужие секции не стираем.
3. **Свежесть: перед каждым поиском файлы перечитываются.** Кэша между поисками не держим — «поиск идёт по свежей версии» буквально. Внутри одного поиска перечитывания нет (граница «одного поиска» ≈ 5 минут из промта): читаем один раз на старте поиска и ищем по этой памяти.
4. **Недоступный файл — не молчим.** Собираем по каждому недоступному файлу сообщение **с полным путём** («файл недоступен — откройте его заново»), показываем оператору списком и **продолжаем** поиск по остальным файлам. Файл, ставший недоступным посреди поиска, — тот же порядок (ошибка при чтении → в тот же список).
5. **Поиск — по значениям ячеек (Excel) и по тексту абзацев (Word), регистронезависимо, вхождением подстроки.** Excel: сохраняем **номер строки, наименования столбцов и всю строку целиком**. Word: показываем найденный абзац и **спрашиваем** оператора, показать ли строки ниже (вопрос, а не молчаливое усечение).
6. **Справа — карточка двигателя по ТОЧНОМУ совпадению номера.** Ищем и по документному номеру (канон-ключ), и по внутреннему клейму «41/26». «Похожее» не берём: план библиотеки прямо запрещает эвристику. Нет карточки — пишем «в базе нет», а не пустую панель. Показываем заполненные характеристики и **перечень недостающих** (по дефам «Двигатель» из БД).
7. **Перенос — только через `engines:card:save`.** Это единственная дверь с гейтами дублей и авто-этапами; второй вход «в обход» разошёлся бы с ней (класс brain G363). Писать в карточку можно только коды из белого списка `CODE_TO_COL`.
8. **Автоперенос — только при совпадении типа и формата.** Правило: значение-дата → поле даты; значение «41/26» → пара внутреннего номера; текст → текстовое поле. Несовпадение типа/формата — **объяснение, а не молчаливая запись**. Перед переносом — предпросмотр «что будет скопировано → куда», и только потом кнопка «Скопировать данные в карточку двигателя».
9. **Ручное копирование работает всегда.** У каждого показанного значения — кнопка копирования в буфер обмена (`navigator.clipboard.writeText` — как в `ui/utils/listContextActions.ts:38`), откуда значение вставляется и в карточку двигателя. Правка карточки прямо в правой панели — работает всегда.
10. **Границы.** Только чтение: в выбранные файлы **не пишем** ничем (никакого «сохранить в файл»). Диск целиком не индексируем — только явно выбранные файлы. Большие книги Excel читаем с потолком (строк/столбцов) и временем — если файл не читается за разумное время, оператор получает сообщение, а не зависание.

## Этап A — домен и чтение файлов (PR A)

### A.1. Домен (`shared/src/domain/fileSearch.ts`)

- Типы: `FileSearchSource` (`id`, `path`, `name`, `kind: 'excel' | 'word' | 'text'`, `addedAt`, `size`, `modifiedAt`), `FileSearchExcelMatch` (`sheetName`, `rowNumber`, `headers`, `values`, `matchedColumnIndex`, `matchedValue`), `FileSearchWordMatch` (`paragraphIndex`, `text`, `snippet`, `hasMoreBelow`), `FileSearchUnreadable` (`path`, `reason`), `FileSearchResult` (`query`, `matches`, `unreadable`, `scannedFiles`, `durationMs`).
- Чистые функции: `matchExcelRows(rows, query)`, `matchWordParagraphs(paragraphs, query)`, `buildEngineCardTransferPreview(card, match)` (предпросмотр «поле ← значение» с совместимостью типа), `engineCardMissingCharacteristics(card, knownCodes)` (что в карточке не заполнено).
- Сторож: `shared/src/domain/fileSearch.test.ts` — матчинг строк, заголовки столбцов, Word-вопрос про строки ниже, совместимость типов в предпросмотре, «в базе нет».

### A.2. Чтение файлов (`electron-app/src/main/services/fileSearchService.ts`)

- `readSearchSource(path, kind)` → строки/абзацы; xlsx — `exceljs` (`workbook.xlsx.readFile`), docx — `JSZip` + `docxXmlToText`, txt/csv — plain-текст.
- `searchInSources(sources, query)` → `FileSearchResult`: недоступный файл → запись в `unreadable` с полным путём, остальные ищутся дальше.
- Потолки: `MAX_SHEET_ROWS` (строк на лист), `MAX_COLUMNS`, `MAX_MATCHES`, таймаут на файл — при превышении сообщение оператору, не зависание.

### A.3. IPC

- `fileSearch:pick` — свой диалог (`dialog.showOpenDialog`, мультивыбор, фильтры xlsx/xlsm/docx/txt/csv), возвращает `FileSearchSource[]`.
- `fileSearch:search` — `{ sources, query }` → `FileSearchResult`.
- `fileSearch:sources:get` / `fileSearch:sources:set` — машинно-локальное хранение в `sync_state` (per-user JSON).
- `engine:findExactByNumber` — точный поиск двигателя (документный номер **или** клеймо «41/26»): возвращает `{ id, engineNumber, internalNumberFull, rmzCode }` либо null. Без `similar`.
- Всё это в `main/ipc/register/fileSearch.ts` + регистрация в `registerIpc.ts` + объявление в `shared/src/ipc/types.ts` + прокси в `preload/index.ts`.
- Префикс `fileSearch:` → `PREFIX_RULES` в `main/ipc/sectionGate.ts` (раздел «Производство» — модуль работает с данными двигателей).

## Приёмка (критерии плана #33 → чем проверяем)

| # | Критерий | Проверка |
|---|---|---|
| 1 | Файл изменён на диске → следующий поиск покажет свежую версию | юнит-тест main: записать файл → найти → переписать → найти снова (результат изменился) |
| 2 | Из модуля нельзя изменить файл | в сервисе нет ни одной записи в файл (только `readFile`); сторож на странице |
| 3 | Файл стал недоступен → сообщение с путём, поиск по остальным продолжается | юнит-тест main: один путь битый + один живой → в `unreadable` путь, второй найден |
| 4 | Excel: наименования столбцов и все значения, каждое копируется | юнит-тест домена + сторож кнопки копирования |
| 5 | Word: найденный текст + вопрос про строки ниже | юнит-тест домена (`hasMoreBelow`) + страница спрашивает |
| 6 | Справа карточка с тем же номером: характеристики и недостающие; нет карточки — «в базе нет» | юнит-тест домена (недостающие) + смоук |
| 7 | Перенос: предпросмотр «что → куда», попадает в нужное поле; несовпадение типа не пишет молча | юнит-тест домена (совместимость) + запись идёт через `engines:card:save` |
| 8 | Кнопка копирования кладёт значение в буфер обмена | смоук: значение вставлено в карточку двигателя |

## Границы (что сознательно не входит)

- Поиск по PDF и по картинкам (OCR) — не входит: промт говорит про Excel и Word.
- Индексирование папок и сетевых каталогов целиком — только явно выбранные файлы.
- Перенос в сущности кроме карточки двигателя — только при **точном** соответствии полей; сейчас таких соответствий нет, поэтому перенос только в карточку двигателя.
- «Похожее» по смыслу (эвристика) — запрещено планом: только точное совпадение номера.
