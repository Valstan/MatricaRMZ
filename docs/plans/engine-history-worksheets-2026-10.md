## Шаг A. Вкладка истории: только две кнопки (PR-1)

- Убрать всегда видимую инлайн-форму этапа (селект + дата + примечание + «Отметить этап»).
  Вверху остаются две кнопки: **«Добавить этап ремонта»** и **«Добавить запись»** («операцию» не трогаем).
- «Добавить этап ремонта» раскрывает форму: этап (селект) + **цех** (сейчас его нет — добавить,
  `stages.save` цех уже принимает, см. `BulkStageAddDialog.save`) + дата этапа + примечание
  (необязательно) + **«Применить» / «Отмена»** (как у ручной записи «Сохранить»/«Отмена»).
  Гейты (дубль-проход, отгрузка) остаются как были.
- «Добавить запись»: оставить **дата + действие (свободный ввод с подсказками) + цех + комментарий**;
  убрать **причину** и **«+ поле»** (произвольные extra-поля). Уже записанные причины/extra
  продолжают показываться в ленте — режем только ввод.
- Сторож: две кнопки вверху (`data-repair-history-add` + новая `data-repair-stage-form-open`),
  инлайн-селекта вне формы нет, причины и «+ поле» во вводе нет.

## Шаг B. Лента входит в окно без горизонтальной прокрутки (PR-2)

- Сейчас `table width:100%` + `whiteSpace: nowrap` + `overflowX: auto` — длинные «Причина и примечание»
  и «Кто» уезжают за край.
- Таблица центрируется (`margin: 0 auto`, `max-width` по контейнеру), колонки дат/типа — `nowrap`,
  «Событие»/«Цех»/«Примечание»/«Кто» — перенос (`normal`, `word-break: break-word`).
- Смоук CDP: открыть карточку с длинными примечаниями, горизонтального скролла нет, все колонки видны.
