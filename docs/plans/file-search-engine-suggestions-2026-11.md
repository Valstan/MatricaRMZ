# Поиск по файлам: подсказки номера двигателя и три режима поиска

> Первоисточник — промт КАРМАНА **#155** (зачитка владельца 25.11.2026, проект `MatricaRMZ`), прочитан 26.11.2026.
>
> Промт из библиотеки — **задание владельца, а не готовое решение** (`AGENTS.md` §«Промты и планы проекта из КАРМАНА»): он сверён с нашим кодом и уточнён ниже. Каждое уточнение помечено — чем решено и почему.

**Статус:** код готов 26.11.2026 (ветка `feat/file-search-engine-suggestions`). **Дата:** 2026-11-26. **Нить:** поиск по файлам → подсказки номера двигателя + режим «Фото двигателя».

## Заводская линза (три строки)

- **Участок:** приёмка и дефектовка — оператор находит фотографии двигателя в своей папке по номеру.
- **Кормит ли затор:** не кормит. Главный затор модели — «начало сборки: ручной подбор совместимых деталей из обезличенного фонда»; модуль ищет фото по номеру двигателя, а не детали в фонде. Косвенно помогает разбору: оператор сразу видит все снимки нужного двигателя, а не один случайно подошедший файл.
- **Инвариант потока:** не ломает. Модуль читает папки и локальную реплику карточек и ничего в них не пишет; записи в карточку двигателя не касается. Обезличивание деталей, партия/экземпляр (`stamped_number`), маршрутный лист и сдельщина не затрагиваются.

## Глобальная линза (три строки)

Глобальная линза: выпадашка подсказок — `electron-app/src/renderer/src/ui/components/SuggestInput.tsx` + `hooks/useSuggestionDropdown.ts` · дубль: нет (в реестре `docs/GLOBAL_MODULES.md` модуля подсказок нет; готовый блок проекта — `SuggestInput`, он и взят, самодельной выпадашки нет) · действие: **доработать** `SuggestInput` двумя аддитивными пропсами (`waitForOptions` — не показывать пустой список; `onSubmit` — Enter запускает поиск), поведение по умолчанию прежнее.

Ещё одна линза, по образу `ui/utils/counterpartyOptions.ts` («один источник контрагентов: строгая таблица + легаси-EAV, мёрж, подпись и поисковый текст для подсказок»): источник подсказок по номеру двигателя сделан так же — **один мёрж** (строгая реплика карточек + легаси-EAV, свежее побеждает) в одном сервисе, а не два чтения в двух местах.

## Решения (уточнения промта под наш код)

1. **Источник подсказок — отдельный IPC с лимитом по локальной реплике карточек** (`fileSearch:engineNumberSuggestions`), а не список двигателей в renderer: список тяжёлый (планшет, большая база), а точечный запрос с лимитом — дешёвый. **Почему не «по набитому номеру», как в глобальном поиске:** это другое поле (`stamped_number` в операциях), номером двигателя оно не является.
2. **Порядок выдачи — доменный: точное → суффикс → вхождение.** Совпадение буквальное («цифры есть в номере»), без «похожести на глаз»: правило живёт в `shared/src/domain/fileSearchEngineSuggest.ts` и проверяется тестом.
3. **Подсказки — только когда ввод похож на номер:** цифры и разделители, цифр не меньше четырёх. Слово («акт») подсказок не даёт — иначе выпадашка мешала бы искать по содержимому файлов.
4. **Запрос к базе — с задержкой 300 мс** (как `DEEP_DEBOUNCE_MS` в глобальном поиске).
5. **Выбор подсказки подставляет полный номер в строку** (не дописывает): в строке остаётся ровно полный номер, дальше — обычный поиск.
6. **Режим «Фото двигателя» — отдельная область совпадения** (`FileSearchFolderSearchScope = 'any' | 'folder'`), а не второй обход: совпадение только по названию ПАПКИ, находка — папка со всем содержимым. Старый режим не тронут (`any` — как было).
7. **Режимы — кнопками рядом со строкой поиска**, выбранный — залитой кнопкой плюс строка подсказки под рядом («что ищем» видно словами, а не только цветом).
8. **Переключение режимов отбор не трогает:** смена режима — только `setMode`; сброс отметок живёт в самом поиске (старые `id` выдал прошлый поиск, печатать их нельзя).
9. **Выпадашка — готовая компонента проекта** (`SuggestInput`). В неё добавлены два аддитивных пропса: `waitForOptions` (пустой список не показываем — «Нет совпадений» мешало бы вводу) и `onSubmit` (Enter в поле запускает поиск — раньше это делал `Input`).

## Приёмка (критерии промта #155 → чем проверяем)

| # | Критерий | Проверка |
|---|---|---|
| 1 | При вводе 4+ цифр выпадают подсказки с полными номерами из базы | юнит-тест сервиса + домена |
| 2 | Выбор подсказки подставляет полный номер в строку | сторож страницы (`onChange={setQuery}`) |
| 3 | Слово подсказок не даёт и вводу не мешает | домен (`isFileSearchEngineNumberLike`) + `waitForOptions` у `SuggestInput` |
| 4 | Режим «Фото двигателя»: только папка, в выдаче все её фотографии | юнит-тест main на фикстуре «папка `Э06АТ0889_41-26` с фото + одноимённый файл рядом» |
| 5 | Старые режимы не сломаны | юнит-тесты main (`scope` по умолчанию — `any`) + полный прогон тестов |
| 6 | Переключение режимов не сбрасывает отбор | сторож страницы (смена режима — только `setMode`) |
| 7 | Гейты зелёные | `corepack pnpm -F @matricarmz/electron-app test`, `corepack pnpm -r typecheck`, `lint` |

## Открытые вопросы владельцу

- **Сколько подсказок показывать:** взято 12 (как в глобальном поиске), потолок 20. Промт оставлял это на усмотрение владельца.
- **Что показывать в подсказке:** номер двигателя (главное — его и подставляем) + внутренний номер и номер РМЗ, если они есть. Марка не показана: в подсказке для поиска по папке она лишняя.
- **Внутренний номер в подсказках:** пока ищем по **номеру двигателя** («Э06АТ0889»); по внутреннему клейму («41/26») подсказок нет — папка названа по номеру двигателя, и это просил промт.
- **Потолок `MAX_IMAGES_PER_MATCH` (200 картинок в одной находке):** при срабатывании показываем замечание оператору («показаны первые 200 картинок из N») — как было. Отдельного решения владельца не требовалось.
- **Печать и действия над найденным** — отдельные заявки («печать из результатов поиска», «контекстное меню по выбранным файлам»), здесь не дублируются.

## Границы (что сознательно не входит)

- **Печать из результатов и контекстное меню** — отдельные заявки.
- **Поиск по PDF и OCR** — не входит (было не входит).
- **Индексирование диска целиком** — не входит: папки выбирает оператор, как раньше.
- **Табличный раздел на планшете** — не входит: домен `FileSearch` на планшете объявлен исключением с причиной (`android-app/src/core/tabletDomains.ts`), префикс `fileSearch:` покрывает и новый канал.
