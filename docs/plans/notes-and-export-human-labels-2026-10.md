## 1. Заметки: набранный текст стирался сам

**Симптом.** Печатаешь в заметке — через мгновение текст исчезает и возвращается серверная копия.

**Причина.** Эффект слияния серверных заметок с черновиками зависел **от собственной карты отметок**:

```ts
useEffect(() => { … }, [notes, dirty]);   // было
```

Проход эффекта ставил новую карту `dirty` → зависимость менялась → эффект перезапускался → на следующем проходе читал снимок, где отметки `dirty` для этой заметки ещё не было (она появлялась в том же проходе), и подставлял в `textarea` серверный текст. Плюс автосохранение брало `drafts[id]` из замыкания рендера — версия без последнего символа.

**Правка.**
- Домен черновиков вынесен в `ui/utils/noteDrafts.ts`: `mergeDraftsFromNotes`, `pruneDirtyFlags`, `markDirty`, `clearDirty`, `noteDraftFromNote`, `ensureTextBlock`, `makeAutoTitle`, `getTextFromBody`, `newNoteBlockId`. Слияние возвращает **тот же объект**, если ничего не поменялось, — эффект не гоняет лишние рендеры.
- `NotesPage.tsx`: зависимость эффекта — только `[notes]`; отметки читаются через `dirtyRef`, сохранение — через `draftsRef`. Правило зафиксировано в комментарии домена: **несохранённый текст сильнее серверной копии**.

**Сторожа.** `noteDrafts.test.ts` (9) — слияние, отметки, автотайтл. `NotesPage.guard.test.ts` (4) — эффект не зависит от `dirty`, сохранение читает `ref`, а не замыкание.

## 2. Выгрузка Word/Excel/письмо: только наименования

**Причина (прод-случай).** Текст ячейки рождается в рендерере: страница описывает колонку как `render → ReactNode`. Если в разметке стоит `{row.customerId}`, в файл уезжает `8f14e45f-ceea-…`. Отдельная беда — **шапка отбора**: ступень без справочника (`Заказчик`, `Контракт`, `Марка`, `Цех`) хранит значением идентификатор, а подпись лежит только в строке списка.

**Правка — сетка на последнем шаге, а не «подписи руками на каждой странице».**

| Точка | Что делает |
|---|---|
| `shared/domain/humanLabels.ts` → `humanCellText` | снимает идентификаторы из готового текста, чистит пустые скобки и сегменты без значения; идентификатор без текста → `—` |
| `ui/utils/listPrintColumns.ts` → `normalize` | React-ячейка → текст: тот же фильтр (пустой прочерк списка остаётся пустым — печатная таблица ставит свой) |
| `ui/utils/listExportSpec.ts` | ячейки, `sample` для определения типа колонки и **строки шапки `filters`** проходят через `humanCellText`; пустая ячейка → `HUMAN_LABEL_DASH` |
| `shared/domain/facetSummary.ts` → `facetSummarySpecs` / `describeFacetSelectionForRows` | подписи значений ступеней берутся из `valueOf(row)` по строкам списка; шапка больше не печатает `id` |

`describeFacetSelectionForRows` подключён там, где значением ступени служит идентификатор: `EnginesPage`, `EnginesReportPage`, `EnginesNowAtPlantReportPage`, `ContractsPage`, `WorkSheetsPage`, `WorkSheetsReportPage`.

**Точечные утечки** (id был единственным содержимым ячейки): `ContractsPage` (контрагент → прочерк), `SupplyRequestsPage` (`(без номера)` вместо `r.id`), `StockDocumentsPage` (убран `warehouseId`), `PpeCardDetailsPage` (номенклатура/сотрудник/склад/нормы группы → прочерк), `woPrintModel` (склад наряда через `pickHumanText`), `WorkSheetsPage` и `WorkSheetsReportPage` (вид работ и группировка по `typeName`), `NomenclaturePage` (тип без подписи → `—`), `WorkOrdersPage` (статус в печать — подписью через `printValue`).

**Сторожа.** `listExportSpec.test.ts` (4) — id в ячейке становится прочерком, название с приклеенным id остаётся названием, шапка отбора чистится, обычный текст не трогается. `facetSummary.test.ts` (15) — шапка называет заказчика, ступень со справочником берёт подпись из справочника, неизвестное значение не теряет отбор.

## 3. Заводская линза

- **Участок:** выгрузка/печать (лист списка, наряд, карточка СИЗ) — не движение двигателя по этапам.
- **Кормит ли затор:** нет — меняется подпись в документе, не маршрут и не сроки.
- **Инвариант потока:** не ломается. Ни одна правка не трогает статусы, остатки, привязки и провенанс: id остаются в данных, убираются только из человекочитаемого текста.
