# План: реестр глобальных модулей + линза + аудит дубликатов + каталог действий по объекту

**Источник:** промты КАРМАНА **#124** (задача), **#125** (план), **#128** (дополнение) — внешний трекер. Этот файл — внутрирепозиторная копия плана и его состояния (канон `AGENTS.md` §Команды управления сессией: внерепозиторный план копируется в `docs/plans/`, иначе следующая машина его не видит).

**Статус:** части 1–4 выполнены и слиты — **PR #2006** (`8dec0855`). Миграция следующих карточек на каталог — **PR #2011** (`f61ebc0c`), слит в `main`. Открытым остался пункт про дубли (см. «Что открыто»).

## Задача

В карте приложения выделить блок глобальных модулей (тех, что работают на всю систему), чтобы при разработке новой вещи сначала проверялось — может, такой модуль уже есть; провести глобальную проверку дублирующихся модулей; завести гибкий модуль действий по объекту — кнопки показываются только те, что у объекта есть, мёртвых кнопок нет.

## Части

1. **Реестр глобальных модулей** — [`docs/GLOBAL_MODULES.md`](../GLOBAL_MODULES.md) (куратируемый, отдельно от карты: карта уже 52 КБ), короткий блок в [`docs/CODEBASE_MAP.md`](../CODEBASE_MAP.md), правило в `AGENTS.md`, сторож `globalModules.guard.test.ts`.
2. **Линза глобальных обработчиков** — скилл `.claude/skills/global-lens/SKILL.md` (по образцу `factory-lens`): ритуал из трёх строк в плане, формат `Глобальная линза: <модуль-кандидат> · дубль: нет | есть (<файлы>) · действие: …`.
3. **Аудит дубликатов** — критерий: дубль = вторая реализация логики; тонкая обёртка над общим движком — не дубль; клиент/серверные зеркала вынесены отдельно. Находки и решения — в реестре, раздел «Дубли».
4. **Каталог действий по объекту** — знание в `shared/src/domain/objectCapabilities.ts` (`OBJECT_CAPABILITIES`, `OBJECT_KINSHIP`, `suggestCapabilityAdditions`), сборка кнопок в `objectActions.ts` (`buildCardActions`), общий тип `ObjectActionDeclaration`, панель `CardActionBar` с декларативным пропом `actions`.

## Развилки (решены по #128)

1. Реестр — отдельным файлом, не в карте (карта нарушает бюджет «≤2 экрана»).
2. Границы аудита: клиент/серверные зеркала — не дубликат, сервер авторитетен.
3. Каталог действий — общий домен на знание + renderer-модуль на кнопки; per-модульных копий нет, объявление действия одно для списков и карточек.
