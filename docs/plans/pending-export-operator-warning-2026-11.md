# План: клиент предупреждает оператора о неотправленных данных, лежащих файлом

**Нитка:** жалоба 23.11.2026 (промты КАРМАНА **#82 + #83**, письмо Мозга
`2026-11-23-operator-data-not-pushed`) — «данные оператора не уходят на сервер».

**Что делаем:** ту часть претензии, которая **не упирается во внешнее окно** (снимок машины
оператора и слово владельца на прод-запись). А именно — правило, которое сам мандат Мозга
называет кандидатом: «перед сбросом клиент предупреждает оператора, что неотправленное
остаётся в файле экспорта».

**Прод не трогаем.** Ни одной записи на сервере, ни одной миграции.

## Что показал разбор (по коду, 23.11.2026)

1. **Пересборка локальной базы удаляет неотправленное из базы.** `resetLocalDatabase`
   (`electron-app/src/main/services/syncService.ts`) выгружает неотправленные строки в
   `pending-export-<ts>.json` рядом с базой и только потом сносит `matricarmz.sqlite`.
   Данные не пропадают «в никуда» — но они больше не в базе, а реплей после первой
   успешной синхронизации **может не пройти** (строка не подходит под новую схему), и тогда
   файл остаётся на диске навсегда.
2. **Остаток файла никто не видит.** `replayPendingExports` пишет в лог
   `pending replay partial: N rows not restored` и отправляет это в «критические события»
   сервера — но ни оператор, ни администратор на парке об этом не узнают. Оператор видит
   пустой интерфейс и думает, что работает.
3. **Причина выгрузки терялась.** По остатку файла нельзя было понять, что вызвало
   пересборку: расхождение схемы, прерванная полная загрузка или ручной сброс.

Именно эта тишина и стоила оператору данных: «внесено очень много данных, но они не
уходят на сервер» — и никто об этом не узнал.

## Решение

**Правило: пока файл-выгрузка лежит на машине, оператор видит об этом баннер, а данные
можно отдать администратору одним действием.**

| Что | Где |
|---|---|
| Тип сводки и текст отчёта | `shared/src/domain/pendingExport.ts` (новый) |
| Чтение остатков выгрузок | `electron-app/src/main/services/sync/pendingExportState.ts` (новый) |
| Причина выгрузки едет в файл | `syncService.ts` — `exportPendingRowsToDisk(db, reason)` |
| Сводка в статусе синка | `syncManager.ts` → `syncWorker.ts` → `syncProxy.ts` → `SyncStatus.pendingExport` |
| Каналы: отчёт и «показать файл» | `ipc/register/authAndSync.ts`, `preload/index.ts` |
| Баннер | `renderer/src/ui/App.tsx` |

**Ключевые решения (и почему):**

- **Отчёт не уходит на сервер.** Данные лежат на машине оператора, и администратору нужен
  сам файл, а не строка в чате. Поэтому канал `sync:pendingExport:report` только собирает
  текст, оператор копирует его и прикладывает файл сам. Это отличает фичу от баннера
  застрявшей очереди, который отправляет отчёт на сервер.
- **Показ файла в Проводнике, а не путь текстом.** Имя файла приходит из интерфейса —
  открывать можно только `pending-export-*.json` из папки данных программы. Путь с
  именем пользователя Windows в отчёте не едет (D-041), а оператору хватает кнопки.
- **Причина сброса едет в сам файл.** Файл и есть свидетельство: по нему видно, что
  вызвало пересборку, даже спустя месяц.
- **Проба с троттлингом (30 с) и кэш разбора по (имя, размер, mtime).** Файлы крупные, а
  статус синка интерфейс спрашивает постоянно — читать их на каждый тик нельзя.

## Чего этот шаг НЕ делает

- **Не чинит данные оператора.** Для этого нужен снимок `%APPDATA%\MatricaRMZ\` с её
  машины (см. [`docs/pending/dannie-operatora-ne-uhodyat-na-server.md`](../pending/dannie-operatora-ne-uhodyat-na-server.md)).
  Без снимка починить нечего, и обновлять клиент у неё нельзя: пересборка БД сотрёт
  неотправленное.
- **Не трогает прод.** Ни одной записи на сервере.
- **Не меняет семантику гейта доступа** (промты #84/#85) — это решение за владельцем.

## Приёмка

1. **Гейты:** typecheck, typecheck:test, lint, тесты пакетов — зелёные.
2. **Живой смоук (CDP):** в стенде положить рядом с базой файл `pending-export-*.json` с
   пакетами → программа показывает баннер «Неотправленные данные лежат файлом на этой
   машине: N записей» → кнопка «Показать файл в папке» открывает Проводник → «Скопировать
   отчёт» кладёт текст в буфер → файл удалён → баннер гаснет.
3. **Приёмка владельцем:** претензия оператора — после снимка и правки прод-стороны.

## Урок в пул (письмо Мозгу)

«Сброс локальной БД сохраняет данные только в файле экспорта, а реплей может не пройти» ⇒
кандидат на правило экосистемы: **клиент обязан показывать оператору остатки выгрузки и
давать путь к файлу**, иначе «не отправлено на сервер» неотличимо от «потеряно».
