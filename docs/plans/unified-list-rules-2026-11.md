2. **✅ Верхний уровень (тот же PR).** Списки: двигатели, договоры, сотрудники, наряды, контрагенты, свойства инструмента — переведены на объявление действий, подключены к контуру, строки помечены `data-list-row`.
3. **✅ Карточки (PR #1934, ветка `feat/unified-list-rules-cards`).** Кнопки ↑/↓ (`RowReorderButtons`) заменены **единой ручкой «⠿»** из кита — перетаскивание мышью + перемещение стрелками по клику + блок из нескольких строк. Собран общий кит перестановки: `hooks/useListReorder.ts` (сборка), `utils/listReorder.ts` (мост «новый порядок → массив строк»), `components/ListReorderHandle.tsx` (ручка); добавлены `data-list-row` / `data-list-row-key`, **граница списка** (`scopeRef` — перетаскивание не целит в соседний список) и линия места вставки. Два решения, которых не было в ките верхнего уровня: **ключ строки — её номер** (у строк карточек своего id нет, а выдуманный id пришлось бы хранить и передёргивать при каждой правке — вторая механика рядом с китом) и **пересчёт номеров блока после сдвига** (иначе второе нажатие стрелки двигает уже другую строку). ## ШАГ 4 — отчёты: что именно в объёме (D-248 ③)

Потолок «84 файла со списками» из плана #68 посчитан по всем `list-table` / `<table` / `VirtualTable`
и включает компоненты, диалоги и вложенные панели. По **D-248 ③** в объём входят **только
таблицы-страницы**; списки внутри диалогов, выпадающих списков и вложенных панелей — не входят.
Фактический перечень отчётных списков (проверено по коду 23.11.2026):

**Итого в объёме шага 4 — 3 отчётных списка** (три страницы, по одной табличной странице на страницу).

**Что сознательно НЕ в объёме** (записано в `PENDING_FOLLOWUPS`, отдельной задачей):

- `pages/ReportPresetPage.tsx` — общая таблица-превью пресетов (`list-table`, строки `report-row-${idx}`).
  Вне по трём причинам: (1) строки **позиционные** — устойчивого ключа строки нет, а киту он нужен
  для выделения контуром и выделения (`data-list-row-key`); выделение по индексу после смены фильтра
  указывало бы на другую строку; (2) это механизм сразу для всех пресетов отчётов — правка задевает
  всю программу и по масштабу не равна шагу «отчёты → кит»; (3) рядом лежат особые случаи —
  печатная форма `work_order_payroll` и `assembly_forecast_7d`, а печатные формы и экспорт по
  условию нити не трогаются.
- `pages/CustomReportsPage.tsx` — таблица **конструктора** отчётов: строки позиционные
  (`g${gi}r${i}`), вперемешку с итоговыми строками групп; это редактор запроса, а не список-отчёт.
- `ui/components/AssemblyForecastReportView.tsx` — таблиц не содержит (карточки), в объём не попадает.

**Чекбокс выделения в отчёты не добавляем:** его нет и в контрагентах, договорах, сотрудниках,
нарядах и свойствах инструмента — там выделение идёт через контекстное меню и контур. Отчёт — список
для чтения: удалять в нём нечего, поэтому пункта «Удалить» в его меню **нет вовсе**, а не гаснет.

## ШАГ 4 — что сделано (23.11.2026, `feat/unified-list-rules-reports`)

**Общая обвязка на три страницы — `pages/reports/reportListKit.ts`.** Три отчёта устроены
одинаково, значит и правила поведения должны быть одни: обвязка держит выделение, меню,
колонки для копирования и объявление действий, а страница даёт только свои данные (строки и
колонки). Своего копита у отчётов нет — общий кит (`useListSelection`,
`useListBehaviorSettings`, `ListLassoLayer`, `utils/listContextActions.ts`) не тронут.

По каждой из трёх страниц:

- `data-list-root="true"` на корне — иначе клик мимо не гасит выделение;
- `data-list-row` / `data-list-row-key` на строках — по ним работает выделение контуром;
  **заголовок группы строкой не считается** (его не выделяем и в контур не берём);
- `ListLassoLayer` — контур (Ctrl + рамка), включается общей настройкой `listBehavior.lasso`;
- меню строки — по модели объявления действий: **«Распечатать»** и **«Скопировать»**;
  **пункта «Удалить» нет вовсе** — в отчёте удалять нечего (это и есть приёмка №5);
- печать из меню открывает **свой** диалог печати отчёта (тот же, что и кнопка в тулбаре) с
  объёмом «выделенные» — второй путь печати не заводим;
- выгрузка и печать уважают выделение: `selectedRows={listKit.selectedRows}`;
- колонки копирования — те же, что на экране (текст берётся из того же `render`, что и печать).

## Приёмка (по плану #68)

1. Перетаскивание: видно перетаскиваемую строку и место вставки. *(кит готов; живой список с перестановкой — в шаге 3)*

4. Клик мимо снимает выделение — везде. *(✅ правило прежнее, но единое; в отчётах — `data-list-root` на корне страницы)*
5. В меню списка, где удаление запрещено, пункта «Удалить» нет. *(✅; в отчётах — пункта нет вовсе: объявление удаления в обвязке отчётов его не содержит)*
6. Настройка одна — меняется в одном месте и действует во всех списках. *(✅: «Настройки → Интерфейс → Правила списков», суперадмин, глобальные дефолты; отчёты берут правила из того же источника)*

## Заводская линза (три строки)

- **Участок:** список нарядов и мастер-данных (двигатели, договоры, сотрудники) — экран оператора верхнего уровня.
- **Кормит ли затор:** нет. Главный затор — начало сборки (ручной подбор деталей из обезличенного фонда, `FACTORY_MODEL.md` §3); список нарядов — вход в работу, а не узкое место.
- **Не ломает ли инвариант потока:** нет. Правила поведения указателя (мышь/клавиатура/меню) не трогают ни наряды, ни этапы движения двигателя, ни права, ни порядок сохранения данных.

## Осторожности

- **Одно правило — один источник.** 84 списка × своя копия поведения = разъезд. Правило живёт в ките; список даёт только свои данные и объявление действий. Сторож: `electron-app/src/renderer/src/ui/listKit.guard.test.ts`.
- **Не сломать планшет.** Гейт `WorkSheetsPage.guard.test.ts:155-157`: drag-and-drop — приоритет, стрелки — для планшета ⇒ клавиатурное перемещение **добавляем сверху**, а не вместо.
- **Портал меню обязателен** (грабля G506) — `PopupLayer` в `ListContextMenu` не тронут.
- **`data-list-root` обязателен** на каждом списке, иначе клик по таблице гасит выделение.
- **Видимое изменение поведения меню:** пункта «Удалить» больше нет там, где удалять нельзя. Ни один список не должен был полагаться на серый пункт как напоминание.
- **Клавиатура и фокус:** перемещаемая строка объявляется (`aria-live`/`aria-label` в ручке), иначе движение «вслепую».
