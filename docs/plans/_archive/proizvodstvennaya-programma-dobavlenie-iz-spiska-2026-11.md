# Производственная программа: добавление двигателей из списка двигателей

**Промт КАРМАНА:** #44 (задание) + #45 (план владельца от 19.11.2026).
**База чтения плана:** `../MatricaRMZ`, чтение read-only. План владельца — задание, а не готовое решение: ниже он уточнён под наш код.

## Цель

В списке двигателей: выделить пачку галочками → правая кнопка → «Добавить в производственную программу» → модалка выбора программы (текущая, что в работе, или новая на следующие две недели) с периодом «с … по …» → двигатели становятся строками плана по тем же правилам, что и при добавлении внутри самой программы.

- **Запись строк плана** — только REST `PUT /production-program/:id/rows` (право `production_program.edit`), сервис `replaceProductionProgramRows` (`backend-api/src/services/productionProgramService.ts:392`) — **полная замена набора**.
- **Серверное чтение плана со строками** — `GET /production-program/:id` → `getProductionProgram` (`productionProgramService.ts:131`) отдаёт `{ row, lines }` свежими с сервера.

## Ключевая находка (уточнение плана): набор собираем из СВЕЖИХ строк сервера

Замена набора на сервере **полная**: строки, которых нет в отправленном наборе, снимаются мягко. Значит «добавить пачку» нельзя делать по данным реплики: зеркало программ публикуется раз в 60 с, а клиент читает реплику — за это время в плане может появиться строка, добавленная другим оператором или другим компьютером. Отправка набора по устаревшей реплике **снесла бы чужую строку**.

Поэтому: перед записью читаем строки плана **с сервера** (`GET /production-program/:id`), дополняем их новыми и отправляем полный набор тем же `saveRows`. Одна дверь записи, как и требует план.

## Шаги

1. **Домен: строка плана из карточки двигателя.** Общая функция `productionProgramRowFromEngine` в `shared/src/domain/productionProgram.ts` — одна точка правды для всех мест добавления (сегодня — только модалка нового входа; страница программы переходит на неё же). Поля строки берутся из карточки двигателя; состояние — из `suggestedProductionProgramStates` по виду договора; подпись группы — `productionProgramContractLabel`.
2. **IPC: прочитать план со строками с сервера.** `productionProgram:get` (`GET /production-program/:id`) в `electron-app/src/main/ipc/register/productionProgram.ts` + preload + тип в `shared/src/ipc/types.ts`.
3. **Модалка выбора программы** (`components/ProductionProgramAddEnginesDialog.tsx`): список доступных программ (текущая, что в работе, и новая на следующие две недели), выбор галочкой, у каждой — период «с … по …» (по умолчанию — период программы, редактируется), кнопка «создать программу на …» рядом. Список двигателей с их отказами: «уже отгружен» и «ещё не прибыл» в план не берутся — отказ показываем оператору, а не пропускаем молча.
4. **Пункт меню в списке двигателей** — bulk-ветка `menuItems` в `EnginesPage.tsx`: «🏭 Добавить в производственную программу (N)». Пункт доступен **только для пачки** и только при праве `production_program.edit` (в `App.tsx` — `caps.canEditProductionProgram`).
5. **Запись.** Взять строки выбранной программы с сервера, дописать новые строки (постоянный id, `orderNo` — по позиции), отправить тем же `saveRows`. Для новой программы — сначала `create` с выбранным периодом, затем строки.
6. **Итог оператору** — через `onNotify`: сколько добавлено, сколько отказано и почему.

## Осторожности

- **Одна дверь записи строк.** Свой путь записи в обход `saveRows` вернёт пару «удалить + вставить» (чинили 10.11) и — что важнее — будет снимать чужие строки.
- **Постоянный id строки** — `crypto.randomUUID()`, как на странице программы.
- **Нумерация:** клиент шлёт `orderNo = i + 1` по текущему порядку; при добавлении пачки нумерация пересчитывается целиком, иначе упрётся в частичный уникальный индекс `erp_production_program_rows_order_uq`.
- **Права:** пункт меню — по существующему праву `production_program.edit`, а не «всем, кто видит список»; сервер всё равно режет запись.
- **Отказ по движку — виден.** Список отказов показываем оператору (двигатель + причина), а не отбрасываем молча.
- **Синхронизация:** путь записи не обходит публикатор зеркала — иначе правка не дойдёт до других компьютеров.

## Что не трогаем

- Хук `useListSelection` и чекбоксы списка — работают, менять не нужно.
- `ListContextMenu` и `listContextActions` — общий паттерн, используется и в других списках.
- Внутрипрограммное добавление двигателя (`ProductionProgramPage.tsx`) — переиспользовать, не дублировать.
- Строгие таблицы `erp_production_programs` / `erp_production_program_rows` — новых атрибутов не заводим (EAV-заморозка).
- Серверную замену набора строк (`productionProgramService.ts:392`, порядок операций `:442-488`).
