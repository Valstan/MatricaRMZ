# Рекламация: отслеживание по очереди заездов 🗓 since:2026-11-11

**Заказ владельца (11.11.2026):** после переделки модуля рекламаций рекламация **не отслеживается в отчётах и в фильтрах списков** — её не видно нигде, кроме вкладки «Рекламация» в карточке двигателя и истории двигателя. Связи не подправились под новый модуль. Нужно перепроверить и восстановить отслеживание во всех местах программы, где рекламация отслеживается или проставляются статусы.

## Что нашли (причина)

Модуль рекламаций стал очередью заездов (PR #1666, миграция `0125`): одна строка `erp_engine_reclamations` — один заезд по рекламации, `queue_no` — порядок. Очередь — источник правды, и её читает только вкладка и история двигателя.

Всё остальное отслеживание читало **EAV-зеркало** карточки (`reclamation_flag`, `reclamation_accepted_date`, `reclamation_shipped_date` и текстовые соседи). А зеркало поддерживалось **только при сохранении карточки**: вкладка «Рекламация» после сохранения очереди клала значения в pending-атрибуты карточки (`onPatchFlag` / `onPatchMirror`), и они уезжали в EAV лишь с карточкой. Кнопка «Сохранить очередь» писала очередь на сервер и **больше ничего**.

Отсюда ровно то, что видел владелец: очередь есть (вкладка, история), а признак и даты рекламации — нет ни в списке, ни в отчётах, ни в ведомостях. Разорванные связи (все они читали зеркало):

| Где | Что читается | Стало |
|---|---|---|
| Список движков | `EngineListItem.isReclamation` | синяя метка, сортировка, колонка «Рекламация» |
| Фасеты списка | `isReclamation`, `reclamationAcceptedDate` | ступень «Рекламация», ступень «Дата приёмки рекламации» |
| Отчёт «Двигатели» | те же поля | колонка «Рекламация», группировка «По месяцу рекламации» |
| Отчёт «Сейчас на заводе» | `isReclamation` | колонка «Рекламация» |
| Ведомости и этапы | `WorkSheetRow.engineIsReclamation` | ступень и колонка «Рекламация» |
| Печать | `enginePrintModel` | пометка «рекламация» в поиске и печати |
| Производственная программа | `isReclamation`, даты | «В ремонте (рекламация)», «На заводе (рекламация)» |
| Статус двигателя | `engineStateLabel` | «Отгружен» / «На заводе» по ветке рекламации |
| Источник правды по датам | `resolveEngineTruthDates` | приход/отгрузка по рекламации, а не по основному циклу |
| ИИ-инструменты (сервер) | `erp_engine_cards.reclamation_*`, EAV | счётчик и список рекламационных движков |

Две причины, по которым «просто поддерживать зеркало» — не решение: EAV-атрибут держит **одну** рекламацию (в очереди их может быть несколько), и зеркало, которое поддерживается другим действием, и есть тот самый класс поломки, который чиним.

## Что чиним

1. **Источник правды — очередь.** Факты отслеживания (признак «рекламационный», даты приёма и отгрузки) считаются из локальной реплики очереди (`erp_engine_reclamations`, pull-only) доменным правилом «текущий заезд» — последняя по `queue_no`. Правило одно и на клиенте, и в домене.
   - `shared/src/domain/engineReclamations.ts` → `engineReclamationFacts`.
   - `electron-app/src/main/services/engineReclamationReplica.ts` → чтение реплики.
   - `listEngines` (список, отчёты, печать, ПП, статус, источник правды по датам) и `getEngineReclamationFlags` (ведомости и этапы) читают очередь. Список характеров дефекта — тоже из очереди.
2. **Зеркало EAV поддерживается при сохранении очереди** — для клиентов парка прежней версии (они читают признак и даты из EAV) и для серверной проекции карточки с ИИ-инструментами. На сервере живой триггер `trg_mirror_engine_card_attr` пересобирает `erp_engine_cards` из EAV, поэтому серверные поверхности оживают сами; правок сервера не требуется.
3. **Добор pull'а** после сохранения очереди: очередь приезжает журналом, и без добора синяя метка ждала бы следующего круга синхронизации.

## Заводская линза

`Заводская линза: учёт рекламаций и отчётность по ним · затор: не касается (рекламация не разбирает детали и не трогает начало сборки — главный затор по модели) · поток: не ломает — заезды двигателя по-прежнему идут по порядку, даты не пересекаются (гейт очереди), признак и даты рекламации снова видны в отчётах, а не прячутся в атрибутах карточки.`

## Сторожи

- Отслеживание не читается из EAV-зеркала: в `engineService` нет `defs['reclamation_flag']` и соседей — только очередь (`engineReclamationReplica.guard.test.ts`).
- Зеркало поддерживается при сохранении очереди, а не карточки (`engineReclamations:save` → `syncEngineReclamationMirror`).
- Реплика очереди остаётся server-write: клиент её читает и в неё не пишет (прецедент ПП).
- Домен-правило «текущий заезд»: последняя по `queue_no`, а не первая.
