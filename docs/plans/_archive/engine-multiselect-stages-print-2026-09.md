## PR-F: Логика дефектовки и статуса «утиль» (`fix/defect-stage-single-date-util-status`)

### Цель
Одна дефектовка на двигатель (фиксированная дата), иерархия этапов, снятие статуса «утиль» при укладке/сборке.

### Изменения

**Backend (`backend-api/src/services/`):**
1. `engineService.ts` / `workSheetService.ts`:
   - Поле `defect_stage_date` на `engines` (или в `operations` с флагом `is_defect_stage`) — дата первой дефектовки, не меняется при новых версиях листа
   - При создании/обновлении листа дефектовки — дата не перезаписывается, только `answers`/`meta_json`
2. Валидация иерархии при создании этапа (`upsertOperation`):
   - Порядок: `defect` (0) → `arrival` (10) → `crankcase` (20) → `assembly` (30) → `qc` (40) → `shipment` (50)
   - Нельзя создать этап с `priority` < максимального существующего у двигателя (кроме дефекта — он всегда первый)
3. Снятие статуса «утиль»:
   - При создании этапа с `priority >= 20` (укладка/сборка/…) — сбрасывать `engine.util_flag = false` / `engine.util_reason = null`
   - В дефектовке `util` остаётся в истории (`answers.util_items`), но глобальный флаг снимается

**Frontend:**
- Карточка двигателя: розовый фон «утиль» исчезает при появлении укладки/сборки
- Валидация в `WorkSheetRowDialog`: предупреждение, если пытаются поставить этап выше по иерархии

**Миграция:**
- Заполнить `defect_stage_date` у существующих двиглей (первая дефектовка по дате)

**Тесты:**
- Дефектовка не меняет дату при обновлении листа
- Нельзя добавить сборку до укладки
- Укладка снимает розовый «утиль» в списке и карточке
- Гейты зелёные

### Acceptance Criteria
- [ ] Дата дефектовки фиксирована навсегда (первая версия листа)
- [ ] Иерархия этапов валидируется: дефект < укладка < сборка < ОТК < отгрузка
- [ ] При создании укладки/сборки глобальный флаг «утиль» снимается
- [ ] В списке двигателей розовый фон исчезает
- [ ] Гейты зелёные

## PR-H: Выпадающие меню — компактная ширина, таймаут 15 с (`feat/popup-compact-width-timeout`)

### Цель
Выпадающие меню в полях ввода (autocomplete/dropdown) должны быть по ширине контента, а не фиксированной ширины. Не скрываются пока курсор на них или идёт взаимодействие (стрелки клавиатуры). Скрываются через 15 с неактивности или по клику мимо.

### Изменения

**Frontend:**
1. `components/PopupLayer.tsx` / `useAnchoredPopup` — добавить опцию `compactWidth: boolean` (ширина по содержимому, а не по самому широкому элементу)
2. Таймаут автоскрытия: с 2–3 с до **15 с** (константа `POPUP_AUTO_CLOSE_MS`)
3. Не закрывать при:
   - `mouseenter` на попап
   - Фокус внутри попапа
   - Нажатие стрелок вверх/вниз (навигация по списку)
4. Закрывать при:
   - Клик мимо (вне попапа и его якоря)
   - Таймаут 15 с без активности
   - `Escape`

**Тесты:**
- Попап не закрывается при навигации стрелками
- Закрывается через 15 с без активности
- Закрывается по клику мимо

### Acceptance Criteria
- [ ] Ширина попапа = ширине самого широкого элемента (не фиксированная)
- [ ] Не закрывается при курсоре на нём или навигации клавиатурой

   - Кнопка «Удалить» — удаление этапа, созданного по ошибке (если нет записей в истории)
2. Доступ: суперадмин + Сапегин + Фатыхова (как в PR-E)

**Backend:**
1. `POST /work-sheet-types/merge` — принимает `{ sourceId, targetId }`:
   - Все `operations` с `work_sheet_type_id = sourceId` переводятся на `targetId`
   - `sourceId` помечается как удалённый (или удаляется, если нет других ссылок)
2. `POST /work-sheet-types/rename` — принимает `{ id, newName }`
3. `POST /work-sheet-types/delete` — принимает `{ id }` (только если нет записей в истории)

**Тесты:**
- Слияние переводит все записи на целевой этап
- Переименование обновляет название везде
- Удаление этапа с записями в истории отклоняется
- Гейты зелёные
