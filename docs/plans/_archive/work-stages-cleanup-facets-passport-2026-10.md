## P1. Чистка дублей (факт выше)

Правило владельца: группа = (двигатель, kind, код типа) с `pass<2` и N>1 строк →
живой остаётся **поздняя** (по `at`, при равенстве — по `updatedAt`), остальные —
мягкое удаление **через журнальный путь** (иначе парк не узнает). Повторы
(`pass>=2`) и одиночки не трогаем.

- Скрипт `backend-api` `stages:dedupe-duplicates`: по умолчанию **dry-run** —
  печатает группы (двигатель, код, даты, id). `--apply` — только после того, как
  владелец видел конкретный список (удаление живых данных = гейт #025).
- Сторож: юнит на правило «поздняя жива, ранние помечены, повторы не тронуты».
- После apply — повторный прогон скрипта должен показать 0 групп (приёмка).

## P2. Единые фильтры этапов (списки + отчёты)

Проблема: ступени «Есть этап / Последний этап / Дата этапа» живут в списке
двигателей (считаются по всей истории: sheet + stage + авто-строки), а в списке
этапов работ их нет — оператор, отобрав «последний этап» в одном списке, видит
другое число двигателей, чем в другом. Плюс отчёты (`Этапы работ`,
`Этапы на заводе`) едут на своих копиях логики и уже разъехались.

- В список этапов добавить движковые ступени: `engineLastStage` (последний этап
  двигателя — тот же `lastStageCode`, что в списке двигателей, включая
  авто-строки из других документов) и `engineHasStage`. Значения берутся из
  уже посчитанной истории, новых запросов нет.
- Отчёты перевести на те же дескрипторы (`workSheetFacets`, движковые ступени),
  а не копии: один источник — одинаковые числа везде.
- Терминология фильтров: везде **«Заказчик»** (сейчас местами «Контрагент»).
  Только подписи ступеней, сущности и права не трогаем.
- Приёмка: один и тот же отбор («последний этап = Сборка») в списке двигателей,
  списке этапов и отчёте даёт одно и то же множество двигателей (CDP-прогон
  на стенде или сверка скриптом — по ситуации).
