# Поиск в списках: строго по умолчанию, «похожие» — только по кнопке

**Источник:** промты КАРМАНА **#10** («Поиск в списках: по умолчанию строго, „Похожие“ — только по кнопке») и **#14** (план из библиотеки).
**Владелец:** 13.11.2026 — «Поиск в списках надо доработать… сейчас внизу выдачи слишком много лишнего, операторы в нём путаются».
**Ветка:** `feat/search-strict-default` (воркаут `D:\valstan\REPO\MatricaRMZ-search`).

## Что просили

1. Пока в поле набирают буквы и цифры — поиск **строгий**: совпадение символ в символ.
2. Расширенный режим («похожие»: опечатки, часть слова, другая раскладка) включается **только по кнопке «≈ Похожие»**.

## Что было не так (проверено в коде)

- **Режим лежал в состоянии списка**, а список сохранён в `sessionStorage` (`useListUiState`). «Похожие» переживало и смену экрана, и перезапуск программы: оператор получал широкую выдачу, не нажимая кнопки, и не понимал, откуда «лишнее».
- **Сброс фильтров не возвращал строгий режим** — кнопка «Сбросить фильтры» снимала ступени, а режим поиска оставался.
- **Намерение не уезжало в серверный запрос явно**: клиент передавал `similar` только когда режим был «похожие», а сервер сам решал, что прислали. Поведение было верным, но «строго» означало «параметр не прислали» — это отсутствие решения, а не решение.

## План (сделан)

1. **Единый хук `useSearchMode`** (`ui/hooks/useSearchMode.ts`): режим живёт в состоянии компонента, а не в состоянии списка. Сбрасывается:
   - при показе панели снова (`useOnTabVisible`) — «похожие» не переживает перезапуск списка;
   - при очистке поля — начал новый поиск → снова строгий;
   - явно, через `reset()` — сброс фильтров возвращает строгий.
2. **Все экраны поиска переведены на хук** (20 страниц): режим взят из одного места, правило одно, а не по экрану.
3. **Намерение едет в серверный запрос явно**: `similar=true|false` — в `main/services/erpService.ts` (запрос), в `backend-api/routes/warehouse.ts` (разбор) и в `listWarehouseStock` (режим матчера).
4. **Пустая выдача подсказывает кнопку на любом экране**: текст живёт в одном файле (`ui/components/SearchModeHint.tsx`), экраны подключают общий хелпер.

## Сторожи (`ui/pages/SearchMode.guard.test.ts`)

- каждый экран с поиском берёт режим из `useSearchMode` (одно правило);
- режим не лежит в состоянии списка (ни `searchSimilar` в типах, ни `listState.searchSimilar`);
- хук сбрасывает режим на показе панели, на очистке поля и по `reset()`;
- сброс ступеней на экране возвращает строгий режим;
- пустая выдача на любом экране подсказывает «≈ Похожие»;
- сервер получает `similar` всегда, а не только когда режим «похожие».

## Чего НЕ делали

- Алгоритм похожего поиска не трогали (вариации, опечатки, раскладка — он заложен и покрыт `ui/utils/search.test.ts`).
- Выпадающие пикеры (`SearchSelect`) оставлены терпимыми к опечаткам: там оператор выбирает глазами из короткого списка (решение владельца 22.09.2026).
- «Похожие» в `PartsDedupePage` (дедупликация деталей) — другой экран, не трогали.
