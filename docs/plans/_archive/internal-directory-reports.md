# Внутренняя структура и быстрые отчёты

**Status:** COMPLETED  
**Started:** 2026-08-14  
**Branch:** `feat/internal-directory-reports`

## Контекст

ИИваныч вернул UUID цехов/подразделений вместо названий и сообщил об отсутствии доступа. Причина предварительно подтверждена: канонические цеха живут в `directory_workshops`, но таблица отсутствует в AI SQL-whitelist и нет специального tool структуры. Подразделения канонически представлены EAV-сущностями типа `department`; сотрудники ссылаются на `department_id` либо `workshop_id`.

В программе уже есть «Мои отчёты» — конструктор поверх готовых источников с фильтрами, колонками, сортировкой, группировкой, печатью и CSV. Расширяем его, не создавая второй параллельный конструктор.

## Целевое поведение

1. ИИваныч получает специальный read-only tool структуры предприятия и отвечает названиями, кодами и численностью, без UUID в пользовательском ответе.
2. Новый источник отчётов «Структура предприятия» содержит по одной строке на цех/подразделение: вид, код, название, всего сотрудников, работающих и уволенных.
3. «Кадровый реестр» дополнен цехом, подразделением, единым названием/видом структуры, датой рождения и днём рождения без года.
4. «Отчёт по нарядам» дополнен автором создания и организационной привязкой автора/наряда, когда она известна данным.
5. Все новые поля доступны в «Мои отчёты» для условий, группировки, сортировки, выбора колонок, печати и CSV.

## Практические сценарии

- официальный список цехов и подразделений с численностью или без неё;
- список работников одного цеха/подразделения;
- все работающие/уволенные, принятые или уволенные за период;
- дни рождения всех работников либо выбранной структуры;
- сотрудники без назначенной структуры, должности, табельного номера или даты рождения;
- количество нарядов по автору, ответственному, цеху/подразделению, статусу, типу, марке и периоду;
- сочетания условий через существующий конструктор и сохранение личного/общего шаблона.

## Гейты

- unit-тесты AI tools и чистой логики отчётов;
- build shared + typecheck + lint + backend tests;
- живой CDP-smoke: источники видны, структура формируется, фильтр/группировка работают, печатное окно открывается.

## Не входит

- Иерархия parent/child между подразделениями: фактического утверждённого дерева в данных нет. Добавлять только после получения оргсхемы владельца.
- Миграция `department` из EAV в отдельную SQL-таблицу: текущая ссылка единообразна и работоспособна; миграция не нужна для исправления доступа и отчётности.
