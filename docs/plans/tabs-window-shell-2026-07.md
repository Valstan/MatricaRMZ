# План: вкладочная оболочка окна («резиновый интерфейс» v2)

**Status:** IN PROGRESS — этап 1 ✅ (2026-07-27), следующий — этап 2.
**Заказ владельца:** 2026-07-27, устно в сессии.
**Масштаб:** крупный рефакторинг renderer-оболочки (App.tsx + все страницы списков/карточек). Делать в несколько сессий, поэтапно, за фиче-флагом.

## Context

Отказываемся от деления «резинового» интерфейса на три экрана. Вместо этого — **одно окно с панелью вкладок**.

## Требования владельца (дословно, нормализовано)

1. **Две закреплённые вкладки** (нельзя закрыть, всегда в панели):
   - **«РАЗДЕЛЫ»** — крайняя слева, кнопки навигации по разделам программы.
   - **«Список …»** — всегда вторая (справа от «РАЗДЕЛЫ»); вместо «…» подставляется название списка, открытого из «РАЗДЕЛЫ» (напр. «Список Двигатели»).
2. Эти две вкладки могут **делить окно на две части**: «РАЗДЕЛЫ» — четверть экрана слева, «Список …» — три четверти справа.
3. **Открытие карточки** (из списка или из разделов) → **новая вкладка на весь экран**; «РАЗДЕЛЫ» и «Список …» сворачиваются, но **сохраняют наполнение и позицию фокуса/курсора**.
4. **Лимит вкладок — 10.** При >5 открытых — **красное предупреждение**: «открытых вкладок многовато, закрой отработанные — иначе конфликты или забудешь сохранить».
5. **Активная вкладка подсвечивается.**
6. **Названия вкладок — человекопонятные** (ФИО, номер двигателя, название детали), не технические коды/UUID.
7. **Ширина шапок вкладок:** по ширине названия; растягивать на весь экран не надо; **сжимать только когда не влезают** в ширину окна.
8. **Карточки — резиновые по всей доступной ширине** (поля данных не должны сжиматься, пока на экране есть место).
9. **Карточки компактнее по высоте:** ещё сократить межстрочные расстояния; **длинные списки внутри карточек — сворачиваемые и по умолчанию свёрнутые**.
10. **Прогресс загрузки + блокировка редактирования:** при открытии списка/карточки/документа — крутящийся спиннер (как загрузка Windows); пока объект не загружен целиком — редактирование заблокировано; после загрузки спиннер исчезает. То же — для операций с **прикреплёнными файлами** (начался процесс → спиннер, завершился → убрать).

## Этапы

### Этап 1 — разведка и каркас (без изменения поведения) — ✅ 2026-07-27
**Ключевая находка разведки:** V2Shell («Резиновый») уже несёт бо́льшую часть механики — `v2OpenCards` (вкладки карточек + фокус + dirty-guard + session-restore, персист в `shellPrefs.v2.session`), колонку списка (`v2ActiveListTab`), панель кнопок (`ButtonPanel` + `buttonLayout`). Поэтому v3 сделан **надстройкой над механикой v2**, а не с нуля.

Сделано (PR этапа 1):
- `shared/uiShellV2.ts`: `shellVersion: 'v3'`, `V3Prefs/V3Session`, лимиты `V3_MAX_TOTAL_TABS=10` (2 закреплённые + 8 карточек), `V3_WARN_TOTAL_TABS=5`, хелперы `v3CanOpenCard`/`v3ShowTabsWarning`, sanitize + тесты. Дефолт остаётся v2.
- `shellV3/V3TabShell.tsx` + `shellV3.css`: полоса вкладок ([РАЗДЕЛЫ][Список …][карточки…]), сплит ¼/¾, карточка fullscreen; сплит и карточка держатся смонтированными (display:none) — наполнение/фокус/несохранённое не теряются; красное предупреждение при >5 вкладках; подсветка активной; ширина шапки по названию (ellipsis при нехватке места).
- App.tsx: `isV2` теперь включает v3 (вся v2-механика работает), `isV3` — только рендер-ветка; кап карточек 8 в v3; `v3PinnedFocus` (возврат на закреплённые без закрытия карточки); кнопка «🗂 Вкладки (бета)» в шапке (вход только явным кликом).

Гейты: shared build + typecheck (electron/backend/web-admin) + lint + тесты (shared 499, backend 462) — зелёные. CDP-смоук v3 отложен до этапов 2–3 (дефолтное поведение не менялось, v3 — explicit opt-in бета).

Известные хвосты каркаса (в этапы 2–3): v3 пока пишет сессию в `v2.session` (V3Session не задействован); split-«2 рядом» из v2 в v3 не рендерится (session-restore secondary в v3 надо гасить); лимит 10 не блокирует открытие 11-й (кап пока вытесняет старейшую); заголовки карточек = v2CardTitle (`kind · id6` для не-двигателей — очеловечить).

### Этап 2 — закреплённые вкладки и сплит 1/4 + 3/4
- Вкладка «РАЗДЕЛЫ» = текущее левое меню, переехавшее в контент вкладки.
- Вкладка «Список …» с динамическим названием; сплит-режим, когда активны обе.
- Сохранение фокуса/скролла списков при сворачивании (не размонтировать контент — скрывать через display/keep-alive).

### Этап 3 — карточки во вкладках
- Открытие карточки = новая вкладка fullscreen; заголовок — человекопонятный (использовать `formatClientLabel`-подобные резолверы имён, номер двигателя `41/26` и т.п.).
- Лимит 10, предупреждение при >5, подсветка активной, крестики закрытия с диалогом «Сохранить?» (существующая логика закрытия карточек).
- Интеграция с recovery-драфтами (модалка «Восстановление несохранённых карточек» должна восстанавливать вкладки).

### Этап 4 — резиновые компактные карточки
- Аудит карточек: убрать max-width/фиксированные ширины, поля растягиваются на доступную ширину.
- Уменьшить вертикальные отступы строк данных (общие токены spacing, не точечные правки).
- Компонент `CollapsibleSection` для длинных списков в карточках; по умолчанию свёрнуто, состояние — в локальном UI-state.

### Этап 5 — прогресс загрузки и блокировка
- Общий компонент `LoadingOverlay` (спиннер) поверх списка/карточки, пока данные не загружены; форма в readonly до завершения.
- То же для операций с вложениями (upload/download/open).

### Этап 6 — приёмка и смоуки
