# СИЗ: сквозной переход на карточку сотрудника и правка его данных прямо из карточки СИЗ

**Промты КАРМАНА:** #40 (текст владельца) + #41 (план из библиотеки), 18.11.2026.
**База чтения плана:** `a75277a1` (v3.133.0). **Наш код:** `main` @ `567aa5b9` (v3.134.0).

## Задание владельца (дословно)

> Сквозной переход: из карточки СИЗ — в карточку сотрудника, и наоборот: из карточки сотрудника — в карточку СИЗ.
>
> Данные, которые подтягиваются в карточку СИЗ из карточки сотрудника (структурное подразделение, размеры), должны редактироваться прямо в карточке СИЗ.

## Что уже есть (сверено с нашим кодом)

- **Карточка СИЗ** — `electron-app/src/renderer/src/ui/pages/PpeCardDetailsPage.tsx`. Открывается вкладкой: `App.tsx:3786` `openPpeCardEmployee(id)` → `v2OpenCardGuarded('ppe_card', id, …)`, рендер `App.tsx:6076`.
- **Карточка сотрудника** — `pages/EmployeeDetailsPage.tsx`, открывается `App.tsx:3778` `openEmployee(id)`; рендерится в двух местах (`App.tsx:5795` — вторая панель, `App.tsx:6510` — основная).
- **Размеры уже подтягиваются** в карточку СИЗ из EAV-карточки сотрудника: `PpeCardDetailsPage.tsx:302` `loadEmployeeSizes` → `admin.entities.listByEntityTypeWithAttrs('employee')`, ключ — **табельный номер** (`personnel_number` ↔ `erp_employee_cards.personnel_no`).
- **Серверные реквизиты** (`ppe:employees:card` → `backend-api/src/services/ppeOrderNormsService.ts`) считаются **живо** из EAV: `sizeClothes`/`sizeShoes`/`height` — атрибуты `ppe_size_clothes`/`ppe_size_shoes`/`ppe_height`, `departmentId` — атрибут `department_id`. Название подразделения (`departmentName`) приходит из снимка импорта ЗУП (`attrs_json`), а не из EAV.
- **Единственная дверь записи карточки сотрудника** — IPC `employees:setAttr` (`electron-app/src/main/ipc/register/employees.ts:56`) → `saveEmployeeCardGated` → `employees:card:save`/`employees:setAttr`. Гейты: `employees.create` (кадровое право) либо `employees.position.edit` **только** для атрибута `role`; серверный гейт синка — `shared/src/domain/ledgerAuthz.ts:253` (`own_employee` c `EmployeesCreate`).
- **Отделений-исключений в гейте раздела** ровно одно: `sectionGate.ts:348` `isPositionWrite` (должность + `employees.position.edit`).

## Что решаем и как (уточнение плана под наш код)

### 1. Связь «карточка СИЗ ↔ карточка сотрудника» — табельный номер

id у них **разные**: карточка СИЗ живёт в строгой `erp_employee_cards` (зеркало ЗУП), карточка сотрудника — в EAV. Серверная колонка `erp_employee_cards.entity_id` (ссылка на EAV) **в зеркальный DTO не входит** — клиент её не видит. Поэтому общий ключ — табельный номер, и он уже применён в этом модуле (см. `loadEmployeeSizes`).

- Связь строим **в домене** (shared), а не в странице: `shared/src/domain/ppeEmployeeLink.ts` — индекс «табельный номер → id EAV-карточки + фактические размеры + подразделение».
- **Неоднозначность — правило, а не случайность:** два сотрудника с одним табельным номером → переход **не предлагаем** (иначе откроем чужую карточку). Размеры при этом показываем (значение одинаковое у обоих).

### 2. Переходы — существующим механизмом, без второго способа навигации

- **СИЗ → сотрудник:** кнопка «Открыть карточку сотрудника» в карточке СИЗ, колбэк `onOpenEmployee(employeeId)` → `App.tsx` передаёт `openEmployee` (тот же вход, что из списка сотрудников).
- **Сотрудник → СИЗ:** кнопка «Карточка СИЗ» в карточке сотрудника, колбэк `onOpenPpeCard(ppeEmployeeId)` → `App.tsx` передаёт `openPpeCardEmployee`.
- id для обратного перехода ищем по табельному номеру в `ppe.employees.list()` (реплика `erp_employee_cards`).
- **Ограничение (фиксируем, не чиним здесь):** строка `erp_employee_cards` появляется только из импорта ЗУП. Сотрудника, заведённого руками в программе, в зеркале СИЗ нет — карточка СИЗ для него не заводится вовсе. В этом случае кнопка не показывается, а подпись объясняет причину.

### 3. Правка подтянутых данных — в карточке сотрудника, не в карточке СИЗ

Размеры и подразделение принадлежат сотруднику. Свою копию в карточке СИЗ не заводим — иначе «в карточке СИЗ одно, у сотрудника другое».

- Пишем **существующими атрибутами** (`ppe_size_clothes`, `ppe_size_shoes`, `ppe_height`, `department_id`) через **ту же единственную дверь** `employees:setAttr` — иначе обойдутся гейт дублей и права.
- **Право — то же, что и в карточке сотрудника** (`employees.create`, кадровое). Без права поля только для чтения. **Новых прав не заводим** (план #41: «Права сотрудников — не расширяем»). Прецедент узкого права (`employees.position.edit`) не трогаем.
- **Открытый вопрос владельцу (не решаем агентом):** размеры сотрудника сегодня не может записать никто, кроме кадровика — у кладовщика нет ни одного права на запись в карточку сотрудника. Если размеры должен править **кладовщик**, это отдельное решение: новое узкое право (`employees.sizes.edit`) + гейт IPC + исключение из гейта раздела + серверный `ledgerAuthz`. Отмечено в handoff и PENDING.
- **Подразделение** показываем **живым** (EAV `department_id` + справочник подразделений). Снимок импорта ЗУП (`departmentName`) — в подсказке, если он расходится с живым значением: иначе оператор правит «не то».
- **Сразу после правки** карточка СИЗ перечитывает данные сотрудника (локальная реплика EAV обновляется мгновенно) — старое значение на экране не остаётся.

### 4. Чего не делаем

- Новых EAV-атрибутов (EAV-заморозка).
- Новых прав и расширения `employees.create`.
- Собственной копии размеров/подразделения в карточке СИЗ.
- Правки снимка личной карточки (`ppe_employee_cards`) — он остаётся снимком формы приложения №3.

## Стражи (тесты)

- **Домен (shared):** индекс связи «табельный номер → карточка сотрудника»; два сотрудника с одним номером → переход не предлагаем; пустые размеры — пустые, а не «—».
- **Клиент (electron-app, guard-тесты по исходнику):** кнопки перехода на месте; запись идёт в карточку сотрудника (`employees.setAttr`), а не в карточку СИЗ; без права поля только для чтения.
- **Право:** правка из карточки СИЗ требует того же права, что и правка из карточки сотрудника.

## Что сделано (2026-11-19)

**Домен (shared):** `shared/src/domain/ppeEmployeeLink.ts` — индекс связи «табельный номер → карточка сотрудника» (`buildEmployeeLinks`), чтение фактических размеров (`readEmployeeSizes`), обратный поиск «карточка сотрудника → карточка СИЗ» (`findPpeEmployeeIdByPersonnelNo`). Неоднозначный номер помечается — переход по нему не предлагается.

**Карточка СИЗ** (`PpeCardDetailsPage.tsx`): новый блок «Данные сотрудника» — подразделение (живое, из EAV `department_id`), размер одежды, размер обуви, рост. Правка идёт **в карточку сотрудника** через единственную дверь `employees:setAttr` (те же права и гейт дублей, что и в карточке сотрудника); без права поля только для чтения. Кнопка «Открыть карточку сотрудника» (переход в карточку сотрудника по id из связи). Перед записью размеров определения атрибутов до-регистрируются тем же кодом, что и в карточке сотрудника (иначе дверь отвечает «Неизвестный атрибут»).

**Карточка сотрудника** (`EmployeeDetailsPage.tsx`): кнопка «Карточка СИЗ» — переход в карточку СИЗ сотрудника (по табельному номеру в зеркале `erp_employee_cards`).

**App** (`App.tsx`): переходы подключены штатными входами — `openEmployee` и `openPpeCardEmployee` (никакой новой навигации).

**Проверки:** домен — 6 тестов (shared), стражи переходов и правки — 10 тестов (electron-app), CDP-смоук `.claude/skills/verifier-electron/scripts/cdp-ppe-employee-crosslink.mjs` — **20/20 PASS** на живом клиенте (связь по табельному номеру, правка размера из карточки СИЗ с проверкой, что значение landed в карточку сотрудника, оба перехода, уборка за собой).

**Смоук вскрыл дефект, который тесты не видели:** на стенде определения атрибутов `ppe_size_shoes`/`ppe_height` не были заведены — дверь записи отвечает «Неизвестный атрибут». Поэтому карточка СИЗ до-регистрирует нужные определения (те же коды, что и карточка сотрудника) и говорит понятным текстом, если права не хватило.

## Открытый вопрос владельцу

**Кто должен править размеры.** Сейчас — тот же, кто ведёт кадровую карточку (`employees.create`); кладовщик не может записать размеры нигде (у него нет ни одного права на запись в карточку сотрудника). Если размеры должен править **кладовщик** — это отдельное решение: новое узкое право (прецедент `employees.position.edit`), гейт IPC, исключение из гейта раздела «Персонал» и серверный `ledgerAuthz`. Пункт — в [`PENDING_FOLLOWUPS.md`](../PENDING_FOLLOWUPS.md).
