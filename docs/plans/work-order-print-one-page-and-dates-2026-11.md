# Наряды РМЗ: печать на один лист A4 и даты выполнения работ

**Промт:** КАРМАНА #165 (зачитка владельца 26.11.2026).
**Статус:** сделано по коду (печать — один лист; даты — период/ежедневно). Открыты: полевой приёмке глазами владельца и два решения владельца (крайний объём наряда; что делать со старыми закрытыми нарядами без дат).

## Заводская линза (участок · кормит ли затор · не ломает ли инвариант)

- **Участок:** наряды РМЗ — цеха 1–4, закрывают операторы; печать наряда = бумажный маршрутный лист в цеху.
- **Кормит ли затор:** нет (затор — начало сборки, подбор деталей из ремфонда). Но печать наряда — это «факт выполнен» на бумаге: без нормального бланка цех не может закрыть смену.
- **Не ломает ли инвариант потока:** нет. Дата выполнения работ — **факт по каждой работе**, она НЕ трогает дату выполнения наряда (`completedDate`), статус наряда и складские документы. Миграций таблиц нет: дата лежит в payload.

## Глобальная линза (три строки)

- Готовый модуль, который делает это: **есть** — слой печатных форм (`woPrintModel.ts` + `printPreview.ts`), обе формы наряда и выгрузка в Word уже собираются из него. Второй сборщик не заводили.
- Готовый модуль для дат: **нет**. Дата работы — новая величина, её вводим в payload наряда (строки работ), без новых таблиц.
- Реестр глобальных модулей (`docs/GLOBAL_MODULES.md`) править не пришлось: набор модулей не менялся.

## Шаги 2–3. Что сделано с листом (причина устранена, а не размер подогнан)

1. **Поля печати — `@page { margin: 12mm }`** (вместо обнулённых), `body` в печати без полей ⇒ полоса набора 186 мм, ровно как в предпросмотре A4. Края листа больше не упираются в непечатаемую зону принтера.
2. **Таблицы работ и бригады — `table-layout: fixed` + `<colgroup>`**: ширины колонок задаёт форма (весами), а не браузер. Ни одна колонка не выходит за полосу набора, длинные значения переносятся (`overflow-wrap: anywhere`).
3. **Колонка «Ед.» расширена** (вес 12): «нормо-час» переносится по дефису, а не ложится на пять строк. Это и был главный раздуватель строк (Д4).
4. **Колонки «Вид работ» и «Наименование изделия»** получили ширину по фактической длине текстов РМЗ (18 и 30 весов).
5. **Слоты подписей одного блока — в две колонки** (61,7 → 33,1 мм).
6. **Реквизиты шапки — ряды выровнены** по общему числу колонок (недостающие ячейки добиты пустыми).
7. **Плотнее вёрстка**: отступы секций 14→6 px, поля ячеек 7→4 px, межстрочный интервал таблиц работ 1,18, подпись «Итог» компактнее.
8. **Шапка таблицы повторяется на втором листе** (`display: table-header-group`) — если наряд всё же не влез, продолжение читается.

**Итог:** все 15 нарядов корпуса печатаются **ровно одним листом A4**, ни одна колонка не обрезана, ячейка росписи целиком.

## Шаги 3–9. Дата выполнения работ: модель

`shared/src/domain/workOrder.ts` (payload наряда, v6):

- `WorkOrderWorkLine.workDate?: number` — **дата выполнения работы** (ms, локальная полночь из date-input).
- `WorkOrderWorkLine.workAssigneeId?: string` — **исполнитель работы**: сотрудник бригады, которому принадлежит дата. Дата хранится вместе с исполнителем ⇒ даты разных сотрудников не смешиваются.
- `WorkOrderPayload.workDateMode?: 'period' | 'daily'` — режим дат наряда.
- `WorkOrderPayload.workPeriods?: Array<{ employeeId: string; from: number; to: number }>` — периоды: общий (`employeeId` пуст) и/или по сотрудникам бригады.

**Таблиц не добавляли** (миграций нет): всё лежит в payload наряда. Версия payload поднята 5 → 6; старые наряды без новых полей читаются как раньше (поля просто отсутствуют, печать дат не показывает).

**Дата работы ≠ дата выполнения наряда.** `completedDate` (дата выполнения наряда) и `completedAt` (время закрытия) не тронуты: статус наряда (`deriveWorkOrderStatusCode`) и колонка «Дата выполнения» в отчёте «Наряды» считаются как раньше — это закрыто тестами (`shared/src/domain/workOrderWorkDates.test.ts`).

## Шаги 4–6. Режимы дат в карточке и на печати

**Карточка наряда** (`WorkOrderDetailsPage.tsx`, компонент `WorkOrderDatesEditor.tsx`):

- Переключатель **«Период» / «Ежедневно»** — над таблицей «Виды работ».
- Режим «период»: поля «с … по …» для периода наряда; если бригада из нескольких человек — своя пара дат по каждому сотруднику («один работает по дням, другой закрывает наряд за период»).
- Режим «ежедневно»: в таблице «Виды работ» появляются колонки **«Дата»** (календарь по работе) и **«Исполнитель»** (сотрудник бригады), если бригада больше одного человека.

**Печать** (обе формы — `assembly` и `simple`, `woPrintModel.ts`):

- «Период» → в реквизитах строка **«Период»** со значением «с 13 мая по 2 июня»; у отдельных работ колонки дат нет.
- «Ежедневно» → в таблице работ колонка **«Дата»** («13 мая») и **«Исполнитель»**; период по сотруднику печатается отдельной строкой реквизитов «Период · Петров П.П.».
- Обе формы печатают даты одинаково; выгрузка в Word и письмо собираются из **тех же секций** (`buildWorkOrderPrintModel`), поэтому файл несёт ту же дату, что и лист.

## Открыто владельцу

1. **Предельный объём наряда.** 12 работ с длинными наименованиями теперь влезают в один лист (265,6 мм при пределе 273 мм) — но впритык. Если в цеху такие наряды обычны, решаем: держать один лист (кегль видов работ можно уменьшить оператором в панели печати) или разрешить два листа с пометкой «продолжение».
2. **Старые закрытые наряды без дат.** Приводить ли их к новому виду (разложить дату выполнения наряда по строкам) — это отдельная работа и риск переписать историю. Сейчас они печатаются как раньше.
3. **Отчёт по зарплате.** В «Виды работ по нарядам» дата в колонке «Дата» — это дата наряда, а не факт по каждой работе. Разложить по факту — решение владельца (в эту работу не входило).
