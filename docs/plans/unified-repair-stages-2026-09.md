## Решение владельца (зафиксировано из заявки)

- Дефектовка + разборка = один этап **«Разборка, дефектовка»**. Кнопка «Провести
  дефектовку» и лист остаются; кнопка автопроставляет этап, но этап ставится и
  вручную (галочка + дата, без захода в дефектовку).
- Список этапов в каждом двигателе — **по шаблону** (пустой, с иерархией).
  Существующие данные переносятся (ничего не теряется). Новые карточки получают
  список из шаблона автоматически.
- Шаблон этапов редактируется вручную: новые этапы + приоритет; приоритет —
  порядком в списке, желательно drag-and-drop с автоперенумерацией.
- Субординация по датам: этап не может быть датирован раньше нижележащего
  (ОТК раньше сборки — отказ). Возврат назад (обкатка → сборка) — помечается,
  история сохраняется, дальше — новый проход вверх (`pass`, как сейчас у строк
  этапов). Текущее место двигателя — по последнему этапу (п. 6 таблицы).
- Старые статусы ремонта и отдельный ввод этапов упраздняются **после приёмки**;
  страница «Этапы работ» остаётся сводкой по заводу (read-only).

## Состав этапов — утверждён владельцем 28.09.2026

Линейка (приоритет = порядок): Принят на завод → Разборка, дефектовка →
Комплектовка сделана → Укладка → Сборка → Обкатка → Выходной контроль ОТК →
Отправлен заказчику → Принят заказчиком. Боковая ветка (вне порядка):
утиль и брак (признан утильным / отправлен как утиль / забракован / хранение).
«Вал» узлом-этапом не стал (исключён). Ручные записи истории и переезды между
цехами этапами не становятся — остаются пометками в ленте.

## Шаги выполнения

1. **Домен шаблона (shared):** тип `RepairStageTemplate` (код, название, приоритет,
   автопростановка из кнопок да/нет) + правило «дата не раньше нижележащих» +
   правило возврата (`pass`). Чистые функции + тесты. Без UI.
2. **Хранилище:** строки единого списка — `operations` (`repair_history_entry`,
   новый `entryType: 'stage'` + `stageCode/pass` в meta). Статусы/акты/sheet-строки
   при переносе становятся такими строками (старые записи не трогаем — только
   читаем их как историю).
3. **Перенос данных:** скрипт-миграция (dry-run + `--apply` + row counts в PR):
   статусы с датами → строки; sheet-строки → строки; даты актов → строки;
   «Разборка, дефектовка» сливается из двух источников. Дедуп по (двигатель, этап, день).
4. **UI карточки:** вкладка «История ремонта» = единый список (дата, этап, открыть/
   править/создать, сортировка по датам, правка дат, ручная галочка дефектовки).
   Кнопка «Провести дефектовку» автопроставляет этап (и остаётся).
5. **Шаблон этапов:** экран справочника (CRUD узлов + приоритет drag-and-drop);
   новая карточка двигателя получает пустой список по шаблону.
6. **Гейты:** субординация дат при записи; возврат назад → пометка + новый `pass`;
   текущее место — по последнему этапу (фильтры/отчёт `engineFactoryStage` на
   новом источнике).
7. **Страница «Этапы работ»:** перевод в read-only сводку (ввод только из карточки). ✅ 29.09: `canEdit={false}` + подсказка; мёртвый инлайн-редактор снесён [#1046](https://github.com/Valstan/MatricaRMZ/pull/1046) (guard: список не пишет и не оповещает `matrica:engines-changed`).
8. **Удаление старого:** статусы-галочки и старый ввод — после приёмки владельцем
   (отдельным OK, как G4). Синк-паритет + планшет (android-порт того же). ⏳ ждёт приёмки.
9. Каждый шаг — свой PR с гейтами (typecheck/lint/test + CDP-смоук вкладки).

## Что НЕ входит

- Переименование существующих узлов; новые узлы кроме ОТК (их заводит владелец).
- Изменение печатных форм (только если попросят отдельно).
