# Окно приветствия: короткие новинки и три анимации (промт КАРМАНА #162)

**Промт:** КАРМАНА #162 «Окно приветствия: короткие новинки и три анимации» (зачитка владельца 26.11.2026).
**Ветка:** `feat/release-welcome-variants-2026-11-26` · **Машина:** PC79 · **План:** 26.11.2026.

## Проблема

Окно приветствия после обновления читалось плохо и было дорогим по вниманию:

1. **Текст едет.** Лента новинок крутилась вверх (`releaseWelcomeTeleprompterScroll`, 108 с) — оператор ждал, пока текст уедет, чтобы прочитать. Текст был продублирован вдвое ради бесшовной прокрутки.
2. **Кегль мелкий.** Новинка набрана 17px при межстрочном 1.68, восемь строк на релиз × два дня релизов в окне.
3. **Маркеры `**` видны.** Разбор `**` в жирный был только в плашке обновления (`App.tsx`), текст новинок рисовался как есть — оператор видел `✦ **Списки ведут себя одинаково.** В каждом списке…`.
4. **Оформление одно.** Сине-фиолетовое сияние с деталями и угольками. Владелец хочет три варианта: нынешний, вьюнки с заводскими деталями и снежинки с сугробом и логотипом — выбор случайный на клиента и на релиз.

## Глобальная линза (три строки)

- Искали готовый модуль: `docs/GLOBAL_MODULES.md` — **окна приветствия в реестре нет**; ближайшее — `photoPrint` (печать), `updateDispatcherService` (обновления). Обеда нет: делаем **своё**, в рамках существующего окна.
- Готовый код, который переиспользуем: `renderEnginePartSvg` (`App.tsx`) — детали завода уже нарисованы; `releaseWelcome` (`shared/src/domain`) — данные новинок и `buildReleaseWelcomeDigest`.
- Новый глобальный модуль **не заводим**: выбор оформления — чистая функция в `shared` (домен), а не отдельный сервис.

## Заводская линза

**Не касается.** Окно приветствия не трогает производственный поток: нет нарядов, этапов, актов, склада, BOM, бригад и отчётов ППО. `docs/zavod/FACTORY_MODEL.md` не читаем.

## Решения по открытым вопросам промта (уточняем под себя)

| Вопрос промта | Решение | Почему |
| --- | --- | --- |
| Где считать случайность | **В главном процессе**, по `clientId` + номеру релиза; рендерер получает готовый вариант | Шаг 8 промта; рендерер со своей случайностью менял бы оформление при перезапуске |
| Логотип от владельца | **Заглушка**, файл не ждём: главный процесс ищет `welcome-logo.png/svg` рядом с программой и отдаёт картинкой; нет файла — рисуем заглушку, окно не падает | Файла нет; код анимации при получении файла не меняется — подхватывается тот же путь |
| Сугроб заливает экран | **Потолок роста ~22% высоты окна**: сугроб растёт до потолка и дальше не растёт | Текст должен остаться читаемым при долго висящем окне |
| Прокрутка | **Убираем автоскролл, прокрутка остаётся запасным путём** (`overflow-y: auto`) | Текст виден сразу и сам не едет; если не влез — оператор прокручивает сам |
| Старые записи истории | **Не переписываем** (закрытые записи не трогаем). Компактное правило действует **с 3.148.0**; гейт ловит нарушение на новых записях | Переписывание прошлого — переделка истории; текст окна и так переживает длинные строки прокруткой |
| Формат `**` в данных | **Разбор в рендерере**, данные не чистим: старые записи сохраняют вид | Данные выпущенных релизов — закрытые записи |
| Планшет | **Те же три варианта**: оформление — CSS, а не код под Windows | Планшетная версия показывает окно тем же renderer |
| Тяжесть на слабых машинах | **Только CSS-анимации, без canvas**: снежинки — 18 узлов, вьюнки — 8 побегов, детали — те же SVG | Поколение парка — слабые машины; тяжёлый DOM недопустим |

## Шаги

1. **Текст новинок.** `shared/src/domain/releaseWelcome.ts`:
   - `parseReleaseWelcomeLine(text)` — разбор строки на `marker` / `lead` (жирный) / `rest`; символы `*` не остаются в тексте;
   - `RELEASE_WELCOME_HIGHLIGHT_MAX_CHARS` (предел длины строки) и `RELEASE_WELCOME_COMPACT_FROM` ('3.148.0') — с какой версии правило обязательно.
   - Рендерер рисует зачин `<strong>`, эмодзи-маркер — в колонке точки, кегль крупнее, автоскролл снят, прокрутка — запасным путём.
2. **Выбор варианта.** `pickReleaseWelcomeVariant(clientId, version)` в `shared` (FNV-1a по `clientId|версия` → один из трёх). `ui:releaseWelcome:get` отдаёт `variant` и `logoDataUrl`; в рендерере своей случайности нет.
3. **Вьюнки.** Побеги снизу вверх (`stroke-dashoffset` — рост стебля), листочки, на концах — детали из `renderEnginePartSvg`. Палитра зелёно-красная.
4. **Снег.** Снежинки разного размера, ветер сдувает часть в стороны; сугроб растёт снизу до потолка и держится; сверху висят ёлочные игрушки; логотип летит **за** снежинками (мигает, кружится, наезжает камерой, отлетает и мельчает).
5. **Канон.** Правило компактного текста — в `AGENTS.md` §Release process и `.claude/commands/reliz.md`.
6. **Гейты.** Тесты домена (вариант, разбор строки, правило компактности) + сторож окна (кегль, отсутствие автоскролла, прокрутка запасным путём, `**` разбирается, вариант не выбирается в рендерере, три оформления в CSS).

## Границы (что НЕ трогали)

- **Плашка обновления** («‹Перезапуск›») — не трогали.
