# План: Меню производственной программы — по общему киту списков

**Основание:** промт КАРМАНА **#67** (пункт 6: «контекстное меню = ровно то, что список
умеет» — недоступного пункта быть не должно **вовсе**, а новое действие списка обязано
попадать в меню само), **D-247**/**D-248**, план
[`unified-list-rules-2026-11.md`](unified-list-rules-2026-11.md) (шаг 5 — «шов с ПП»),
хвост [`pending/pp-seam-with-list-kit.md`](../pending/pp-seam-with-list-kit.md).

## Что было в коде (проверено 23.11.2026)

ПП была последним списком программы, чьё меню собиралось **руками в странице**
(`ProductionProgramPage.tsx`, блок `menuItems`):

- свои подписи и свои счётчики: «Распечатать выделенные (3)», «Скопировать выделенные (3)»,
  «Отправить почтой (3)»;
- «Открыть карточку» у строки **без двигателя** (группа «Требует данных») — **гасился серым**
  вместо того, чтобы исчезнуть: пункт враньёт о том, что список умеет;
- «Выделить»/«Снять выделение» — своими пунктами, а не из кита;
- «Убрать из программы» — при отсутствии права ведения плана пункта не было (это правильно),
  но вырано было не правилом кита, а проверкой в странице.

## Что стало

Меню ПП собирает **общий сборщик кита** — `buildListContextMenuItems`
(`utils/listContextActions.ts`); список **объявляет** свои действия
(`ListActionDeclaration`), и меню собирается из объявления:

| Действие | Объявление | Правило |
|---|---|---|
| Открыть карточку | своё, `scope: 'single'` | `available: Boolean(engineId)` — у строки без двигателя пункта **нет вовсе** |
| Распечатать | `listPrintAction` (кит) | общие подписи и счётчик пачки — из кита |
| Скопировать | `listCopyAction` (кит) | то же |
| Отправить почтой | своё | почты в ките нет — и это нормально: действие объявляет список |
| Убрать из программы | своё, `danger` | `available: canEdit` — нет права ⇒ нет пункта |
| Выделить / Снять выделение | кит | `onSelect` / `onClearSelection` из общего хука выделения |

## Границы

- Общий кит не трогаем: `utils/listContextActions.ts`, `hooks/useListSelection.ts`,
  `components/ListContextMenu.tsx` — ими занята параллельная линия (PR #1934, «карточки»).
- Правка только в `pages/ProductionProgramPage.tsx` (страница ПП) и её стороже.
- Права, порядок строк на сервере, печатные формы и данные не трогаются: меняется только
  способ сборки меню.

## Заводская линза (три строки)

- **Участок:** производственная программа — рабочий список плана (двигатели по договорам).
- **Кормит ли затор:** нет. Главный затор — начало сборки (ручной подбор деталей из
  обезличенного фонда, `FACTORY_MODEL.md` §3); меню плана — не узкое место.
- **Не ломает ли инвариант потока:** нет. План, порядок строк, этапы движения двигателя и
  права не тронуты; изменилось только то, какие пункты есть в меню строки.

## Приёмка (руками, после сборки)

1. ПКМ по строке плана: меню **«Выделить» · «Открыть карточку» · «Распечатать» ·
   «Скопировать» · «Отправить почтой» · «Убрать из программы»** — и ни одного серого
   (недоступного) пункта.
2. ПКМ по строке **без двигателя** (блок «Требует данных»): пункта «Открыть карточку»
   **нет вовсе**.
3. Выделить две строки → ПКМ: «Распечатать выделенные (2)», «Скопировать выделенные (2)»,
   «Отправить почтой выделенные (2)», «Убрать из программы (2)», «Снять выделение».
4. У пользователя **без права** ведения плана: пункта «Убрать из программы» нет.
5. Пункт «Открыть карточку» открывает карточку двигателя.
