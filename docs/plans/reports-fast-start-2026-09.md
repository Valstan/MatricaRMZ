# Отчёты: быстрый повтор и витрина шаблонов (пакет владельца 12.09, этап 2)

**Статус:** в работе с 2026-09-12. Владелец: «огромный список отчётов, у каждого много настроек; хотим повторить недавний отчёт — не помним, каким пользовались и что выставляли; пока всё настроишь — уходит время». Заказаны четыре вещи: витрина популярных шаблонов, автоподстановка частых настроек, подбор отчёта ИИванычем, общие «Мои отчёты».

## Что уже есть (разведка 12.09, не строить заново)

| Механизм | Где | Состояние |
|---|---|---|

| Именованные шаблоны фильтров пресета | `reports:filterTemplates*`, тип `ReportPresetFilterTemplate` | Работают, **уже роумятся** секцией профиля `reportFilterTemplates` (`userUiProfile.ts`), но видны только внутри своего пресета и без описания |

Считает по локальной реплике `audit_log` (свои прогоны), поштучно по каждому фильтру, с порогом «значение встречалось ≥2 раз и ≥40 % построений» |

**Открытия владельца это не заметил, потому что порог не набирается:** 8 построений за три недели, из них 5 по одному пресету, — значит «популярное» почти всегда `null`. Отдельную работу по пункту «автоподстановка» заводить не нужно, нужно дать ей данные (шаг A) и показать, что подставилось (шаг B).

## Замер прода 12.09 — он меняет конструкцию

```
ui.report_open    72 строки   19.07 → 06.09   актор — один
ui.report_build    8 строк    22.08 → 06.09   из них 5 по одному пресету
```

Вывод: **«популярные настройки по парку» строить не из чего** — отчётами пользуется по сути один человек, и построений единицы. Витрина, посчитанная по телеметрии, у владельца будет пустой ещё месяцы, а автоподстановка «самого частого набора» подставит единственный случайный.

Поэтому порядок меняется: сначала программа должна **запоминать, что именно строили и с какими настройками**, и давать это повторить. «Популярность» становится сортировкой того же журнала по частоте — и наполняется сама, по мере работы.

## Шаги

### A. Журнал построенных отчётов помнит настройки — ✅ сделано (PR этапа 2а)
- `ReportPresetHistoryEntry` (`shared/domain/reports.ts`) получает `filters`, `disabled`, `rowCount`; санитайзер истории в `electron-app/src/main/ipc/register/reports.ts` (`sanitizeHistoryEntries`) валидирует их с потолком по размеру JSON, как у шаблонов фильтров.
- Запись — там же, где сейчас (`ReportPresetPage.buildPreview`), одним вызовом `historyAdd`.
- Роуминг: новая секция профиля `reportHistory` по образцу `reportFilterTemplates` (`shared/domain/userUiProfile.ts` + гидрация в `App.tsx`) — отчёт, построенный на одной машине, виден с другой.
- Дедуп: одинаковый пресет с одинаковым набором фильтров не плодит строки, а поднимает `lastAt` и счётчик `times` — это и есть будущая «популярность».

### B. Витрина «Шаблоны отчётов» (отдельный экран)
- Собирает в одном месте: сохранённые шаблоны фильтров **всех** пресетов (сейчас видны только внутри своего), строки журнала из шага A, «Мои отчёты».
- Карточка: название, тема, **описание настроек словами** (период, марки, контракты — именами через `ReportOptionSource`, не идентификаторами), когда строили последний раз и сколько раз, кнопка «Открыть с этими настройками».
- Сортировка по частоте и по свежести; поиск по названию и описанию.
- Шаблон фильтров получает необязательное поле «описание» (`ReportPresetFilterTemplate.description`), чтобы владелец подписал «для сверки с бухгалтерией».

### C. Открыть отчёт с готовыми настройками — ✅ сделано (PR этапа 2а)
Сегодня пресет открывается **только** по идентификатору: `openReportPreset(presetId)` (`App.tsx`), `ReportPresetPage` не принимает фильтров вовсе. Без этой точки невозможны ни повтор из журнала, ни витрина, ни ссылка ИИваныча с настройками. Делается первым:
- `openReportPreset(presetId, opts?: { filters, disabled })` + состояние рядом с `selectedReportPresetId`; проп передаётся в обе точки отрисовки (главная вкладка и вторая панель).
- В `ReportPresetPage` — одноразовый эффект, применяющий переданный набор тем же способом, что и `applyFilterTemplate`. **Важно:** эффект автоподстановки популярных настроек не должен затирать переданный набор — он выполняется на смену пресета.

### D. ИИваныч подбирает и открывает
- `suggest_report`: вместо совпадения слов — подбор моделью по каталогу (`callLlmJson`), с возвратом готовых фильтров (контракт/заказчик/период через `find_entity`).
- Маркер расширяется до «пресет + фильтры», клиент открывает отчёт уже настроенным (точка из шага C).

### E. «Мои отчёты» — за пользователем, а не за машиной — ✅ сделано (этап 2б)
Шаблоны фильтров пресетов уже роумятся секцией профиля `reportFilterTemplates`; «Мои отчёты» (конструктор) — нет, они живут в `settings` машины. Роуминг делается тем же способом (секция профиля + санитайзер), **без миграции БД** — это дешевле синк-таблицы и снимает «на другом компьютере моих отчётов нет».

## Что уже отгружено (этап 2а)

- Журнал помнит `filters`, `disabled`, `rowCount` и число повторов; одинаковый набор — одна строка с растущим счётчиком (`reportHistorySignature` в shared).
- Журнал роумится секцией профиля `reportHistory`; слияние с другой машины — `reports:historyMerge`.
- Каталог показывает настройки словами (`reportFilterSummary.ts`: имена вместо идентификаторов, свёртка длинных списков, пропуск дефолтов) и открывает отчёт уже настроенным; добавлен раздел «Часто повторяемые отчёты».
- Попутно закрыт дефект: каталог не перечитывал журнал после построения отчёта в соседней вкладке (событие `matrica:report-history-changed`).
- Проверено живьём: `cdp-report-history-filters.mjs` — PASS.

**Этап 2б:** личные шаблоны «Моих отчётов» роумятся секцией профиля `customReportTemplates`. Общий бакет (`__shared__`) осознанно не роумится: профиль личный, и общий шаблон, приехав в него, стал бы личной копией у каждого оператора — общие шаблоны ждут серверного хранения. Вливание не трогает строку, которая уже есть на машине (у шаблонов нет серверной копии, и перезапись была бы невосстановима). Проверено живьём двухфазным смоуком: шаблон сохранён, профиль машины стёрт, шаблон вернулся с сервера.

Осталось по плану: **B** (отдельный экран витрины со всеми шаблонами и описаниями), **D** (ИИваныч отдаёт ссылку с фильтрами).
