# Вид двигателя: обязателен при создании карточки и переопределяется, когда появился контракт

**Промты КАРМАНА:** #36 (текст владельца) + #37 (план из библиотеки), 18.11.2026.
**База чтения плана:** `a75277a1` (v3.133.0). **Наш код:** `main` @ `b9604242` (v3.134.0).

## Задание владельца (дословно)

> При создании нового двигателя — проверка перед сохранением карточки: вид (военный или гражданский) должен быть выставлен. Если контракт у двигателя уже выбран, вид берётся из контракта. Если контракт не выбран — оператора нужно принудительно попросить поставить вид вручную (военный или гражданский), без этого карточку сохранить нельзя.
>
> И нужна стража-проверка: если у двигателя позже появится контракт, вид должен быть переопределён глобально — во всех списках, отчётах и прочих местах, где вид показывается или фильтруется. То есть вид двигателя — это всегда вычисляемое значение с приоритетом: контракт → карточка двигателя → контрагент.

## Что уже было сделано (PR #1807, «вид двигателя — одно правило на всю программу»)

- **Вид — вычисляемое значение** по общему правилу `shared/src/domain/engineKind.ts` → `resolveEngineKind`: договор → карточка двигателя → контрагент. Источников нет вовсе — вида нет (`null`), а не «ГОЗ по умолчанию».
- **Хранение** — строгая колонка `engine_kind` в `erp_engine_cards` и `erp_counterparties` (миграция `0133`), EAV не трогаем (заморозка).
- **Вид показывается** в списке двигателей (колонка «Вид» + подпись источника в подсказке), в отчёте «Двигатели», в карточке двигателя, и отбирается ступенью фильтра «Вид» (значение «Вид не задан» — отдельное, чтобы двигатели без вида не выпадали из отбора молча).
- **Появление договора переопределяет вид САМО** (вычисляемость), ручное значение **не переписывается** — оно просто перестаёт быть первым источником.

**Не сделано (эта нить):** вид у нового двигателя **не обязателен** — карточка сохранялась без вида, и двигатель молча выпадал из отбора «военка/гражданка». Требование владельца: без вида карточку сохранить нельзя.

## Что решаем

### 1. Гейт — в единственной двери записи карточки

`saveEngineCardGated` (`electron-app/src/main/services/engineCardWrite.ts`) — единственная дверь записи карточки двигателя; у карточки два входа: сама карточка и пачечный приём (`engineBulkIntakeService` зовёт ту же дверь). Проверка в форме обошлась бы пачкой (класс brain G363).

- **Строгость — только при первичном заведении.** «Первичное заведение» = у сущности ещё нет строки (`entities`), потому что карточка материализуется первой реальной записью (deferred-create). Правка старой карточки, заведённой до появления вида, блокироваться **не должна** — иначе программа станет непригодна для части парка. Такие карточки видны в списке по ступени «Вид не задан».
- **Договор важнее ручного значения:** если договор выбран — вид берётся из него, оператора не спрашиваем (спорное ручное значение не мешает заведению).
- **Вид заказчика (третий источник приоритета) гейтом не принимается:** по требованию владельца при заведении вид выбирает оператор, а не подставляется из карточки контрагента.
- Гейт стоит **до** `ensureEngineRow`: отбитая запись не должна оставлять сущность-призрак.

Правило живёт в домене (`engineKindRequirement` в `shared/src/domain/engineKind.ts`), дверь его зовёт — тогда карточка и пачка решают это правило одинаково.

### 2. Вид договора — читается по id, тем же правилом, что у списка

`getContractKindById` в `engineService.ts`: договора нет — вида нет (`null`); договор есть, но секций нет — вид по умолчанию (ГОЗ), как в списке; секции есть — вид из них.

### 3. Пачка — вид общий на пачку, проверка ДО заведения

- В диалоге приёма появляется поле «Вид двигателя»: **видно, когда договора нет**; с договором — только подпись «возьмётся из договора».
- Проверка в сервисе — **до** заведения: иначе отказ на середине пачки оставил бы половину заведённых карточек без вида. Строки со своим договором вид не требуют (вид из их договора).
- «Пропустить» и «дописать существующую» карточку вид не требуют — там заведения нет.

### 4. Карточка — предупреждение до сохранения

В карточке двигателя при выбранном договоре вид уже **только для чтения** («из договора», а если ручное значение расходится — «перекроется договором»). Для нового двигателя без вида добавлена явная подсказка: «Вид обязателен для нового двигателя: без него карточку не сохранить».

### 5. Стража-проверка (отчёт/сторож, а не фоновая переписка)

- **Сторож-тест** `engineKindRequired.guard.test.ts`: гейт в двери и **до** deferred-create; пачка идёт через ту же дверь и требует вид до заведения; вид везде считается по общему правилу (`resolveEngineKind`), а не читается из ручного поля; в карточке видно, что ручное значение перекроется; в списке есть ступень «Вид не задан».
- **Фоновая переписка поля — вредна** и её нет: она конфликтовала бы с ручным значением и ломала бы историю («почему у двигателя вчера был ГОЗ, а сегодня гражданский» — потому что вчера договора не было).

## Что не трогаем

- `saveEngineCardGated` — правило **добавляем** внутрь двери, существующие гейты (дубли, deferred-create, авто-этапы) не меняем.
- `contract_sections` — вид договора остаётся там.
- Пачную приёмку — не обходим дверь.
- EAV — новых атрибутов не заводим (заморозка).
