> Порядок фаз зафиксирован владельцем: **боль → печать/выгрузки → данные/фильтры**.

## Решения владельца (зафиксированы 19.10.2026)

1. Порядок — «боль первой»: зависание → вырезание OpenCode-узлов → автозапуск/трей → печать и Word/Excel → даты/фильтры/рекламации/возвраты/соединение отчётов.
2. Переименования ступеней: «Все этапы» → **«История»**, «Где сейчас?» → **«Текущее состояние»**; «Дата этапа» — без изменений.
3. «Дата этапа»: отбор по дате **конкретного прохода** (двигатель попадает в день D, если любой его этап был в D) + быстрый выбор одного дня.
4. «Дата внесения» — убрать из показа по умолчанию, оставить в настройках колонок (аудит).
5. Возвраты: логику ставит программа; оператор может снять/поставить галочку и вписать причину к той же записи; номер прохода считается по порядку записей с галочкой (снял — нумерация у следующих поправилась).
6. Зависание ловится в диалоге «Добавить этап» списка этапов, на 2–3-м добавлении (внутри одной сессии работы).
7. Автозапуск: тихий старт **только** при запуске вместе с Windows; холодный запуск с ярлыка — окно запуска показываем. Закрытие окна = свернулось в трей, **у всех**.
8. Word/Excel: диалог «Сохранить как» с запоминанием пути, по умолчанию «Документы»; сначала списки, потом печатные формы карточек.

## P3. Автозапуск, трей, горячий старт (M + диагностика)
**Цель:** стартовала с Windows — тихо, без окон, с иконкой в трее; дальше открывается мгновенно.

**Что известно по коду:**
- Автозапуск — ярлык `MatricaRMZ.lnk` с `--minimized` в папке «Автозагрузка» (`main/services/clientAutostartService.ts`), вызов в `main/index.ts:469-481`.
- Тихий режим: окно создаётся скрытым (`show: false`), статус-окно не показывается первым вызовом, трей создаётся **только** при тихом запуске (`index.ts:750`).
- Окно запуска (`main/services/startupStatusWindow.ts`) показывается с задержкой 3.5 с; «бесконечный прогресс» = старт висит.
- Порядок старта (`index.ts:500-767`): ключ БД → SQLite → миграции → **сверка схемы с сервером** → сид → IPC → аудит → **применение серверных настроек** → `recoverStuckUpdateState` → `applyPendingUpdateIfAny` → `runAutoUpdateFlow` (может выйти/перезапуститься на установку обновления) → только потом `createWindow()`. Любой сетевой шаг или залипшее обновление держат старт.
- Закрытие окна: `mainWindow.on('close')` → диалог в рендерере; `window-all-closed` не выходит, только если есть трей.
- Рядом живёт watchdog (`watchdogHandshakeService.ts`) — проверить, не конфликтует с новым поведением.

**Шаги:**
1. Диагностика по реальной машине (прод-диагностика/критические события/лог клиента `matricarmz.log`) — на каком шаге висит.
2. Тихий старт: при `--minimized` окно запуска **не показывать вообще** (включая `setStartupStage`/`raise*` пути).
3. Таймауты: сверка с сервером и применение серверных настроек — с таймаутом и «работаем офлайн»; обновление не должно блокировать открытие окна.
4. Трей — **всегда** (не только при тихом старте); закрытие окна = свернулось в трей; «Выход» — только явной командой в меню трея (и, если нужно, в меню программы).
5. Холодный старт с ярлыка при отсутствии трея — окно запуска показываем (как сейчас).
6. Повторный клик по ярлыку/иконке при живом трее — мгновенный показ скрытого окна (заготовка single-instance уже есть).

**Ход (19.10.2026, PR #1381):** сделано всё, кроме шага 1 в его буквальной части «по реальной машине» — вместо гадания добавлен инструмент: каждый этап старта пишется в `matricarmz.log` строкой `startup-stage: <мс> -> <этап>` и итог `startup: window created after Nms`, так что следующий «залипший старт» виден по логу без разбора.

- **Шаг 2 (тишина):** `setStartupStatusSilent(minimizedLaunch)` — окно этапов не создаётся и больше не всплывает по таймеру 3.5 с (раньше `setStartupStage` его взводил, и автозапуск мигал окном). Явная просьба оператора (повторный ярлык) снимает тишину в `raiseStartupStatus`.
- **Шаг 3 (сеть):** сверка схемы при старте — одна попытка 4 с вместо 2×20 с (у синка остались прежние 2×20); окно создаётся ДО сетевой проверки обновлений — `runAutoUpdateFlow` ушёл в фон, до окна остались только локальные `recoverStuckUpdateState` + `applyPendingUpdateIfAny` (иначе окно мелькнуло бы и погасло на установке).
- **Шаг 4 (трей):** трей создаётся всегда; `close` → `hide()` + одноразовый шарик-подсказка; «Выход» — пункт меню трея, идёт через подтверждение рендерера с 25-секундным сторожем (зависшее окно не превращает выход в ничто); `app:close-response` теперь `app.quit()`, а не `close()` — иначе трей не давал приложению умереть.
- **Шаги 5–6:** нет иконки/не Windows — окно показываем, закрытие работает по-старому (подтверждение); повторный клик по ярлыку и второй экземпляр показывают скрытое окно.

**Живая проверка (PC79, Electron 43, стенд):** тихий старт — окно скрыто (`IsWindowVisible=false`), окна этапов нет, `tray: created`; обычный старт — окно видно через 4.5 с (проверки обновлений в это время ещё идут в фоне); `WM_CLOSE` → `window closed to tray`, процесс жив, окно скрыто; второй экземпляр выходит, а скрытое окно возвращается; ответ рендерера на close-request гасит приложение до нуля процессов с `quit-flush: done`.

**Приёмка (на живой машине):** автозапуск с Windows — ни одного окна, иконка в трее, клик → мгновенно; закрыл окно — программа жива; запуск с ярлыка после полного выхода — видно окно запуска; после открытия — горячий старт.
