# История заездов: вкладка в карточке двигателя, свой договор и контрагент у каждого заезда (промты КАРМАНА #42 + #43)

**Источник задачи:** промт владельца КАРМАНА **#42** (19.11.2026) + план владельца **#43** из библиотеки мозга.
**Статус:** в работе. **Ветка:** `feat/engine-arrivals-history-tab`.

## Цель (словами владельца, #42)

> История заезда двигателя с одним и тем же номером, скорее всего, лучше заносить в одну и ту же карточку двигателя: сделать вкладку «История заездов» и хранить данные там.
>
> Но в каждом заезде могут быть разные договоры, разные поставщики и заказчики — поэтому по каждому заезду это заполняется отдельно.
>
> При этом нужно учитывать историю заездов, то есть и старые заезды. Когда нужна текущая информация, старые заезды и старые даты брать не нужно; когда нужна история вообще по всем движениям — берутся все заезды, отъезды и так далее.

Три требования: **(1)** вкладка «История заездов» в карточке двигателя; **(2)** у каждого заезда — свои договор и контрагент; **(3)** разделение «текущая информация» (карточка) и «вся история» (вкладка).

## Что уже есть (сверено с кодом, 20.11.2026)

- **Сборка заездов внутри карточки уже есть** — `shared/src/domain/engineReclamations.ts`: `buildEngineVisits()` (:257) собирает `EngineVisit[]` = основной цикл (заезд №1) + рекламации по `queue_no` (№2, №3 …), с датами прихода/отгрузки и подписью. Правило порядка и гейт непересечения дат — там же (`validateEngineReclamationQueue`).
- **Лента заездов сегодня живёт блоком внутри «Истории ремонта»** — `electron-app/src/renderer/src/ui/components/EngineHistoryFeedPanel.tsx:761-791` (блок «Заезды двигателя», `data-engine-visits`).
- **Очередь рекламаций — строгая таблица** — `erp_engine_reclamations` (`backend-api/src/database/schema.ts:2742`), миграция `0125_engine_reclamations.sql`, уникальный индекс `(engine_id, queue_no)`.
- **В строке заезда НЕТ договора и контрагента** — в ней только даты, дефект, акт, комментарий. Это и есть содержательная нехватка под требование владельца.
- **Повторные заезды (старые заезды) — отдельные карточки с тем же номером** — `repeat_arrival_flag` / `previous_arrival_id` (`schema.ts:991-994`); группировка и роль заезда («свежий» / «архивный», «N из M») считается доменом `shared/src/domain/repeatArrival.ts` (`arrivalPlacements()` :66, `arrivalPlacementLabel()` :103); список двигателей уже показывает бейдж «архивный заезд» (`pages/EnginesPage.tsx:852-874`).
- **Соседей по номеру карточка уже умеет находить** — `window.matrica.engines.findDuplicateCandidates({engineNumber, excludeEngineId})` → `exact[]` с `arrivalDate`, `isRepeatArrival`, `isNumberCollision` (`shared/src/ipc/types.ts:367-381`), то есть ровно тот набор, который нужен `arrivalPlacements()`.
- **Заказчик — из договора** — `shared/src/domain/engineCustomer.ts` (`resolveEngineCustomer`): договор → контрагент, иначе поле карточки; источник наружу отдаётся (`contract` | `card` | `none`).
- **Даты движения — из источника правды** — `shared/src/domain/engineReclamation.ts` (`resolveEngineTruthDates`): рекламация выше основного цикла.

## Уточнения к плану #43 (наша правка, библиотеку не переписываем)

1. **Без `workshop_id` в строке заезда.** План #43 копировал поля карточки; но цех из карточки двигателя выведен по решению 2026-10 («двигатель не привязан к цеху; цех — атрибут этапа ремонта `work_sheets`», `EngineDetailsPage.tsx:2550-2552`), и владелец цех у заезда не просил. Лишняя колонка — лишняя правда.
2. **«Поставщик» и «заказчик» — это один контрагент программы.** Импорт двигателей из ведомости комплектности кладёт `supplierName` в `customer_id` карточки (`backend-api/src/scripts/importEnginesFromCompletenessCsv.ts:951-956`), договор и карточка называют это поле «Контрагент» (`ContractDetailsPage.tsx:163`, `EngineDetailsPage.tsx:2565`), раздел называется «Контрагенты — Поставщики и партнеры». Значит заезду нужен **договор + контрагент**, а не два разных поля.
3. **Заказчик заезда выводится из его договора** — тем же правилом `resolveEngineCustomer`, что и у карточки: в заезде хранится договор, а поле контрагента — запасной путь (двигатель без договора). Иначе появятся две правды.
4. **«Старые заезды» — это карточки-архивы с тем же номером**, а не строки очереди: у номера бывает несколько карточек, и владелец говорит «двигателя с одним и тем же номером — в одну и ту же карточку». Вкладка собирает заезды **номера**: архивные карточки + основной цикл этой карточки + её рекламации. Слияние карточек в одну сущность не делаем (план #43 прямо вели «механику группировки по номеру не трогать») — вкладка показывает историю номера в одной карточке, данные остаются там, где лежали.
5. **Нумерация заездов сквозная по дате** — «Заезд 1, 2, 3 …» по времени прихода, а подпись строки («основной цикл» / «рекламация №1» / «старый заезд 2024») остаётся той же, что в домене: заезд №1 карточки — основной цикл, №2 и далее — рекламации.

- Блок «Заезды двигателя» из `EngineHistoryFeedPanel` **переносится** в новую вкладку (план #43, шаг 1): лента событий ремонта остаётся в «Истории ремонта».

- Разделение «текущее / история»: вкладка «Основное» — текущее (как сейчас); вкладка «История заездов» — вся история, с подписью сверху, что текущее — на «Основном».
