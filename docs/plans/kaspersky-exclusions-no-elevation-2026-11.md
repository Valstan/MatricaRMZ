# Касперский: система исключений без повышения прав

- **Заказ владельца:** 2026-11-12 (устно, в сессии)
- **Статус:** в работе
- **Ветка:** `feat/kaspersky-exclusions-no-elevation`
- **Связано:** [ADR-0003](../adr/0003-signed-code-ecosystem-one-kaspersky-rule.md) (подпись и доверие по сертификату — **не сработало**, откат на исключения), [ADR-0002](../adr/0002-single-executable-root-not-program-files.md) (единый корень), [`scripts/client-ops/`](../../scripts/client-ops/README.md) (помощник), [`docs/pending/nastroit-doverennuyu-zonu-antivirusa-na-parke.md`](../pending/nastroit-doverennuyu-zonu-antivirusa-na-parke.md)

## Замысел владельца (дословно по смыслу)

1. «История с подписями и сертификатами не прошла» — доверие по сертификату не подтвердилось на парке, значит работаем **системой исключений**.
2. «Какие файлы внести в исключение Касперского, как это сделать более или менее автоматически?» — две ссылки (два файла: исключения + доверенные программы) формирует помощник; этим занимается **системный администратор**. Нужно, чтобы это было удобно для него.
3. «Написать отдельную инструкцию, коротенькую последовательность действий для системного администратора» — отдельный документ, короткий, именно для админа.
4. В самой программе:
   - **с нуля** (после удаления Касперским, или чистый компьютер) — инструкция **автоматически выходит на экран**;
   - **при обновлении** — инструкция не показывается, но нужна **кнопка в интерфейсе**, чтобы быстро найти и открыть;
   - по нажатию кнопки скрипт **распаковывается и запускается автоматически** (предполагается, что Касперский уже приостановлен);
5. **Всё без повышения прав.** «У нас программа работает в аккаунте пользователя без повышенных прав, поэтому и все эти исключения тоже без повышенных прав… все скрипты, которые поднимают права, всё это надо убрать, всё это без админа работает, и все настройки делать без админ прав.»

## Что установлено замерами (факты, а не предположения)

- **Все процессы клиента — один файл.** На живой машине (PC79) 7 процессов `MatricaRMZ.exe`: главный, `--type=gpu-process`, `--type=renderer`, три `--type=utility` (network/node/audio). Это один PE-образ, различаются только флагом `--type=`. Значит **одно исключение на этот файл покрывает все процессы**, а «дочерние процессы» отдельной строкой вносить не нужно.
- **Отдельные исполняемые файлы продукта** (16 PE в папке установки, 560 МБ, 364 файла): клиент, деинсталлятор, сторож, `elevate.exe`, 8 DLL Electron, 4 нативных модуля `.node`. Рядом с ними `app.asar` (94,7 МБ) и 58 `.pak` — это данные, не код.
- **Подпись на месте, но доверия не даёт.** Все 16 PE подписаны (`Status: Valid`, боевой CA в обоих машинных хранилищах на PC79). Механика «доверенное системное хранилище сертификатов» на живой активированной машине **не включалась ни разу** — по справке вендора она есть, но результата на парке нет. Решение владельца: **развивать исключения**.
- **Что реально пишется и сканируется:** `matricarmz.sqlite` — **338 МБ**, лог — 22 МБ, кэш обновлений — 136 МБ. Это и есть главная нагрузка на сканер; исполняемые файлы подписаны и потому дешёвы для проверки.
- **Текущий список на машине (помощник, режим `Signature`):** 7 папок-исключений + 5 ярлыков + 2 маски `%TEMP%` + 7 масок вида `C:\Users\*\...` = 16 строк исключений, и **1** доверенная программа (`MatricaRMZ.exe`) — остальное покрывает подпись.
- **Что покрывает подпись, а что нет.** Подпись закрывает только PE-образы. Данные (`.sqlite`, логи, `.asar`, `.pak`, кэш обновлений) подпись **не** покрывает — их закрывают исключения на папки. Поэтому «история не прошла» означает: доверенные программы надо вернуть в список **полностью** (Legacy-режим), а не «оставить одну строку».
- **Потребительский Касперский не имеет API.** `avp.com` не умеет добавлять исключение (`HELP` даёт только `EXPORT`/`IMPORT`/`SCAN`/…), а Самозащита блокирует правку конфигурации извсе. Значит **шаг внесения в список всегда делает человек** — наш код может только подготовить файлы и инструкцию. Это ограничение вендора, его не обойти.
- **Как отличить «с нуля» от «обновления».** electron-builder передаёт приложению флаг `--updated` при запуске из установщика в режиме обновления (`common.nsh`: `${if} ${isUpdated} StrCpy $startAppArgs "--updated"`), и NSIS-шаблон различает режимы через `${isUpdated}`. Свой установщик уже использует `${ifNot} ${isUpdated}` (см. `electron-app/installer/installer.nsh:226`) — рабочий приём в этом репозитории.

## Решение

### 1. Скрипты работают без повышения прав

- `matrica-ops.ps1`: убрать авто-подъём при старте (`Start-Process -Verb RunAs`) и кнопку «Перезапустить от администратора». Окно открывается как есть, права не спрашивает и не требует.
- `kaspersky-matrica.ps1`: убрать раздел «Корень доверия — повышенный шаг» и кнопку установки корня (`RunAs`). Доверие по сертификату — откат, шага с правами в сценарии больше нет.
- `lan-share-firewall.ps1` и `opencode-cleanup.ps1`: правило брандмауэра и снятие задачи планировщика по определению требуют прав администратора. Их **не выкидываем** (полезны админу), но они перестают быть частью автоматики оператора: окно честно пишет, что этот шаг делает тот, у кого есть права, и даёт готовую команду.
- `Запустить-от-администратора.cmd`: больше не нужен — elevated-запуск не требуется. Убираем из архива и из приёмки.

### 2. Доверенные программы — полный список (откат с подписи)

- Помощник переводится в режим **`Legacy` по умолчанию**: доверенными вносятся все исполняемые файлы продукта (клиент, сторож, оба апдейтера, инсталлятор) — подпись на парке доверия не даёт, значит закрывать их должна явная строка доверенных.
- Ключ `-TrustMode` сохраняется: `Signature` остаётся как явный выбор (если механика сертификатов однажды подтвердится), но **по умолчанию — `Legacy`**.

### 3. Инструкция системному администратору — отдельный короткий документ

- Новый файл `scripts/client-ops/admin-instruction.ru.md`: короткая последовательность действий администратора (импорт двух файлов → галочки на доверенной программе → проверка). Без длинных объяснений «почему».
- Существующая `guide.ru.md` (33 КБ) — это памятка **оператору**; она остаётся, но из неё уходит раздел про сертификаты.

### 4. В программе: автопоказ «с нуля» и кнопка при обновлении

- **Маркер «с нуля».** Установщик в `${ifNot} ${isUpdated}` (то есть не при обновлении) пишет файл-метку в папку данных клиента. Обновление метку не пишет — значит «с нуля» отличается от «обновления» надёжно, без догадок по датам.
- **Автопоказ.** При старте клиент читает метку: если она есть — показывает окно с инструкцией (и ссылкой на скрипт). Метку после показа убирает, чтобы не мучить повторно.
- **Кнопка в интерфейсе.** В окне «Скрипты обслуживания» — заметная кнопка «Настройка исключений в Касперском». По нажатию: распаковать архив и **запустить помощника автоматически** (без прав). Это ровно то, что просит владелец: кнопка = «я администратор, Касперский приостановлен, дай мне список».
- Нажатие кнопки **не** требует остановки Касперского: архив под паролем `111` непроницаем для сканера, а распаковка идёт в папку данных клиента, которая уже стоит в исключениях.

## Границы (что НЕ делаем)

- Не переупаковываем клиент в один `.exe` и не уходим в контейнеры: portable ломает автообновление (на Windows поддерживается только NSIS) и триггерит детект упаковщиков; Windows-контейнеры не умеют GUI-приложения. Это рассмотрено и отклонено — см. раздел «Почему не» ниже.
- Не трогаем сам факт подписи релизов: подписанный EXE по-прежнему лучше неподписанного (меньше шума у сканера и в UAC). Убираем только **зависимость от подписи** в настройке доверия.
- Не автоматизируем внесение в Касперский — этого не умеет сам продукт (Самозащита). Готовим файлы + инструкцию.

## Почему не «одним файлом» и не «в контейнер» (решение зафиксировано, чтобы не переоткрывать)

- **Single-file/portable.** Electron не имеет поддерживаемого режима «весь клиент в одном `.exe`». Ближайшее — `portable` у electron-builder: 7-Zip SFX, который на каждый запуск распаковывается во временный каталог и оттуда запускается. Официальная документация Electron прямо предупреждает, что распаковка файлов во временный каталог «может вызывать срабатывание антивирусных сканеров»; Касперский отдельно детектит упаковщики и SFX (класс `Packed`). Плюс ломается автообновление: на Windows `electron-updater` поддерживает только NSIS. Итог — срабатываний станет **больше**, а не меньше.
- **Docker/контейнеры на Windows.** Microsoft прямо: контейнеры «поддерживают только серверные приложения, у которых нет интерактивного сеанса» — GUI-приложение в Windows-контейнер не идёт. Плюс KES сканирует содержимое контейнеров (компонент Container Scan), то есть от Kaspersky это не лечит. Плюс лицензия Docker Desktop бесплатна только при <250 сотрудниках и <$10 млн выручки.
- **Что реально решает задачу:** один исполняемый файл клиента + полный список доверенных программ + исключения на папки с данными. Дочерние процессы Electron — тот же файл, поэтому отдельных строк под них не нужно.

## Заводская линза
