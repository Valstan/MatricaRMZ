# Нитка: класс «застрявшая очередь» — отчёт не должен врать, очередь не должна быть слепой (26.11.2026)

**Основание.** Инцидент 26.11.2026: тревога «очередь отправки на сервер застряла» на машине `PC20`
(win32, клиент 3.147.0) — 3 строки `audit_log`, самая старая 24.11 08:14:49. Разбор (read-only, прод не
трогали) — [`docs/pending/trevoga-ochered-zastryla-otchet-po-ustarevshey-probe.md`](../pending/trevoga-ochered-zastryla-otchet-po-ustarevshey-probe.md).
Суть: **данные не потеряны, очередь уехала сама за 5 секунд до нажатия кнопки** — отчёт описал
состояние, которого уже нет.

**Решения владельца (26.11.2026):** (1) чинить отчёт + видимость + бюджет; (2) оператор видит свои
строки журнала при pull; (3) шум журнала (телеметрия и повторные пуши) — отдельная нитка + проверка
no-op на проде.

**Глобальная линза:** готовые модули есть — отчёт (`shared/src/domain/stuckPending.ts`), снимок
диагностики (`electron-app/src/main/services/sync/diagnosticsReporter.ts`), сборка push
(`electron-app/src/main/services/syncService.ts` + `sync/pushBudget.ts`), видимость при pull
(`backend-api/src/services/sync/pullReadFilter.ts` + `syncPrivacy.ts` + `shared/src/domain/ledgerAuthz.ts`)
· дубль: нет (новый модуль не нужен) · действие: **доработать существующие модули**.

**Заводская линза:** участок — синхронизация (не производственный поток) · кормит ли затор — нет (главный
затор — начало сборки) · не ломает ли инвариант — нет: правится только видимость и отчётность очереди.

## Что чиним

1. **Отчёт не должен описывать прошлое.** Тревога собирается из последней троттлированной пробы, а
   очередь к этому моменту уже могла уехать. Правки: проба **в момент нажатия** кнопки; если очередь
   пуста — говорить «очередь уехала», а не поднимать тревогу; «последний успешный синк» — из
   **сохранённого** `LastSyncAt` (счётчик в памяти пуст после перезапуска); причина отказа не
   обнуляется молча, даже если она офлайн-класса.
   Файлы: `electron-app/src/main/ipc/register/authAndSync.ts`, `electron-app/src/main/services/syncManager.ts`,
   `shared/src/ipc/types.ts`, `shared/src/domain/stuckPending.ts`, `electron-app/src/renderer/src/ui/App.tsx`.
2. **Очередь в `audit_log` не должна быть слепой.** Таблицы нет в клиентском снимке диагностики ⇒ ни
   сервер, ни автолечение её не видят (ни на одной машине). Правка: `audit_log` в снимке — по общему
   правилу отложенных строк (телеметрия `ui.*` в застрявшие не считается).
   Файлы: `electron-app/src/main/services/sync/diagnosticsReporter.ts`, `electron-app/src/main/services/sync/localPending.ts`.
3. **Бюджет push'а не должен отсекать таблицы молча.** Пять таблиц берут строки через `takePending`
   (отсечение называется в логе), остальные — сырым `.limit(limitFor(…))` ⇒ при съеденном бюджете
   получают **ноль** строк и **ни строчки** в лог. Правки: называть отсечение для всех таблиц;
   в `audit_log` **бизнес-строки идут первыми**, телеметрия `ui.*` — на остаток (иначе тысячи
   телеметрических строк вытесняют `app.session.*` и другие бизнес-строки — ровно тот класс, что
   был с «зомби» 24.11).
   Файлы: `electron-app/src/main/services/syncService.ts`.
4. **Граница (решение владельца): оператор вытягивает свои строки журнала.** Сейчас `audit_log` при
   pull — только для админов ⇒ операторский клиент не может получить свои журнальные строки обратно,
   а потерянный ответ push'а оставляет строку в очереди навсегда. Правка: не-админ видит только
   строки с `actor` = свой логин; админы — как прежде.
   Файлы: `backend-api/src/services/sync/pullReadFilter.ts`, `backend-api/src/services/sync/syncPrivacy.ts`,
   `backend-api/src/services/sync/pullChangesSince.ts`, `backend-api/src/routes/ledger.ts`.
   Граница расширяет видимость персональных данных ⇒ решение владельца зафиксировано (26.11.2026).

## Границы и риски

- Правка 4 расширяет видимость: оператор увидит **свои** журнальные строки (не чужие). Объём у оператора
  — его собственные строки (десятки-сотни), не вся таблица.
- Правка 3 меняет порядок отбора в `audit_log`: бизнес-строки раньше телеметрии ⇒ телеметрия может
  уехать позже (она и раньше была «отложенной» по правилу `ui.*`).
- Правка 1 меняет текст тревоги и поведение кнопки: при пустой очереди отчёт **не уходит** на сервер.
- Схема не меняется, миграций нет.
