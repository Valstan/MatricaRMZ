# Обновление программы: одна полоса, монотонный прогресс, честные секунды

**Промты КАРМАНА:** #6 (текст владельца, 08.11.2026) + #7 (план из библиотеки, 08.11.2026).
**Наш код:** `main` @ `23ddfedd` (v3.135.0), ветка `feat/update-single-progress-bar`.
**План #7 написан для базы `3a9ad09c` (v3.110.0) — поэтому сначала сверка с нашим кодом, потом правки.**

## Что просит владелец (промт #6, своими словами)

- Обновление тихое и незаметное: качается только то, что реально изменилось.
- Пока программа работает — обновление идёт в фоне, оператора не дёргаем.
- Перезагружать программу только когда это действительно требуется; тогда сверху «вышло
  обновление, нажмите ‹Перезапуск›» (кнопка перезапуска уже есть).
- Если обновление долгое — обязательно видно, что оно идёт.
- **Полос одна**: тонкая, длинная, посреди экрана; на ней «Матрица с такой-то версии на
  такую-то версию»; прогресс **только вперёд** (под скачивание своя часть полосы, под
  установку своя, под остальные шаги своя); показывать, сколько секунд осталось.

## Решение по нити

Делаем **два PR** (порядок релизов из плана #7):

1. **PR A — одна полоса + этапные веса + ETA** (этот план).
2. **PR B — тихий режим**: фон без модалки, перезапуск по кнопке «Перезапуск» в шапке.

«Обновлять программу частями» на уровне модулей **не делаем** — ADR-0001 Блок 6: единый
атомарный артефакт, а «частичность» достигается на уровне загрузки (дельта).

## PR A: что именно сделано

### Домен — `shared/src/domain/updateProgress.ts` (новый)

Единое правило, из которого считают и главное окно, и окно апдейтера:

```
скачивание 0–60 · проверка 60–70 · установка 70–95 · перезапуск 95–100
```

- `UPDATE_STAGE_RANGES` — часть полосы у каждого этапа.
- `stageOverallPct(stage, stagePct)` — общий процент по этапу.
- `monotonicOverallPct(prev, next)` — процент **не убывает** (главное требование владельца).
- `formatEtaSeconds` — «осталось 18 с» / «оценка недоступна» (нет данных — прочерк, а не 0).
- `formatUpdateProgressLabel` — «Матрица3-РМЗ (135) → Матрица3-РМЗ (136) · 42% · осталось 18 с».
- `estimateDownloadRate` — скорость по **дельте байтов за окно** (накопленные делить на время
  нельзя — получилась бы скорость с самого начала, а не текущая).

Тесты домена: `shared/src/domain/updateProgress.test.ts` — 13 кейсов.

### Главный процесс — `electron-app/src/main/services/updateService.ts`

- `applyProgress(...)` — **единая точка правды**: этап → общий процент → состояние главного
  окна. Окно апдейтера и главное окно получают одно и то же число.
- `nextOverallPct` — монотонность; сбрасывается только на новой попытке (`checking`).
- `trackDownloadProgress` — скорость/ETA считаются ОДИН раз на оба окна (раньше ETA жил
  только в окне апдейтера).
- `etaForStage` — «сколько секунд осталось **до окончания установки**»: остаток загрузки +
  оценка установки. Оценка установки — из **прошлой** установки: `noteInstallStarted` пишет
  метку при старте установки, `noteInstallTimingOnBoot` (вызывается на старте программы) по
  ней считает длительность. Пока замера нет — «оценка недоступна», а не 0.
- `UpdateRuntimeState` расширен: `stage`, `overallPct`, `fromVersion`, `toVersion`, `etaSeconds`.
- Dev-флаг `MATRICA_SIMULATE_UPDATE_BAR=1` — имитация фонового обновления в главном окне
  (в проде env не выставлен): без него полосу не на чём увидеть, потому что в dev фон выключен.

### Рендерер

- `V3TabShell.tsx`: одна полоса `.v3-update-bar` — тонкая, длинная, **посреди экрана**;
  подпись «X → Y», процент, «осталось N с»; `pointer-events: none` (работать можно).
  Старая заливка `.v3-tabs-progress` под вкладками **убрана** (и из JSX, и из CSS).
- `shellV3.css`: стили новой полосы.
- `App.tsx`: полоса показывается, когда обновление ИДЁТ (`checking/downloading/verifying/
  installing/restarting`); «скачано, ждёт перезапуска» — не в списке (там скажет сообщение,
  это PR B).

### Страж — `electron-app/src/renderer/src/ui/updateProgress.guard.test.ts`

Прежние проверки сохранены; добавлены: этапные веса и монотонность в main, одно и то же
число в обоих окнах, одна полоса в главном окне и отсутствие старой, версии и ETA в
состоянии, «оценка недоступна» вместо нуля, фон не открывает окно апдейтера.

## Чего сознательно НЕ делаем в PR A

- Не трогаем окно апдейтера (`update.html`) — оно остаётся для ручной установки; общий
  процент в нём теперь тот же, что в главном окне.
- Не трогаем модалку «сейчас/позже» — это PR B (тихий режим).
- Не переносим дельту — она уже в начале каскада.
- Не меняем ABI, миграции и права (`updates.use` остаётся на установке).

## Открыто на PR B

- Модалка «Обновление скачано» после фоновой загрузки → тихое сообщение оператору
  («вышло обновление, нажмите ‹Перезапуск›») + текст новой версии из `RELEASE_WELCOME_HISTORY`.
- Кнопка «Перезапуск» в шапке: если обновление уже скачано — сначала применить его
  (иначе «нажмите ‹Перезапуск›» не даст новой версии), иначе обычный перезапуск.
