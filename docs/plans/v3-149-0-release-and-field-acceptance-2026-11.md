**Статус:** план. **Дата:** 2026-11-27. **Ветка после мержа:** `main` → теги `v3.149.0` и
`android-v3.149.0`.

## Шаги выката (канон — не переписываем)

Порядок — [`AGENTS.md` §Release process](../../AGENTS.md) и команда
[`/reliz`](../../.claude/commands/reliz.md). Кратко:

1. `node scripts/bump-version.mjs` → номер выпуска (текущий станет 3.149.0).
2. Запись в `shared/src/domain/releaseWelcome.ts`: `highlights` — **только** новинки для
   оператора, одной короткой фразой на строку (≤160 знаков), `releaseDate` = дата выката,
   `epigraph` — новая цитата, `outro` — одна подсказка. `intro` не заполняем.
3. PR → merge → `git tag v3.149.0` и **тем же ходом** `git tag android-v3.149.0`
   (без второго тега планшетный парк останется на прежней версии).
4. Прод: `bash scripts/prod-ops/deploy-backend.sh` (артефакт `backend-dist`, миграций в
   этом релизе нет → шаг `db:migrate` не нужен; новых рантаймовых зависимостей нет →
   `pnpm install` на проде не гнать).
5. Артефакты обновления: `.exe` → его `.blockmap` (**отдельным** `gh release download`) →
   `latest.yml`, только под финальными именами, `touch` свежих файлов; дождаться, пока
   `latest.json` совпадёт с `.exe` по размеру (GOTCHAS **M40**).
6. APK: `gh release download android-v3.149.0 --pattern "*.apk" -D ~/upload`, перенести в
   `/opt/matricarmz/updates/android/MatricaRMZ-3.149.0.apk` (версия — в имени файла),
   `cleanup-old-apks.sh`.
7. Проверка: `/health` → версия 3.149.0 на обоих инстансах, `/updates/status`, планшетный
   `dispatcher/update-plan` — не `up-to-date`.

> Место на проде: свободно **1.7 ГБ** при 10 ГБ (83 %) — перед выкатом артефактов место
> проверить; при нехватке — сначала уборка (`~/upload`), не снос откатной копии.

## Полевая приёмка глазами оператора (4 пункта — решение владельца 27.11)

Приёмка — на **живой машине парка**, не на стенде. Оператор проходит по пунктам и говорит,
что видит; агент не «сдаёт приёмку за оператора».

| # | Что проверяем | Как | Что должно быть |
|---|---|---|---|
| 1 | **Новое имя фото и переименование вложений** | на планшете: снять фото → программа спрашивает имя (предлагает своё, текст выделен) → загрузить; правой кнопкой по вложению → «Переименовать» → задать имя | файл сохранён под заданным именем; имя одинаково в записи файла на сервере, в списке карточки и в скачанной копии |
| 2 | **Планшет: меню и открытие файла** | открыть/закрыть панель, дать интерфейсу постоять, открыть вложение-фото | левое меню не уезжает само, кнопка «Меню» на месте; «Открыть» показывает фото **в программе**, а не текст ошибки |
| 3 | **Фото двигателя по номеру и прогресс поиска** | ввести 4+ цифры номера → подсказки полного номера; запустить поиск по папке | подсказки с полными номерами, выбор подставляет номер; полоса прогресса и «Отмена» работают; «показать ещё» до 20 |
| 4 | **Журнал действий и мастер печати фото** | открыть журнал действий; на панели вложений → «Через мастер печати» | журнал называет объект и раздел; мастер печати открывается (на планшете пункт не показывается — это норма) |

**Границы (решение владельца 27.11 — оставляем как есть):** сам файл в хранилище не
переезжает (переименовывается запись и имя, не байты); списки других карточек не
обновляются; файлы на диске оператора не переименовываются; переименование — только
одного файла.

## Наполнение парка видами — после выкатки

Оператор: «Контрагенты» → выделить заказчиков (галочками или лассо) → «Проставить вид…» →
выбрать вид один раз. Вид ставится 61 заказчику; варианты — ГОЗ / Гражданский / Не задан
(«Не задан» — это `null`). Пункт — [`../pending/prostat-vid-pachkoy-zakazchikam-i-dogovoram.md`](../pending/prostat-vid-pachkoy-zakazchikam-i-dogovoram.md).
