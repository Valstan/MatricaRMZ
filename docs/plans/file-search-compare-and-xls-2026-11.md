# План: поиск по файлам — вёрстка находок, названия вместо id, сверка с карточкой, поддержка .xls (16.11.2026)

> Продолжение нити «Поиск по файлам» ([`file-search-module-2026-11.md`](file-search-module-2026-11.md), сделано 14.11.2026, PR #1732, релиз v3.127.0). Модуль сделан, но оператор с ним неудобен: находки выводятся сжатой таблицей, в карточке видны технические id, а разницы между карточкой и файлом не видно вовсе.

**Заводская линза (три строки)**

- **Участок:** карточка двигателя и приёмка — оператор сверяет карточку своего двигателя с файлами (движение двигателей, дела ремонта, табели).
- **Кормит ли затор:** не кормит. Главный затор модели — «начало сборки: ручной подбор совместимых деталей из обезличенного фонда»; модуль работает по одному двигателю. Косвенно снимает ручной перебор данных по карточке.
- **Инвариант потока:** не ломает. Обезличивание деталей, партия/экземпляр (`stamped_number`), подпись и ответственный, маршрутный лист не затрагиваются: модуль читает файлы и пишет только атрибуты карточки двигателя через единственную дверь `engines:card:save`.

## Что делаем

1. **Вёрстка находок.** Таблица со столбцами файла заменена списком «подпись — значение»: в таблице столбцы сжимались, и значения выходили по одному символу в строке («Э 0 6 А Т 0 8 8 9» в столбик).
2. **Вместо id — названия.** Ссылки карточки (контракт, заказчик, марка, «прежний заезд») расшифровываются в номера и названия из локальной реплики: в карточке было «Контракт ed135695-…», а в файле «303» — это не «разные значения», а «нечего сравнивать».
3. **Явная сверка «файл ↔ карточка».** У каждой находки пометка (совпадает / расходится / в карточке пусто / в карточке нет такого пункта), у каждого пункта карточки — пометка (есть в файлах / расходится / только в карточке). Отдельным блоком: что расходится, что есть что перенести, что только в файлах, что только в карточке.
4. **Сопоставление по названиям разные.** Пункты называются по-разному («Номер договора» в файле и «Контракт» в карточке), поэтому сначала ищем совпадение **по значению**, и только потом — по названию.
5. **Поддержка `.xls`.** У оператора в «РМЗ» десятки книг старого формата (табели, «Дела ремонтов», «шт.21.10.2026») — это OLE2/BIFF8, `exceljs` их не читает.
6. **Шапка таблицы ищется, а не берётся первой строкой.** Выгрузки 1С начинаются титулом («ЖУРНАЛ», «учёта дел ремонта…»), и шапка столбцов стоит ниже; раньше первой непустой строкой считалась титульная, и в находках вместо названий столбцов было «ЖУРНАЛ».

## Решение по `.xls` (развилка, заданная владельцем 16.11)

`exceljs` читает только zip-контейнер (xlsx/xlsm). Старый `.xls` — OLE2-контейнер с BIFF-потоком, нужен отдельный ридер. Взята библиотека `@e965/xlsx` (SheetJS 0.20.x, чистый JS, без зависимостей): версия 0.20.3 — после фиксов известных CVE SheetJS, в отличие от `xlsx@0.18.5` из npm.

**Проверено на реальных файлах оператора** (только чтение, `D:\valstan\YandexDisk\РМЗ\…`): «ДЕЛА РЕМОНТОВ 2026.xls» — листы `Лист1`, `ЯМЗ-238Н`, `9Р4-6У2`, `Лист2`; поиск «Э06АТ0889» находит строку 265 со значениями `259-26`, `АО "РПТП "Гранит"`, `В-46-2С1`, `Э06АТ0889`, `хороший`; шапка определяется как «Номер дела», «Организация-поставщик», «Двигатель», «заводской номер».

## Что НЕ входит

- Двухуровневая шапка (объединённая группа + подзаголовок) склеивается в одну строку («Двигатель / заводской номер») — сейчас подшапка дописывает только пустые ячейки шапки.
- Сверка не трогает находки в Word и текстовых файлах: там нет полей, только абзац — они показываются как есть, с пометкой «сверьте глазами».
- Запись в карточку — по-прежнему только через `engines:card:save` с предпросмотром «что → куда».
