# Большой рефакторинг MatricaRMZ: три клиента + накопленные дефекты

> При старте выполнения: скопировать этот план в `docs/plans/grand-refactor-2026-08.md` (правило AGENTS.md — планы живут в репо, видимы с других машин), дальше вести его там.

## Context

После интенсивного августа (таб-оболочка «всё во вкладках» тремя релизами за один день 07.08, реорг МЕНЮ, Android-порт Ф0–Ф3, переезд инсталлера, слоты/авансы контрактов за неделю 29–31.07) в коде накопились костыли и рассинхроны. Владелец заказал масштабный рефакторинг по трём направлениям — Windows-клиент, планшетный клиент, web-admin — плюс конкретные жалобы:

1. Контракты: слоты создаются только под последнюю строку марки; суммы/цены берутся из одной строки; авансы распределяются «с 1-го по N-й»; нужен ретро-прогон по всем контрактам + автораскладка двигателей + сигналы о расхождениях.
2. Прокрутка в списках перестала работать (Windows, после таб-оболочки).
3. Кнопку аккаунта — рядом с кнопкой синхронизации (непонятно, под кем работаем).
4. После открытия наряда клик в МЕНЮ схлопывает вкладку наряда, список нарядов пуст, «нет доступа».
5. Импорт 1С: HTTP 502 на заведении позиции, «импорт не проведён».
6. Планшет: список нарядов не грузится, меню толком не работает, вкладки не открываются.
7. Новая фича: сетевая пошаговая мини-игра между пользователями.

**Решения владельца (2026-08-08, в этой сессии):**
- Web-admin остаётся лёгкой отдельной SPA: подтянуть визуал под стиль клиента, все админ-функции собрать в раздел «ВебАдмин» в МЕНЮ. Полный порт renderer в браузер — отклонён.
- Игра — «Цех-дуэль» (изобретённая): дуэль 1×1 «собери двигатель первым», ход = выбор 1 из 3 скрытых карт действий, исход решает серверный бросок.
- Планшетные фиксы проверяет владелец сам: CI собирает debug-APK, владелец ставит на DIGMA.

### Импорт 1С / 502 (`Stock1cImportDialog.tsx`, backend)
502 = Node не ответил (ловимые ошибки этого роута → 400). Причины по рангу: (1) keep-alive гонка nginx↔Node (у Node дефолтные 5 с, не заданы `keepAliveTimeout`/`headersTimeout`); (2) рестарты без graceful shutdown (SIGTERM-хендлеров нет; 07.08 — три релиза подряд); (3) синхронный ledger-цикл на каждую позицию (read+parse+stringify всего state.json + fsync под локом с `Atomics.wait`, ×546); (4) OOM. Клиент: без ретрая 502 (готовый `httpAuthedWithGatewayRetry` в `adminMasterdataRemoteService.ts:51-73` не используется), таймаут ретраит POST (риск дублей — нет идемпотентного id), повтор в том же окне диалога опасен (двойная дельта по проведённым складам). Проводка 546-строчного документа — 1000+ последовательных запросов при `proxy_read_timeout 30s` — кандидат на следующую стену (504).

### Игра «Цех-дуэль» — инфраструктурные рамки
WebSocket в проекте нет; ходы — тонкий REST + поллинг 3–5 с при открытой вкладке (образец: web-admin чат 2.5 с). В ledger/sync игру НЕ пускать (прод-инцидент CPU от мелких частых записей). Состояние матча — серверные таблицы мимо sync (паттерн `statistics_*`), сервер-арбитр держит скрытую информацию и броски. Очки — не в EAV сотрудника (`own_employee` = игрок пишет сам себе). Вкладка = 6 точек интеграции (menuActions, V3TabShell kind, App.tsx). Графика inline-SVG (прецеденты `MockupCanvas`, `IvanychFigure`), звук/бейдж «твой ход» — готовые механизмы чата.

## Целевая модель вкладок (ядро рефакторинга)

Новый модуль `shared/src/domain/tabsModel.ts` (+ unit-тесты) — чистый редьюсер, покрываемый тестами без DOM:

```ts
type WorkTab =
  | { id: 'menu'; kind: 'menu' }                                  // singleton, index 0, незакрываемая
  | { id: `list:${TabId}`; kind: 'list'; tabId: TabId }           // ЛЮБОЙ раздел (снимает G)
  | { id: `card:${TabId}:${string}`; kind: 'card'; cardKind: TabId; entityId: string; title: string }
  | { id: 'chat' | 'ai_chat' | 'settings' | 'game'; kind: ... };  // обычные члены, не производные

type TabsState = { tabs: WorkTab[]; activeId: string; secondaryCardId: string | null };
// actions: OPEN_LIST / OPEN_CARD / FOCUS / CLOSE / RETITLE / SET_SECONDARY / RESTORE
// результат: { state, rejected?: 'card_limit' } — лимит виден, а не молчит (F, L)
```

Инварианты редьюсера (каждый — unit-тест): `menu` не закрывается; `CLOSE` активной → фокус на соседа слева, fallback `menu` (снимает C, D, O); дедуп по id; `FOCUS('menu')` ничего не закрывает; `activeId` валиден по построению — «пустой экран» невозможен.

Принципы интеграции:
- Стейт: `useReducer` в App.tsx + контекст `ui/shell/TabsContext.tsx`. `selected*Id` остаются (десятки страниц зависят), но направление инвертируется: `open*`-хелперы диспатчат `OPEN_CARD`; эффекты-наблюдатели (upsert 2972-3013, collapse 2781-2793, `openedListTabs`, `tabList`-IIFE, `activeTabKey`, `chatOpen`/`aiChatOpen`, `v2ActiveListTab`) — удаляются.
- Слой совместимости: `setTab`/`requestTabSwitch`/`closeCardSession`/`finalizeCardClose` сохраняют сигнатуры; dirty-guard карточек не трогается — `CLOSE` карточки диспатчится только из finalizeCardClose.
- Состояние страниц (дефект B): **keep-alive** (display:none) для list/chat/ai_chat + `TabVisibilityContext` (пауза поллинга скрытых); карточки остаются single-mount (dirty-guard/epoch-машинерия построена на единственной карточке). Платформенный флаг «single-mount на Android» как страховка по памяти WebView.
- Персист: расширить `V3Session` (`shared/src/domain/uiShellV2.ts:57-63`) до `{tabs, activeId, secondaryCardId}`; fallback-чтение старого формата; dual-write в `v2.session` на один релиз (prefs синкаются на сервер — возможен откат клиента).
- Единый источник скрытий (E): гейт `handleMenuTab` по `sectionGatedTabs`; `V2_LIST_TABS` деградирует до визуального флага.

## Риски (топ-5)

1. **R3 ломает CDP-смоуки/chromeContract-тесты** → DOM-классы не переименовывать, смоуки обновлять в том же PR, редьюсер покрыт unit-тестами до первого UI-PR, R3 = 3 отдельных зелёных PR/релиза.
2. **Ретро-скрипт слотов vs старые клиенты** (старый клиент пересинкает слоты старой логикой при открытии карточки) → жёсткий порядок R5, идемпотентный перезапускаемый скрипт, контрольный dry-run через 2-3 дня.
3. **Keep-alive на планшетном WebView** (память/таймеры) → TabVisibilityContext, замер на DIGMA, платформенный флаг single-mount.
4. **Деплой R2a** (правка таймаутов на живом проде без graceful shutdown) → тихое окно, сначала shutdown-хендлер, потом таймауты; R2b только после R2a.
5. **Миграция персиста сессии** (prefs синкаются на сервер, откат клиента читает новый формат) → санитайзеры отбрасывают незнакомое, dual-write на один релиз.
