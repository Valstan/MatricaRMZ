# Производственные программы: плашки по свежести правки и программа на весь экран

> Первоисточник — промт КАРМАНА **#179** (зачитка владельца 27.11.2026): «плашки слева должны идти по свежести правки, открытая программа — разворачиваться на весь экран с полным названием и периодом, плашки при этом сжиматься в вертикальные полоски с периодом и всегда уметь развернуться обратно».
>
> План из библиотеки — **задание владельца, а не готовое решение** (`AGENTS.md` §«Промты проекта из КАРМАНА»): он сверен с нашим кодом и уточнён ниже.

**Статус:** код готов 28.11.2026 (ветка `feat/production-program-tiles-fullscreen-2026-11`). **Дата:** 2026-11-28. **Нить:** производственная программа → порядок плашек → раскладка экрана.

## Заводская линза (три строки)

- **Участок:** планово-производственный отдел (ППО) — ведёт производственные программы завода по цехам и договорам.
- **Кормит ли затор:** не кормит напрямую. Главный затор модели — «начало сборки: ручной подбор совместимых деталей из обезличенного фонда»; модуль ПП — планирование объёма, а не подбор деталей. Косвенно помогает: программа, которую видно на весь экран и поднятая наверх по свежести правки, — это та, над которой ППО работает прямо сейчас.
- **Инвариант потока:** не ломает. Правка **не меняется**: те же кнопки, та же шапка, та же запись серверной дверью. Сортировка и раскладка — только экран.

## Глобальная линза (три строки)

- **Модуль-кандидат:** порядок плашек по свежести и раскладка «программа на весь экран».
- **Дубль:** нет. Общего модуля «порядок карточек по свежести» в реестре нет; `PageToolbar`/`FacetFilter`/`ListColumnChips` — про другое (панель, фильтры, колонки). Правила вынесены в отдельный модуль экрана (`utils/productionProgramLayout.ts`), потому что их проверяет сторож, а не потому что это «общий механизм».
- **Действие:** новый модуль не нужен — новый **файл правил экрана** (без общего регистратора в `GLOBAL_MODULES.md`: правило живёт на одной странице и в общий реестр не тянется).

## Что уже есть (сверено с кодом, а не по памяти)

- **Порядок плашек** задавался серверной репликой: `main/ipc/register/productionProgram.ts` отдаёт программы по `periodStart, createdAt` — то есть «как приехали». Свежая правка наверх не поднимала никого.
- **Время последней правки уже в данных**: `ProductionProgramDto.updatedAt` приезжает в реплике (никакой новой таблицы и новой серверной двери не потребовалось).
- **Период программы — тоже в реплике**: `periodStart`/`periodEnd`; подпись периода для печати и выгрузки уже собирается из них (`formatProductionProgramPeriod`).
- **Правка программы идёт серверной дверью**, а на экране живёт «несохранённая» (канон #1240) — отсюда и решение по свежести несохранённой правки (ниже).
- **Раскладка экрана**: сетка из двух колонок `minmax(260px, 340px) minmax(0, 1fr)` — программа занимала правую половину.

## Решения (развилки промта, закрытые по умолчанию)

1. **Программа с несохранённой правкой.** По умолчанию: **берёт время с клиента** — правка в руках оператора свежее всего, что есть в системе, иначе она осталась бы внизу списка до прихода зеркала. Метка снимается, когда реплика показала другое серверное время (зеркало догнало правку) — сравнение по значению, а не по «время правки позже времени сервера», чтобы правило не зависело от расхождения часов клиента и сервера. → владельцу.
2. **Что считать «время изменения».** По умолчанию: **время последней правки программы целиком** (шапка или строки — не различаем): серверное `updatedAt` программы + клиентская метка, пока правка не уехала. Программа меняется и шапкой, и строками — одна дата отвечает на вопрос «что оператор трогал последним». → владельцу.
3. **Формат вертикальной надписи.** По умолчанию: **`01.11–15.11` и год на второй строке** («Период 01.11–15.11 вертикально читается неважно; возможно, нужен год и месяцы покрупнее»). Подробности (название, цех, статус, сводка) — в подсказке полоски. → владельцу.
4. **«На весь экран» и планшет.** По умолчанию: **та же раскладка на планшете** — узкий рельс 88 px + программа на остаток. Отдельного экрана для планшета не заводим: двух колонок рядом не читается только потому, что левая была широкая; узкий рельс читается. → владельцу.
5. **Сжатый список при большом числе программ.** По умолчанию: **рельс прокручивается** (`max-height` + вертикальная прокрутка), полоски не растягивают экран. Сколько полосок влезает — по высоте окна. → владельцу.
6. **Возврат к списку и правка.** По умолчанию: **возврат не съедает правку** — программа остаётся выбранной, её строки и пометка «не сохранена» живут на месте, а отложенное сохранение уходит на сервер **сразу** (не по таймеру). На плашке видна пометка «правка не сохранена». → владельцу.
7. **Печать не трогаем.** Экран — экран: печатная форма плана и выгрузка остались как были.

## Что сделано (28.11.2026)

- **Правила экрана** (`electron-app/src/renderer/src/ui/utils/productionProgramLayout.ts`): `sortProductionProgramsByFreshness` (тотальный порядок: свежесть → серверное время → id, поэтому список не «прыгает» при живом обновлении реплики), `productionProgramFreshnessAt`, `productionProgramLayout` (колонки и вид списка), `productionProgramStripLabel`, `productionProgramPeriodLine`.
- **Экран** (`ProductionProgramPage.tsx`): плашки по свежести правки; клиентская метка правки (`localEdits`) снимается, когда зеркало догнало; открытая программа — на всю ширину, рельс плашек сжат в вертикальные полоски с периодом; кнопка «К списку» (возврат) в рельсе; переключатель «развернуть/свернуть список»; крупная шапка программы (полное название + вид периода и обе даты); развёрнутый список — панель **поверх** программы (программа ширину не отдаёт).
- **Сторож** (`utils/productionProgramLayout.test.ts` — правила числами; `pages/ProductionProgramPage.layout.guard.test.ts` — что страница берёт эти правила). Проверен временной правкой: откат к «порядок из реплики» и к «программа на половине экрана» роняет сторож.
