## Заводская линза (три строки)

- **Участок:** приёмка и дефектовка — оператор ищет папку с фотографиями двигателя на сетевом диске и печатает её.
- **Кормит ли затор:** не кормит. Главный затор модели — «начало сборки: ручной подбор совместимых деталей из обезличенного фонда»; модуль ищет фото по номеру двигателя, а не детали в фонде. Косвенно помогает приёмке: обход сетевой папки больше не обрывается молча на 30 секундах.
- **Инвариант потока:** не ломает. Модуль читает папки и ничего в них не пишет; записи в карточку двигателя не касается. Обезличивание деталей, партия/экземпляр, подпись и ответственный, маршрутный лист, сдельщина против нормо-часов не затрагиваются.

## Глобальная линза (три строки)

- **Модуль-кандидат:** общий прогресс поиска (канал main → окно + отмена + полоса).
- **Дубль:** нет. Готового модуля «прогресса поиска» в проекте не было: прогресс синхронизации (`sync:progress`) — про другое (свой канал, свой экран, свой смысл состояний), прогресс передачи файлов (`files:progress`) — про байты, а не про перебор папок. Копии не строим: новый модуль нужен, потому что владелец просил **один** прогресс на всю программу, а не по копии в каждом экране.
- **Действие:** новый модуль (`main/services/searchProgress.ts` + `shared/src/domain/searchProgress.ts` + полоса `SearchProgressBar.tsx`), запись в реестр глобальных модулей — [`GLOBAL_MODULES.md`](../GLOBAL_MODULES.md); сторож `SearchProgressBar.guard.test.ts` не даёт завести вторую полосу или вторую подписку.

## Что уже есть (сверено с кодом, а не по памяти)

- **Образец прогресса — синхронизация.** `sync:progress`: событие из главного процесса в окна (`main/ipc/register/authAndSync.ts:95` → `BrowserWindow.getAllWindows()` → `win.webContents.send`), окно слушает его и рисует полосу (`ui/services/liveDataService.ts:44`, `ui/shellV3/V3TabShell.tsx`). Второй образец — прогресс передачи файлов (`main/services/fileTransferProgress.ts`): реестр в main + вещание в окна + `progress:list` для окна, открывшегося посреди операции.
- **Отмена в проекте есть** — `AbortController` в main (проверка связи с сервером) и `signal?: AbortSignal` в сервисе ИИ-ассистента. Прецедент отменяемой работы есть; в поиске отмены не было.
- **Поиск по папкам** — `main/services/fileSearchFolderService.ts`: `searchFolderSources` обходит дерево (`MAX_FOLDER_DEPTH = 3`), собирает `scannedFolders`, `durationMs`, примечания; **общий потолок обхода — `SCAN_TIMEOUT_MS = 30000`** («сетевая папка не должна держать поиск вечно»), при его срабатывании в примечания уходит «Поиск остановлен по времени (30 с) — часть папок не просмотрена».
- **Поиск по файлам-источникам** — `main/services/fileSearchService.ts`: `searchFileSources`; потолок на **один файл** — `READ_TIMEOUT_MS = 30000` (страховка от «нечитаемого» файла, а не ограничение поиска).
- **Двухуровневый поиск по карточкам** — `main/services/cardContentSearchService.ts`: `searchEntityCardContent` (тир-2 списка: значения карточек в локальной реплике, пачками по 400 id) и `searchEnginesByStampedPartNumber` («№ на детали»). IPC — `search:cardContent`, `search:enginesByStampedNumber` (`main/ipc/register/erp.ts:101`).
- **Глобальный поиск** — `shared/src/domain/globalSearch.ts`, `backend-api/src/services/globalSearchService.ts` (серверный уровень L3: номенклатура и складские документы), renderer — `ui/components/GlobalSearchOverlay.tsx` (L1/L2 в памяти, L2.5 — поиск по содержимому карточек, L3 — сервер). Клиент ходит на сервер через `main/services/erpService.ts:globalSearchQuery` (`httpAuthed`, потолок запроса 15 с). **Потолка в 30 секунд на стороне сервера нет** — вопрос промта («если предел там, локальная правка его не снимет») проверен: сервер отдаёт ответ по двум индексированным выборкам.
- **Мгновенный поиск по спискам** — `shared/src/domain/tieredSearch.ts` (ранжирование по уже загруженным строкам) и `shared/src/domain/searchFields.ts` + хук `ui/hooks/useSearchField.ts`. Данные уже в памяти — отвечает сразу.
- **Экран поиска** — `ui/pages/FileSearchPage.tsx`: при поиске ставится только флаг «занято» (кнопки гасятся), прогресса нет, статус наполняется по завершении или при ошибке. Сторож — `pages/FileSearchPage.guard.test.ts`.

## Решения (уточнения промта под наш код)

1. **Один канал и один компонент — как у синхронизации.** Домен — `shared/src/domain/searchProgress.ts` (`SearchProgressEvent`: состояние, вид поиска, что читается сейчас, «просмотрено N из M», «найдено K», прошедшее время). Main — `main/services/searchProgress.ts`: реестр поисков, `AbortController` на каждый поиск, вещание `search:progress` в окна, троттлинг (не чаще раза в 200 мс — иначе сетевая папка зальёт окно событиями), `search:progress:list` для окна, открывшегося посреди поиска. Renderer — `ui/services/searchProgressService.ts` (единственная подписка) и `ui/components/SearchProgressBar.tsx` (единственная полоса, смонтирована в `ui/App.tsx`).
2. **Счётчики «N из M» — по папкам-источникам, а «в дереве» — отдельной строкой.** В дереве папок общее число папок заранее неизвестно, поэтому «из M» считается по выбранным оператором папкам-источникам (их число известно сразу), а счётчик «в дереве папок: N» идёт отдельной строкой. В конце обхода «просмотрено папок: N из N» совпадает с `result.scannedFolders`, «найдено: K» — с `result.matches.length`.
3. **Общий потолок обхода снят; остался потолок на ОДНУ папку** (`FOLDER_READ_TIMEOUT_MS = 30000`): «зависшая» сетевая папка уходит в «недоступна — пропущена», а остальные папки ищутся дальше. Общий потолок снять нельзя было без этого: неактивный сетевой диск держал бы поиск до нажатия «Отмена».
4. **Потолок на чтение одного файла оставлен** (`READ_TIMEOUT_MS = 30000`): это страховка от «нечитаемого» файла, а не ограничение поиска. Отмена при этом стала честной: чтение идёт через `raceWithAbort`, поэтому отмена во время чтения **не оставляет процесс висеть** — хендлер возвращает частичный результат сразу.
5. **Совпадения находятся во время обхода, а не после** — иначе «найдено: K» в полосе расходилось бы с результатом, а находки появлялись бы только в конце. Порядок находок и картинок сохранён прежним.
6. **Троттлинг событий — 200 мс** (предложение промта, согласованное исполнителем): событие на каждый прочитанный файл в сетевой папке устроило бы поток в окно.
7. **Имена обрезаются, а не переносятся** (предложение промта): длинные имена в сетевых папках с кириллицей не должны ломать полосу.
8. **Полоса — поверх содержимого (`position: fixed`), в углу, `pointer-events: none` снаружи.** Список не сдвигается, поля и кнопки не перекрываются, на планшете полоса остаётся читаемой (`min(420px, 100vw - 32px)`).
9. **Полоса одна — в оболочке (`ui/App.tsx`), а не на каждой странице.** Отсюда и «переключение вкладки»: поиск идёт в главном процессе, полоса видна с любой вкладки; окно, открытое посреди поиска, забирает состояние через `search:progress:list`.
10. **Мгновенный поиск по спискам полосы не получает** — данные уже в памяти, полоса только мешала бы вводу. Сторож проверяет, что ни одна страница списка не подключает полосу или сервис прогресса.
11. **Отмена — честная.** `search:cancel` (renderer → main) срабатывает `AbortController`; поиск сам прекращает работу, отдаёт частичный результат, а в статусе страницы сказано «Поиск отменён — показано то, что успели найти».
12. **Серверный глобальный поиск отменяется по-настоящему:** `httpAuthed`/`fetchWithRetry` научились понимать внешний `AbortSignal` (раньше он подменялся на сигнал таймаута), и отменённый запрос не повторяется.

### Развилки, которые решает владелец

1. **Потолок на одну папку** — 30 секунд (по умолчанию, как было для всего обхода). Владельцу: подтвердить или поднять (вопрос в `pending/potolok-odnoj-papki-pri-obhode-papok.md`).
2. **Потолок на чтение одного файла** — оставлен 30 секунд (страховка от «нечитаемого» файла). Владельцу: подтвердить «оставить» или «поднять» (тот же файл pending).
3. **Найденное во время поиска** — по предложению промта, показываем сразу: полоса идёт дальше, находки появляются по мере обхода.
4. **Другие долгие операции** (печать больших отчётов, выгрузка файлов, полная синхронизация) — в тот же механизм не входят: полная синхронизация уже со своим прогрессом, а выгрузка идёт через файловые каналы. Вопрос владельцу оставлен открытым (в pending не заводили: это отдельная нитка).
