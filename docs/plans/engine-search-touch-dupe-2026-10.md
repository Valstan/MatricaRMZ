## Задача B. Дата изменения карточки двигателя = макс. с историей

**Факт:** колонка «дата изменения» списка = `entities.updatedAt`. Записи карточки
(`setEngineAttribute`, `engineService.ts:1667`) её трогают, а записи операций —
нет (`operationService.upsertOperation`, `workSheetService.upsert`, сохранение
листов/актов). История — часть карточки, обязана двигать её дату.

**Работа:**
1. Touch `entities.updatedAt` (+ `syncStatus pending` на клиенте) при любой записи
   операции с `engineEntityId`: client (`operationService`, `workSheetService`,
   сохранение inventory-листа/чек-листа) и сервер (`applyPushBatch` ветка
   operations — через `writeSyncChanges`-совместимый путь, иначе pull не увидит).
2. Сторож: запись истории двигает `entities.updatedAt`.
3. Одноразовый бэкфилл несвежих карточек:
   `entities.updatedAt = max(updatedAt, lastActivity)` + прогон на проде с row counts
   в теле PR (паттерн `warehouse:migrate-component-type --apply`).
4. PENDING/PROJECT_STATE обновить по факту.

**Ветка:** `feat/engine-history-touch-card` → PR-B.
