# Пакет владельца 22.09 (вторая порция): наряды + видимый вотчдог

## Context

Владелец после приёмки v3.46.0 дал список по нарядам (Рамзия, оператор нарядов) и одно наблюдение по клиенту:

1. Стрелочки числовых полей наряда меняют сотые (`step="0.01"`), а нужны целые рубли/штуки; копейки — руками.
2. Нет кнопки «Обновить цены»: оператор правит приказ о ценах → возвращается в наряд → строки со старой ценой. Старые наряды трогать нельзя (история цен), новый — по кнопке.
3. Строки наряда уезжают за правый край экрана.
4. Печать: галочками убирать/оставлять подписи (и целиком). Вкладка «Подписи» в карточке у владельца выглядит пустой; бригада должна попадать в блок росписи.
5. Кнопку «Сброс» в наряде убрать.
6. Вотчдог/старт клиента: восстановление идёт молча (окна нет, повторный клик по ярлыку тихо гаснет, сторож переустанавливает без окна). Владелец полчаса не понимал, что происходит. Решение владельца: показывать **оба** — окно статуса при старте Матрицы и уведомления от внешнего сторожа.

Все правки — в `electron-app` (renderer/main), `shared` (тип настроек печати) и `watchdog/` (Go). Бэкенд не трогаем. Каждый пункт — свой PR (по правилу пакета 22.09), handoff едет в каждом PR (D-066).

## Шаг 1 — стрелочки: шаг 1 у всех числовых полей наряда

`electron-app/src/renderer/src/ui/pages/WorkOrderDetailsPage.tsx`, четыре литерала `step="0.01"`:
КТУ ~L1752, начислено ~L1767, Кол-во ~L3359, Цена ~L3377.

Ставим `step="any"`: по HTML-спецификации спиннер при `step=any` шагает на 1, а любое дробное значение остаётся валидным (с `step="1"` браузер помечал бы `20.50` невалидным и мог скрутить при стрелке). Решение владельца — все поля, включая КТУ и «начислено».

Проверить `min={0.01}` у КТУ: со стрелкой вниз от 1 даёт 0.01 — оставить min как есть, стрелка упрётся в min.

Гейты, читающие файл текстом (не трогают step): `engineCustomerChain.guard.test.ts`, `ListChrome.guard.test.ts`.

## Шаг 2 — кнопка «Обновить цены»

Там же. Рядом с кнопками над таблицей «Виды работ» (блок ~L3060) — `Button variant="ghost"` «Обновить цены из справочника», только при `canEditNow` и когда есть строки с `serviceId`.

Логика (новая функция `refreshLinePrices`):
1. `const refs = await getWorkOrderRefs({ force: true })` (`services/workOrderRefsCache.ts` L167; без `force` кэш 2 мин отдаст старую цену) → `setServices(refs.services)`.
2. Для каждой строки `freeWorks[i]` с `serviceId` — `applyServiceSnapshotToLines(lines, i, serviceId)` (L1434) поверх свежего `services` (функция берёт цену из `serviceById` — передать свежую карту, не ждать ре-рендера).
3. `patch({...payload, freeWorks: next})`, пометить dirty; подсказка в `title`: «Подставить текущие цены из карточек услуг. Старые наряды не трогаются — только эта карточка».
4. Строки без услуги (свободный текст) не трогаем; после подстановки — пересчёт `amountRub` тем же путём, что и при ручной смене цены (см. onChange цены L3385).

Никакого автообновления при открытии — история цен старых нарядов остаётся.

## Шаг 3 — ширина наряда

Причина (`global.css` L1802-1826): `table.work-order-table { width: max-content }` + ячейки `white-space: nowrap; overflow: visible` + панель `fit-content` → таблица растёт с содержимым и уезжает за `min(98vw,1600px)`; узкие фиксированные колонки Кол-во 65 / Ед. 50 / Цена 80 px не вмещают input со спиннером.

Правка:
- Обёртки в `WorkOrderDetailsPage.tsx` (L2075, 2089, 2103, 2780, 2929, 3061, 3473): `maxWidth: 'min(95vw,1200px)'` → единая переменная/константа `WORK_ORDER_CARD_WIDTH = 'min(98vw, 1600px)'`; для блока работ — `100%` от viewport карточки (наряд «во всю ширину экрана»).
- `global.css`: у `.work-order-table` `width: 100%; table-layout: fixed` в **простом** режиме; колонка «Наименование услуги» — гибкая с `white-space: normal; overflow-wrap: anywhere` (длинные названия переносятся, не выдавливают таблицу). Остальные ячейки — nowrap как сейчас. `.work-order-works-panel min-width: 900px` → снять (на узком экране горизонтальная прокрутка внутри `.list-table-wrap`, а не за край страницы).
- Colgroup: Кол-во 65→90, Цена 80→110 (input со спиннером), Ед. 50→56.
- Проверить на стенде при 1366×768 и 1920×1080 (у Рамзии, судя по жалобе, узкий экран).

## Шаг 4 — печать и подписи

### 4a. Галочки подписей в окне печати

`shared/src/domain/workOrder.ts` `WorkOrderPrintSettings` (L256): добавить
```ts
/** Блоки подписей, снятые галочкой в панели печати (id из getWorkOrderSignatureBlocks). Пусто = печатать все. */
hideSignatureBlocks?: string[];
/** Убрать все подписи целиком. */
hideSignatures?: boolean;
/** Убрать колонку/строки росписи бригады. */
hideCrewSignatures?: boolean;
```
Санитайзер настроек печати в том же файле (~L308) — пропустить новые поля (массив строк, булевы).

`components/WorkOrderPrintDialog.tsx`: после группы «Печатать в шапке» — группа **«Подписи»**: главный чекбокс «Печатать подписи» (`!hideSignatures`), под ним по чекбоксу на каждый блок из `getWorkOrderSignatureBlocks(kind)` (только блоки с непустыми `resolveWorkOrderSignatureSlots`) и «Роспись бригады». Тот же паттерн `applySettings(next)`, что у `hideOrderDate`. Сохраняется в шаблоны печати (`utils/woPrintTemplates.ts` — там уже сериализуется весь объект настроек; `stripOrderScoped` новые поля не режет) и в `printSettings` наряда.

`utils/woPrintModel.ts` `buildSignaturesHtml` (L181): пропускать блоки из `hideSignatureBlocks`, при `hideSignatures` возвращать `''` (секция уже опускается при пустой строке, L376/L521). `hideCrewSignatures` → в простой форме прячем колонку `Подпись` (L459-472), в сборочной — см. 4b. Тест `woPrintModel.test.ts` — по случаю на каждый флаг.

### 4b. Бригада в росписи

- Простая форма уже имеет колонку «Подпись» у бригады (L456-472) — оставляем, это и есть «роспись после распечатки».
- Сборочная форма (L308-321) колонки нет — добавить такую же `td.wo-sign-cell` последней колонкой (управляется `hideCrewSignatures`).
- В карточке, вкладка «Подписи»: сверху read-only блок «Бригада — распишутся в таблице бригады при печати»: список ФИО из `payload.crew` (`crewMemberLabel` уже есть в `woPrintModel.ts` — вынести в shared/utils или переиспользовать через импорт). Без отдельных слотов: «слот на человека» отвергнут в комментарии L456-458 (растёт с бригадой) — сохраняем это решение.

### 4c. «Вкладка Подписи пустая»

Код вкладки полон (L1860-2065, `CollapsibleSection defaultOpen`). Гипотезы для проверки на стенде первым делом: (1) для не-сборочных видов блоки `issue`/`completion` имеют пустые `defaultCaptions` (`workOrderSignatures.ts` L127-136) — два пустых блока «Подписи не добавлены» под одним заполненным, выглядит как «пусто»; (2) `SectionCard` внутри `hidden`-обёртки + grid-класс `entity-card-span-full` вне grid-родителя.

Правка независимо от причины: убрать `CollapsibleSection` (на своей вкладке сворачивание бессмысленно, а свёрнутая — размонтирует контент); пустые блоки `issue`/`completion` у простых форм не рендерить вовсе (они существуют только чтобы не осиротить старые подписанные наряды — `L100-105`), показывать их только если в `payload.signatureBlocks` есть слоты. Кнопка «+ Добавить подписанта» и шаблоны — остаются. «Сохранить подписи в шаблоне» (L1919-1952) уже даёт «на все наряды автоматически» через шаблон наряда — проверить на стенде, что применение шаблона при создании наряда подтягивает подписи (`L1394`).

## Шаг 6 — видимое восстановление

### 6a. Клиент: окно статуса запуска (`electron-app/src/main`)

Новый `services/startupStatusWindow.ts` по образцу `showUpdateWindow` (`updateService.ts` L870-925: `BrowserWindow` 640×360 без меню, свой html через `file:///`-URL из-за asar-бага, push состояния через preload). Своя html-страница `startup-status.html` рядом с update-ui html (тот же resolver-паттерн `resolveUpdateUiHtmlPath`).

- Показ: таймер 1500 мс после `requestSingleInstanceLock` (`index.ts` L365) — быстрый старт окна не видит; медленный — видит «Матрица РМЗ запускается…» с текущим этапом.
- Этапы (`setStartupStage(label)` из `index.ts` между L408 и L631): «Открываю базу данных» → «Обновляю структуру базы» (migrate/align) → «Проверяю данные» (seed) → «Проверяю обновления» → «Загружаю окно». Ветка лечения базы (L486-546) — «Восстанавливаю базу данных, это может занять несколько минут». Update-flow показывает своё окно — статусное прячем на время `updateUiWindow`.
- `second-instance` (L369): если `mainWindow` ещё нет — показать/поднять статусное окно немедленно (без 1500 мс), чтобы повторный клик по ярлыку не гас молча.
- Закрытие: в `maybeShowMainWindow` (L89) и при `app.quit`. Не блокирует закрытие пользователем (крестик = оставить запуск идти в фоне, не quit).
- Dev-проверка: env `MATRICA_SIMULATE_STARTUP=slow` по аналогии с `MATRICA_SIMULATE_UPDATE` (L614) — искусственные задержки этапов.

### 6b. Сторож: нативное окно статуса (`watchdog/main.go`)

Сторож — Go GUI-бинарь без окна; win32 через `syscall` уже используется (`CreateToolhelp32Snapshot`, L383-407). Добавить `watchdog/statuswin_windows.go`: топмост окно без рамки-меню (CreateWindowExW + STATIC-текст, message loop в отдельной goroutine, `SetWindowTextW` для смены этапа, `DestroyWindow` по завершении).

- Показывать **только когда начинается действие** (после решения `reason` в `main`, L207+; и сразу на `--repair`, чтобы ярлык «Восстановить Матрицу РМЗ» отвечал мгновенно «Проверяю установку…»). Здоровые проходы раз в 15 мин — по-прежнему без окна.
- Этапы: «Матрица РМЗ: проверяю установку» → «Скачиваю установщик … %» (в `findInstaller`/download, L589-614, есть прогресс байтов) → «Переустанавливаю Матрицу, до 15 минут — не выключайте компьютер» (`runSilentInstaller` L780) → «Восстанавливаю ярлыки» → финал «Готово, запускаю Матрицу» / «Не удалось восстановить — сообщено администратору» (3–5 с, потом закрыть; лог `watchdog.log` как сейчас).
- Обновить `watchdog/README.md` (раздел про поведение) и семгреп-грабли M57 (`unsafe` в Go) учесть при написании syscall-кода.
