# ДС в карточке двигателя — появляются сразу после ввода договора, без «Сохранить»

> **Тип:** plan · **Статус:** active · **Создан:** 2026-10-21 · **Релиз:** 3.85.0

## Симптом (владелец, 21.10.2026)

В карточке двигателя выбирается номер контракта, вторым полем — дополнительное соглашение
этого контракта. Но ДС в списке не видно: показывается только «договор номер такой-то».
После нажатия «Сохранить» ДС появляются. Оператору нужен выбор ДС **сразу после ввода
контракта**, без промежуточного сохранения.

## Причина (по коду)

`EngineDetailsPage` строит опции секций в `useEffect` по `contractId`:
`window.matrica.admin.entities.get(contractId)` → `parseContractSections` →
`buildContractSectionOptions`. Пока `contractId` не появился, дропдаун секции показывает
одно значение. `contractId` появляется:
- при выборе договора из подсказки `EntityReferenceField`, либо
- при сохранении карточки (там номер резолвится в сущность).

Отсюда симптом: оператор **вводит номер** договора руками и ждёт ДС, а сущность ещё не
разрезолвлена — секций нет, и «спасает» только сохранение.

Вторая возможная причина того же симптома — кэш `lookups` (60 с): только что заведённое ДС
не видно ни в карточке, ни в подсказке. Проверяется на стенде первым шагом.

## Решение

1. **Резолв договора по номеру на вводе**: debounce ~300 мс, поиск в `contract`-сущностях
   по номеру (нормализованно: пробелы/регистр), при однозначном совпадении — `contractId`
   проставляется без сохранения, секции подтягиваются сразу.
2. **Неоднозначность** (несколько договоров с похожим номером) — не угадываем: показываем
   подсказку со списком, оператор выбирает.
3. **Секции пересчитываются** не только по `contractId`, но и по факту обновления договора
   (после появления нового ДС), иначе оператор, заведший ДС только что, снова увидит старый
   список.
4. **Кэш lookups:** если 60-секундный кэш мешает — точечно инвалидировать запись контракта
   при создании ДС, а не снимать кэш целиком.

## Код

- `electron-app/src/renderer/src/ui/pages/EngineDetailsPage.tsx` — эффект секций + резолв.
- `electron-app/src/renderer/src/ui/components/EntityReferenceField.tsx` — резолв по номеру
  (если механизм общий, а не локальный для карточки).
- `shared/src/domain/contract.ts` — нормализация номера для поиска (рядом с существующими
  `canonicalContractSectionKey` / `buildContractSectionOptions`).
- Тесты: домен (резолв/неоднозначность), guard-тест карточки (секции приходят до сохранения),
  CDP-смоук: контракт с двумя ДС → новый двигатель → ввод номера договора → ДС видны.

## Гейты и выпуск

Обычные гейты монорепо + CDP-смоук шага. Едет в 3.85.0 вместе с пачкой приёма.
