# План: Печатные формы — блок подписей редактируемый (можно добавить подпись с другим человеком, профессией и должностью)

**Основание:** задача владельца (23.11.2026): «Матрица РМЗ задание подкорректировать печатные
формы… Блок подписей нужно сделать редактируемым, чтобы можно было добавлять другие подписи,
с другими людьми, с другими профессиями, должностями. Добавлять и удалять подписи, чтобы можно
было. А то сейчас вот производственную программу открыли на печать, и там надо добавить еще одну
подпись, а мы не можем, никак».
**Конкретный случай приёмки:** ПП → «Печать» → блок «Подписи» → добавить строку подписи.

## Что было в коде (проверено по коду, 23.11.2026)

| Что | Где было | Почему не работало |
|---|---|---|
| Блок подписей в печатной форме ПП | `components/ProductionProgramPrintPreview.tsx`: список **галочек** «печатать / не печатать» | **Добавить подпись было нельзя**: убрать — можно, добавить — нет. Ровно то, о чём владелец |
| Слоты подписи в домене | `shared/src/domain/productionProgram.ts`: `PRODUCTION_PROGRAM_SIGNATURE_SLOTS` (8 строк из образца), `ProductionProgramSignatureSlot = {caption, employeeId, fullName}` | Тип слота был, а **редактора не было нигде** |
| Слияние сохранённых слотов с образцом | `resolveProductionProgramSignatureSlots()`: сохранённое **накладывалось** на образец по названию должности | Своя должность («Начальник цеха № 4») **выбрасывалась молча**, а удалённая строка **возвращалась сама** |
| Хранение на сервере | `production_programs.signature_slots` (JSON-строка), маршрут `PATCH /production-program/:id`, синх-публикатор, локальная реплика | Канал был **целиком** — не хватало только клиентского редактора и правила слияния |
| Состав подписей в модели печати | `buildProductionProgramPrintModel(input)` принимает `signatureSlots` | Страница ПП **не передавала** `signatureSlots` в модель: сохранённый состав не доходил до печати и выгрузки |

Вывод: инфраструктура была готова, не хватало двух вещей — **редактора** и **правила слияния**.

## Шаги (PR-flow)

1. **✅ Домен: сохранённый состав — как есть.** `resolveProductionProgramSignatureSlots(saved)`:
   `saved != null` → сохранённые строки как есть (своя должность остаётся, удалённая не
   возвращается); `saved == null` → образцовые 8 строк. Добавлен
   `productionProgramSignatureSlotsFromRaw(raw)` — разбор того, что лежит в строке программы, с
   тремя состояниями: **нет значения ⇒ образец**, **пустой список ⇒ подписей нет** (оператор
   удалил все), **битый JSON ⇒ образец**.
2. **✅ Редактор блока подписей** (`components/SignatureSlotsEditor.tsx`): должность (с
   подсказками из образца), человек из кадрового реестра, ФИО от руки (если сотрудник не
   выбран), удаление строки, добавление строки, порядок — **общим китом списков** (ручка «⠿»).
3. **✅ Печатная форма ПП**: блок «Подписи» стал редактируемым. Галочка «печать» осталась
   (снятая строка не идёт на лист), но отбор идёт **по ключу строки**, а не по названию
   должности: должность меняется при правке, и отбор по названию молча терял бы строку.
4. **✅ Состав — данные программы.** Правка уходит в программу (`signatureSlots`) и в выгрузку
   файлом: кто подписывает лист — это часть документа, а не настройка принтера. Кегли и галочки
   «печать» остались видом печати (в окне, в программу не пишутся).

## Решения, которые стоит знать

- **Где живёт состав.** Правка идёт из печатной формы (владелец споткнулся именно там), но
  сохраняется в программу. Альтернатива — править состав в самой программе, а в печати только
  показывать; владелец просил редактирование «в печатной форме», поэтому редактор живёт там.
- **Отбор печатаемых строк — по ключу строки, а не по должности.** Должность — меняемое
  название; отбор по названию после правки терял бы строку. В `productionProgramPrintHtml`
  поэтому убран параметр `signatureCaptions`: отобранный состав приходит во вход.
- **Автоподбор сотрудника по должности НЕ включали.** В домене есть
  `findProductionProgramSignatory` (по образцу: «Коммерческий директор» → сотрудник с такой
  должностью), но он не был подключён нигде. Подключать его — это менять ФИО, которые печатаются
  сегодня (сейчас печатаются ФИО из образца: «Беркута А.А.» и т. д.). Это отдельное решение
  владельца, а не следствие этой правки.
- **Правка не может быть «одной на программу» против образца.** Образцовые 8 строк — это
  ФИО из Word-образца; новый подписант в них не появится.
