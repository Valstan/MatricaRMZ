## Решения владельца, как мы их читаем

1. **Отдельный склад спецодежды — да, отдельным подразделением.** Значит не фильтр по категории в общем списке остатков, а **отдельная локация**: в `warehouse_locations` это единственный справочник складов (`type`, `code`, `name`), отдельной сущности «склад» в проекте нет. Кладовщик в карточке СИЗ видит только эту локацию.
2. **Остатки грузит отчёт.** Не ручной ввод: иначе учёт разойдётся с бумажкой. Отчёт — выгрузка 1С «Остатки товаров» (xlsx).
3. **Повторная загрузка того же отчёта не удваивает остаток.** Значит импорт — **корректировка** (дельта к текущему остатку), а не приход. Повтор даёт нулевую дельту.
4. **Номенклатура отчёта — торговые позиции завода** («Костюм МОТОР цв. чер-зел. тк. смесовая (96-100/170-176)», «Каска РОСОМЗ СОМЗ-55 FAVORIT 75514»), а приказные нормы живут отдельным слоем («Костюм для защиты от механических воздействий (истирания)»). **Мост между слоями — отдельная работа** (см. «Этап 3»), молча сшивать их не будем: владелец сам отделял их в промте #20 («у каждой позиции набора норм своя номенклатура и свой сертификат»).

## Этап 1 — Склад СИЗ (PR A)

### 1.1. Локация «Склад СИЗ»

- Склад — это `warehouse_locations` (единственный справочник складов). Заводим локацию `code='workwear'`, `type='regular'`, `name='Склад СИЗ (спецодежда)'`.
- Заводится **лениво, при первом импорте остатков** (`warehouseLocationsService.upsertWarehouseLocation`): `code` уникален, повторный импорт не плодит локации, миграция не нужна.
- Вкладка «Склад СИЗ» (`PpeStockPage`) показывает остатки **этой локации**, а не фильтр по категории по всему складу. Категория `workwear` остаётся фильтром-подстраховкой (номенклатура отчёта заводится с этой категорией).

### 1.2. Парсер отчёта «Остатки товаров» (домен, `shared`)

- Новый файл `shared/src/domain/ppeStockReport.ts`:
  - `parsePpeStockReport(rows)` → `{ reportDate: number | null, rows: PpeStockReportRow[] }`, где `PpeStockReportRow = { name, unit, qty, sum }`.
  - Правила: найти строку-шапку (в строке есть «номенклатура» и «количество»), читать строки ниже; строку «Итого» пропускать; дату взять из заголовка «Остатки товаров на <дата> г.»; количество — число (в отчёте целое), сумма — число с запятой.
  - Ничего не выдумывать: отчёт без шапки → пустой результат и понятная ошибка, а не «позиций: 0».
- Сторож: `shared/src/domain/ppeStockReport.test.ts` — на фикстуре, повторяющей шапку отчёта владельца (без его файла в репо).

### 1.3. Сервис импорта остатков (`backend-api`)

- Новый файл `backend-api/src/services/ppeStockImportService.ts`:
  - `previewPpeStockImport({ filename, contentBase64 })` — разбор xlsx (ExcelJS, как в `ppeImportService`), сопоставление каждой позиции отчёта с номенклатурой (точное имя → по базе без размера), план построчно: `create` (номенклатуры нет) / `match` (найдена) / `update` (найдена по базе, размер уточняется) + расхождение с текущим остатком.
  - `applyPpeStockImport({ previewId, contentBase64 })` — создаёт и **проводит** складской документ `stock_inventory` в локации `workwear` со строками `adjustmentQty = остаток_отчёта − текущий_остаток`. Повтор того же отчёта → дельта 0 → остаток не удваивается.
  - Номенклатура, которой нет: заводится с `category='workwear'`, `itemType='material'`, имя — как в отчёте, код — свой (`СИЗ-СТ-…`). Приказные строки не трогаем.
- Маршруты: `POST /ppe/stock-import/preview`, `POST /ppe/stock-import/apply` (гейт — `erp.documents.post`: действие кладовщика со складом, как и проведение выдачи).
- Маршруты клиента: `ppe:stockImport:preview` / `ppe:stockImport:apply` (write-каналы → `sectionGate.ts` `WRITE_CHANNELS`; иначе сторож `sectionGateWriteChannels.guard.test.ts` упадёт).

### 1.4. Клиент

- `PpeStockPage`: кнопка «Загрузить остатки отчётом» → файл (`.xlsx`) → «Проверить файл» → план построчно → «Применить». Показываем склад и дату отчёта.
- Остатки — из `warehouse:stock:list` с фильтром по локации `workwear` (серверный фильтр `warehouseId` есть).

### 1.5. Сторожи и приёмка

- `ppeStockReport.test.ts` (shared) — парсер: шапка, «Итого», пустой файл, мусор в шапке.
- `ppeStockImportService.test.ts` (backend) — план: позиция найдена / новая; повторный apply не удваивает остаток (дельта 0).
- `humanLabels.guard.test.ts` — если трогаем пресеты СИЗ, фикстура непустая.

## Этап 2 — Карточка выдачи СИЗ (PR B, шаблонизация по документам владельца)

- Печатная форма по образцу: 11 колонок — «Наименование СИЗ · № сертификата соответствия · Выдано (Дата, Кол-во, % износа, подпись в получении) · Возвращено (Дата, Кол-во, % износа, подпись работника о сдаче, подпись кладовщика в получении)».
- Источник строк — нормы карточки сотрудника (`ppe_norm_lines` → `erp_nomenclature`) + история выдач (`ppe_issue_entries`: дата, кол-во, % износа, дата возврата).
- Два режима печати:
  - **по сотруднику** — его нормы и его история (бумажка под подпись);
  - **бланк по должности** — нормы должности без привязки к человеку (то, что у владельца лежит на столе у кладовщика).
- Источник истины по форме — `shared/src/domain/ppeIssueCard.ts` (чистая функция сборки модели + печать), тест на модель.

## Этап 3 — за пределами этой нити (в PENDING)

1. **Мост «приказная норма ↔ торговая позиция завода».** Данные у владельца теперь есть (22 карточки + отчёт остатков): по должностям видно, что «Слесарь-ремонтник» = «Костюм МОТОР + Кепка-жокейка СОЮЗ-2 + Ботинки ТОФФ ТРУД МП + Очки РОСОМЗ + Перчатки ×5 размеров». Без этого моста склад остатков (торговые позиции) и нормы выдачи (приказные позиции) не сойдутся — заявка на закупку («потребность − остатки») считает по разным номенклатурам. Это и есть незакрытый пункт PENDING «СИЗ: у каждой позиции набора норм — своя номенклатура» (since 2026-11-11) — имена теперь можно взять из карточек владельца.
2. **Карточка смывающих средств (мыло/крем)** — по образцу «Личная карточка №43»: нормы (200 гр × 12, 100 мл × 12), сертификаты, журнал выдачи с датой, количеством, способом выдачи (дозатор/индивид.) и распиской. Промт #21.
3. **Форма выдачи с остатком.** Показывать в карточке СИЗ остаток по складу СИЗ и подсвечивать позицию, совпавшую с размером сотрудника (`matchEmployeeSizePosition` это уже умеет). Позиции выдачи — только спецодежда (не общий справочник номенклатуры).
