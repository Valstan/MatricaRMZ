# Пакетный приём двигателей: необязательные поля, внутренний номер, дата дефектовки, «Обновить»

Запрос владельца 20.10.2026. Продолжение нитки [`_archive/engine-bulk-intake-2026-10.md`](_archive/engine-bulk-intake-2026-10.md)
(приём списком вышел в 3.81.0, 20.10). Один PR, выпуск **3.82.0**.

## Что просил владелец

1. **Все поля формы приёма — необязательные.** Было: марка, контрагент, договор и дата прихода обязательны.
2. Добавить поля **«Внутренний номер»** и **«Дата дефектовки»**.
3. Оставить «Пропустить», добавить **«Обновить»**: модуль смотрит, каких предложенных данных в
   существующем двигателе нет, и **дописывает только недостающее**. Пример владельца: первый раз пачкой
   завели двигатели «только с номером заказчика», второй раз тем же списком принесли внутренний
   номер/договор — карточки надо дополнить, а не пропустить.

## Решения по ходу (и почему)

- **«Обновить» = дозаполнение, не перезапись.** Заполненное в карточке не трогаем: там могла быть
  ручная правка, которой оператор пачки не видел. Расхождение (в карточке другое значение) показываем
  в строке словами «в карточке другое: договор — не перезаписываю», иначе оператор решит, что пачка
  переписала договор.
- **Внутренний номер — построчно, а не полем на пачку.** Уникальна пара (номер, год), поэтому один
  внутренний номер на 50 двигателей физически невозможен: второй же двигатель отбился бы гейтом дублей.
  Колонка в превью; столбец из таблицы вставляется в первую строку и расходится вниз
  (`onPaste` → `splitEngineBulkIntakeNumbers`). Короткий «41» получает **текущий** год, полный «41/26» —
  свой (как в карточке).
- **«Дата дефектовки» → этап «Разборка/Дефектовка»** (вопрос владельцу задан, выбран этот путь).
  Отдельного поля в карточке нет с 01.10.2026 (план `bulk-stage-dialog-and-defect-dates-2026-10`):
  канон даты — акт/строка этапа, и именно строка этапа задаёт стадию завода. Пишем
  `ensureRepairStageRow('disassembly_defect')`: идемпотентно (есть этап — не трогаем), дата подчиняется
  линейке. Дата одна на пачку, как дата прихода.
- **Отказы по дате и правам не молчат.** Если дата раньше прихода (запрет `findStageDateConflict`) или у
  оператора нет права писать этапы, этап не встанет — это попадает в итог строкой
  «этап дефектовки не встал: N», а не теряется.
- **Обязательность только на клиенте и снимается целиком**: на сервере (`erp_engine_cards`) все
  предметные колонки nullable, поэтому карточка «только с номером» допустима и там.
- **Дополненный договор занимает плановое место.** Если у карточки договора не было, а теперь появился —
  двигатель садится в план договора (`placeEngineIntoContractSlot`), иначе он есть, а денег под него нет.

## Код

- `shared/src/domain/engineBulkIntake.ts` — действие `update`, `EngineBulkIntakeOffer`,
  `engineBulkIntakeMissingFields` / `engineBulkIntakeConflictingFields` (одни правила для превью в форме и
  для записи в main), `readBulkIntakeInternalNumber`, `engineBulkIntakeInternalNumberDuplicates`,
  `splitEngineBulkIntakeNumbers`; расширен `EngineBulkIntakeExisting` (марка-id, внутренний номер+год,
  `hasDefectStage`).
- `electron-app/src/main/services/engineBulkIntakeService.ts` — индекс по реплике + EAV отдаёт новые поля,
  наличие этапа дефектовки берётся пачкой из `operations`; ветка `update` пишет только недостающие коды
  через `saveEngineCardGated` (гейты дублей пропускают «сам себя»), затем этап дефектовки.
- `electron-app/src/renderer/src/ui/components/EngineBulkIntakeDialog.tsx` — поля без звёздочек, колонка
  «Внутренний номер», третья кнопка «Обновить» + «всем „обновить“», в строке «не хватает: …» / «всё уже есть».
- Тесты: `shared/.../engineBulkIntake.test.ts` (21), `engineBulkIntakeService.test.ts` (18),
  `EngineBulkIntakeDialog.guard.test.ts` (10); смоук `.claude/skills/verifier-electron/scripts/cdp-engine-bulk-intake.mjs`
  получил шаг «дубль → Обновить».
