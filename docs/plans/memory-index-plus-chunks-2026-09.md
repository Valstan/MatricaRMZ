# Раскладка локальной памяти: индекс + файл на запись

> План по мандату brain **D-097** ([ADR-0013](../../../brain_matrica/adr/0013-memory-layout-index-plus-chunk-files.md), письмо `2026-09-18-d097-one-memory-for-the-ecosystem-read-by-index-write-by-mail`). Правило в каноне — `AGENTS.md` §«Одна память на экосистему». Дата отчёта — 02.10 (календарь `PENDING_FOLLOWUPS`).

## Context

Правило D-097 п.4: локальный реестр памяти больше 50 КБ раскладывается как **индекс + файл на запись**, потолок держит гейт. Причина та же, что у Мозга (его `GOTCHAS.md` был 1 МБ одним файлом): агент, которому нужна одна грабля, грузит в контекст весь реестр, либо ищет `grep → Read offset`, что после любой правки выше по файлу даёт не ту запись.

Замер 2026-09-21 (`wc -c`):

| Файл | Размер | Как читается сегодня | Порог |
|---|---|---|---|
| `docs/COMPLETED.md` | 496 КБ | по требованию, целиком («это уже сделано?») | ×10 |
| `docs/GOTCHAS.md` | 424 КБ | grep по индексу → Read с offset; 143 записи `M1`–`M143` | ×8 |
| `docs/PENDING_FOLLOWUPS.md` | 352 КБ | по требованию, целиком; календарь — отдельной секцией | ×7 |
| `docs/PROJECT_STATE.md` | 22 КБ | по требованию, целиком | в норме |

`SESSION_HANDOFF.md`, `CODEBASE_MAP.md`, `docs/machines/*` — в норме и по назначению обязаны оставаться одним файлом.

## Что переносимо (строка 1 отчёта D-097)

Из 143 записей `GOTCHAS.md` **указатель на запись Мозга несут 4** (M-записи со ссылкой на `G176`, `G334` и родню); ещё ~44 упоминают brain/pool в тексте без адреса записи. По ответу Мозга 18.09 наши классы последних двух недель лежат у него как **G363–G382 и #325–#327** (≈20 записей), но у нас те же классы записаны полным текстом (M135–M143), а не указателем — ровно расхождение #087. Полный аудит «переносима / локальна» по каждой из 143 записей не считан: он делается **в ходе раскладки**, по одной записи, а не отдельным проходом по 424 КБ.

## Порядок раскладки

Один реестр — один PR, механически, без переписывания текста записей. Начинаем с `GOTCHAS.md`: у него уже есть формальная структура (Tier-1 таблица + `## M<N>`), и это единственный из трёх файлов, к которому обращаются по одной записи.

### Шаг 1. `docs/GOTCHAS.md` → индекс + `docs/gotchas/M<N>.md`

1. Скрипт-разрезчик (одноразовый, в `scripts/`, удаляется после): каждый блок `## M<N>` … до следующего `## M` → `docs/gotchas/M<N>.md` (заголовок, Симптом / Корень / Диагностика / Лечение как есть).
2. В `GOTCHAS.md` остаётся шапка + таблица индекса; в каждую строку добавляется ссылка `[M<N>](gotchas/M<N>.md)`; при разрезании в строку индекса дописывается **суть лечения** одной фразой (у Мозга так: симптом-якорь + суть + ссылка), чтобы 80 % вопросов закрывались индексом.
3. Записи, чей класс уже есть у Мозга (M135–M143 → G363–G382, и те 4, что уже ссылаются на `G<N>`), получают в файле первую строку «**Пул:** [G<N>](../../../brain_matrica/cross-project-ideas/gotchas/G<N>.md)»; локальный текст **не удаляется** — там наша специфика (имена файлов, номера PR), это и есть «специфичное для стека».
4. `/close_session` §грабли: новая грабля = новый файл `docs/gotchas/M<N>.md` + строка индекса. Якоря `GOTCHAS.md#m<N>` в старых PR/письмах остаются валидными адресами индекса.
5. Гейт: тест-сторож (vitest в `electron-app`, рядом с прочими `*.guard.test.ts`, либо шаг CI) — `docs/GOTCHAS.md` ≤ 50 КБ, каждая строка индекса ссылается на существующий файл, каждый файл `gotchas/M<N>.md` есть в индексе.

### Шаг 2. `docs/PENDING_FOLLOWUPS.md` → индекс + `docs/pending/<slug>.md`

Труднее: секции — проза с историей, ключа вида `M<N>` нет. Порядок:

1. Сначала **ротация** (месячная чистка по D-097 п.5): секции с ✅ внутри и без открытого остатка — в `COMPLETED.md` одной строкой, из PENDING вон. Ожидаемо снимет треть объёма.
2. Остаток: каждая `### `-секция → `docs/pending/<slug>.md`; в индексе — строка `приоритет · заголовок · since · ссылка`. **Календарь дат остаётся в индексе** — это «одна дверь для дат» (#152), её переносить нельзя.
3. Тот же гейт на 50 КБ.

### Шаг 3. `docs/COMPLETED.md` — не разрезать, а архивировать

Это done-индекс по замыслу: одна строка на нитку/релиз. 496 КБ означает, что он давно не «тонкий» — строки разрослись в абзацы. Порядок: записи старше текущего поколения (v2026.* CalVer и раньше) → `docs/_archive/COMPLETED-2026H1.md` как закрытая запись; в живом файле — только поколение 3.x, и правило «одна строка» в шапке. Гейт тот же.

## Открытые вопросы для владельца

- Порядок шагов 1 → 2 → 3 или только шаг 1 к 02.10, остальное — датами после отчёта. По умолчанию: шаг 1 к 02.10, для 2 и 3 даты назначаются в отчёте.
- Гейт — тест-сторож в `electron-app` (дёшево, уже есть образец) или отдельный шаг CI в `.github/workflows/test.yml`. По умолчанию: тест-сторож, он и так гоняется CI.
