# График отпусков: сетка месяцев, сотрудники из базы, период с понедельника

**Промты КАРМАНА:** #38 (текст владельца) + #39 (план из библиотеки), 18.11.2026.
**Замысел владельца:** «График отпусков — наподобие табеля рабочего времени, но график отпусков. На экране рисуется сетка месяцев, в каждом месяце — два столбца. Кнопкой „+“ добавляются сотрудники из базы данных. Для каждого сотрудника задаются даты: с понедельника и на две недели, то есть выбирается любой период, обычно стандартный — две недели: с понедельника по воскресенье, через две недели.»

## Что уже было

- **Данные отпусков лежат в строгой таблице `ppe_absences`** (миграция 0110): `employeeId` → `erp_employee_cards`, `fromMs`, `toMs`, `kind`. По ним же идёт расчёт норм выдачи — то есть **второго места хранения отпусков не нужно**.
- **Двери на сервере и в клиенте готовы**: `GET/POST /ppe/absences`, `DELETE /ppe/absences/:id` (`backend-api/src/routes/ppe.ts`), IPC `ppe:absences:list/create/delete` (`electron-app/src/main/ipc/register/ppe.ts`), preload `window.matrica.ppe.absences.*`. Права — как у соседних записей СИЗ: чтение `erp.dictionary.view`, запись `erp.dictionary.edit`.
- Не хватало только **экрана**: отпуски можно было завести лишь из карточки выдачи, общей картины не было ни у кого.

## Что сделано

1. **Домен (`shared/src/domain/ppeVacationSchedule.ts`)** — вся арифметика графика, чтобы её можно было проверить тестом, а не глазами:
   - `vacationHalves(year)` — сетка: 12 месяцев × 2 половины (1–15 и 16–последний день);
   - `absenceSegments(absences, year)` — раскладка периодов по колонкам: отступ полосы пропорционален началу периода, ширина — числу закрытых дней; период через границу месяца виден в обеих половинах;
   - `defaultVacationPeriod(now)` — **две недели с ближайшего понедельника** (конец = понедельник + 13 дней, воскресенье второй недели);
   - `findOverlappingAbsence(...)` — пересечение с уже заведённым отпуском.
2. **Экран `PpeVacationSchedulePage.tsx`** — год переключается («‹ 2026 ›»), строки — сотрудники, добавленные кнопкой «+ Сотрудники» (список из базы с поиском по ФИО и табельному номеру). Клик по клетке — задать отпуск; клик по полосе — удалить. Пересечение с существующим отпуском спрашивает подтверждение: молчаливого дубля не заводим. Набор строк графика — машинно-локальный (как раскладки колонок): это рабочий список кладовщика, он не должен ездить между машинами.
3. **Меню**: вкладка «График отпусков» в группе «Кладовщик» (рядом с «Карточками СИЗ»), доступ по разделам — складскому, поиск по меню — по слову «отпуск».

## Стражи

- Домен: 7 тестов (половины месяца, период по умолчанию, отступ и ширина полосы, период через границу месяца, пересечения).
- Клиент: 5 сторожей по исходнику — двери СИЗ, никакого своего хранилища, период по понедельникам, предупреждение о пересечении, вкладка в меню и в доступе.

## Что не делаем

- Не заводим второго хранилища отпусков: график читает и пишет `ppe_absences` — расчёт норм выдачи не должен разойтись с картинкой.
- Не меняем права: запись отпуска — тем же правом, что и остальные записи СИЗ (`erp.dictionary.edit`).
- Не добавляем печать и выгрузку: их отдельным запросом владельца, когда график прижится.

## Заводская линза

Производственный поток не трогает: это контур ППО (кадры и СИЗ), не наряды и не склад. Инвариант потока не ломается, затор не кормится.
