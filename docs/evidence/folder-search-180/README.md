# Замер: почему поиск по папкам шёл «по одной папке» (промт КАРМАНА #180)

> Замер сделан 27.11.2026 на машине PC79 (Windows 11, локальный SSD) инструментом
> [`scripts/folder-scan-benchmark.mjs`](../../../scripts/folder-scan-benchmark.mjs).
> Инструмент меряет четыре вещи отдельно: чтение папки, запрос метаданных по
> файлам, число запросов и общее время — в двух режимах («как было» и «как
> стало»).

## Вывод коротко

**Версия «переполнен индекс» отвергнута числами и кодом: индекса в программе
не было вообще.** Причина медленного обхода — три вещи, измеренные по отдельности:

1. **Обход шёл строго по одной папке.** Рекурсия `await walk(child)` ждала
   папку, и несколько добавленных папок тоже шли по очереди.
2. **На КАЖДЫЙ файл делался отдельный запрос метаданных** (размер и дата) со
   своим потолком ожидания. На сетевой папке это тысячи последовательных
   сетевых запросов.
3. **Индекса и кэша не было.** Каждый поиск — полный обход с нуля, поэтому
   стоимость поиска прямо пропорциональна числу файлов в дереве, а первая
   папка шла «тёплой» (кэш ОС), вторая — «холодной».

Замер это подтверждает: на реальной папке **метаданные съедают 90 % времени**
обхода, а снятие лишних запросов и параллельный обход дают **×28…×38** на
той же папке.

## Доказательство «индекса не было»

Код до правки (`git show origin/main:electron-app/src/main/services/fileSearchFolderService.ts`):

- `:416` — `await walk(childPath, childRelative, level + 1);` — рекурсия строго
  последовательная: папка ждёт папку.
- `:428` — `const st = await statWithTimeout(childPath, signal);` — отдельный
  запрос метаданных **на каждый файл**, каждый со своим потолком ожидания.
- `:452` — `await walk(source.path, '', 0);` — каждый поиск начинает полный
  обход заново.

В файле нет ни `Map`, ни кэша, ни карты индекса: искать «переполненный индекс»
было нечего. Версия владельца отвергнута.

## Числа

Оба режима обходят ОДНО И ТО ЖЕ дерево (одинаковый набор папок и файлов,
одинаковый потолок глубины 3).

### Дерево «фото двигателей» (200 папок по 20 фотографий = 4 000 файлов)

| Проход | Режим | Всего | Чтение папок | Метаданные | Запросов: папок / файлов |
|---|---|---|---|---|---|
| 1 (холодный) | «как было» | 220 мс | 26 мс | **172 мс** | 201 / **4 000** |
| 1 (холодный) | «как стало» | **13 мс** | 44 мс | **0 мс** | 201 / **0** |
| 2 (тёплый) | «как было» | 215 мс | 22 мс | **175 мс** | 201 / **4 000** |
| 2 (тёплый) | «как стало» | **11 мс** | 32 мс | **0 мс** | 201 / **0** |

Выигрыш: **×16,9** на холодном, **×19,6** на тёплом.

### Реальная папка `C:\Windows\System32` (1 198 папок, 18 564 файла)

| Проход | Режим | Всего | Чтение папок | Метаданные | Запросов: папок / файлов |
|---|---|---|---|---|---|
| 1 (холодный) | «как было» | 3 112 мс | 198 мс | **2 798 мс** | 1 198 / **18 564** |
| 1 (холодный) | «как стало» | **81 мс** | 231 мс | **0 мс** | 1 198 / **0** |
| 2 (тёплый) | «как было» | 2 040 мс | 130 мс | **1 816 мс** | 1 198 / **18 564** |
| 2 (тёплый) | «как стало» | **72 мс** | 216 мс | **0 мс** | 1 198 / **0** |

Выигрыш: **×38,4** на холодном, **×28,3** на тёплом.

**Доля метаданных в «как было»: 2 798 из 3 112 мс = 90 %** (и 1 816 из
2 040 = 89 % на тёплом проходе). То есть время обхода определяли не папки, а
запросы метаданных по файлам.

### Что это значит для сетевой папки оператора

Замер сделан на **локальном SSD**, где запрос метаданных — это обращение к
кэшу ядра. На сетевой папке (`\\\\server\\share`) каждый такой запрос — это
сетевой круг: 4 000 файлов = 4 000 кругов вместо 201 (папок). Умножение на
время круга (единицы–десятки миллисекунд в локальной сети, сотни в «дальней»
сети) даёт ту самую картину владельца: «идёт по одной папке».

Отдельно видно и «тёплое/холодное»: второй проход по той же папке всегда
быстрее (2 040 мс против 3 112 мс) — это кэш ОС. Отсюда и картина владельца:
«первая папка быстрая, вторая медленная» — первая была тёплой от прошлой
операции, вторая шла в холодную.

## Как перепроверить на боевых папках

Инструмент только читает, ничего не пишет. Запускать на машине оператора:

```powershell
node scripts/folder-scan-benchmark.mjs "D:\\Фото" "\\\\server\\share\\Фото" --repeat 2
```

Ключевое в выводе — доля «метаданные» в строке «как было» и выигрыш режима
«как стало». На сетевой папке выигрыш ожидается заметно больше локального: на
ней метаданные — это сеть.

## Что сделано по итогу замера

- **Лишние запросы метаданных убраны** из пути поиска: для совпадения по имени
  они не нужны, а размер добирается **одним проходом** только для картинок,
  попавших в результат (`fillImageSizes`, параллелизм 8).
- **Обход идёт с ограниченным параллелизмом** (4 папки одновременно,
  `FOLDER_WALK_CONCURRENCY`) вместо строго последовательного.
- **Построена карта дерева папки** (`FileSearchFolderIndex`: путь, имя, тип,
  размер, дата), она строится **в фоне отдельным процессом** при добавлении
  папки, а следующий поиск по этой же папке отвечает по карте и диск не
  трогает — сторож
  [`fileSearchFolderService.index.guard.test.ts`](../../../electron-app/src/main/services/fileSearchFolderService.index.guard.test.ts)
  падает, если это откатится на обход диска.
