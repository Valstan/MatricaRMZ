# M95 — сборка APK падает на «X is not exported by shims/…», хотя PR с этой правкой был зелёным

**Область:** android / гейты

- **Симптом:** `vite build` планшета останавливается на `"<новый экспорт>" is not exported by "src/shims/<модуль>.ts", imported by "../electron-app/src/main/services/<файл>.ts"`. Падение всплывает НЕ в том PR, где появился экспорт, а в следующем — часто в релизном, где менялся `shared/`.
- **Корень:** двойной. (1) Сборка планшета тянет **main-процесс** electron-app: часть модулей подменяют шимы (`android-app/src/shims/`), остальные компилируются как есть — значит новый экспорт в шимованном модуле обязан появиться и в шиме. (2) Гейт `build-apk` на PR слушал только `android-app/**`, `shared/**`, `electron-app/src/renderer/**` — то есть **не тот путь, который его и ломает**. Путь `electron-app/src/main/**` добавлен 2026-08-26.
- **Диагностика:** ошибка называет и шим, и импортирующий файл — читать её буквально, а не искать «поломку сборки». Локальная проверка одной командой: `corepack pnpm -F @matricarmz/android-app build`.
- **Лечение:** дописать в шим no-op с той же сигнатурой и комментарием, ПОЧЕМУ он пустой (на планшете сторожа нет). Пустой экспорт без объяснения читается как забытая реализация.
- **Урок шире случая:** гейт, который не слушает путь своей же поломки, создаёт худший вид ложного зелёного — правка уезжает в main, а краснеет потом чужой PR. Заводя шим или платформенную развилку, сразу проверь, какие пути видит её гейт.
- **Поймано:** 2026-08-26, релиз v3.13.0 (экспорт `reportWatchdogAutostartIfBroken` из PR #694).
