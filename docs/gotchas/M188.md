# M188 — `certutil -user -addstore Root` зависает, `Import-Certificate` отказывает: корень сертификата ставится только через .NET API

**Область:** [M188](#m188--certutil--user--addstore-root-зависает-import-certificate-отказывает-корень-сертификата-ставится-только-через--net-api)

- **Симптом:** установка корневого сертификата в доверенные на машине парка не проходит ни одним «очевидным» способом. `Import-Certificate -CertStoreLocation Cert:\CurrentUser\Root` отвечает **«Для данной операции пользовательский интерфейс запрещен»** (нужен подтверждающий диалог, а сессия неинтерактивная). `certutil -user -f -addstore Root rootca.cer` **не возвращается** — висит на невидимом диалоге подтверждения, и в CI/агентской сессии это тупик: команда не падает, а просто не заканчивается (проверено на PC79, 04.11.2026).
- **Корень:** оба инструмента — обёртки над диалогом подтверждения, а не над API. Сам API хранилища (`.NET X509Store`) диалога не показывает вовсе.
- **Лечение:** ставить корень через .NET API — он отрабатывает молча и без прав администратора:
  ```powershell
  $x = New-Object System.Security.Cryptography.X509Certificates.X509Certificate2($cer)
  $s = New-Object System.Security.Cryptography.X509Certificates.X509Store('Root','CurrentUser')
  $s.Open([System.Security.Cryptography.X509Certificates.OpenFlags]::ReadWrite)
  $s.Add($x); $s.Close()
  ```
  Готовая реализация — [`scripts/signing/sign-matrica.ps1`](../../scripts/signing/sign-matrica.ps1), режим `-Mode InstallRoot`.
- **Вторая половина грабли — установка идёт от 45 секунд до нескольких минут, и это не зависание.** Замерено на PC79 04.11.2026: первая установка нового корня — **207 с**, повторная того же сертификата — 9,4 с, `TrustedPublisher` на том же .NET API — 3 мс. Причина не в сертификате: у него нет ни CRL Distribution Points, ни AIA, цепочка строится локально — задержка на стороне Windows при добавлении в хранилище `Root`. На парке оператор должен знать про это: иначе он решит, что установщик встал, и бросит его. Скрипт печатает предупреждение перед установкой.
- **Почему это важно именно тут:** установщик клиента **per-user без прав администратора** ([ADR-0002](../adr/0002-single-executable-root-not-program-files.md)), и подпись кода ([ADR-0003](../adr/0003-signed-code-ecosystem-one-kaspersky-rule.md)) должна ставиться тем же путём — без UAC на каждой машине. Диалог подтверждения здесь ломает всю схему: парк встаёт на «нажмите окно в окне Касперского», которого никто не видит.
- **Проверка:** после установки `Get-ChildItem Cert:\CurrentUser\Root | Where-Object Subject -like '*MatricaRMZ*'` показывает корень, а `signtool verify /pa <файл>` даёт `Successfully verified` (до установки корня — `terminated in a root which is not trusted by the trust provider`).
- **Сторожа:** [`scripts/signing/sign-matrica.ps1`](../../scripts/signing/sign-matrica.ps1) (`-Mode InstallRoot`), тест руками — 04.11.2026 на PC79.
- **Пул:** [M94](M94.md) — там неподписанный `.ps1` съедался сканером до того, как для него завели исключение; здесь та же природа: инструмент на машине парка должен обходиться без диалогов, иначе он не доедет.
