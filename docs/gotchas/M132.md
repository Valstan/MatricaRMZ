# M132 — удаление пакетов из `node_modules` не освобождает место: блоки лежат в сторе

**Область:** [M132](#m132--удаление-пакетов-из-node_modules-не-освобождает-место-блоки-лежат-в-сторе)

- **Симптом (прод, 15.09.2026):** `du -sh node_modules` показывает 975 МБ, но `pnpm store prune` снимает 12 пакетов, а после удаления 341 каталога из `.pnpm` свободное место на диске не меняется вовсе.
- **Корень:** pnpm кладёт файлы в `node_modules/.pnpm` **хардлинками** в глобальный стор. Блоки одни и те же, у инода два имени. `du` по каждому пути отдельно считает их себе, поэтому и стор (934 МБ), и `node_modules` (975 МБ) «весят» почти весь объём — а union у них 993 МБ. Пока на инод ссылается стор, удаление ссылки из `node_modules` освобождает ноль.
- **Диагностика:** `du -shc <стор> <node_modules>` **одной командой** — общий итог считает хардлинки один раз, и разница между итогом и слагаемыми и есть степень разделения. У нас собственных блоков у `node_modules` оказалось 59 МБ из 975.
- **Лечение:** снимать ссылки, потом `corepack pnpm store prune` — только он убирает вторую половину пары. Порядок обратный (сначала prune) бесполезен: стор считает референсным всё, на что ссылается хоть один проект.
