# M224 — в редактируемом списке теряется фокус при вводе: ключ строки React содержит редактируемое поле

**Область:** интерфейс клиента (`electron-app/src/renderer/src/ui/`), любой список, который оператор правит прямо на экране

- **Симптом:** в поле списка вводят один символ — и курсор из поля пропадает. Дальше печатать можно только заново кликнув по полю. Список при этом выглядит исправным, значения меняются, ошибок нет.
- **Корень:** ключ строки React содержал **редактируемое** поле: `key={`${slot.caption}-${index}`}` в списке подписей печатной формы (`components/PrintSignatureBlockEditor.tsx`). Меняется должность ⇒ меняется ключ ⇒ React считает строку **другим элементом**: старая размонтируется, новая монтируется, поле теряет фокус. Чем длиннее правка, тем заметнее: печатать приходится по символу.
- **Почему молча:** значение поля обновляется правильно (оно в состоянии), ошибок нет, тесты проходят — а проблема видна только руками: «кликнул, набрал букву, курсор пропал». Юнит-тест на данные её не ловит: сломан **фокус**, а не значение.
- **Диагностика:** открыть список, начать печатать в поле, которое меняет состав строки. Второй симптом — при смене сортировки/перестановки строки «подменяется» содержимое соседних полей: это тот же ключ по индексу. Правило: **в списке, который правят, ключ React не должен содержать редактируемых полей** — ни данных строки, ни её подписи; максимум — устойчивый id или позиция.
- **Лечение:** ключ по позиции строки (`key={`pp-signature-slot-${index}`}`) либо по устойчивому id, если у строки он есть. Отдельно: если рядом с таким полем стоит выбор из справочника (`EntityReferenceField`), его массив опций тоже должен быть **один на список** (`useMemo`) — иначе сбросится и набранный запрос.
- **Родня в коде:** `components/PrintSignatureBlockEditor.tsx` (подписи печатных форм), по образцу — `pages/WorkOrderDetailsPage.tsx` (`WorkOrderSignatureSlots`, ключ `wo-signature-slot-${idx}`).
- **Правило на будущее:** **редактируемое поле ⇒ ключ строки не содержит его значения.** Правило звучит мелко, но ловит целый класс «поле не работает», который не воспроизводится в тестах и стоит оператору времени.
