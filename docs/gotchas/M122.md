# M122 — отложенное создание родителя + автосохранение ребёнка: ребёнок раньше родителя, сироты и двойники

**Область:** sync / отложенное создание

- **Симптом:** `client.sync.blocked_rows` («критично») на каждый новый двигатель, на сервере — `sync dependency rows skipped` для `operations → engine_entity`; через 5–40 секунд всё сходится само. За утро 10.09 — 22 доклада на 22 новых двигателя, ни одной потерянной строки. Заодно у двигателей по два списка деталей, созданных с разницей в 12 мс: один пустой, второй заполняется.
- **Корень, половина первая:** `createEngine` выдаёт id без строки в базе (deferred create, Phase 2) — строка появляется с первым записанным полем. Панель списка деталей при открытии сама сохраняет автозаполненный лист — и операция ссылается на двигатель, которого нет ни локально, ни на сервере. Клиент честно отвечает «зависимости нет и у меня», кладёт строку в карантин и докладывает. Брошенная карточка оставляет лист-сироту навсегда.
- **Корень, половина вторая:** `save()` берёт `operationId` из замыкания React, два автосохранения подряд оба видят `null`, а `saveRepairChecklistForEngine` без номера листа всегда вставлял новый. На 10.09 двигателей с двумя живыми листами — 206, из них 133 пары созданы в пределах 5 секунд; в сентябре так созданы все новые пары.
- **Почему держалось:** отложенное создание и автосохранение по отдельности правильны, стык виден только в синхронизации, и то чужим симптомом. Пункт «PC19 держит единственную копию работы» (09.09) стоял на этом же классе: восемь «строк работы» оказались четырьмя брошенными карточками по два пустых листа.
- **Диагностика:** для каждой строки из пропуска — есть ли двигатель на сервере сейчас и когда он создан (клиентский `created_at`) против `created_at` листа. Двигатель моложе листа на секунды — этот класс. Содержимое отвергнутых строк лежит в `ledger_tx_index` (журнал пишется до применения, M116): «единственная копия на машине» проверяется там, а не догадкой.
- **Лечение (3.25):** main откладывает автозаполненный лист, пока нет строки двигателя (`auto: true` → ответ `deferred`), правка оператора сначала создаёт двигатель (`ensureEngineRow`); без номера листа сервис берёт существующий лист двигателя. Панель дописывает отложенный лист, когда карточка сохранила двигатель, и при закрытии карточки. Сторожа — `checklistService.test.ts`, `RepairChecklistPanel.guard.test.ts`.
- **Общая форма:** всё, что пишется САМО под id отложенно создаваемого родителя, обязано ждать родителя; ручная правка ребёнка — уже содержимое, она родителя материализует.
- **Поймано:** 2026-09-10, разбор тревоги прода. Родня: **M116** (тот же PC19, прошлый слой), **M121** (число, не отвечающее на свой вопрос).
