# M92 — `gh release download` молча отдаёт обрезанный (или нулевой) файл на крупном ассете

**Область:** релиз / артефакты

- **Симптом:** команда завершается успешно, файл на диске есть — но он в разы меньше ассета. На релизе v3.11.0 APK скачался как **212 КБ** вместо 25 МБ, повторные попытки давали **0 байт**, и ни одна из них не напечатала ошибки. Родственно **M18** (мульти-`--pattern` роняет blockmap): `gh` не проверяет полноту скачанного.
- **Корень:** флаки-сеть на пути к GitHub CDN. Ошибки на этом пути и так известны (на самом проде `gh release download` воспроизводимо валится TLS-таймаутом, см. AGENTS.md §Release шаг 8a) — просто здесь она не падает, а обрывается тихо.
- **Диагностика:** взять эталонный размер у самого GitHub, а не глазами: `gh api repos/Valstan/MatricaRMZ/releases/tags/<tag> --jq '.assets[] | "\(.name) \(.size)"'`. Второй ориентир — соседние версии на проде: `ls -la /opt/matricarmz/updates/android/` (APK стабильно ~25 МБ, инсталлятор ~136 МБ).
- **Лечение:** качать **циклом со сверкой размера**, а не одной командой:
  ```bash
  for i in 1 2 3 4; do rm -f "$D/app-release.apk"; gh release download android-vX.Y.Z --pattern "*.apk" -D "$D" --clobber >/dev/null 2>&1;
    [ "$(stat -c%s "$D/app-release.apk" 2>/dev/null || echo 0)" = "<size из gh api>" ] && break; done
  ```
  Запускать **из каталога репо** — вне git-контекста `gh` вообще отказывается работать (`failed to run git: fatal: not a git repository`) и оставляет пустой каталог, что легко принять за «скачал ноль байт».
- **Цена ошибки:** незамеченный обрезанный APK уезжает `scp`'ом на прод, Диспетчер честно отдаёт его планшетам по имени файла — и парк получает битый установщик. Проверять размер **до** `scp`, а не после.
- **Поймано:** 2026-08-25, релиз v3.11.0, шаг 8a.
