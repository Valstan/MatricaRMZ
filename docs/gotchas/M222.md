# M222 — ответ агента MiniMax приходит текстом вместо `tool_use`: нативной схемы у вендора нет, формат задаёт промпт

**Область:** ИИваныч / воркер MiniMax (`backend-api/src/minimaxWorker/`)

- **Симптом:** ИИваныч не вызывает инструменты — отвечает текстом там, где нужен вызов (поиск двигателя, эскалация, вложение таблицы), либо ответ приходит вовсе пустым, либо агент шлёт «почти-JSON» и цикл встаёт. При этом HTTP-запросы к провайдеру уходят, расход токенов виден, а в логе воркера — тишина.
- **Корень:** **у аккаунтов MiniMax нет пригодного публичного API** (вендор отвечает `401` + `2062 no active token plan subscription`) — очки чекина тратятся только в сценариях MiniMax Code. Значит, движок — не прокси к API, а **реализация семантики агента-CLI**. А нативная строгая схема у MiniMax не работает вовсе: `--output-schema` даёт `STRUCTURED_OUTPUT_INVALID` на любой схеме (замерено в «Сарафане», ADR-0017). Формат ответа задаёт **системный промпт агента**, а разбор — наш слой. Без явного преобразования свободного текста в `tool_use`-структуру весь агентный цикл ИИваныча и 4 мета-инструмента (`escalate_to_admin`, `attach_table`, `save_learning_note`, `enable_full_tools`) не работают.
- **Почему молча:** «текст вместо вызова» — это валидный HTTP 200 с валидным телом. Ни гейт, ни тест на контракт ответа этого не видят: сломанный формат выглядит как обычный ответ модели.
- **Диагностика:** в логе воркера — `minimax worker: ответ агента разобран с замечаниями` (замечания разбора: «не разобран», «инструмент “X” не запрошен», «вход приведён к объекту»). В журнале бэкенда — `ai chat direct: empty answer` с `stopReason` и списком вызванных инструментов. Смотреть туда, а не в код вызова модели.
- **Лечение:** контракт ответа задан в промпте агента явной строкой (`backend-api/src/minimaxWorker/agentPrompt.ts`, `ANSWER_CONTRACT`): строго один JSON `{"text": …, "tool_use": {name, input}}`, больше ничего. Разбор — `toolUseShaper.ts`: **снисходителен к обёрткам** (голый JSON, блок кода ```json, JSON в тексте вокруг), **строг к смыслу** (инструмент вне запрошенного списка отбрасывается, вход-не-объект приводится к объекту), каждое замечание уходит в журнал. Юнит-тесты на каждую форму — `toolUseShaper.test.ts`.
- **Родня в коде:** `backend-api/src/minimaxWorker/minimaxAgent.ts` (сборка команды CLI: `--output-format json`, `--system-prompt-file`, `--file`, **без** `--output-schema`), `backend-api/src/minimaxWorker/agentProfile.ts` (ключ записи токен-стора выводится из **абсолютного пути** профиля; рантайм считает запись битой без `refreshToken`, `generation`, `loginEpoch` — refresh Карман не отдаёт, пишется заглушка).
- **Правило на будущее:** когда движок умеет только CLI-агента, **формат ответа — это часть контракта, а не деталь реализации**: его надо задавать в промпте, разбирать отдельным слоем и закрывать тестами на каждую форму ответа. Иначе «агент ответил текстом» выглядит как «модель не поняла задачу».
