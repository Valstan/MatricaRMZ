# M117 — гейт считает попытки, а называет их строками: один клиент держит статус `critical` вечно

**Область:** диагностика / гейты

- **Симптом:** здоровье конвейера синхронизации — `critical`, причина «skipped dependency rows 24h=10076». Отставаний нет, `23505` нет, парк работает. Ощущение массовой потери данных, которой не было: различных строк — восемь.
- **Корень:** снимок пропусков писал только СЧЁТЧИК (`count`) без id, и порог (`> 500 за сутки`) сравнивался с суммой попыток. Клиент, повторяющий 8 строк каждые 40 секунд, даёт 6 264 «пропущенных строки» в сутки. Порог перекрыт в 12 раз навсегда — а вместе с ним перекрыт и сигнал: за те же сутки 220 из 224 критических событий были этим же циклом.
- **Общая форма:** величина, по которой стоит порог, обязана отвечать на вопрос, которым порог назван. «Сколько данных не доехало» — это различные строки; «крутится ли цикл» — это попытки. Одно число не отвечает на оба вопроса, и подмена не видна, пока цикла нет.
- **Лечение:** снимок несёт `rowIds` (с потолком), свёртка считает различные строки (`foldSkippedRowsSnapshots`), попытки остаются отдельной величиной и печатаются в причине как `attempts=N`. Старые снимки без id считаются попытками — иначе сутки после выката гейт слепнет.
- **Поймано:** 2026-09-08. Родня: brain #284 «гейт без области» (порог, условие которого не может стать ложным), M113 (итог, не покрывающий свои части).
