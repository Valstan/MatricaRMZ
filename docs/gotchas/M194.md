# M194 — Артефакты релиза под промежуточным именем исчезают с прод-диска, а `scp` рапортует об успехе

**Область:** [M194](#m194--артефакты-релиза-под-промежуточным-именем-исчезают-с-прод-диска-а-scp-рапортует-об-успехе)

- **Симптом:** при выкате v3.114.0 (10.11.2026) файлы `.exe`, `.exe.blockmap` и `latest.yml`, залитые на прод под именами `*.incoming` (замысел: подмена атомарная, пересканировать каталог нельзя поймать полузалитый файл), **исчезли через секунды после заливки**. `scp` при этом отчитывался кодом 0, в `-v` было видно `Transferred: sent 148216 bytes` и `Exit status 0` — выглядит как «залилось, а файла нет». Проверка `ls` каталога показывала только файлы прошлого релиза. APK, залитый в подкаталог `android/`, при этом уцелел.

- **Корень:** **на целевой машине стоит path-юнит, который чистит каталог по факту изменения.** `/etc/systemd/system/matricarmz-updates-prune.path` содержит `PathChanged=/opt/matricarmz/updates` — он срабатывает на **любое** изменение каталога и запускает `matricarmz-updates-prune`, который удаляет всё, что не похоже на инсталлятор: из содержимого остаются только новейшие `MatricaRMZ-Setup-*.exe` с их `.blockmap` плюс `latest.json` / `latest.yml` / `latest.torrent` / `pending-update.json`. Файл `*.incoming` под правило не попадает → удаляется сразу после заливки. Подкаталог `android/` path-юнит не смотрит — поэтому APK выжил.

- **Диагностика:** (1) код возврата `scp` здесь бесполезен — SFTP-режим рапортует об успехе по факту передачи, а не по факту наличия файла; (2) спросить на сервере, что чистит каталог: `systemctl list-timers | grep -i matrix`, `systemctl cat matricarmz-updates-prune.path`, `cat /usr/local/bin/matricarmz-updates-prune`; (3) полезно положить файл и сразу `ls` — исчезновение мгновенное указывает именно на чистку, а не на копирование.

- **Лечение:** класть артефакты **только под финальными именами**, порядком: `.exe` → его `.blockmap` (блокмап переживает чистку только рядом со своим `.exe`) → `latest.yml` (в списке исключений всегда). Никаких промежуточных имён (`.incoming`, `.part`) в каталоге обновлений: их там не существует — чистка срабатывает на само изменение каталога, то есть и на появление промежуточного файла. Если нужен атомарный swap — делать его в **подкаталоге** (как `android/`) или дописывать в файл, а не переименовывать. Правило выката — `AGENTS.md` §Release process, шаг 7; факт выката — `docs/machines/es-vps.md`.
