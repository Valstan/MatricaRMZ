# M148 — выкат прошёл, а на проде старый код: по `/health` этого не видно

**Область:** [M148](#m148--выкат-прошёл-а-на-проде-старый-код-по-health-этого-не-видно)

- **Симптом (30.09, релиз 3.53.0):** `deploy-backend.sh` без аргумента отработал успешно, `git pull` притянул 3.53.0, оба инстанса ответили, `/health` отдал `version: 3.53.0` — а на проде лежал **dist, собранный 29.09 для 3.52.0** (PR #1051). То есть весь релиз на сервере отсутствовал, и ни один привычный признак этого не показывал.
- **Корень (два слоя):**
  1. `backendVersion` (`backend-api/src/version.ts`) читает `require('../package.json')` — то есть `package.json` **из клона**, а не из артефакта: `git pull` обновил его раньше, чем лёг dist, и `/health` начал отвечать версией, которой на сервере нет. Версия в ответе — это версия исходников, а не исполняемого кода.
  2. Без явного run-id скрипт берёт «последний успешный прогон `backend-dist` на main» запросом `gh run list`. На боксе этот запрос вернул прогон **29.09** (транзиентно/кэш — сразу после тот же запрос отдал правильный прогон 30.09). Единственный признак, что ответ устарел, скрипт печатал: `ВНИМАНИЕ: собранное и исходники в клоне — с разных коммитов`.
- **Почему это не поймала приёмка:** `/updates/status`, раздача инсталлятора, диспетчер и health обоих портов — всё зелёное. Ни один из них не знает, из какого коммита собран `dist`.
- **Правила:**
  1. **В выкате всегда передавать run-id явно:** `bash scripts/prod-ops/deploy-backend.sh <run-id>`. «Последний успешный» — это запрос к сети во время выката, и его ответ однажды устарел ровно в тот день, когда выкатывали.
  2. **`ВНИМАНИЕ: … с разных коммитов` — это стоп, а не строка в логе.** Смотреть, откуда взялся прогон, и повторять выкат по id (сейчас скрипт только предупреждает — hardening в `PENDING`).
  3. **Признак «новый код на сервере» искать в самом артефакте**, а не в `/health`: `grep` по `dist/` на символ из нового коммита (в этом выкате — `row-history` в `dist/routes/ledger.js` и `rowsIn` в `dist/services/engineInventoryLinesService.js`). Общий приём: одна строка, которая есть только в новом коде.
  4. **`/health` не годится как доказательство версии** — он отвечает версией клона. Чинить `backendVersion` (брать значение, вшитое в артефакт) — отдельная задача.
