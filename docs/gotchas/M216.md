# M216 — В проде `logInfo` без флага `critical` не пишется вовсе: важная строка настройки исчезает из журнала

**Область:** прод-логирование (`backend-api/src/utils/logger.ts`), канал тревог в МАКС (`backend-api/src/services/criticalEventsMaxService.ts`)

- **Симптом:** канал тревог в МАКС настроен (токен в комнате КАРМАНА прочитан, адресат определён из
  сообщения боту), но в журнале прод-бэкенда **ни одной** строки про адресат — ни «определён», ни
  «пока не известен». Канал при этом не работает: тревоги уходят в `канал МАКС не настроен (нет
  токена/адресата)`, а понять, что адресата надо просто положить в комнату, негде. Проверено
  19.11.2026 на боевом боксе.

- **Корень:** **прод-режим логгера глотает `info` целиком.** В `logger.ts`:
  `shouldLog(level, critical)`: при `critical === true` пишем всегда; иначе в `dev` — всё, а в
  `prod` — **только `warn` и `error`**. То есть `logInfo('канал МАКС: адресат определён', …)` без
  третьего аргумента `{ critical: true }` не пишется **ни в journal, ни в файл** — и выглядит как
  «сервис молчит». Классика: строка «вроде должна быть» + прод-режим = нет строки вообще.

- **Второй слой ловушки:** адресат, определённый из сообщения боту, **некуда было записать**.
  Сервер вычитывает сообщение (`GET /updates`) и отвечает в тот же чат, показав `chat_id`, — но
  в комнату он писать не может: бокс держит **read-only** токен (`GET /api/secrets/self` →
  `canWrite: false`), а правило «писать комнату с бокса нельзя» — осознанное (бокс восстанавливают
  этой комнатой). Вдобавок `GET /chats` у МАКС отключён — список своих чатов бот не узнаёт. Итог:
  адресат был известен ровно минуту и пропадал.

- **Диагностика:** спросить логгер, а не искать строку:

  ```js
  // backend-api/src/utils/logger.ts
  shouldLog('info', /* critical */ false); // в prod → false
  ```

  И проверить, что нужная строка помечена: `logInfo('…', {…}, { critical: true })`.

- **Лечение:** (1) важные строки настройки и состояния — только с `{ critical: true }`; (2) то, что
  сервер узнал, но не может записать (адресат бота, вычисленный идентификатор), — оставлять в
  подсказке на диске (`logs/max-target.json`) и **напоминать о нём при старте** с указанием ключа,
  который надо положить в комнату; (3) закрыть стражем: тест проверяет, что обе строки про
  адресат идут с `critical: true` (см. `criticalEventsMaxService.guard.test.ts`).

- **Чего НЕ делать:** не «улучшать логгер» под задачу (то есть не включать `info` в проде) —
  это завалит журнал. Помечать флагом точечно.

- **Родственная находка:** тот же класс — «канал настроен, но сообщения об этом не видно» — см.
  [M217](M217.md): проверять нужно не наличие ключа, а достижимость адреса с боевого бокса.
