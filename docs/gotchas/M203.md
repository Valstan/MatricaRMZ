# M203 — CI: `test` красный из-за распаковки Electron в раннере, а не из-за кода

**Симптом.** Джоб `test` в CI красный, и в логе — не про ассерты, а про установку Electron:

```
Error: failed to create '/home/runner/work/MatricaRMZ/MatricaRMZ/node_modules/.pnpm/electron@43.0.0/node_modules/electron/dist/icudtl.dat': File exists (os error 17)
Error: Electron failed to install correctly. Please delete `node_modules/electron` and run "npx install-electron --no" manually.
FAIL src/main/services/engineBulkIntakeService.test.ts
```

Тестов, к которым это относится, код может не касаться вовсе: падает любой набор, которому
нужен бинарник Electron.

**Что это.** Электрон распаковывается в раннере во время прогона, и распаковка иногда
натыкается на уже существующий файл (`File exists`). Это гонка в окружении CI, а не
регресс: тот же коммит локально зелёный, и на соседних прогонах CI зелёный тоже.

**Как отличить от своего регресса.** Смотри, что именно в логе: `AssertionError` с
ожидаемым/полученным — это про код; `Electron failed to install correctly` и `icudtl.dat:
File exists` — про раннер. Имя упавшего теста в этом случае случайно (тот, что первым
потребовал бинарник).

**Лечение.** Перезапуск джоба:

```bash
gh run rerun <run-id> --failed
```

Правкой кода здесь лечить нечего — и не надо: зелёный прогон после перезапуска и есть
доказательство, что регресса не было.

**Почему записано.** Такой красный CI выглядит как «моя правка сломала тесты» — и в ответ
начинают чинить то, что сломано не было. Проверка: локальный прогон того же коммита плюс
`git log` — что именно менялось в PR.
