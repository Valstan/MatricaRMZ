# M238 — Коммит уехал в чужую ветку: в рабочей папке полосы была выбрана не та ветка

**Область:** параллельные полосы в одном репозитории: рабочая папка полосы переиспользована
соседней полосой (в воркауте выбрана чужая ветка, рядом чужие незакоммиченные правки).

- **Симптом:** правки внесены в своей папке, `git commit` прошёл без ошибки — а коммит оказался
  **на соседней ветке**: у соседа в `git status` пропали его файлы, в его PR уехала моя правка
  дока, а моя ветка осталась без моего коммита.
- **Корень:** worktree = папка + **ветка, выбранная в ней**; `git commit` кладёт коммит на
  выбранную ветку, а не на ту, о которой агент думает («моя ветка, на которой я работаю»).
  Переключить ветку в папке с чужими незакоммиченными файлами нельзя (унесёт или заблокирует
  чужую работу) ⇒ папка остаётся на чужой ветке, а «своя» ветка живёт отдельно, в своей папке.
- **Диагностика:** (1) `git branch --show-current` в папке перед каждым коммитом — дешевле всего;
  (2) `git log --oneline -2 origin/<чужая ветка>` — там твой коммит; (3) `git status --short` в
  папке показывает **чужие** файлы — верный признак, что папка общая.
- **Лечение (по шагам, чужая работа не теряется):**
  1. **Сохранить свой коммит:** `git branch -f <моя ветка> <sha своего коммита>` — из любого
     worktree репозитория; ветка снова указывает на твой коммит.
  2. **Вернуть соседней полосе её ветку:** в её worktree — `git reset --soft HEAD~1`. Указатель
     ветки возвращается назад, а **индекс и файлы остаются как были** ⇒ чужие незакоммиченные
     правки не тронуты.
  3. **Убрать свои правки из чужого дерева:** `git restore --source=HEAD --staged --worktree --
     docs/…` (или по конкретным файлам) — чужая папка возвращается к своему состоянию.
  4. **Дальше — только в своём worktree:** `git worktree add <свой путь> -b <своя ветка>
     origin/main`, коммит — там.
- **Понятки:** 26.11.2026, полоса 3 (машина **PC79**), нитка «промт КАРМАНА #167» (ПП: сквозной
  «№ п/п»), PR **#2107**. Соседняя полоса в это время вела «scrap stage gate» в
  `.claude/worktrees/m3/faza` (ветка `feat/scrap-stage-gate-2026-11` + чужие незакоммиченные
  файлы). Мой коммит сначала уехал на её ветку; починка — по шагам выше, чужие файлы остались
  нетронутыми. Смежные грабли того же вечера: `gh pr merge --squash --delete-branch` ломает
  worktree ([M237](M237.md)), а `git branch -D` машина режет (мягкая замена — `git update-ref -d
  refs/heads/<ветка>`).
- **Правило на будущее:** перед **каждым** коммитом — `git branch --show-current`; свой коммит
  только в том worktree, где HEAD = своя ветка; папку, в которой видны чужие незакоммиченные
  файлы, под свою ветку не переиспользовать — заводи отдельный воркаут.
