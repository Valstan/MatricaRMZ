# M185 — Кнопка шапки карточки не знает про вкладки со своей схемой сохранения

**Область:** [M185](#m185--кнопка-шапки-карточки-не-знает-про-вкладки-со-своей-схемой-сохранения)

- **Симптом:** оператор правит вкладку карточки двигателя, жмёт «Сохранить и выйти» — карточка закрывается, а правка пропала. Рядом стоящая «Сохранить» выглядит работающей, и в чём именно теряется — непонятно: кажется, что сохранение есть, ведь «Сохранить» только что отработал.
- **Корень:** у карточки несколько вкладок, и они живут **по разным схемам сохранения**. «Основное» пишется кнопкой шапки (`engines:card:save`), лист актов — самой панелью (`checklists.engineSave`), платежи — **своей** кнопкой «Сохранить платежи» и своим флагом `dirty`. Кнопка шапки про платежи не знала: карточка сохраняла своё и закрывалась, а несохранённые платежи оставались в памяти вкладки и исчезали вместе с ней (жалоба владельца 01.11.2026).
- **Лечение:** вкладка с чужой схемой отдаёт карточке ручку (`registerHandle` → `flush(): Promise<boolean>`), а карточка сбрасывает её **до** сохранения и закрытия. Отказ — карточка не закрывается, оператор видит причину. Ручка отдаёт результат, а не «ничего»: `save()` вкладки платежей теперь возвращает `boolean`.
- **Как поймать рано:** проверка на живом клиенте обязана сверяться с **сервером**, а не с экраном: «на экране есть, в базе нет» — это и есть потеря. Сверка `engines.get` + `checklists.engineGet` ловит её сразу.
- **Правило на будущее:** у карточки с кнопкой «Сохранить и выйти» **каждая** вкладка либо пишется самой кнопкой шапки, либо отдаёт карточке ручку сброса. Своя кнопка на вкладке при закрывающей кнопке в шапке — это рассинхрон, который стоит закрывать ручкой, а не молчанием.
- **Аудит всех карточек (01.11.2026, по запросу владельца «проверь сам во всех видах карточек»):** карточек с кнопкой «Сохранить и выйти» — 14, из них с дырами было две.

  | Карточка | Как закрывается | Вердикт |
  |---|---|---|
  | Договор, контрагент, сотрудник, марка двигателя, заявка в снабжение | `if (ok) props.onClose()` | ✓ |
  | Сборка (BOM двигателя) | `if (await saveBom()) props.onClose()` | ✓ |
  | Инструмент / свойство инструмента | `if (ok)` / `if (!(await saveAll())) return;` | ✓ |
  | Номенклатура, складской документ | `if (ok) props.onClose()` | ✓ |
  | Группа марок | закрытие внутри `try`, после успешной записи | ✓ |
  | Двигатель | сохранение бросает при отказе, платежи сбрасываются до сохранения | ✓ (#1543) |
  | **Наряд** | было: `await flushSave(...)` без проверки результата → неуспех тихо уносил правки, карточка закрывалась | ✗ исправлено |
  | **Простые справочники (товар, услуга)** | было: `saveAllAndClose` → `checkDuplicatesBeforeSave` → `saveAllAndClose` — бесконечная рекурсия; кнопка не делала ничего: ни записи, ни закрытия | ✗ исправлено |

  Инвариант «закрытие только под успехом сохранения» теперь держит сторож `cardSaveButtons.guard.test.ts`: он перечисляет все карточки с кнопкой и падает, если появится новая карточка вне списка.
