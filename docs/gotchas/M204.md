# M204 — `touch` двух файлов одной командой оставляет блокмап свежее `.exe`

**Симптом.** Выкатка прошла, а чистка каталога обновлений (`matricarmz-updates-prune`)
оставила **старый** установщик: свежий `.exe` исчез, `latest.json` продолжал указывать на
прежний файл, клиенты получали 404 на инсталлятор. По версии всё верно — на диске свежий
файл лежал, но чистка его выбрала не тем.

**Почему.** Чистка выбирает оставляемый установщик **по времени файла** (`ls -1t`), а не по
версии (это M196). В выкатке 12.11.2026 файлы освежались так:

```bash
touch MatricaRMZ-Setup-3.121.0.exe MatricaRMZ-Setup-3.121.0.exe.blockmap
```

`touch` идёт по файлам подряд, и блокмап получает mtime на долю секунды позже. `ls -lt`
показывает блокмап **выше** установщика — а именно установщик чистка выбирает по свежести.
При близких mtime порядок решает уже сортировка по имени, и результат зависит от локали.

**Лечение.** Освежать установщик **последним** и отдельно, с паузой:

```bash
cd /opt/matricarmz/updates
sleep 1 && touch MatricaRMZ-Setup-X.Y.Z.exe
ls -lt | head -3     # первым обязан быть .exe текущего релиза
```

**Проверка после заливки (обязательная).** Первым в `ls -lt` должен лежать `.exe` текущего
релиза, а `latest.json` — совпадать с ним по размеру (M40). Пока это не сходится, релиз
не объявлен.

**Почему это не поймали гейты.** Ни один локальный гейт не смотрит в каталог обновлений на
проде: чистка живёт только там, а время файла — свойство конкретной ФС и конкретного
порядка команд. Ловится только глазами на месте, после заливки.
