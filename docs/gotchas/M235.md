# M235 — Печать картинок: «Invalid printer settings», «Value does not fall within the expected range» и мёртвое окно мастера

**Область:** печать фотографий (карточка, панель вложений, выдача «Поиска по файлам»).
**Симптомы (25–26.11.2026, PC79):** владелец жаловался, что печать из выдачи «Поиска по файлам» не сработала («принтер не нашёл»); при разборе нашлись **три разные поломки**, и все три молчали.

## 1. «Invalid printer settings» — это не offscreen и не «принтер не найден»

- **Что проверено (живой прогон, 26.11.2026):** на машине пять принтеров (`Get-Printer` → все `Normal`, принтер по умолчанию — Canon MF3010), спуллер `Spooler` — `Running`. Chromium при этом видит все пять (`webContents.getPrintersAsync()` → 5 штук), но `webContents.print()` **всегда** возвращает `ok=false, reason="Invalid printer settings"` — и в скрытом окне, и в видимом, и с явным `deviceName`, и в режиме `silent` (там при выдуманном имени — отдельная ошибка «Invalid deviceName provided»).
- **Ложная грабля в коде:** комментарий «печать из offscreen-окна падает Invalid printer settings» в `fileService.ts` вводил в заблуждение — offscreen тут ни при чём. Ошибка означает, что **печатающий модуль Chromium не смог собрать настройки печати** для этой машины.
- **Как отличать:** «принтера нет» — это про СИСТЕМУ (список принтеров пуст, отказ «Принтер не найден»); «Invalid printer settings» — про печатающий модуль Chromium, принтеры при этом в системе есть. Ошибка внятная только вместе с причиной.
- **Что сделано:** общий модуль печати (`electron-app/src/main/services/photoPrint.ts`) при этой ошибке **не теряет печать** — уводит её в системный мастер печати фотографий и говорит оператору почему.

## 2. Окно мастера печати фотографий умирает вместе с процессом, который его открыл

- **Симптом:** `Start-Process -FilePath <фото> -Verb print` из одноразовой команды — окно «Печать изображений» появляется и **пропадает**, едва команда завершилась. Оператор ничего не успевает: печать «не сработала».
- **Почему:** окно мастера живёт, пока живёт процесс-открыватель (COM-обработчик `photowiz.dll` грузится в его адресное пространство).
- **Как надо:** процесс, открывший мастер, должен **пережить** мастер. В `localImagePrint.ts` скрипт открытия печатает `started` (сигнал «глагол сработал») и затем живёт (`Start-Sleep`), а вызывающий отвечает оператору по этому сигналу, не дожидаясь закрытия мастера.
- **Проверено:** с keep-alive окно «Печать изображений» видно **из другого процесса** (перечисление видимых окон через `EnumWindows`), то есть мастер действительно живёт.

## 3. Помощник мастера: два дефекта, из-за которых мастер не открывался никогда

- **`SHParseDisplayName` объявлена с ЧЕТЫРЬМЯ параметрами вместо пяти** (`pszName, pbc, &pidl, pcchEaten, pdwAttributes`): нативная функция читает `pcchEaten`/`pdwAttributes` из мусора → `E_INVALIDARG` → «Value does not fall within the expected range». С пятью параметрами все шаги проходят: `SHParseDisplayName` → `BindToObject` → `ILFindChild` → `GetUIObjectOf` → `QueryContextMenu` (115 пунктов).
- **`ConvertFrom-Json` в PowerShell 5.1 кладёт массив в конвейер ОДНИМ объектом**: `@(... | ConvertFrom-Json)` схлопывает его в один элемент, и приведение к `[string]` **склеивает пути пробелом** → оболочка получает несуществующий путь → тот же `E_INVALIDARG`. Рабочая форма: `ConvertFrom-Json -InputObject (...)` **без** `@()`.
- **Рядом:** весь C#-блок помощника должен быть **ASCII**: скрипт пишется в UTF-8 без BOM, а PowerShell 5.1 читает `.ps1` как ANSI — кириллица приезжает «кракозябрами» (в комментариях безвредно, в поиске заголовка окна — ломает). Кириллицу в C# писать **Unicode-escape'ами** (`"\u041F\u0435\u0447\u0430\u0442\u044C"`).

## 4. Глагол «Печать» у множественного выделения мастер не открывает

- На PC79 (26.11.2026) контекстное меню множественного выделения строится (115 пунктов), но мастер по нему **не открывается**: окно не появляется (проверено: перечисление видимых окон — пусто). Работает глагол «Печать» у **одного** файла.
- **Практический вывод:** один мастер на весь набор — не опора, а запасной путь; основной путь — по одному окну на файл (это ограничение глагола «Печать», о котором владелец знает).

## Где править

- `electron-app/src/main/services/photoPrint.ts` — общий шаг печати (диалог ИЛИ мастер, проверка принтера, внятный отказ, запасной путь).
- `electron-app/src/main/services/localImagePrint.ts` — глагол «Печать» у одного файла + keep-alive, чтобы окно мастера жило.
- `electron-app/src/main/services/photoPrintWizard.ts` — помощник мастера (5 параметров `SHParseDisplayName`, `-InputObject` без `@()`, ASCII-блок, ожидание закрытия окна мастера).
- Гейт: `electron-app/src/main/services/photoPrint.test.ts`.
