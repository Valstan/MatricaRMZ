# M242 — Тест обхода папок роняет джоб CI «unhandled ENOENT»: teardown сносит временную папку, пока её читает фоновый скан

**Область:** `electron-app/src/main/services/fileSearchFolderService.progress.test.ts` (тесты
обхода папок с прогрессом) — и вообще любой тест, который снимает временный каталог, пока его
ещё читает фоновая задача.

- **Симптом:** джоб CI «Test electron-app» падает при **полностью зелёных тестах**
  («Tests 3294 passed»), а в логе — `Serialized Error: { errno: -2, code: 'ENOENT',
  syscall: 'scandir', path: '/tmp/matrica-folder-progress-XXXX' }` и предупреждение
  «This might cause false positive tests». Красный джоб при зелёных проверках читать как
  «моя правка сломала» — не надо: это гонка в teardown.
- **Корень:** `afterEach` сносит временную папку (`rmSync(dir, { recursive: true, force: true })`),
  а фоновое сканирование папки ещё живо и читает её → `scandir` получает ENOENT как
  необработанное отклонение, и vitest роняет весь прогон.
- **Диагностика:** прогнать файл в одиночку — `corepack pnpm -F @matricarmz/electron-app exec
  vitest run src/main/services/fileSearchFolderService.progress.test.ts`. Зелёный (особенно
  3 раза подряд) ⇒ это перегруз/флейк, а не регресс: правка не при чём, джоб надо перезапустить
  (`gh run rerun <run-id> --failed`).
- **Лечение:** перезапуск джоба. Настоящая правка (teardown должен дождаться завершения
  фонового сканирования, а не сносить папку под ним) — отдельной правкой теста; сама по себе
  она вне зоны любой продуктовой правки.
- **Понято:** 27.11.2026, нить «подсказки номера» (промт КАРМАНА #155, PR **#2133**/#**#2134**):
  docs-only PR #2134 получил красный «Test electron-app» при 3294/3294 зелёных; локальный прогон
  файла — 3/3 зелёный, джоб после перезапуска зелёный.
- **Правило на будущее:** красный джоб при зелёных тестах и `ENOENT` по временной папке — это
  класс флейков teardown, а не твоя правка. Порядок: файл в одиночку → перезапуск джоба →
  (если повторяется) правка teardown отдельным PR.
