# M128 — «таймингозависимый флейк» оказался общим файлом: шим стоял только на браузерном таргете

**Область:** android-порт / тесты

- **Симптом (14.09.2026):** `android-app/src/core/boot.test.ts` → «без логина SyncManager честно отказывает» падает `expected true to be false` в полном прогоне пакета (примерно два раза из трёх на PC79), а в одиночку зелёный 5 из 5. Три недели числился перегрузом параллельного `-r test`.
- **Корень:** `androidShims` подменял `sessionSidecarStore` **только при `target: 'browser'`**. В vitest грузился настоящий десктопный модуль на sync `node:fs`, а `app.getPath` android-шима отдаёт фиктивный `/android/appData` — на Windows это `<диск>:\android\appData\MatricaRMZ\auth-session.json`, ОДИН файл на все параллельные воркеры. Логин любого тест-файла писал туда сессию, а `getSession` в другом файле подхватывал её fallback'ом «БД пуста → sidecar». Изоляция воркеров vitest тут бессильна: канал — файловая система, а не модульное состояние.
- **Диагностика:** флейк «зелёный в одиночку, красный в пачке» с *общим ресурсом вне процесса* выглядит ровно как перегруз. Отличать так: прежде чем списать на тайминг — искать общий файл. `app.getPath` шима отдаёт **не путь, а ключ** (комментарий в `shims/electron.ts`), поэтому любой невышимленный модуль с `node:fs` пишет по нему в корень диска. Проверка одной командой: после прогона тестов посмотреть, не появился ли `<диск>:\android\` (там же копится `userData/matricarmz.log` от невышимленного логгера — безобидно, но по тому же механизму).
- **Лечение:** шимить в vitest всё десктопное, чего на планшете нет (`sessionSidecarStore`, `watchdogHandshakeService`), а не только в браузерном бандле — тест обязан исполнять то же, что планшет. Сторож — `authOverShims.test.ts` «сессия не уезжает в файл: свежая БД не залогинена» (без шима честно краснеет).
