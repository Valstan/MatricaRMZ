# M237 — `gh pr merge --delete-branch` сносит рабочий worktree: `.git`-файл удалён, индекс пуст, а `git` начинает видеть главный клон

**Область:** PR-flow (`gh pr merge --squash --delete-branch`) в репо, где нитка ведётся в
отдельном worktree (`.claude/worktrees/<имя>`), а в главном клоне параллельно работает
соседняя линия.

- **Симптом:** после `gh pr merge --squash --delete-branch` в своей рабочей папке:
  `.git`-файл **исчез**, из дерева вычищены корневые dot-пути (`.claude/`, `.github/`,
  `.gitignore`, `.npmrc`, `.prettierrc.json`), остальное на месте; `git status` в этой папке
  показывает **состояние главного клона** (чужие незакоммиченные правки соседней линии!), а
  `git ls-files` отдаёт **0** — индекс пуст, весь репозиторий «удалён».
- **Корень:** gh не может удалить локальную ветку, пока она выбрана в worktree, и сначала
  пробует снести сам worktree (`git worktree remove`). Операция **не атомарна**: `.git`-файл и
  dot-пути к этому моменту уже удалены, а удаление остального обрывается на Windows на
  занятых файлах (процессы стенда держат `node_modules`) ⇒ остаётся «половина worktree».
- **Диагностика:** `git -C <worktree> rev-parse --git-dir` → указывает на `.git` **главного**
  клона вместо `.git/worktrees/<имя>`; `git -C <worktree> ls-files | Measure-Object -Line` → 0;
  `git worktree list` не показывает папку; `git -C <главный клон> status` при этом показывает
  правки **соседней линии** — это ловушка: `git add -A` в такой папке собрал бы чужую работу.
- **Лечение:** (1) создать админ-каталог `.git/worktrees/<имя>/` с `HEAD`
  (`ref: refs/heads/<ветка>`), `commondir` (`../..`), `gitdir` (путь к `.git`-файлу worktree) и
  сам `.git`-файл worktree (`gitdir: <путь к .git/worktrees/<имя>>`); (2) `git read-tree HEAD` —
  пересобрать индекс; (3) `git checkout HEAD -- <снесённые пути>` — вернуть dot-папки;
  (4) `git switch -c <новая ветка> origin/main` — перевести полосу на свежую базу.
  Альтернатива — `git worktree prune` + `git worktree add` заново (но тогда нужна установка
  зависимостей в новой папке).
- **Понятки:** 26.11.2026, полоса 6 (машина **PC79**), нитка «промт КАРМАНА #168», PR **#2101**
  (слит `041c56af`). Соседняя полоса в это время вела нитку #169 в главном клоне — из
  «половины worktree» её изменения были видны как свои, и любой `git add -A` в m7 забрал бы
  чужую работу. Сопутствующая деталь того же вечера: файл
  `better-sqlite3-multiple-ciphers/build/Release/better_sqlite3.node` держит **backend-процесс
  стенда** — и `rm` (в корзину), и копирование падают («The system call level is not correct» /
  «используется другим процессом»), пока стенд жив; Node-ABI возвращается только после
  остановки backend'а.
- **Правило на будущее:** `gh pr merge --squash` — **без** `--delete-branch`; ветку сносить
  руками (`git branch -d`) уже после того, как стенд погашен и файлы не заняты. Если
  `--delete-branch` уже применён: сначала проверить `rev-parse --git-dir` в своей рабочей
  папке — если он указывает на главный клон, **не выполнять** в ней `git add`/`commit`
  (это чужая линия), а починить починку выше.
