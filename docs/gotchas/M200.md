# M200 — PowerShell: список из одного элемента разворачивается в строку, `+` склеивает пути в один

**Область:** client-ops скрипты (`scripts/client-ops/kaspersky-matrica.ps1`, `matrica-ops.ps1`)

- **Симптом:** список доверенных программ уезжает в файл импорта Касперскому **склеенным в одну
  строку** вместо нескольких путей: вместо `C:\...\MatricaRMZ.exe` и `C:\...\Ярлык.lnk` в плане
  оказывается один путь вида `C:\...\MatricaRMZ.exeC:\...\Ярлык.lnk`. Импорт такой файл либо
  не принимает, либо молча делает вид, что доверенных программ нет. Поймано 12.11.2026 приёмкой
  помощника (`scripts/client-ops/kaspersky-matrica.tests.ps1`).

- **Корень:** **PowerShell разворачивает массив из одного элемента до строки** при выводе и при
  участии в операторе `+`. `$ourExes` (один путь) — это строка, а не массив; `$ourExes +
  $ourShortcuts` даёт конкатенацию двух строк, а не массив из двух элементов. Молча: тип не
  меняется, ошибок нет — просто элементы склеиваются. С двумя и более элементами то же выражение
  работает правильно, поэтому баг виден только на «чистой» машине, где программа установлена
  один раз.

- **Диагностика:** печатать не значение, а его тип и счёт:

  ```powershell
  $merged = $ourExes + $ourShortcuts
  Write-Host "merged=$merged type=$($merged.GetType().Name) count=$(@($merged).Count)"
  ```

  `type=String count=1` при ожидаемых двух путях — вот этот случай.

- **Лечение:** **всегда оборачивать в `@()`** — массив остаётся массивом при любом счёте:

  ```powershell
  $merged = @($ourExes) + @($ourShortcuts)
  ```

  То же касается любой конкатенации списков в этих скриптах: `@()` вокруг каждого операнда.

- **Чего НЕ делать:** не полагаться на «счёт элементов» как на защиту — список из одного элемента
  в PowerShell **не массив**, и проверка `if ($paths.Count -gt 0)` такой случай тоже не спасёт
  (`Count` у строки есть, но это длина строки).
