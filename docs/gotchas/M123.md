# M123 — префиксный гейт раздела захватил запись телеметрии вместе с чтением журнала

**Область:** права / гейт разделов

- **Симптом:** у оператора вне «Администрирования» в логе сервера на каждый визит вкладки — `unhandledrejection: … 'audit:add': Нет доступа к разделу «Администрирование»`. В журнале действий телеметрия за неделю есть у пятерых из десяти активных пользователей.
- **Корень:** в `sectionGate.ts` правило `['audit:', 'administration']` — самый длинный префикс отдал разделу весь namespace, а `audit:add` пишет каждый (`uiUsageLog`). `void promise` без `.catch` превращал отказ в ошибку лога.
- **Почему держалось:** гейт fail-open для незасеянных и суперадмина — владелец и тестовые стенды отказа не видят; телеметрия best-effort, её пропажа ничего не ломает на экране. С 3.1.0 (02.07) по 10.09.
- **Лечение:** правило сужено до `audit:list`; `.catch` в `uiUsageLog`. Сторож — `sectionGatePrefix.test.ts`.
- **Общая форма:** префиксное правило гейта годится, только если ВСЕ каналы namespace принадлежат одному разделу. Сквозной канал (запись телеметрии, lookup из чужих карточек) в таком namespace закрывается у всех, кто в раздел не входит.
- **Поймано:** 2026-09-10, обзор клиентских логов за двое суток.
