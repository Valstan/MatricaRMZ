# M165 — на проде не видно «answered», и это не сбой

**Область:** AI / логи прода

- **Симптом:** вопрос Ииваныча получает ответ, а в `journalctl -u matricarmz-backend-primary` нет ни строки `ai chat direct: answered`, ни `server engine: ...`. Выглядит так, будто отвечал кто-то другой (клиент, релей), и приёмка серверного звена «недоказуема».
- **Корень:** `backend-api/src/utils/logger.ts` в проде (`MATRICA_LOG_MODE=prod`) пропускает только `warn`/`error` — `logInfo` не пишет ничего. Строки про старт воркеров в журнале есть только потому, что печатаются до/вне этого режима.
- **Что делать:** успех серверного ответа доказывать не строкой «answered», а тремя фактами: (1) в журнале **нет** `server engine failed, falling back to deepseek` и нет 402; (2) ответ содержит реальные данные, которые сверяются прямым SQL; (3) движок в это время работает — `stat -c %Y /home/opencode/.local/share/opencode/opencode/opencode.db-wal` меняется каждые 1–5 с.
- **Вторая половина:** копия `opencode.db` **без `-wal`** показывает устаревшее состояние — сессии до чекпоинта живут в WAL, и по такой копии легко ложно заключить «движок не работал» (проверено 21.10: две копии подряд дали 0 сессий, а WAL в это время писал).
- **Поймано:** 2026-10-21, приёмка контура A на проде.
