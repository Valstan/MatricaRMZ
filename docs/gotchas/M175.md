# M175 — значение env-файла с пробелами без кавычек: systemd его съел, а bash-скрипты на боксе умирают

**Область:** прод / env / bash

- **Симптом:** на боксе любой скрипт, подключающий `/etc/matricarmz/matricarmz.env` (`set -a; . "$ENVFILE"`), печатает `line 69: -n: command not found` и — если у скрипта `set -e` — обрывается на этой строке. Бэкенд при этом работает: systemd свой `EnvironmentFile` разобрал нормально.
- **Корень:** `AI_SERVER_ENGINE_ROTATE_CMD=sudo -n /usr/local/lib/neural/tunnel-watchdog.sh --rotate-next` — значение с пробелами без кавычек. `EnvironmentFile` в systemd допускает такое (и **снимает** кавычки при разборе), а bash при подключении файла видит `sudo` с аргументами и вторую «команду» `-n`. Один файл — два парсера, и они не одинаковы: env-файл читают ещё сторож туннеля (алерты, выбор вопроса), наши ops-скрипты и `install.sh`.
- **Лечение:** значение с пробелами — **в кавычках**: `AI_SERVER_ENGINE_ROTATE_CMD="sudo -n /usr/local/lib/neural/tunnel-watchdog.sh --rotate-next"`. Так файл читают оба парсера (systemd кавычки убирает, bash — тоже). Проверка на месте: `bash -c 'set -euo pipefail; set -a; . /etc/matricarmz/matricarmz.env; set +a; echo ${#AI_SERVER_ENGINE_ROTATE_CMD}'` — должно быть числом, не ошибкой; и `/proc/<pid>/environ` у бэкенда обязан показать команду **без** кавычек (это доказательство, что systemd разобрал верно). `install.sh` теперь сам линтует env-файл на «значение с пробелами без кавычек».
- **Поймано:** 2026-10-25, при сборе метрик для Мозга: скрипт с `set -euo pipefail` упал на подключении env — движок и сторож к тому моменту работали сутки.
