# M190 — Сборка electron-builder на Windows падает на распаковке winCodeSign: нужны симлинки, Developer Mode не помогает

**Область:** [M190](#m190--сборка-electron-builder-на-windows-падает-на-распаковке-wincodesign-нужны-симлинки-developer-mode-не-помогает)

- **Симптом:** `electron-builder --win --x64` на Windows-разработчике доходит до шага «packaging», собирает `win-unpacked` — и падает:
  ```
  ⨯ D:\...\app-builder.exe process failed ERR_ELECTRON_BUILDER_CANNOT_EXECUTE
    ERROR: Cannot create symbolic link : ...\winCodeSign\...\darwin\10.12\lib\libcrypto.dylib
    ERROR: Cannot create symbolic link : ...\libssl.dylib
    command='7za.exe' x -snld -bd '...\winCodeSign-2.6.0.7z' '-o...\winCodeSign'
  ```
  Подпись в этот момент ещё не начиналась — падает **подготовка инструментов**. Проверено на PC79 04.11.2026.

- **Корень:** архив `winCodeSign-2.6.0.7z` содержит **симлинки** (для darwin-инструментов), и `7za` создаёт их на Windows при распаковке. Создание симлинка на Windows требует привилегии `SeCreateSymbolicLinkPrivilege`, которая есть у администраторов, но **отсутствует у фильтрованного токена** (UAC). Отсюда `exit status 2`.

- **Developer Mode НЕ помогает.** Включённый `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\AppModelUnlock\AllowDevelopmentWithoutDevLicense=1` на Windows 11 26300 **не** даёт непривилегированного создания симлинков — проверено: `New-Item -ItemType SymbolicLink` продолжает отвечать «Для этой операции требуется привилегия администратора». Второй рычаг `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\SymlinkEvaluation=1` тоже включён и тоже не помогает по той же причине: привилегия выдаётся при повышении прав, а не через реестр.

- **Лечение — единственное рабочее: запустить сборку с повышенными правами.** Симлинки создаются, `winCodeSign` распаковывается, сборка идёт до конца.
  ```powershell
  Start-Process powershell -ArgumentList '-NoProfile','-ExecutionPolicy','Bypass','-File','build-elevated.ps1' -Verb RunAs
  ```
  На GitHub-раннере проблемы нет: там процесс идёт с повышенными правами, поэтому релизные сборки в CI идут штатно (проверено по логам релизов v3.100–v3.103 и по своему прогону).

- **Диагностика:** «Cannot create symbolic link» в логе electron-builder = **не** проблема сертификата и **не** проблема конфигурации сборки. Не тратить на неё время: либо повысить права, либо builds на CI.

- **Побочная польза:** этим же elevated-прогоном на PC79 впервые проверена **полная** сборка с подписью — 13/13 артефактов подписаны своим ключом (`signtool verify /pa /v` → `Issued to: MatricaRMZ Test Root CA`), и сборка **без** сертификата тоже проходит (`EXITCODE=0`, подписанных нашим — 0). До этого локальная сборка обрывалась на winCodeSign, и поведение «без ключа» оставалось непроверенным.
