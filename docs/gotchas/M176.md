# M176 — «зеркало застыло»: сверка EAV с `erp_*` по английскому имени колонки даёт ложную тревогу

**Область:** EAV / зеркало / методика сверки

- **Симптом:** зеркало `erp_engine_cards` не менялось с 22.10 14:59, и сверка «по EAV» показывает 400 двигателей на заводе против 382 в зеркале, отгрузок 1615 против 1587. Выглядит как тихая поломка триггера: ошибок в журнале нет, карточки «не приезжают».
- **Корень:** сверка искала EAV-атрибуты по **английским** именам колонок зеркала (`arrival_date`, `status_customer_sent_date`). В `attribute_defs` имена **русские** — «Дата прихода», «Дата Отправлен заказчику», «Дата Принято заказчиком», «Дата Принят на хранение». Запрос по английскому имени возвращал ноль строк, и «400» было посчитано по другому (неверному) набору. По русским именам: `Дата прихода` — 1903, в зеркале `arrival_date` — 1903; «на заводе» — 382 и 382; живых двигателей 2566, живых строк зеркала 2566, отсутствующих в зеркале 0. Зеркало не двигалось потому, что с 22.10 менялись значения, которых в нём нет, — это норма, а не застой.
- **Лечение:** сверять EAV с зеркалом **только по именам из `attribute_defs`** (их можно получить: `select ad.name from attribute_defs ad where ad.entity_type_id = <тип>`), а не по догадке о схеме; и всегда помнить, что `erp_engine_cards` содержит и удалённые двигатели (2954 строки против 2566 живых) — считать только через join с живыми `entities`.
- **Поймано:** 2026-10-25, при разборе ответа Ииваныча на вопрос «сколько двигателей на заводе»: тревога оказалась ошибкой методики, а не поломкой.
