# M164 — движок контура A отвечает `failed` за 2 секунды (403 free-тира)

**Область:** AI / движок / контур A

- **Симптом:** сессия серверного движка (`opencode` на проде, контур A) завершается за ~2 секунды с `idle.outcome = failed`; в логе бэкенда только `server engine: no answer {"failure":"движок вернул failed"}` — без причины. Модель при этом жива: та же сессия **без** `permissions` отвечает нормально.
- **Корень:** free-тир движка отдаёт `403 provider.auth` «OpenCode's free tier can only be used from within OpenCode», если в правах сессии запрещены **файловые** инструменты — `read`, `glob`, `grep`, `list`. Стандартные запреты (`shell`, `bash`, `edit`, `write`, `patch`, `webfetch`, `websearch`) и «прочие» (`multiedit`, `apply_patch`, `task`, `skill`, `todowrite`) проходят. Проверено перебором на живом движке v2.0.32: `[read,glob,grep,list]` → 403 за 2 с, любой другой набор → `succeeded`.
- **Вторая половина грабли (диагностика):** движок кладёт ошибку и в `idle`, и в `assistant`, а в массиве сообщений `idle` часто идёт **первым**. Кто читает ошибку «по порядку сообщений», получает пустое «failed» и ищет причину вслепую — брать ошибку с любого сообщения (`serverEngine.ts` → `failureOf`).
- **Что делать:** файловые инструменты в правах сессии не запрещать (остаточный риск невелик: движок под своим пользователем, env бэкенда `root:valstan 640` ему не читается). Сторож — `serverEngine.test.ts` («read нельзя запрещать — free-тир отдаёт 403»).
- **Поймано:** 2026-10-21 на приёмке контура A на проде (вопрос «сколько двигателей в работе?» → `failed` через 2 с).
