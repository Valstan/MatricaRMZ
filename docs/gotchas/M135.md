# M135 — право, выдаваемое поимённо, нельзя держать на цикле «всё админу» и на одном клиентском гейте

**Область:** [M135](#m135--право-выдаваемое-поимённо-нельзя-держать-на-цикле-всё-админу-и-на-одном-клиентском-гейте)

- **Симптом (владелец, 15.09.2026):** «доступ к редактированию ведомостей вразнобой — слишком много людей допущено, видимо, администраторы». Право `work_sheets.edit` ни одна операторская роль не давала, но admin / superadmin / легаси `user` получали его молча: `defaultPermissionsForRole` раздаёт ВСЕ коды циклом и вычитает короткий список.
- **Корень (два слоя).** (1) Новый код права по умолчанию попадает в «всё админу» — «выдаётся поимённо» держится только если код явно исключён из цикла (образец — `audit.view`). (2) Строка ведомости — запись `operations` типа `repair_history_entry`, уезжает обычным синком; гейт `work_sheets.edit` стоял только в IPC клиента, а серверная политика (`ledgerAuthz`) видела лишь `operation_type` и требовала `operations.edit` (есть у мастеров), причём admin / `user` обходили requirement вовсе. Отличить строку ведомости от ручной записи можно только по `meta_json` (`entryType: 'sheet'`).
- **Диагностика.** У «поимённого» права проверять три места: цикл ролей в backend `auth/permissions.ts`, IPC клиента и серверный гейт синка. Один зелёный гейт из трёх — не гейт. Для строк, которые пишутся через синк, спросить: «по какому полю сервер узнаёт эту строку?» — если только по `operation_type`, а различие в meta, сервер её не узнаёт.
- **Лечение.** Код исключён из цикла (`= r === 'superadmin'`), сторож в `WorkSheetsPage.guard.test.ts`; `ledgerWriteRequirement` получил `operationMetaJson` и `isWorkSheetRowWrite`; в `ledgerAuthzGuard` — универсальный backstop ДО ветки `!operatorScoped` (`forbidden:work_sheet_row`), права грузятся и для admin, если в батче есть такая строка. Снятие у уже существующих — скрипт `perm:revoke-work-sheets` (явный `allowed=false`, не удаление строк).
- **Смежное:** M123 (гейт по префиксу канала), G29 (необратимое на проде — с подтверждением в том же ходе).
