# M220 — Релиз нарезан и опубликован на GitHub, а парк остался на прежней версии: артефакты не залиты на прод

**Область:** релизный процесс, раздача обновлений, `/opt/matricarmz/updates`

- **Симптом:** бэкенд на проде уже новой версии (`/health` → `3.135.0`), релиз на GitHub
  опубликован (`v3.135.0`, инсталлятор и `latest.yml` в ассетах), а весь парк сидит на 134 и
  «не обновляется»: `/updates/latest-meta?current=3.134.0` отдаёт 134, `/dispatcher/update-plan`
  отвечает `up-to-date`, `/updates/file/MatricaRMZ-Setup-3.135.0.exe` → 404.

- **Причина:** в релизном процессе (`AGENTS.md` §Release process, шаг 7) пропущен сам выкат
  артефактов на прод. Шаги 4–6 (выкат бэкенда, миграции) прошли, тег `v3.135.0` нарезан и
  GitHub Actions собрал релиз — а копирования `.exe` + `.blockmap` + `latest.yml` в
  `/opt/matricarmz/updates` на боксе не было. Сервер честно раздаёт то, что лежит на диске:
  `latest.json` → `3.134.0`, и клиенты правда «не видят обновления».

  Ловушка: клиент НЕ ходит за релизом на GitHub сам — каскад начинается с серверного
  `latest-meta`. Публикация релиза на GitHub не означает, что парк его увидит. Если сервер
  отдаёт версию ≤ текущей, весь каскад (LAN → Yandex → GitHub) не запускается вовсе.

  Следы, по которым узнать: `ls -lt /opt/matricarmz/updates/` (нет `.exe` нужной версии),
  `cat /opt/matricarmz/updates/latest.json` (старая версия), `curl /updates/status`
  (`latest.version` старее релиза). Второй след: `latest.yml` на проде может быть от ДРУГОГО
  релиза (при выкате 3.134.0 остался манифест 3.133.0) — значит, шаг 7 выполняли не полностью.

- **Диагностика:**
  1. `curl -sS https://<прод>/updates/status` → `latest.version`, `lastError`;
  2. `curl -sS 'https://<прод>/updates/latest-meta?current=<версия_клиента>'` → что сервер отдаёт;
  3. `curl -sS 'https://<прод>/dispatcher/update-plan?platform=windows&current=<версия_клиента>'`
     → `action: "up-to-date"` вместо `"update"`;
  4. на боксе: `ls -lt /opt/matricarmz/updates/`, `cat /opt/matricarmz/updates/latest.json`.

- **Лечение:** долить артефакты по шагу 7 релизного процесса — скачать на бокс (CDN оттуда
  отдаёт нормально), сверить `sha512` инсталлятора с манифестом, перенести `mv` в пределах одной
  ФС, обновить `mtime` (`touch`), дождаться, пока `latest.json` совпадёт с `.exe` по размеру
  (пересев раз в минуту), и принять: `/updates/status` → нужная версия, `lastError: null`,
  инсталлятор и `.blockmap` → 200, `dispatcher/update-plan` → `action: "update"`. Для планшетов —
  отдельно `.apk` в `updates/android/` (версия в имени файла).

  Проверка, что релиз действительно доехал до парка: `/dispatcher/update-plan` с текущей версией
  парка должен вернуть `action: "update"` и целевую версию.
