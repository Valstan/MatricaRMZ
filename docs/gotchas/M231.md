# M231 — Имя прода и базы — `matricarmz`: ошибка в одну букву даёт два разных «прод сломался»

**Область:** работа с продом — SSH-алиас и имя базы (`~/.ssh/config`, `backend-api/src/database/db.ts`). Не про код программы: про то, как пишут и проверяют команды доступа.

- **Симптом:** два разных сообщения от живого и исправного прода, оба выглядят как авария: (1) `ssh matricrmz` → `Could not resolve hostname matricrmz` (как будто упала сеть или сработал fail2ban); (2) `sudo -u postgres psql -d matricrmz -At -c '…'` → `FATAL: database "matricrmz" does not exist` (как будто упала или переехала база). При этом бэкенд отвечает `{"ok":true,"version":"3.147.0"}`, артефакты на месте, клиенты работают.
- **Корень:** в проекте имя — **`matricarmz`** (SSH-алиас, база, каталоги `/opt/matricarmz`, `/etc/matricarmz`, юниты `matricarmz-backend-*.service`; имя базы — дефолт в коде: `database: process.env.PGDATABASE ?? 'matricarmz'`). Написание **без** «a» (`matricrmz`) встречается в устаревшей строке `PGDATABASE=matricrmz` в `backend-api/.env` в дереве на боксе — такого имени в PostgreSQL просто нет, поэтому psql честно отвечает «нет такой базы».
- **Диагностика (до вывода «прод сломался»):** (1) `sudo -u postgres psql -lqt` — список баз (в списке только `matricarmz` + шаблоны ⇒ база на месте, просто имя другое); (2) `select count(*) from client_settings` в найденной базе — данные живы; (3) `select datname, count(*) from pg_stat_activity where backend_type = 'client backend' group by datname` — к какой базе подключён живой бэкенд (есть соединения ⇒ бэкенд БД видит); (4) `ssh -G <алиас> | Select-String '^(hostname|port|user) '` — эффективная конфигурация подключения **без сети**: если в выводе `hostname` совпал с опечатанным именем, блок `Host` не найден, сеть тут ни при чём.
- **Лечение:** использовать живое имя (`ssh matricarmz`, `psql -d matricarmz`); при «не резолвится» — сначала `ssh -G`, при «нет базы» — сначала `psql -lqt`. Никаких «починок» прода не требуется.
- **Понятки:** 26.11.2026, закрытие сессии после выката v3.147.0. Запрос к БД был написан по памяти (без «a») и упал с «database does not exist» — выглядело как «прод сломан», пока не сверили список баз и живые соединения `pg_stat_activity` (5 соединений с `matricarmz` ⇒ бэкенд в порядке). Проверено также: `psql -d matricarmz` отдаёт 95 строк в `client_settings`.
- **Правило на будущее:** **«Could not resolve hostname» и «database does not exist» — это про ИМЯ, а не про поломку.** Сверяй имя (список баз, `ssh -G`) раньше, чем объявлять аварию; и записывай команды в доки из канона, а не по памяти.
