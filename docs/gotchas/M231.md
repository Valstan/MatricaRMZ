# M231 — После squash-merge гейт закрытия сессии красный: «branch has no upstream — never pushed», хотя работа уже в `main`

**Область:** git-процесс репозитория — PR-flow (ADR-0002, squash-merge), sync-гейт `scripts/git_sync_check.ps1 -Gate` (шаг `/close_session` §9.5), уборка локальных веток (`/close_session` §4).

- **Симптом:** PR слит (`gh pr merge --squash --delete-branch`), в `git log origin/main` твой коммит есть, рабочее дерево чистое — а `powershell -ExecutionPolicy Bypass -File scripts/git_sync_check.ps1 -Gate` печатает `[git-sync WARNING] session NOT synced - close blocked: branch 'fix/…' has no upstream - never pushed` и выходит с кодом 1. Сессия формально не закрывается, хотя на GitHub всё есть. Второй симптом того же класса: `git branch -d <имя>` отказывается удалять слитую ветку («not fully merged»), хотя PR давно в `main`.
- **Корень (три складываются):** (1) **squash-merge не делает твои коммиты предками `main`** — merge-коммит новый, с одним родителем, ⇒ `git branch --merged origin/main` **не показывает** твою ветку, и `git branch -d` отказывается её удалять (инструкция `/close_session` §4 в этом случае не срабатывает); (2) **`--delete-branch` удаляет ветку на origin** ⇒ у локальной ветки пропадает upstream (`@{u}` → ошибка), и гейт видит «ветка никогда не пушилась»; (3) гейт честно меряет «есть ли незапушенная работа», но **не различает** «не пушилась» и «удалена после merge» ⇒ красный статус в обоих случаях.
- **Диагностика:** (1) `git log --oneline origin/main -3` — есть ли твой squash-коммит; (2) `git diff --stat <твоя-ветка> origin/main` — если в diff только чужие файлы соседних полос, твоя работа в `main` целиком; (3) `git branch -vv` — у ветки `upstream: gone` ⇒ это удалённая ветка после merge, а не непушенная работа; (4) `git log origin/main..<твоя-ветка>` — пусто ⇒ незакоммиченного в GitHub нет.
- **Лечение:** (1) удалить локальную ветку принудительно — `git branch -D <имя>` (только после сверки diff, как в диагностике); (2) перевести рабочее дерево на базу от свежего `origin/main` — `git checkout -b base/<линия>-<дата> origin/main` (ветку `main` занимает основное дерево репозитория — в worktree её не checkout'ить); (3) прогнать `scripts/git_sync_check.ps1 -Gate` ещё раз — теперь зелёный: ветка с upstream, `ahead = 0`.
- **Понятки:** 2026-11-26, полоса 2 (worktree `.claude/worktrees/m2`), промт КАРМАНА #141 — PR #2048 слит squash'ем (`7b8c6b5e`), гейт закрытия ругался на уже удалённую ветку `fix/history-panel-buttons-left-2026-11-25`.
- **Правило на будущее:** **после squash-merge локальная ветка — мусор, а не работа.** Не «не пушилась», а «уже в `main`»: сверяй diff с `origin/main`, удаляй принудительно, гейт перезапускай на базовой ветке от `origin/main`. Красный гейт ≠ недоделанная работа — сначала прочитай текст сообщения: он различает «грязное дерево», «нет upstream» и «есть непушенные коммиты».
