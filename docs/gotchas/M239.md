# M239 — индекс грабель у потолка: новая грабля не влезает, потому что гейт требует строку за каждым файлом

**Область:** память репозитория — `docs/GOTCHAS.md` (индекс грабель) и `docs/COMPLETED.md`
(done-индекс) при заведении новой записи.

- **Симптом:** грабля заведена — файл `docs/gotchas/M<N>.md` написан, а строка в индексе
  `docs/GOTCHAS.md` не влезает: индекс весит 51 062 байт при потолке 51 200 (сторож
  `electron-app/src/main/services/docsMemoryLayout.guard.test.ts`: `INDEX_LIMIT_BYTES = 50 * 1024`),
  а строка с кириллицей весит ~200 байт. Гейт падает на `индекс не толще потолка`.
  Тот же класс был и в `docs/COMPLETED.md`: на 26.11.2026 он стоял на 153 571 байте
  при потолке 153 600 — запись нитки влезла только потому, что была сокращена до одной
  строки таблицы.
- **Корень:** **индекс и файл записи связаны гейтом**: «каждый файл записи попал в индекс»
  и «за каждой строкой индекса стоит файл записи». Значит завести граблю нельзя, не
  тронув индекс: без строки гейт упадёт на «файл записи не попал в индекс», со строкой —
  на потолке байт. Ротации индекса нет и быть не может: архивные записи не обязаны иметь
  файл в `docs/gotchas/`, а правило требует обратного. Потолок поднимать нельзя — он
  держит форму, а не память агента.
- **Диагностика:** `node -e "const fs=require('fs');const t=fs.readFileSync('docs/GOTCHAS.md','utf8');console.log(Buffer.byteLength(t.replace(/\r\n/g,'\n'),'utf8'))"`
  — сторож мерит **содержимое** (переводы строк нормализуются), а не байты на диске:
  на Windows разница CR/LF съедает ещё десятки байт. Строка индекса весит ~180–210 байт
  с кириллицей ⇒ запас меньше этой величины означает «новую граблю не завести».
- **Лечение:** **сокращать формулировки существующих строк, а не поднимать потолок**
  (прямо сказано в шапке индекса). Берутся самые длинные строки (медиана ~210 байт,
  максимум ~314) и ужимаются до симптома-якоря: что видно и по чему отличить — детали
  лечения остаются в самом файле грабли. Проверка — тот же сторож: `corepack pnpm
  -F @matricarmz/electron-app test` (файл `docsMemoryLayout.guard.test.ts`).
- **Понятки:** 26.11.2026, полоса 1, нитка «промт КАРМАНА #144» (живая приёмка действий
  с файлами на Верстаке). Находка вскрылась, когда нитка захотела завести СВОЮ граблю и
  не смогла: индекс грабель был на последнем байте, и запись без сжатия чужих строк
  роняла гейт. Второй индекс (`COMPLETED.md`) был на 153 571 из 153 600 — запас 29 байт;
  он с тех пор подрос (ротация `scripts/docs/rotate-completed-index.mjs`), а индекс
  грабель — всё ещё у потолка: 138 байт запаса против ~200 байт на строку.
- **Правило на будущее:** упираемся — **сокращаем формулировки, а не поднимаем потолок**.
  Новая грабля = файл `docs/gotchas/M<N>.md` + строка индекса + сжатие длинных строк
  индекса под её размер; если места нет совсем — это решение владельца про ротацию
  индекса, а не повод поднять байты. Проверка места — ДО написания файла грабли.
