# M111 — один фильтр, три трактовки: цепочка провенанса, сложенная в каждом отчёте заново

**Область:** отчёты / EAV-провенанс

- **Симптом:** оператор выбирает одного и того же заказчика в двух отчётах по двигателям и получает разные наборы. Ошибки нет, оба отчёта «работают», расхождение видно только если сверять построчно. В третьем отчёте — третий ответ.
- **Корень:** заказчик у двигателя в карточке обычно не заполнен, он выводится по цепочке `двигатель → его договор → заказчик договора`. Цепочку каждый отчёт складывал у себя: «Движение по заказчикам» — с фолбэком на договор и с разбором `contract_sections`; «Двигатели» — только поле карточки; «Наряды» — без `counterparty_id` у двигателя и без разделов у договора, по одному легаси-`customer_id`. Три места, три ответа, ни одного признака поломки: тесты у каждого свои и каждый зелёный относительно собственной трактовки.
- **Почему не ловится гейтами:** отличается не результат вычисления, а **область** — какие данные вообще попадают в отбор. Типы одинаковые, значения валидные, счёт сходится. Такое расхождение видит только сверка двух отчётов на одних данных, и её никто не делает, пока не спросит владелец.
- **Диагностика:** грепать по обоим концам цепочки, а не по имени поля — `counterparty_id`, `customer_id`, `parseContractSections` — и смотреть, сколько раз рядом стоит фолбэк. Число разных написаний = число трактовок. Проверять на данных, где промежуточное звено пустое (карточка без заказчика при известном договоре): на полностью заполненных строках все варианты дают одно и то же и расхождение не проявляется.
- **Лечение:** одна функция на цепочку, все читатели через неё (`resolveEngineCounterpartyId` + `buildContractCounterpartyIndex` в `electron-app/src/main/services/reports/context.ts`), и тест, который прогоняет **разные отчёты на одной фикстуре** и требует одинакового отбора — иначе четвёртый отчёт снова сложит цепочку сам.
- **Поймано:** 2026-09-07 при постановке каскада фильтров отбора. Решение владельца: заказчик ищется всеми доступными путями, и одинаково везде, где по смыслу это одно и то же понятие.
