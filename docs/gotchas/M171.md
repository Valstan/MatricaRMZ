# M171 — алерты Telegram настроены, а не уходят: `MATRICA_TELEGRAM_ENABLED=true` против проверки `= "1"`

**Область:** прод / уведомления

- **Симптом:** в `/etc/matricarmz/matricarmz.env` `MATRICA_TELEGRAM_ENABLED=true`, бот и chat_id заданы, но ни одно уведомление не приходит — в том числе аварийное «движок не отвечает».
- **Корень:** сторож (и любой скрипт, копирующий эту проверку) сравнивает строго с `"1"`: `[ "$MATRICA_TELEGRAM_ENABLED" = "1" ]`. Значение `true` (как и `yes`/`on`) не проходит — ветка алерта тихо не выполняется.
- **Лечение:** принимать несколько форм: `case "${…}" in 1|true|yes|on) ;; *) exit 0 ;; esac`; у сторожа держать режим `--test-alert` и **проверять доставку** тестовым сообщением при установке, а не полагаться на «в конфиге включено».
- **Поймано:** 2026-10-24, при установке сторожа: тестовое сообщение не ушло с первого раза.
