# M214 — `detached`/`windowsHide` у Node убивают графическое окно PowerShell: скрипт стартует и сразу уходит

**Область:** клиент (electron-app) · скрипты обслуживания · запуск процесса

- **Симптом:** оператор жмёт плитку «Скрипты обслуживания» (или кнопку «Открыть окно обслуживания»). Программа честно рапортует: «Открываю окно обслуживания — оно появится через несколько секунд». Архив распакован (файлы в `<userData>\Обслуживание` обновлены). **Окна нет.** Никакой ошибки — ни в интерфейсе, ни в логах: процесс PowerShell стартует и уходит с кодом 0 за секунду.
- **Корень:** флаги запуска в Node. `spawn(..., { detached: true })` на Windows поднимает процесс с `DETACHED_PROCESS`, `windowsHide: true` — с `CREATE_NO_WINDOW`. **В обоих случаях у процесса нет консоли, и графическое окно WinForms не показывается** (при `detached` процесс к тому же завершается сразу). Проверено на живом клиенте 19.11.2026 перебором вариантов: `detached:false + windowsHide:false` — окно «Матрица РМЗ — обслуживание машины» видно; `detached:false + windowsHide:true` — процесс жив, окна нет; `detached:true` — процесс мёртв, код 0.
- **Лечение:** спрятать консоль средствами самого PowerShell, а не флагами Node: `powershell.exe -sta -NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File …`, в `spawn` — `stdio: 'ignore'` и **без** `detached`/`windowsHide`.
- **Почему это молчало:** успех проверялся по факту «процесс запущен» (`spawn` не бросает исключения, а `launchClientOps` возвращает `ok`), а окно скрипта — отдельный процесс, который клиент не видит. Ошибка была видна только оператору («ничего не открылось») и только на живой машине.
- **Правило (главное):** окно, которое клиент обещает показать, проверяется **по факту появления окна**, а не по факту успешного `spawn`. Для GUI-скриптов на Windows: сначала перечислить видимые окна (`EnumWindows` + `GetWindowText` + `IsWindowVisible`) и убедиться, что заголовок нужный; `Get-Process … MainWindowTitle` годится не всегда — при скрытой консоли процесс может не считать окно основным.
- **Замечено:** 19.11.2026, приёмка требования владельца «по щелчку по плитке сразу открывается окно скрипта». Попутно выяснилось, что старый путь («Открыть окно обслуживания» в справочном окне) был сломан так же — то есть окно обслуживания не открывалось НИКОГДА, с момента его появления.
