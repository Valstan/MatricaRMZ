# M127 — колонка реплики через drizzle-файл: клиент уходит в self-heal и «аварийное обновление»

**Область:** клиент / миграции реплики

- **Симптом (стенд 13.09.2026, E3 плана bom-simplify):** после добавления `electron-app/drizzle/0026_*.sql` с `ALTER TABLE erp_nomenclature ADD COLUMN …` клиент не открывает окно: в `matricarmz.log` — `sqlite init failed … Failed to run the query`, затем «DB self-heal LOOP detected … entering emergency update mode». CDP отдаёт браузерный эндпоинт без page-таргетов.
- **Корень (два слоя):** (1) drizzle-мигратор клиента гоняется на **всех** базах, включая долгоживущие, где колонку уже добавила цепочка версий `clientSchemaMigrations.ts` или `alignSchemaWithServer` — `ADD COLUMN` в SQLite без `IF NOT EXISTS`, второй раз падает «duplicate column», транзакция откатывается, `index.ts` перестраивает базу; (2) файл без `--> statement-breakpoint` между операторами падает и на свежей базе — `better-sqlite3` исполняет по одному оператору.
- **Лечение:** колонку реплики добавлять **только** идемпотентными PRAGMA-обёртками: шаг цепочки в `clientSchemaMigrations.ts` (`from/to`, `PRAGMA table_info` → `ALTER` при отсутствии) и дубль в `ensureClientSchemaParity` (`migrate.ts`) для баз, минующих цепочку. Drizzle-файлы реплики — для новых таблиц (`CREATE TABLE IF NOT EXISTS`), с breakpoint'ами между операторами. Правило записано в шапке `migrate.ts` — читать её до того, как класть `.sql`.
- **Смежное:** колонка легаси-таблицы (список `LEGACY_SCHEMA_SNAPSHOT_TABLES`) двигает хеш снимка старым сборкам (<3.5.0), а они на это перестраивают базу; такие колонки прячутся из легаси-снимка через `LEGACY_HIDDEN_COLUMNS` (`diagnosticsSchemaService.ts`).
