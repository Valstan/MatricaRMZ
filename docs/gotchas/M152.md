# M152 — Watchdog «not an .exe» на каждой закачке: валидация смотрит staging-путь, а не финальное имя

**Область:** [M152](#m152--watchdog-not-an-exe-на-каждой-закачке-валидация-смотрит-staging-путь-а-не-финальное-имя)

- **Симптом (12.10.2026, прод):** цикл `app_missing` → `recovery_failed: no valid installer: downloaded installer invalid: not an .exe: …\matricarmz-watchdog-3.73.0.exe.part` каждые ~15 мин на машине со снесённым приложением (клиент 3.64.0). Закачка по HTTP 200 проходит, сервер отдаёт целый installer (`/updates/status` без ошибок, размер на диске = манифесту) — режет локальная валидация.
- **Корень:** PR #469 перевёл закачку на схему «качаем в `<имя>.exe.part`, валидируем, переименовываем», а вызов сменился с `validateInstaller(dst, …)` на `validateInstaller(tmp, …)` — суффиксная проверка `.exe` стала видеть только `.part` и резать КАЖДУЮ закачку. Сломан с 04.08.2026: все восстановления сторожем с тех пор падали. Добивка: ветка «нет installer'а» не increment'ила `FailCount`, и backoff 30м–24ч её не касался — ~137 МБ качались вхолостую каждый проход.
- **Лечение:** суффикс проверяется по финальному имени (`TrimSuffix(path, ".part")`, содержимое — по переданному пути); провал поиска installer'а считается в backoff. Сторож — `watchdog/validate/validate_test.go` (staging-имя проходит, голый `.part`/`.txt`/`.bak` — нет; плюс контент-проверки и `backoffFor`), гейт — шаг `go test ./validate/` в `watchdog-build.yml` (подпакет portable: package main под линуксовым GOOS не собирается, а windows-бинарь тестов на линукс-раннере падает `exec format error`).
- **Правило:** временный файл сборки/закачки либо оканчивается на `.exe` (приём апдейтера: `deltaAssemblyTempPath` → `.delta-new.exe`, иначе валидатор режет), либо валидатор знает про staging-суффикс явно. Смена «куда качаем» без правки «что проверяет имя» — тот же класс, что чинился в апдейтере (`installerNaming.ts`). Проверять класс поиском всех вызовов валидатора, а не только изменённой строки.
