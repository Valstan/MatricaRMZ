# M209 — Стендовый клиент не открывает окно вовсе: Node-ABI у двух нативных модулей, а не у одного

**Симптом.** `start-electron.ps1` рапортует «OK: electron.exe PID=…», процессы `electron.exe` живые, CDP-эндпоинт отвечает — но `GET /json/list` отдаёт **пустой список**, ни одной вкладки. Окна нет: ни авторизации, ни приложения. В журнале клиента (`<userData>/matricarmz.log`) — обрыв на старте:

```
sqlite init failed, attempting self-heal: Error: The module '…better_sqlite3-multiple-ciphers…\build\Release\better_sqlite3.node'
was compiled against a different Node.js version using NODE_MODULE_VERSION 137. This version of Node.js requires NODE_MODULE_VERSION 148.
```

…а потом «DB self-heal LOOP detected … entering emergency update mode» — приложение уходит в аварийный режим и окно не создаёт.

**Корень.** Нативных модулей, требующих под ABI Electron, в клиенте **два**, а не один: `better-sqlite3` **и** `better-sqlite3-multiple-ciphers` (второй — сборка с шифрованием, тянется из `electron-app/package.json`). Оба лежат в pnpm-store как hard link'и, и оба собираются под **Node-ABI** (137) — того, что нужен vitest. Electron 43 ждёт **148**. Подмена ABI только у `better-sqlite3` даёт картину «всё починили», а окно всё равно не открывается: клиент падает уже на втором модуле, в том же месте.

**Как лечится.** Подменять ABI **у обоих** пакетов, одной пачкой:

1. взять сохранённый набор для Electron: `.verifier-electron/abi-electron-20261022/` — там **два** файла: `better_sqlite3.node` и `better_sqlite3.mc.node`;
2. положить их в `node_modules/.pnpm/better-sqlite3@…/…/build/Release/better_sqlite3.node` и `node_modules/.pnpm/better-sqlite3-multiple-ciphers@…/…/build/Release/better_sqlite3.node`;
3. после прогона вернуть Node-ABI (`.verifier-electron/abi-backup/`) — иначе `pnpm -F @matricarmz/electron-app test` упадёт на `NODE_MODULE_VERSION`.

Файл в `node_modules/.pnpm` — **hard link** на файл в pnpm-store. Простая перезапись меняет и store: чужая машина (или другая сессия на этой) получит чужую ABI. Безопасный ход — **сначала убрать** ссылку (переместить файл в корзину), потом положить свой: store остаётся нетронутым.

**Тот же корень через `install-app-deps` (23.11.2026).** `corepack pnpm -C electron-app exec electron-builder install-app-deps` пересобирает нативные модули под Electron-ABI **одной командой** (удобно — своп вручную не нужен) и тем же меняет общий pnpm-store: `better-sqlite3` — один инстанс на `electron-app` и `android-app`, и после пересборки **тесты `android-app` (86 шт., Node-ABI) падают** с «NODE_MODULE_VERSION 137». Обратный ход — `corepack pnpm -r rebuild better-sqlite3` (пересборка под Node-ABI сразу во всех пакетах; проверено — 86/86 зеленые). Тот же симптом и то же лечение; важно другое: **красный гейт из-за этого не из-за правки** — и «починить» его можно только сменой ABI, а не правкой кода.

**Правило-признак.** «Клиент стенда не открывает окно: в CDP живой endpoint, но ни одной вкладки» — это не про CDP и не про порт. Это про ABI: главный процесс доходит до `DevTools listening` (значит, Electron запустился), но не создаёт вкладку — потому что упал на нативном модуле при инициализации базы. Лечится свопом ABI **всех** нативных модулей пакета, а не тех, что первыми всплыли в логе.

**Где это сделано.** `electron-app/package.json` — обе нативные зависимости; профиль машины — [`docs/machines/PC79.md`](../machines/PC79.md) (сетки ABI, путь к набору, порты стенда). Смежное: падение клиента на устаревшей сборке `shared` (новый экспорт в `shared/src` без пересборки `dist`) и протухший pid-файл — то же самое, ловится в `matricarmz.log` по строке `startup-stage`.
