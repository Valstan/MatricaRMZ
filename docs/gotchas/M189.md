# M189 — `signtool sign` ЗАМЕНЯЕТ чужую подпись, а `Get-AuthenticodeSignature` после этого показывает прежнего подписавшего

**Область:** [M189](#m189--signtool-sign-заменяет-чужую-подпись-а-get-authenticodesignature-после-этого-показывает-прежнего-подписавшего)

- **Симптом:** файл подписан Microsoft (`d3dcompiler_47.dll`, `dxil.dll` из поставки Electron). `signtool sign` отработал без ошибки («Successfully signed»), файл изменился — но `Get-AuthenticodeSignature` по-прежнему показывает подписавшего **Microsoft**. Ощущение, что подпись не легла. Ошибка в первом варианте этой грабли: я решил, что `signtool` добавляет вторую подпись рядом с чужой и потому «подписывать поверх» бессмысленно.

- **Корень (исправленный, проверено 04.11.2026 на PC79):** `signtool sign` **ЗАМЕНЯЕТ** подпись, а не добавляет вторую. Разбор таблицы сертификатов PE (data directory №4) до и после подписи:
  | файл | до | после |
  |---|---|---|
  | `d3dcompiler_47.dll` (Microsoft) | таблица 10 608 байт | таблица **1 912 байт**, записей **одна** — наша |
  | `where.exe` (Microsoft) | таблицы нет (0 байт) | таблица **1 912 байт**, записей **одна** — наша |

  Подпись Microsoft **исчезает**: `certutil -dump` показывает `Issuer/Subject: CN=MatricaRMZ Test Root CA`, `signtool verify /pa /v` — `Issued to: MatricaRMZ Test Root CA`. То есть подписывать поверх чужой подписи можно, и подпись становится нашей.

- **Почему тогда `Get-AuthenticodeSignature` показывает Microsoft?** Это **не** показатель того, чья подпись лежит в файле. PowerShell 5.1 в этом случае отдаёт подпись из **каталога подписей Windows** (Microsoft Root Certificate Authority 2010), а не из таблицы сертификатов файла. Тот же файл с **переименованием** даёт тот же результат — значит дело не в пути, а именно в выборе источника. Проверено: `Get-AuthenticodeSignature` → `Microsoft`, `certutil -dump` → наш CA, `signtool verify /pa /v` → наш CA.

- **Диагностика (правильная):** «кем подписан файл» читать из **таблицы сертификатов PE**, а не из `Get-AuthenticodeSignature`. Практический способ — `signtool verify /pa /v`: строка `Issued to: <Subject>` и код возврата 0; для неподписанного файла — `No signature found` и код 1.
  ```powershell
  $out = & signtool.exe verify /pa /v $file 2>&1 | Out-String
  if ($LASTEXITCODE -eq 0 -and $out -match 'Issued to:\s*(.+?)\s*$') { $Matches[1].Trim() } else { 'не подписан' }
  ```
  (`Get-AuthenticodeSignature` годится для ответа «есть ли подпись вообще» у файлов, которые мы подписываем сами с нуля, — но не для «чьей она подпись».)

- **Лечение:** правило в инструменте — **подписываем всё, что собираем, включая файлы, подписанные Microsoft**: `signtool` заменяет подпись, и файл становится доверенным по нашему ключу (а это и есть цель ADR-0003). Пропускать надо только то, что подписано **нашим** ключом (идемпотентность) — по отпечатку, а не по статусу `Valid`.
  - `scripts/signing/sign-matrica.ps1` — функция `Invoke-Sign` (локальный инструмент);
  - `scripts/signing/ci-sign-artifacts.ps1` — функция `Get-EmbeddedSigner` (CI, читает таблицу сертификатов).
