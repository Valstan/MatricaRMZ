# M98 — `unattended-upgrades` каждый день рапортует «нечего обновлять», а система отстала на месяцы

**Область:** прод / обновления

- **Симптом:** в `/var/log/unattended-upgrades/unattended-upgrades.log` изо дня в день `No packages found that can be upgraded unattended and no pending auto-removals`, служба зелёная. При этом ручной `apt update` + `apt list --upgradable` показывает сотни пакетов, включая security.
- **Корень:** обновляет **списки** пакетов не тот таймер, который ставит обновления. `apt-daily.timer` (он делает `apt update`) стоял `disabled` при `preset: enabled`, а `apt-daily-upgrade.timer` (он ставит) был `enabled` и честно отрабатывал каждое утро — по кэшу многомесячной давности. Установщик смотрел в протухшие списки и **правдиво** докладывал, что обновлять нечего.
- **Диагностика:** `systemctl list-unit-files 'apt-daily*'` — сверять состояние **обоих** таймеров, не только того, что в логе; `ls -la /var/lib/apt/lists` — дата файлов. Косвенный признак прямо в логе: предупреждение `Could not figure out development release: Distribution data outdated`.
- **Лечение:** `systemctl enable --now apt-daily.timer`, затем `apt update && apt list --upgradable` — проверять по факту, а не по логу.
- **Урок шире случая:** механизм из двух половин рапортует только по своей половине. Зелёный отчёт исполнителя — не доказательство, что он видел актуальные данные: проверять надо источник, которым он питается. Тот же класс, что «гейт, который не исполняет артефакт, который охраняет» (brain #228).
- **Поймано:** 2026-08-30, техобслуживание прод-бокса по мандату владельца: 261 пакет (218 security) не ставился с мая.
