# M163 — первый сейв новой карточки двигателя пустеет через полминуты

**Область:** sync / зеркало

- **Симптом:** оператор заводит двигатель — кнопкой «Добавить двигатель» или «Принять двигатели списком», — карточка заполнена и сохранена; через 30–60 с те же поля пусты. Заполняешь в неё второй раз — держится. У приёма списком то же самое: строки легли заполненными, а после синка все пустые.
- **Корень:** клиент отправляет новую сущность и карточку **одним батчем**, и ветка `entities` применяется раньше ветки `erp_engine_cards`. `INSERT` в `entities` зажигает `trg_mirror_engine_card_entity` → `rebuild_erp_engine_card` заводит строку карточки из EAV (он ещё пуст), то есть **пустую**, со своим `updated_at` = `clock_timestamp()` — позже клиентского сохранения. Присланная строка карточки проигрывает ей по `setWhere: updated_at <= excluded.updated_at` и отбрасывается **молча**: ни seq, ни EAV-следа, ни `skipped`. Издатель публикует пустую pending-строку, pull на клиенте затирает локальные значения и помечает строку `synced` — повтора нет. Второй сейв выживает: сущность уже есть, триггер по `entities` больше не срабатывает.
- **Что делать:** зеркало не заводит строку, когда зеркалить нечего (`0112_engine_cards_first_save_guard.sql`: нет строки И нет живых EAV-атрибутов → `RETURN`). Строку без номера журнала (`last_server_seq IS NULL`) LWW не считает автором: её `updated_at` — часы сервера, а не время оператора. Отказ LWW в ветке карточек перестал быть молчаливым (`addSkipMetric` + `logSkip('engine card rows stale skipped…')`). Приёмка — `engines:first-save-check` на живом PG (в CI — джоба `migrations-check`) и шаг `[9]` в `cdp-engine-bulk-intake.mjs` (push → издатель → pull).
- **Поймано:** 2026-10-20; воспроизведение — тем же `engines:first-save-check` до фикса (7 красных из 7), после — PASS. Триггер зеркала — общий класс: любой `rebuild_*`, стреляющий на `INSERT` сущности, заводит строку раньше, чем до неё доедет авторская.
- **Починка накопленного:** потерянные значения восстанавливаются из журнала — `engines:restore-first-save` (dry-run по умолчанию; берёт карточки, где последнее слово у зеркала `system`, а последний авторский сейв непуст; пишет через `writeSyncChanges`, сверяя, что карточка всё ещё пуста). На проде 20.10 вернул 22 из 22.
