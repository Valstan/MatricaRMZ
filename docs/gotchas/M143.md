# M143 — подсказка пикера рисуется порталом и не открывается установкой значения

**Область:** [M143](#m143--подсказка-пикера-рисуется-порталом-и-не-открывается-установкой-значения)

**Симптом.** CDP-смоук ставит номер в поле пикера (двигатель, деталь, сотрудник), ждёт опции `div[data-idx]` — их нет ни одной. Клик выбирать нечего, поле остаётся «набранным, но не выбранным», и форма честно отказывает: «Выберите двигатель». Драйвер при этом винит гейт или права, хотя до них дело не дошло. Тот же драйвер был зелёным неделю назад.

**Корень.** `SuggestInput` / `SearchSelect` рисуют список через `createPortal` и **только при `dropdown.open`**. Открывает его React-обработчик ввода, а установка значения через сеттер свойства (`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set`) меняет текст и диспатчит `input`/`change`, но состояние `open` в этой ветке не поднимается. До переезда всплывающих слоёв в портал (**M140**, v3.41.0) список жил в потоке и находился селектором даже закрытым — потому старый приём и работал.

**Лечение — печатать по-настоящему, доменом CDP `Input`:**

```js
await evaluate(ws, `const i = vis('input', vis('[data-work-sheet-editor-engine]', PAGE())[0])[0]; i.focus(); i.click(); return {ok:true};`);
await send(ws, 'Input.insertText', { text: 'ДВ-1003' });        // настоящий ввод, а не сеттер
await waitVal(ws, `vis('div[data-idx]').length > 0`, 'подсказка');
// клик по опции — НАТИВНЫЙ opt.click(), синтетический MouseEvent сюда не доезжает
```

**Класс шире одного смоука:** изменение, невидимое типам и тестам (переезд слоя в портал), ломает КАЖДЫЙ драйвер, который трогал поля в обход настоящего ввода. Признак — «смоук покраснел там, где логику не меняли». Рецепты в committed-драйверах, написанные до v3.41.0 (`cdp-work-sheets.mjs`, 16.09), считать устаревшими, пока не перепроверены.

**Смежное, из того же прогона.** Таймаут `Runtime.evaluate` **не означает, что действие не произошло**: страница живёт дальше, и доказательство, собранное после таймаута, противоречиво (драйвер «упал», а строка в базе появилась). Такое принимать за результат нельзя — опрос состояния только короткими повторными `evaluate` со стороны драйвера (цикл ожидания внутри одного `evaluate` висит до таймаута).
