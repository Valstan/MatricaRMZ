# M153 — когда `when` старше прошлой записи, migrator молча пропускает миграцию

**Область:** [M153](#m153--когда-when-старше-прошлой-записи-migrator-молча-пропускает-миграцию)

- **Симптом:** ручная data-only миграция + запись в `_journal.json`, `db:migrate` — «migrations applied», exit 0, повторный накат — то же. Строк новой миграции в таблице нет, в журнале применённых её нет.
- **Корень:** pg-migrator drizzle решает «применять ли» сравнением `Number(last.created_at) < migration.folderMillis`, где folderMillis — поле `when` записи журнала. Скопированное старое число (старше прошлой записи) — миграция пропускается молча, без ошибки и без записи.
- **Диагностика:** `SELECT count(*) FROM drizzle.__drizzle_migrations` — трекинг живёт в схеме `drizzle`, а не в `public` (проверка по `pg_tables ... schemaname=public` даёт ноль и выглядит как «мигратор не работает вовсе»). Сверить `when` новой записи с max применённых.
- **Лечение:** `when` новой записи — текущее время, строго больше прошлой (`drizzle-kit generate` ставит время генерации; вручную — `Date.now()`). После правки повторный `db:migrate` встал как положено.
- **Поймано:** 2026-10-14, миграция `0109_repair_stage_new_codes` (новые этапы линейки).
