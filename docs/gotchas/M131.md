# M131 — библиотека картинок берёт память по числу ядер, а не по памяти машины

**Область:** [M131](#m131--библиотека-картинок-берёт-память-по-числу-ядер-а-не-по-памяти-машины)

- **Симптом (14.09.2026):** воркер бэкенда убит OOM-killer'ом при приёме снимков; на машине разработчика та же правка работает.
- **Корень:** `sharp` держит кэш libvips и пул потоков **по числу ядер**, не спрашивая, сколько памяти есть. На прод-боксе 1536 МБ, снимки по 20 Мп — два-три одновременно, и памяти нет. На разработческой машине это невидимо.
- **Лечение:** сразу при импорте — `sharp.cache(false)`, `sharp.concurrency(1)`, и `limitInputPixels` на разумном потолке. Правило шире `sharp`: у любой библиотеки, выбирающей параллелизм «по железу», целевая машина может быть втрое слабее сборочной.
