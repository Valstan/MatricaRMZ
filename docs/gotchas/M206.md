# M206 — две сборки на один тег: CDN отдаёт смесь, а докачка склеивает два блоба

**Область:** релизы / выкатка

**Симптом.** Релиз собран, тег один, а на прод лежит инсталлятор, который клиент
отвергнет. Два разных лица одного релиза:

1. **Манифест и файл из разных сборок.** `latest.yml` описывает один размер и один
   `sha512`, а скачанный `.exe` — другой файл той же длины. Симптом снаружи: всё
   «правильного» размера, проверка размера проходит, а `sha512` не сходится.
2. **Файл «склеен» из двух блобов.** Скачивание оборвалось на середине (142 385 952
   байт из 142 390 888), и следующая попытка **докачала** (`curl -C -`) остаток от
   ДРУГОГО блоба. Итог — файл правильной длины с мусором внутри: длина совпадает,
   `sha512` нет.

**Почему.** Тег нажали дважды (две сессии выкатывали параллельно). Второй прогон
**перезаписал** ассеты релиза («overwrite published file … reason=already exists on
GitHub»), и в репозитории теперь лежит новая сборка, а CDN по прежнему URL-пути
(`/releases/download/<tag>/<file>`) какое-то время отдаёт старый блоб. Итог —
смесь: новый `.exe` со старым `latest.yml` или наоборот. Склейка из пункта 2 — следствие
того же: докачка не проверяет, что лежащий на диске кусок из ТОГО ЖЕ блоба.

**Диагностика (быстро).** Сверить ассеты релиза с тем, что реально лежит на проде:

```bash
gh api repos/Valstan/MatricaRMZ/releases/tags/vX.Y.Z \
  --jq '.assets[] | [.id,.name,.size,.created_at,.digest] | @tsv'
```

и на проде — `sha512` файла против `latest.yml`:

```bash
openssl dgst -sha512 -binary MatricaRMZ-Setup-X.Y.Z.exe | base64 -w0
grep '^sha512:' latest.yml
```

Расхождение при совпадающих размерах = смесь или склейка.

**Лечение.**

1. **Не докачивать поверх обрыва.** Правило: если `sha512` файла не совпал с
   манифестом — файл сносится и качается **заново**, без `-C -`. Докачка вслепую
   лечит только обрыв, а не склейку.
2. **Переносить на место только согласованную тройку** (`exe` + `latest.yml` +
   `blockmap`): размер и `sha512` из манифеста должны совпадать с фактическим
   файлом. Гейт в скрипте выкатки — до `mv`, а не после.
3. **Манифест и blockmap перекачивать заново каждый раз**: «уже полный» файл при
   `curl -C -` не перезаписывается (сервер отдаёт 416 на Range за концом файла) и
   остаётся прежней версии.
4. **Тег должен ставиться один раз и на мерженый `main`.** Две сборки на один тег —
   это не «лишняя работа», а источник смеси в репозитории: перезапись ассетов.

**Почему это не ловили гейты.** Ни один гейт не смотрит в `/opt/matricarmz/updates`
на проде: чистка, манифест и CDN живут там, а проверка в CI смотрит только на
собранный артефакт. Ловится только на месте, после заливки — сверкой `sha512`.

**Проверка после заливки (обязательная).** `sha512` exe = манифесту; размер exe =
`latest.json`; первым в `ls -lt` — `.exe` текущего релиза (см. M204 про `touch`).

**Пул:** класс «проверяй артефакт по хэшу, а не по длине» переносим в Мозг письмом.
