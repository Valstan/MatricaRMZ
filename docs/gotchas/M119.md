# M119 — гейт прав возвращает УСПЕХ, а его читают как «отказ»

**Область:** права / мост

- **Симптом:** новый IPC-канал отвечает `{ ok: true }` на любой запрос — и на несуществующий идентификатор, и на пустой аргумент. Ошибок нет, типы сходятся, тесты зелёные; просто в базе ничего не появляется, а список всегда пуст. На экране — «комнат нет», хотя комната только что создана.
- **Корень:** `requirePermOrResult(ctx, 'chat.use')` возвращает `{ ok: true }`, когда право ЕСТЬ, и `{ ok: false, error }`, когда его нет. Написано было `const denied = requireChatUse(); if (denied) return denied;` — то есть возвращался успех гейта вместо результата операции. Хуже: функция асинхронная, `await` забыт, и `denied` — это Promise, всегда истинный. Обработчик до сервиса не доходил НИКОГДА.
- **Почему не поймали раньше:** возвращаемый тип обработчика — объединение, в которое `{ ok: true }` укладывается; `typecheck` доволен. Сторожа по исходному тексту проверяют наличие канала, а не то, что он делает. Юнит-тесты сервиса зелёные — сервис исправен, до него просто не доезжают.
- **Как отличить от «не зарегистрирован»:** незарегистрированный канал даёт исключение в `invoke`. Ровный `{ ok: true }` без полезной нагрузки — признак именно этого класса.
- **Лечение:** единственная форма вызова в проекте — `const gate = await requireChatUse(); if (!gate.ok) return gate;`. Имя переменной `denied` для помощника, возвращающего успех, — половина ошибки.
- **Поймано:** 2026-09-08 CDP-смоуком (мост отвечал `{"ok":true}` без `rooms`). Родня: M116/M118 — «две половины по отдельности правильные, стык молчит».
