# M205 — Правка стенда прямо в SQL клиенту не видна: он берёт строки по журналу

**Симптом.** Фикстура поставлена прямо в dev-БД (`UPDATE attribute_values …` по
`entity_id` двигателя), сервер её видит — а список двигателей в клиенте показывает старое:
привязки нет, в ячейке «Привязка» пусто, счётчик «Всего/Показано» не меняется. Перезапуск
клиента (холодная синхронизация) **не помогает**.

**Что это.** Клиент тянет изменения **по журналу** (`ledger_tx_index`), а не «как есть» из
таблиц: строка, записанная мимо `writeSyncChanges`, не имеет номера в журнале — и до клиента
не доходит никогда, ни при инкрементальном pull, ни при холодном. Серверные `UPDATE`/
`INSERT` в таблицы состояния для реплики — это «правка прод-данных в обход журнала», а не
способ подготовить стенд.

**Как отличить.** Признак один и надёжный: в базе значение есть, в интерфейсе — нет.
Проверяется прямо через мост:

```js
await window.matrica.engines.list();   // что видит клиент
```

**Лечение.** Фикстуры стенда ставить **тем же путём, которым пишет оператор**, — через мост:

```js
await window.matrica.engines.setAttr(engineId, 'contract_id', '<id договора>');
await window.matrica.engines.setAttr(engineId, 'contract_section_number', 'ДС 2');
```

Пишется через серверный API, запись попадает в журнал, реплика обновляется — и список
показывает новое сразу.

**Почему записано.** Смоук на стенде дважды упирался в «фикстура есть в базе, а в UI её
нет», и оба раза это выглядело как «клиент сломан» или «правка не применилась». На деле
механизм синхронизации устроен так, что мимо журнала записи не ходят в принципе. Драйвер
смоука теперь ставит и снимает фикстуры сам через мост и возвращает стенд в исходное
состояние — ручной подготовки не осталось (`.claude/skills/verifier-electron/scripts/cdp-binding-column.mjs`).
