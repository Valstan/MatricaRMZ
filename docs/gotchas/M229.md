# M229 — поиск склеивает поля записи в одну строку: совпадение находится «где-то в записи»

**Область:** клиентский поиск — `electron-app/src/renderer/src/ui/utils/search.ts` (`collectRecordText`, `prepareRecordSearch`) + общий тир-матчер `shared/src/domain/tieredSearch.ts`; палитра `GlobalSearchOverlay.tsx`

- **Симптом:** поиск находит строку, но оператор не видит, **почему** она нашлась: «двигатель в выдаче — потому что совпал номер двигателя» и «потому что совпал договор» выглядят одинаково. Запрос «А-100» может совпасть с номером двигателя, с номером договора и с примечанием — и все три строки приходят в одну выдачу вперемешку.
- **Корень:** `collectRecordText` рекурсивно собирает **значения** всех полей записи в одну строку и склеивает их пробелом; имена полей при этом теряются. Дальше тир-матчер скорит эту строку и возвращает **одно число** — какое из полей сработало, из скора не восстановить. Атрибуция совпадения в проекте не была нигде: ни «реестра полей по видам сущностей», ни notion «строка найдена по полю X».
- **Почему молча:** потеря необратима — из склеенной строки поле не выделить, а матчер по-прежнему честно отвечает «нашлось». Проверка «нашлось или нет» проходит, проверки «где нашлось» не было вовсе.
- **Лечение (сделано 25.11.2026, промт КАРМАНА #137):** реестр полей по видам сущностей `shared/src/domain/searchFields.ts` (`SEARCH_FIELDS`) + подготовка полей строки `prepareSearchFields` (один раз на набор строк) + сопоставление `matchPreparedSearchFields` (**тот же** тир-матчер и тот же режим «точный/≈ Похожие», что и в списках ⇒ объяснение не может противоречить выдаче) + группировка `groupRowsBySearchField`. Палитра показывает подгруппы «по номеру двигателя — 3», список — бейдж «по номеру двигателя» у найденной строки.
- **Диагностика (проверяемо):** `matchSearchFields(row, 'engine', 'А-100')` — пусто ⇒ поле не зарегистрировано или строка не содержит его значения; `searchFields.guard.test.ts` — сторож на то, что каждое поле двигателя реально есть в `EngineListItem`.
- **Поймано:** 2026-11-25, зачитка владельца (промт КАРМАНА #137). Сторож: `shared/src/domain/searchFields.guard.test.ts`.
- **Правило на будущее:** **склейка полей — не то же самое, что поиск по полям.** Если выдаче нужно объяснить «где совпало», текст надо готовить по полям с подписями; обратно из склейки поле не восстановить. И объяснение обязано считаться **тем же** матчером, что и сама выдача, — иначе «нашлось» и «по какому полю» разойдутся.
