# M230 — «Очередь застряла», а данные на сервере давно есть: повторный push неизменённой строки пишет в журнал, отказ не назван, а машина не видна

**Область:** синхронизация — журнал изменений, push/pull, снимки диагностики клиента (`backend-api/src/services/sync/syncWriteService.ts`, `backend-api/src/services/sync/applyPushBatch.ts`, `electron-app/src/main/services/sync/diagnosticsReporter.ts`, `electron-app/src/main/services/syncManager.ts`). Продолжение класса [M227](M227.md) (no-op ⇒ не изменение) на другую таблицу и на наблюдаемость.

- **Симптом:** тревога «очередь отправки на сервер застряла» — 624 строки (622 `erp_engine_inventory_lines` + 1 `entities` + 1 `operations`), самая старая ждёт 56 мин при пороге 15 мин. При этом **все 622 строки на сервере есть**, у каждой свой номер журнала, а лист — `synced`. Отказов сервера за день **ноль**: `lww_rejected` — 0, `sync_policy_denied` — 0, «budget cut» — 0. В журнале — **1244 записи на 622 строки** (по две на строку): повторный push неизменённой строки создавал новый `last_server_seq` и новую запись журнала. Счётчик очереди на клиенте при этом не падал — строка возвращалась в `pending` по кругу.
- **Корень (три части, одна болезнь — класс невидим):**
  1. Правило «журнал — лог ИЗМЕНЕНИЙ» было применено к `attribute_values` (M227), но **не к строкам списка деталей** ⇒ повторный push неизменённой строки шёл в журнал и двигал номер строки; следующий push упирался в «серверная копия новее».
  2. Отсев по устареванию для этой таблицы шёл **без `staleReason`** ⇒ отказ уходил с причиной `conflict`, а клиент снимает `pending` только по `lww_rejected` (`skipReasonPolicy.ts`). Плюс отсев по seq бросал **весь батч** (`sync_conflict`), а не одну строку (правило M49).
  3. Наблюдаемость: снимок клиента снимал **5 таблиц** (без строк списка деталей), уходил **после** pull'а (на машине с провисшим pull'ом — никогда), а ошибка отправки глоталась молча ⇒ android-парк не прислал **ни одного** снимка `scope='client'` (0 из 26 524 — все с win32-префиксами), и автолечение (`diagnosticsAutohealService`) очередь не видело.
- **Диагностика:** (1) снимки клиента (`diagnostics_snapshots`, `scope='client'`): `pendingCount` по таблицам и `oldestPendingAt`; (2) журнал: `select count(*) from ledger_tx_index where table_name='erp_engine_inventory_lines'` — растёт ли он на **неизменённых** строках (сравнить `last_server_seq` строки с её последней записью журнала); (3) счётчик строк в очереди у машины против числа строк на сервере — если строки на сервере есть и с номерами, «не уходит» означает «не подтверждено», а не «не доставлено»; (4) строки `operations`/`entities` в очереди — это уже класс M227 (чинено PR #2026, но **не входит в v3.146.0**).
- **Лечение:** (1) сервер отбрасывает неизменённую строку **по общему правилу** (детектор no-op на реестре полей ⇒ без seq и без записи журнала, но с подтверждением клиенту) — второй раз правило не пишется; (2) отсев для таблицы получает `staleReason: LWW_REJECTED_REASON` и `allowSyncConflicts` (одна устаревшая строка не роняет push машины); (3) клиент шлёт снимок **из локального сторожа** (когда очередь застряла, а цикл синка висит — проба идёт мимо `inFlight`), в снимок входит таблица строк списка деталей, а отказ отправки **логируется на сервер**, а не глотается.
- **Понятки:** 2026-11-25, разведка на проде по тревоге Android-машины кладовщика (`android-f54d96db…`, клиент 3.145.0). Строки: `backend-api/src/services/sync/syncWriteService.ts` (детектор no-op), `backend-api/src/services/sync/applyPushBatch.ts` (отсев), `electron-app/src/main/services/sync/diagnosticsReporter.ts` (состав снимка), `electron-app/src/main/services/syncManager.ts` (сторож). Проверки: `backend-api/src/tests/syncNoopJournal.test.ts`, `backend-api/src/tests/syncInventoryLinesNoopJournal.test.ts`, `backend-api/src/tests/syncInventoryLinesPush.test.ts`, `electron-app/src/main/services/sync/diagnosticsReporter.test.ts`, `electron-app/src/main/services/sync/skipReasonPolicy.test.ts`, `electron-app/src/main/services/syncManager.stuckPending.test.ts`.
- **Правило на будущее:** **«очередь застряла» ≠ «данные не доехали».** Первым делом сверяй очередь с сервером (есть ли строки и с номерами журнала): если строки на сервере есть — чини подтверждение и журнал, а не доставку. И второе: **машина, которая не шлёт снимки диагностики, для сервера не существует** — снимок должен уходить вне цикла синка, из локального сторожа, а его отказ — быть виден.
