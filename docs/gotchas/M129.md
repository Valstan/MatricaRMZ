# M129 — подключение скрипта точкой исполняет его `param()` и молча затирает переменные вызывающего

**Область:** [M129](#m129--подключение-скрипта-точкой-исполняет-его-param-и-молча-затирает-переменные-вызывающего)

- **Симптом (14.09.2026, окно обслуживания):** `matrica-ops.ps1` получил от клиента `-ClientExe "…\MatricaRMZ.exe"`, а вкладка раздачи сообщила «клиент не найден». Ошибки нет, путь просто пуст.
- **Корень:** `. .\lan-share-firewall.ps1 -AsLibrary` выполняет блок `param()` подключаемого скрипта **в области видимости вызывающего**. У того свои `$ClientExe` и `$Port` со своими значениями по умолчанию — они перезаписывают одноимённые переменные вызывающего. Совпадение имён параметров у двух скриптов достаточно, чтобы переданное значение исчезло.
- **Лечение:** свои параметры уносить в отдельные имена (`$OpsClientExe`, `$OpsPort`) **до** первого дот-сорсинга и дальше пользоваться только ими. Само подключение обрывать ключом-библиотекой: `[switch]$AsLibrary` + `if ($AsLibrary) { return }` перед главным потоком, иначе дот-сорсинг ещё и выполнит чужой сценарий целиком (для GUI-скрипта — откроет второе окно).
