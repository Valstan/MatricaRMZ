# M96 — ротация `MATRICA_JWT_SECRET` в `.env` «не действует»: свежий токен `token_invalid`, старые живут

**Область:** прод / секреты

- **Симптом:** заменил `MATRICA_JWT_SECRET` в `backend-api/.env`, перезапустил оба сервиса — а свежевыпущенный токен не проходит `/auth/me` (`token_invalid`), при этом старые токены продолжают работать. Выглядит как «ротация не подействовала».
- **Корень:** секрет живёт в ДВУХ файлах. Сервисы берут окружение из systemd `EnvironmentFile=/etc/matricarmz/matricarmz.env`; `backend-api/.env` читают только CLI-скрипты (`run-with-backend-env.mjs`, tsx с dotenv). Переменные systemd уже стоят в окружении процесса, dotenv их не перекрывает — правка `.env` для сервисов невидима.
- **Диагностика:** `systemctl cat matricarmz-backend-primary` → строка `EnvironmentFile=`. Состав файлов сравнивать по именам (`grep -oE '^[A-Z_]+'`), значения не печатать — транскрипт.
- **Лечение:** менять секрет в ОБОИХ файлах одинаково (каждому бэкап с правами 600), затем rolling-рестарт с `/health`; проверка — `/auth/me` новым токеном.
- **Урок шире случая:** у секрета может быть больше одного дома. Перед ротацией выяснить, откуда его читает КАЖДЫЙ потребитель (systemd, dotenv, CI), а не только самый видимый файл.
- **Поймано:** 2026-08-28, отзыв засветившегося release-токена сменой JWT-секрета.
