# M172 — установочный скрипт «отработал», а половину работы не сделал

**Область:** bash / скрипты установки

- **Симптом:** `sudo bash deploy/neural/install.sh` печатает шаги, ставит файлы и юниты, выводит таблицу таймеров — и **на этом заканчивается**: сторож не запущен, тестовый алерт не отправлен. Код возврата 0? Нет — ненулевой, но `sudo … | tail` его скрывает, и в чате видно «вроде прошло». `sudo bash … --dry-run` при этом ставит всё по-настоящему.
- **Корень — две ловушки сразу.** (1) `set -o pipefail` + `systemctl list-timers … | head -3`: `head` закрывает трубу, `systemctl` получает SIGPIPE (141), и `set -e` обрывает скрипт ровно в этом месте — всё, что ниже, не выполняется. (2) `DRY_RUN=1 sudo bash script` не работает: `sudo` сбрасывает окружение, скрипт видит пустую переменную и ставит по-настоящему.
- **Лечение:** в трубах, где нужны первые N строк, — `awk 'NR<=3'` (читает поток до конца, SIGPIPE нет) или явный `|| true`; флаги передавать **аргументом** (`--dry-run`), а не переменной через `sudo`. Проверять установочный скрипт по **следу, который он обязан оставить** (запись в журнале, доставленный алерт), а не по коду возврата за трубой.
- **Поймано:** 2026-10-25, первый прогон `deploy/neural/install.sh` на боксе: `bash -n` чист, гейты зелёные, скрипт молча остановился на середине.
