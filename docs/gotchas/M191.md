# M191 — `app.asar` из каталога сборки не удаляется: файл держит другой процесс, а каталог ещё и помечен EFS

**Область:** [M191](#m191--appasar-из-каталога-сборки-не-удаляется-файл-держит-другой-процесс-а-каталог-ещё-и-помечен-efs)

- **Симптом:** после проверки сборки (`electron-builder --dir` / полная сборка с NSIS) каталог `electron-app/release*` не удаляется ни обычным `Remove-Item`, ни `rmdir /s /q`, ни `robocopy /MIR` с пустым каталогом, ни даже с повышенными правами:
  ```
  Remove-Item -Recurse -Force  → «Отказано в доступе по пути …»
  mavis-trash                 → «The system call level is not correct» (CLIXML, DeleteDirectory)
  robocopy /MIR               → содержимое вычищает, КАТАЛОГ остаётся
  ```
  Остаётся ровно один файл на каталог: `win-unpacked\resources\app.asar` (94,7 МБ).

- **Два наложенных причины, и обе ловушки:**
  1. **Файл держит другой процесс** — не процесс репозитория, а посторонний: `Get-AuthenticodeSignature`/прямое открытие на запись даёт «Процесс не может получить доступ к файлу … так как этот файл используется другим процессом». Проверка «открыть с FileShare.None» — рабочий способ отличить блокировку от проблемы с правами.
  2. **Атрибут EFS (Encrypted).** Сборка шла в зашифрованной папке профиля, и `app.asar` унаследовал шифрование: `Get-Item … | Select Attributes` → `Encrypted`. Зашифрованный файл **читается**, но не переоткрывается на запись и не удаляется, пока атрибут не снят. Сертификат шифрования — `CN=valstan` в `Cert:\CurrentUser\My` (OID 1.3.6.1.4.1.311.10.3.4).

- **Лечение (по порядку):**
  1. снять EFS: `cipher /d /s:"<каталог>"` — после этого атрибут становится `Archive`, и файл снова удаляется обычным способом, если его уже не держит процесс;
  2. если файл всё ещё занят — `MoveFileEx(path, null, MOVEFILE_DELAY_UNTIL_REBOOT)`: файл удаляется при следующей загрузке, когда держатель уже не мешает. Регистрируется в `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\PendingFileRenameOperations` — запись видна как `*1\??\path` (префикс `*1` = файл, `*2` = каталог).

- **Диагностика по шагам** (порядок важен — каждый шаг снимает свой класс проблем):
  ```powershell
  # 1. занят ли файл (а не права):
  try { $fs=[IO.File]::Open($f,'Open','ReadWrite','None'); $fs.Close(); 'свободен' }
  catch { 'держит другой процесс' }
  # 2. не помечен ли EFS:
  (Get-Item $f -Force).Attributes        # 'Encrypted' → лечить cipher /d
  # 3. что осталось после robocopy /MIR:
  Get-ChildItem <каталог> -Recurse -Force
  ```

- **Почему это важно именно здесь:** проверка сборки под подписью (ADR-0003) оставляет после себя ~285 МБ в трёх каталогах `electron-app/release*`. Каталоги в `.gitignore` (`electron-app/release*`), состояние репозитория чистое — но мусор на диске машины парка накапливается, и следующая сборка идёт в тот же каталог. Проверку подписи надо делать в отдельном `--config.directories.output=`, а не в штатном `release/`.
