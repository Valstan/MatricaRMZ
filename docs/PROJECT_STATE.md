# Project State

Короткая оперативная память проекта для ИИ-сессий. **Принципы** (из чего исходить) — [`CONSTITUTION.md`](CONSTITUTION.md), этот файл — **действующие факты** архитектуры/эксплуатации (ст. 9 конституции: принцип ≠ процедура ≠ карта ≠ история).

## Как поддерживать этот файл
- Обновлять только при изменениях высокого уровня: архитектура, контур синхронизации/релиза/деплоя/доступа, обязательные правила, появление/исчезновение важного модуля или источника истины.
- Не писать сюда UI-мелочи, рефакторинги без смены поведения и одиночные багфиксы — это история `git log` / `COMPLETED.md` (ст. 10 конституции: рабочие файлы держат только открытое/действующее).
- `Текущее состояние` — только действующие важные факты; `Последние важные изменения` — **5–10 пунктов максимум**, старое выпалывается (история остаётся в git); `Устаревшие решения` — только то, что может ввести новую сессию в заблуждение.

## Текущее состояние
- Основная точка входа для новой ИИ-сессии: `AGENTS.md` (правила проекта) + slash-команды `/start` / `/close_session` / `/reliz`. `docs/README.md` — справочный hub профильных документов, не протокол сессии.
- Локальная разработка на Windows 11 считается штатной; рабочие шаги и ENV описаны в `docs/WINDOWS_DEVELOPMENT.md`. Специфика конкретного компа (порты, пути, скиллы) — `docs/machines/<hostname>.md`.
- Управление прод-VPS: **только SSH в терминале** по Host-алиасу `matricarmz` (порт нестандартный — хостер форвардит внешний порт на внутренний sshd; значения только в `~/.ssh/config`, в репо их нет; изолированный per-machine ed25519-ключ + `IdentitiesOnly yes` — иначе fail2ban; детали/типовые грабли — `AGENTS.md` §Prod server и §SSH tips). MCP ssh-mcp не используется. Ротация ключей — 90-дневный цикл; PC40 ротирован **2026-08-17**, следующая **≤2026-11-15**. Ротируется **только ключ своей машины** — приватные ключи чужих машин отсюда недоступны, каждая ротирует себя сама.
  - **Фактическая раскладка `authorized_keys` прода — два ключа (сверено 2026-08-19 по отпечаткам, а не по комментариям):** ключ PC40 (ротация 2026-08-17) и ключ RMZ4VAL (2026-06-02). Обе записи с известными владельцами; посторонних нет. Имена файлов, комментарии и отпечатки ключей в репо не пишем (`AGENTS.md` §recon-поверхность) — сверять на месте `ssh-keygen -lf`.
  - **Снято 2026-08-19:** прежний ключ PC40 (от 2026-05-22), стоявший fallback'ом после ротации 17.08. Снят досрочно (плановая дата была 24.08) по решению владельца: PC40 весь день ходил на прод новым ключом, страховка отработала вхолостую. Бэкап `authorized_keys` сделан рядом с файлом, доступ проверен новым соединением сразу после правки.   - Прежняя запись здесь была неверна дважды: «1 строка без комментария неустановленного происхождения» — это **пустая строка** в файле (валидных ключей три, не четыре), а привязка «PC40 = 2026-05-23 / машина-2 = 2026-05-22» перевёрнута: под `2026-05-22` жил как раз ключ PC40. **Мораль:** сверять по `ssh-keygen -lf ~/.ssh/authorized_keys` и отпечатку локального pub-файла, комментарий в ключе — не источник правды.
- Прод-контур backend — dual-instance: `matricarmz-backend-primary.service` (`:3001`) + `matricarmz-backend-secondary.service` (`:3002`) за nginx upstream. Singleton background jobs (sync-pipeline supervisor, critical notifier, schedulers) — только на `primary`; `secondary` — только API. Restart/deploy — последовательно (primary → health → secondary).
- Закрытие ИИ-сессии (`/close_session`) = синхронизация всей работы на GitHub через PR-flow (ADR-0002); сессия не закрыта, пока sync-гейт не зелёный (brain #010). Деплой на прод и клиентский релиз — **отдельный осознанный шаг** (`/reliz` + AGENTS.md §Release process), НЕ автоматическая часть закрытия.
- Клиент-серверное взаимодействие — только HTTPS. Рабочий контур синхронизации клиента — ledger-эндпоинты; legacy `sync/*` не актуален. Клиентский релиз становится видимым автообновлению только после публикации installer-метаданных в ledger (`version`, `fileName`, `size`, `sha256`).
- **«Цех» — единый источник истины = таблица `directory_workshops` (2026-06-08).** 7 строк (коды `1`–`7`). Канон используют: наряды (`workOrderClosingService`), складские локации (FK), `erp_document_headers`, `workshop_repair_templates`, route `/workshops`, карточка двигателя, аналитика. EAV entity-types `workshop_ref`/`workshop` — легаси-дубли (см. «Устаревшие решения»). Любой новый захват/чтение «цеха» обязан идти через `directory_workshops`.
- **Организационная принадлежность сотрудника (2026-08-14).** Подразделения канонически хранятся как EAV-сущности типа `department`, цеха — в `directory_workshops`; карточка сотрудника ссылается через `department_id` либо `workshop_id`. ИИ и отчёты обязаны разрешать эти ссылки в официальные названия и не показывать UUID пользователю. Утверждённого дерева parent/child между подразделениями в данных пока нет — не выдумывать его без оргсхемы владельца.
- **Прод-секреты/env (brain #008):** канонический файл — `/etc/matricarmz/matricarmz.env` (владелец `root`, группа сервисного пользователя, 0640, вне дерева репо), оба юнита грузят через `EnvironmentFile=`. In-tree `backend-api/.env` на проде — **симлинк** на него. В репо только `.env.example`. ⚠️ После `git clean -fdx` на проде пересоздать симлинк: `ln -sfn /etc/matricarmz/matricarmz.env backend-api/.env`.
- **Подпись Android-клиента (2026-08-12).** У планшетного APK постоянный release-keystore: RSA-4096, alias `matricarmz`, срок 30 лет, отпечаток SHA-256 `44:37:2B:1E:2F:17:E3:3A:C6:6F:B0:93:CD:59:68:B5:CB:6D:C1:64:2F:BC:31:5C:BD:AC:A8:1C:DB:A7:D2:39`. Файл хранилища и его пароль лежат **вне репозитория** на PC40 — `%USERPROFILE%\.matricarmz-keys\` (`matricarmz-release.keystore` + `.pw`); в Git не попадают, репо публичный. В секретах репозитория — `ANDROID_KEYSTORE_BASE64` (base64 файла), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` (`matricarmz`), `ANDROID_KEY_PASSWORD`; прочитать их обратно из GitHub нельзя. **Ключ один навсегда:** APK, подписанный другим ключом, Android поверх не поставит — потеря хранилища означает переустановку со стиранием данных на всём парке планшетов. **Бэкап делается свёртком** `node scripts/seal-key-bundle.mjs seal` — он запечатывает в один файл под паролем keystore + `.pw` + `backup-private.pem` (приватный ключ off-site бэкапа, см. `OPERATIONS.md` §9); `self-check` подтверждает побайтовое восстановление. Носители (сейф + копия вне здания) и пароль — на владельце. Релизная сборка планшета — тег `android-vX.Y.Z` (workflow `android-apk-build.yml` → GitHub Release с подписанным APK); Electron-релиз идёт отдельным тегом `vX.Y.Z`.

## Устаревшие решения
- **EAV entity-types `workshop_ref` и `workshop` — легаси-дубли `directory_workshops`, не источник истины (2026-06-08).** `workshop_ref` («Цеха», 7 живых сущностей с расходящимися именами) — сидинг и text-lookup редиректы сняты (PR #267), backend тип не знает. `workshop` («Цех») — пуст (hard-purge единственного орфана под бэкап, G29-подтверждение); оставлен как inert-маркер: `linkTargetTypeCode:"workshop"` теперь канонический маркер, маршрутизирующий на `directory_workshops`. Остаточный inert-легаси (7 сущностей `workshop_ref` + пустые типы) — можно снести отдельной нитью.
- Не считать актуальным **MCP ssh-mcp** / `MCP_SETUP_WINDOWS.md` для прод-VPS — контур снят; только SSH.
- Не считать актуальным «текстовый протокол старта/завершения сессии в `docs/README.md`» — источник истины теперь slash-команды `/start` / `/close_session` / `/reliz` (+ `AGENTS.md`); README — справочный hub.
- Не считать актуальным предположение, что клиент работает по HTTP — только HTTPS.
- Не считать актуальным, что деталь отображается «зеркальной строкой» `erp_nomenclature` с серверной синхронизацией — зеркало удалено (Phase 2 Stage F); деталь = сама строка `erp_nomenclature` (тот же UUID, `spec_json.source === "part"`), spec-поля в `directory_parts`.
