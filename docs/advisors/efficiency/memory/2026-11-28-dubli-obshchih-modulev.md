# Случай: дубли общих модулей — решение по структуре кода — 2026-11-28

**Что советовал (эффективщик).** Выдать решение по трём кандидатам строго в одной из трёх форм
(«доработать существующее / вынести в общий модуль / завести новый») и найти дубли функций и кода.

**Что вышло.**

| Кандидат | Решение |
|---|---|
| Лестницы «где двигатель сейчас» | **доработать существующее**: пороги — в `repairStages.ts` рядом с `repairStageRank`; новый модуль не нужен |
| `escapeHtml` (11 копий) | **завести новый** — в `shared/src/` (main и web-admin в renderer-слой не попадут) |
| «2 копии лестниц в main» | **не делать** — копий нет |
| `photosPrint` ↔ `photosPrintLocalPaths` | **не делать** — обе уже зовут `printPhotos` |

**Вывод.** Перед «завести новый модуль» проверь **примитивы**: ранжирование уже было общим
(`repairStageRank`) — новый модуль стал бы вторым источником правды. И: **настоящий дубль — не копия
функции, а продублированное правило** (порог «готов»), его чинить дешевле и безопаснее, чем сливать
функции.
