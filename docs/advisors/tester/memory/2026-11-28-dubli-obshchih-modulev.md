# Случай: дубли общих модулей — проверка на стенде — 2026-11-28

**Что советовал (тестер).** Проверить на стенде, решает ли программа задачу или уходит в тупик:
один двигатель — одно место или разные ответы на разных экранах.

**Что вышло.** Стенд `main` поднят: backend `127.0.0.1:3001`, `/health` → 200, v3.149.0; БД
`matricarmz_dev` — 31 карточка, **59 движков со строками этапов** (`operations.meta_json` со
`stage`). Живые доменные функции (`shared/dist`) прогнаны на этих данных:

- **расхождение воспроизведено: 20 из 59 движков** — `currentDatedStage` («место по времени») и
  `engineStateLabel` («подпись состояния») дают **разные** ответы (пример: `2f55f0de` → дефектовка
  против «Заведён»);
- порог «готов» = `repairStageRank('obkatka')` = **60**; на стенде движков с рангом ≥ 60 нет —
  расхождение «подпись vs отсчёт» нечем проверять;
- **UI (CDP) не гнался**: правок в UI нет, а ABI-свап `better-sqlite3` под Electron уронил бы
  `vitest` параллельных линий (M209).

**Вывод.** Задача про домен **проверяется без Electron**: живые доменные функции на живых строках
данных стенда — этого хватило, чтобы расхождение перестало быть «теоретическим». Стоимость смоука
(общий ABI) сравнивается с ценой чужих линий — и часто проигрывает.
