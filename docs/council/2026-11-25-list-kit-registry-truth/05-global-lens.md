# Глобальная линза: список вне кита — есть ли готовый обработчик, который это уже делает?

> Первая линза совета (протокол §5). Вопрос: **есть ли уже готовый глобальный обработчик, который делает это?**

**Где искал (источники поиска):**

| Источник | Что нашёл |
|---|---|
| Реестр глобальных модулей (карта приложения) | **реестра в проекте нет** — измерение ведётся по карте монорепо; как только появится — ссылка отсюда |
| `docs/CODEBASE_MAP.md` | карта домен → файл; кит списков в ней отдельной строкой не описан (запись — зона линии 2) |
| Кит домена (`electron-app/src/renderer/src/ui/hooks/useList*`, `components/List*`, `utils/list*`, `shared/src/domain/listBehavior.ts`) | **кит есть и он общий**: `useListBehaviorSettings.ts` (единый источник правил), `useListSelection.ts`, `useListDrag.ts`, `useListKeyboardMove.ts`, `useListLasso.ts` + `components/ListLassoLayer.tsx`, `useListReorder.ts`, `utils/listContextActions.ts` (меню по объявлению действий), `components/ListContextMenu.tsx` |
| Состояние источника | `electron-app/src/renderer/src/ui/listKitRegistry.ts` + сторож `listKitRegistry.guard.test.ts` |

**Вывод:** **готовый модуль найден, новый обработчик не нужен.** Правило «везде одинаково» уже реализовано один раз — в ките; страницы обязаны отдавать киту только свои данные и объявление действий. Поэтому работа нитки «Списки по одним правилам» — это **не новые компоненты, а перенос существующих страниц на существующий кит** и **правка состояния источника** (реестра), а не новый слой поведения.

**Второй шаг плана — «внести в него», а не «написать свой»:** любой новый список программы подключается к киту (`data-list-root`, `data-list-row` + `data-list-row-key`, `ListLassoLayer`, `buildListContextMenuItems`), а его состояние пишется в `listKitRegistry.ts`. Своя копия поведения на странице — запрещена (план нитки, §«Осторожности»: «одно правило — один источник»).

**Покрытие этого измерения:** `dimensions_done: [глобальные-обработчики]` · `dimensions_failed: [реестр-глобальных-модулей — в проекте пока нет (строит линия 2), поиск шёл по `docs/CODEBASE_MAP.md`]`

**Риск, если вывод неверен:** если часть «кита» на самом деле копируется на страницах (а не приходит из общего источника), вывод «переносить страницы на кит» не даст результата — проверяется грепом по страницам на `useListBehaviorSettings` / `ListLassoLayer` и сверкой с `docs/CODEBASE_MAP.md`.
