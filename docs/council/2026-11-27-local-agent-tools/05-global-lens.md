# 05 — Глобальная линза: есть ли готовый модуль

**Вопрос.** Есть ли уже готовый общий модуль (сервис, кит, слой), который делает то, о чём бриф?

## Порядок поиска

### 1. Реестр глобальных модулей — [`docs/GLOBAL_MODULES.md`](../../GLOBAL_MODULES.md)

В реестре **нет** ни клиентского реестра инструментов, ни каталога действий, которые может звать
агент. Ближайшее — каталог действий по объекту (`shared/src/domain/objectCapabilities.ts`,
`electron-app/src/renderer/src/ui/utils/objectActions.ts`): он описывает **кнопки карточек и
списков**, а не «инструменты, доступные агенту». Это разные вещи: кнопка живёт в renderer и
рисуется человеком, инструмент зовёт агент и должен проверять права.

**Находка:** если новый реестр инструментов повторит структуру каталога действий (право + текст
отказа), получится вторая копия правила. Значит, общий слой (право + отказ + форма ответа)
надо положить ОДИН раз — и переиспользовать и в кнопках, и в инструментах.

### 2. Кит домена и общие слои

- `shared/src/domain/objectCapabilities.ts` — «какой тип объекта что умеет»: это про карточки.
- `electron-app/src/renderer/src/ui/utils/objectActions.ts` — шаблоны кнопок, «показывать только то,
  что умеет», подсказка «добавь объекту то, что есть у похожего».
- `electron-app/src/main/services/localMiniMax/dbBridge.ts` — **единственный** путь агента к данным
  (read-only, оператор чтения, именованный канал Windows).

### 3. Сервисы с общей ролью

- `backend-api/src/services/ai/llmTools.ts` — **образец** реестра инструментов ИИваныча: `ToolEntry`
  (`def` + `requires` + `handler`), `can(ctx, perm)`, `MAX_ROWS = 200`, `sanitizeRows`, свои тексты
  отказа при недостаточном праве, запись в базу запрещена. Это СЕРВЕРНЫЙ контур: у агента на
  клиенте другой доступ (только чтение своей реплики), и дублем его считать нельзя.
- `electron-app/src/main/ipc/register/*.ts` — существующие двери записи: каждая проверяет право и
  пишет в реплику через общий путь (`contracts:counterparty:save`, `productionProgram:saveRows` и
  т. д.). **Это и есть то, что должно звать приложение от имени оператора.**

## Ответ линзы

**Кандидат:** серверный реестр `backend-api/src/services/ai/llmTools.ts` (образец формы) + клиентские
двери записи в `electron-app/src/main/ipc/register/` (то, что должно исполняться).

**Дубль:** **нет** — клиентского реестра инструментов, доступных агенту, в программе не существует.
Но есть два места, где дубль может вырасти, если не договориться:
1. «право + текст отказа» — уже есть в каталоге действий по объекту; новый слой должен быть общим;
2. «Добавить списком» — **логику проверки дублей переписывать нельзя**: она живёт в домене
   (`shared/src/domain/productionProgram.ts`, `shared/src/domain/engineBulkIntake.ts`), и инструмент
   обязан её вызвать.

**Действие:** **нужен новый клиентский модуль** (реестр инструментов агента) — готового нет. Но:
- чтение данных он **не изобретает**: мост `dbBridge.ts` уже даёт read-only доступ;
- действия он **не переписывает**: он вызывает существующие двери (`contracts:*`, `productionProgram:*`
  и прочие IPC-регистрации), каждая из которых уже проверяет право и пишет в реплику;
- «Добавить списком» публичного IPC не имеет ⇒ это действие надо **вынести в вызываемую из
  приложения функцию** (и запись в реестр действий приложения), а не «кликать по DOM».

**Что НЕ входит:** серверные инструменты Иваныча (другой контур), расширение моста к реплике на
запись (решение владельца — PENDING §2), новая таблица в схеме реплики.
