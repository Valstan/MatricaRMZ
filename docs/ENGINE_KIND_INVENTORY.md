# Инвентаризация: вид «ГОЗ / гражданка» по спискам программы

> Промт КАРМАНА **#163** (зачитка владельца 26.11.2026): вид должен стать полноценным признаком во
> всех списках — им фильтруют, по нему сортируют и по нему группируют. Шаг 1 плана нитки —
> перечислить все списки программы и по каждому сказать: вид в строке есть, ступень есть,
> сортировка есть, группировка есть.
>
> Правило целиком — в [`../AGENTS.md`](../AGENTS.md) §«Списки, фильтры и признаки».
> Механика (короткая подпись, порядок, ступень, ключ группы) — `shared/src/domain/engineKindList.ts`.

## Как читать таблицу

- **Вид в строке** — откуда строка берёт вид: `двигатель` — значение из строки двигателя
  (посчитано по общему правилу `resolveEngineKind` в `listEngines`), `заказчик` — из строгой
  таблицы `erp_counterparties.engine_kind`, `каталог` — вид двигателя взят из каталога
  двигателей (строка сама вида не несёт).
- **Ступень «Вид»** — есть ли в панели фильтров отбор по виду.
- **Сортировка** — есть ли ключ сортировки у колонки «Вид».
- **Группировка** — есть ли раздел «Вид» в выборе группировки.
- **Кнопка в тулбаре** — есть ли быстрый доступ к отбору по виду (`ГОЗ / Гражд.`).

## Списки, где вида нет и он не применим

| Список | Почему |
|---|---|
| Сотрудники | вид — признак двигателя/договора/заказчика, у сотрудника его нет |
| Дети, организационный модуль | то же |
| СИЗ | то же |
| Склад (номенклатура, остатки, документы) | строки склада не привязаны к двигателю/договору/заказчику; вид в них неоткуда взять |
| Номенклатура, инструменты, свойства | то же |

## Что считается и где

- **Правило расчёта** — `shared/src/domain/engineKind.ts`: `resolveEngineKind`
  (договор → карточка двигателя → карточка заказчика), `engineKindLabel`, `engineKindFacetValue`,
  `ENGINE_KIND_NONE_VALUE`, `parseCounterpartyKind`.
- **Слой списков** — `shared/src/domain/engineKindList.ts`: короткая подпись
  (`CONTRACT_KIND_SHORT_LABELS`), порядок (`engineKindRank`, `compareEngineKind`), ключ группы
  (`engineKindGroupKey`), ряд значений ступени (`ENGINE_KIND_FACET_OPTIONS`), конструктор ступени
  (`engineKindFacetDescriptor`), вид по id двигателя (`engineKindById`).
- **Ступени фильтра** (общий движок) — `shared/src/domain/listFacets.ts`; интерфейс —
  `electron-app/src/renderer/src/ui/components/FacetFilter.tsx`; быстрый доступ —
  `electron-app/src/renderer/src/ui/components/KindQuickFilter.tsx`.
- **Группировка** — `shared/src/domain/listGrouping.ts` (`flattenGrouped`).

## Живые данные (замер 26.11.2026, прод, read-only SELECT)

Свежий замер по прод-базе (`erp_counterparties`, `erp_contracts`, `erp_engine_cards`; неудалённые
строки; вид двигателя посчитан по правилу программы — договор → карточка → заказчик, у договора
без записи вида умолчание ГОЗ):

| Срез | ГОЗ | Гражданский | Вид не задан | Всего |
|---|---|---|---|---|
| Заказчики (`erp_counterparties`) | 0 | 0 | 61 | 61 |
| Договоры (`erp_contracts`) | 73 (из них 20 записаны явно, 53 — по умолчанию) | 5 | 0 | 78 |
| Двигатели (`erp_engine_cards`) | 1 660 | 3 | 910 | 2 573 |

Источник первого правила у двигателей: **договор — 1 663**, ручной вид в карточке и вид
заказчика не сработали ни разу (вида нет ни у одного заказчика), без источников — 910.

**Что это значит для фичи (и почему она всё равно нужна).** Вид заполнен у единиц, поэтому:

- отбор «ГОЗ» покажет почти всё, а отбор «Гражд.» — пять договоров и три двигателя; это
  **честная картина данных**, а не поломка фильтра;
- «вид не задан» — 910 двигателей и все 61 заказчик: это отдельное значение ступени с числом
  строк, и оператор видит, почему строки пропали;
- проставить вид пачкой (заказчикам, договорам) — **отдельная работа**, не эта нитка (см. риск
  в промте: «Вид почти ни у кого не заполнен»).

Замер от 25.11.2026 (запись владельца): из 61 неудалённого заказчика вида не заполнено у 59,
гражданских — 2. Свежий замер показывает 61 строку без вида и ни одной гражданской — значения
за это время не менялись сами по себе, значит расходится способ отбора (в замере от 25.11 часть
заказчиков смотрели по EAV, где вида нет вовсе). Ориентир — свежие числа выше.

Из этого следуют два следствия, зафиксированные в коде:

- ступень «Вид» показывает **полный ряд** значений (ГОЗ / Гражд. / Вид не задан), а не только то,
  что встретилось в строках: иначе ступень собрана по строкам просто исчезла бы из фильтра;
- «вид не задан» — **отдельное значение**: отбор «ГОЗ» не выбирает строки без вида, и они видны
  отдельным значением с числом строк.
