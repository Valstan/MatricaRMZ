# 🟡 `parent_nomenclature_id` вне контракта синка: реплика не несёт родство деталей 🗓 since:2026-10-18

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «🟡 Техдолг»

Найдено при работе над подсветкой размера при выдаче СИЗ (#1371). Поля `parent_nomenclature_id` нет в `ERP_NOMENCLATURE_FIELDS` (`shared/src/sync/registry.ts:217`), поэтому клиентская реплика номенклатуры **никогда не несёт строку-модель** и её размерный ряд: на клиенте родства «родитель ↔ вариант» нет вовсе. Подсветка размера обходит это сравнением позиций внутри набора норм карточки, но дыра шире одного экрана — любой клиентский механизм на родстве (пикер деталей в актах, свёртка вариантов, агрегаты остатков) упирается в ту же стену.

**Решение:** либо завести поле в контракт (реплика + разбор, кто на клиенте им пользуется + restamp таблицы), либо сознательно оставить родство серверным знанием и записать это в контракт-доку, чтобы следующий не искал. Смежно — §«Обобщённые позиции: три PR-кандидата».
