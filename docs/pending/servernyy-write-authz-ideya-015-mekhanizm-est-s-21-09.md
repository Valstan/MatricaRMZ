# 🟡 Серверный write-authz (идея #015): механизм есть с 21.09, остались обход ролей и таблица дверей 🗓 since:2026-09-18

**Сделано 21.09 — механизм вместо восьмого исключения.** В `shared/src/domain/ledgerAuthz.ts` — карта `SYNC_TABLE_OWNERSHIP: Record<SyncTableName, …>` «кто владеет строкой» для всех 25 таблиц контракта (`server` / `session` / `append_only` / `row` + столбец + причина отказа / `type` / `permission` / `schema`). Новая таблица без записи не проходит typecheck; `SERVER_MANAGED_SYNC_TABLES` выводится из карты, а не пишется руками. Два сторожа: shared (карта ↔ `TABLE_REQUIREMENT` ↔ backstop; неизвестная таблица закрыта) и backend (`syncTableOwnership.guard.test.ts` — объявленная построчная проверка существует в `applyPushBatch`, presence не читает клиентский payload, `audit_log` не перезаписывает). Обе дыры закрыты: `erp_reg_stock_*` — `server` (клиент режется до подписи любой ролью), `audit_log` — append-only (актор из сессии, `deleted_at` с клиента не принимается, повторный пуш подтверждается серверной копией строки, чтобы очередь не зациклилась и фан-аут не разошёлся с PG). Табличный дефолт перевёрнут в fail-closed (`?? superadmin`). Снимок и покрытие — [`WRITE_DOORS.md`](WRITE_DOORS.md).
