# 🟡 Застрявшее автообновление парка (было: осталась ОДНА машина PC20) 🗓 since:2026-07-17

**Перепроверено 2026-11-21: застрял не PC20, а весь парк.** Снято состояние по прод-данным (`client_settings`): машин на Windows — **74**, и **ни одна не на 3.140.0**; 3.139.0 — две (PC79, Computer), 3.136.0 — семь, 3.135.0 — одна, 3.134.0 — шесть (включая PC20), 3.89.0/3.90.0 — четыре. Причина прежняя и общая для всех: клиент со скачанным отложенным обновлением переставал искать более новое (`chooseUpdateFlow` появился только в 3.139.0, `6d88e925`), то есть программа не перезапускалась — а «Перезапуск» в шапке появился только в 3.139.0, но и он не помогает, пока версия старая.

**PC20 (машина оператора `alvina`):** жива, `client_id=PC20-a0327b8a-…`, версия была **3.134.0**, heartbeat 21.11 19:13Z. В слоте команды с **16.09** висел `reset_sync_state_and_pull` (`97f1da41-…`) — из-за него автолечение скипало с `reason: pending_request`, и любая новая команда (в т.ч. `reinstall`) не доставилась, пока слот занят. Сторож на машине есть (версия > 2026.622.1241) — канал «сервер → машина» работает, но починить его можно было только перезаписью слота.

**Что сделано (21–22.11, решение владельца):**

- **Правило владельца** «программа не перезапускается долгое время + отставание от последнего релиза ≥ 2 версий → принудительное обновление в 12:30 МСК» — домен `shared/src/domain/forcedUpdate.ts` (+18 unit-тестов), серверная джоба `backend-api/src/services/forcedUpdateService.ts` (+8 тестов). Доставка — существующая команда `reinstall`, её исполняет внешний сторож.
- **Тихая установка теперь поднимает программу** (`electron-app/installer/installer.nsh`): electron-builder в режиме `/S` приложение не запускал, и после принудительного обновления машина оставалась бы с установленной, но не запущенной программой.
- **Скрипт докачки** переписан на сверку по манифесту (`scripts/prod-ops/fetch-client-artifacts.sh`): сверка `size`+`sha512` exe из `latest.yml` и `sha256` всех трёх файлов по цифрам релиза (digest ассетов в GitHub API). Прежняя версия сверяла размеры манифеста и blockmap константами прошлого релиза.
- **Выкат v3.141.0 (22.11):** бэкенд 3.141.0 на обоих инстансах, артефакты клиента и APK разложены, сервер отдаёт 3.141.0 (exe и blockmap — 200).
- **PC20 обновлена:** 02:39 перезаписан слот (`reinstall`), 02:53 сторож поставил 3.141.0, программа поднялась сама, слот очищен (`ackStatus: ok`), клиент отчитывается версией 3.141.0.

**Открыто:** первый проход правила в 12:30 МСК — **посмотрен 22.11, проход отработал**: критическое событие `client.forced_update_sweep` от 22.11 12:30:07 МСК — «по правилу владельца (отставание не меньше 2 версий) обновление получили **1 машина: PC79 (3.139.0 → 3.141.0)**». Это ожидаемо: в проход попадают только живые машины (heartbeat не старше часа), а парк в 12:30 спал; остальные уедут следующим днём. В журнале бэкенда строки `forced update sweep` в `journalctl` не оказалось (лог идёт в `logs/critical-events.ndjson`) — искать надо там.

**Открыто (шаг владельца):** чистка старого APK `MatricaRMZ-3.140.0.apk` (48 МБ) на проде — решение владельца от 10.11 разрешает её без вопроса, но локальный гейт прав не пускает удаляющую команду (`HOST_CAPABILITY_UNAVAILABLE`) и обходить его нельзя ([пункт](chistka-staryh-apk-na-prode-gate-ne-puskaet.md)). Файл безвреден: сервер отдаёт только свежайший APK, свободно ~2,4 ГБ.
