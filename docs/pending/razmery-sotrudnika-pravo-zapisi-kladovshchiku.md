# Размеры сотрудника: право на запись — кладовщику или только кадровику 🗓 since:2026-11-19

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «🔴 Блокеры / ⏳ Ждёт внешнего окна / события»

## Суть

Промт КАРМАНА #40 (18.11.2026): «Данные, которые подтягиваются в карточку СИЗ из карточки сотрудника (структурное подразделение, размеры), должны редактироваться прямо в карточке СИЗ». Сделано 19.11.2026 (план — [`siz-card-employee-crosslink-2026-11.md`](../plans/siz-card-employee-crosslink-2026-11.md)): правка из карточки СИЗ пишет **в карточку сотрудника**, право — то же, что и в самой карточке сотрудника (`employees.create`).

**Открытый вопрос — решение за владельцем:** кто должен править фактические размеры сотрудника (`ppe_size_clothes`, `ppe_size_shoes`, `ppe_height`).

## Почему это отдельное решение

Сейчас размеры не может записать **никто, кроме кадровика**: у кладовщика нет ни одного права на запись в карточку сотрудника (все записи идут через единственную дверь `employees:setAttr` → `saveEmployeeCardGated`, гейт — `employees.create`; исключение есть только для должности — узкое право `employees.position.edit`).

Практика: кладовщик меряет сотрудника при выдаче СИЗ и **знает** размер — но записать его не может, и в программе он появляется только руками кадровика (или из импорта ЗУП). Это делает ветку «размеры редактируются прямо в карточке СИЗ» полезной ровно настолько, насколько у кладовщика есть право на запись в карточку сотрудника.

## Если ответ «кладовщику» — что нужно доделать (один проход)

1. **Новое узкое право** — например `employees.sizes.edit` (прецедент `employees.position.edit`), выдаётся роли `storekeeper` в `OPERATOR_ROLE_EDIT` (`shared/src/domain/permissions.ts`).
2. **Гейт IPC** — `electron-app/src/main/ipc/register/employees.ts`: для кодов `ppe_size_clothes`/`ppe_size_shoes`/`ppe_height` принимать это право наравне с `employees.create`.
3. **Исключение из гейта раздела «Персонал»** — `electron-app/src/main/ipc/sectionGate.ts` (`isPositionWrite` — образец: у кладовщика нет editor'а раздела, а право узкое).
4. **Серверный гейт синка** — `shared/src/domain/ledgerAuthz.ts`: для этих атрибутов `own_employee_any` с правом `employees.sizes.edit` (иначе клиент запишет, а сервер отобьёт).
5. **UI** — карточка СИЗ уже показывает и правит размеры; права хватит, чтобы кладовщик увидел поля редактируемыми.

## Чего делать нельзя

- Расширять `employees.create` кладовщику (открывает кадровую карточку целиком).
- Давать право на запись любых атрибутов карточки сотрудника вместе с размерами.

**Итог сейчас:** правка размеров из карточки СИЗ работает у того, кто ведёт кадровую карточку; у кладовщика поля только для чтения.
