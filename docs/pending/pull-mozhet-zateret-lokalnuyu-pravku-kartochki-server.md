# 🟡 Pull может затереть локальную правку карточки: сервер не говорит, какую строку отклонил по LWW 🗓 since:2026-10-20

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «🟡 Техдолг и отложенное»

Первый сейв больше не теряется (M163 — зеркало не заводит пустую строку), но второй канал той же потери оставлен намеренно: `upsertPulledRowsInChunks` в `electron-app/src/main/services/syncService.ts` применяет приехавшую строку **безусловно** (`set: { …excluded, syncStatus: 'synced' }`), поэтому pull может затереть локальную строку, которая ещё `pending` (не отправлена).

- **Почему не сделано сразу:** наивный гард «не перезаписывать `pending`» сохраняет данные, но при LWW-отказе сервера локальная строка навсегда остаётся `pending` — расхождение вместо потери, и оператор видит значение, которого нет у парка.
- **Что сделать:** (1) в ветке карточек `applyPushBatch` на отброшенную LWW строку отдавать явный `addSkippedRow({ table, row_id, reason: 'conflict' })` (сейчас только `logSkip` + метрика); (2) в клиенте по этому сигналу брать серверную копию, а не кворантинить; (3) поверх — `setWhere: sync_status <> 'pending'` в pull для `erp_engine_cards`; (4) guard-тест: pull не перезаписывает `pending`, но перезаписывает `synced`.
