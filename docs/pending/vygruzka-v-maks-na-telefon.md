# 🟡 «В МАКС на телефон» из вложений: канал не подключён 🗓 since:2026-11-26

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «🟡 Техдолг и отложенное»

## Что это

Заявка владельца от 25.11.2026 (промт КАРМАНА #160, «Контекстное меню над файлами:
почта, печать, ИИ, коллега»): в меню действий над файлами должен быть пункт
**«в МАКС на телефон»** — отправить выбранные файлы сотруднику в мессенджер MAX.

Пункт **не сделан и в меню не показывается**: канала отправки файлов в МАКС нет.
Показывать его было бы враньём — оператор нажмёт и будет ждать отправки, которой
не случится (ровно тот класс, который закрыт сторожем набора действий:
`components/FileActionsMenu.test.ts` — «пункта „в МАКС“ нет»).

## Что уже есть в программе (проверено 26.11.2026)

* **Канал МАКС у программы есть, но только для критических событий** —
  `backend-api/src/services/criticalEventsMaxService.ts`. Он ходит в
  **MAX Bot API** (`https://platform-api2.max.ru/messages?chat_id=…` или
  `?user_id=…`, заголовок `Authorization: {access_token}`) и умеет **только
  текст**: тело запроса — `{"text": "..."}`.
* **Токен и адресат** — `MATRICA_MAX_ALERT_TOKEN` / `MAX_ALERT_CHAT_ID`
  (или `MAX_ALERT_USER_ID`), либо ключи `MAX_ALERT_TOKEN` в комнате КАРМАНА.
  Это ОДИН адресат для тревог, а не сотрудник поимённо.
* **Профиль сотрудника хранит `maxLogin`** (`max_login` — атрибут карточки
  сотрудника, `employeeAuthService.ts`; в программе его заполняет «Настройки»).
  Это логин, а не идентификатор диалога в МАКС.
* **Отправки произвольных файлов и сообщений сотруднику в МАКС нет** — ни в
  клиенте, ни на сервере.

## Что потребуется от канала, когда его подключат

1. **Файлы, а не только текст.** Нынешний контракт канала — `{"text": …}`.
   Для пункта «в МАКС» нужен документ: либо эндпоинт загрузки файлов MAX Bot API
   с последующей отправкой, либо документированный способ передать файл
   сообщением. Пока этого нет — отправлять нечего, даже если адресат известен.
2. **Адресация сотрудника.** `maxLogin` — логин, а канал говорит по
   `chat_id`/`user_id`. Нужно либо уметь открыть личный диалог по логину, либо
   хранить у сотрудника идентификатор диалога в МАКС (и уметь его получать).
   Без этого «отправить сотруднику» превращается в «отправить тревогу тому, кто
   настроен получателем тревог».
3. **Подключение канала для сотрудников Матрицы.** Токен тревог — не токен
   личных отправок: у аварии и у «отправить файл коллеге» разные адресаты и
   разные последствия. Решение владельца: отдельный канал/бот или тот же бот с
   разными адресатами.
4. **Лимиты.** У платформы — не больше 2 сообщений в секунду в один диалог и
   30 rps на бота; отдельно ограничен размер файла. Плюс файл нужно сначала
   забрать с сервера Матрицы (у вложения карточки своего пути на диске нет) —
   это ещё один шаг и ещё одна точка отказа.

## Как закрывать

1. Взять готовый пункт в общий набор (`components/FileActionsMenu.tsx`,
   `FILE_ACTIONS`) — **не заводить второй набор действий**.
2. Реализовать дверь отправки на сервере (адресат по `maxLogin`, файл из
   серверного вложения через `files.meta`/скачивание — с проверкой доступа).
3. Пункт появляется в меню только после того, как канал отвечает: проверка
   доступности — тем же механизмом `available`, что и у остальных пунктов.
4. Оператору говорить результат: файл ушёл в МАКС или канал недоступен — с
   причиной (как у остальных действий над файлами).
