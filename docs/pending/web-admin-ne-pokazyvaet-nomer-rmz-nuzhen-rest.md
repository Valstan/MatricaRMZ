# 🟡 web-admin не показывает номер РМЗ: нужен REST-ответ с номером 🗓 since:2026-10-28

**Статус:** 🟡 техдолг, follow-up серии «сквозной номер РМЗ» (#1493–#1499).

## Что не закрыто

Периметр серии (#1499, brain #166) прошёл по всем дверям клиента: список двигателей, карточка, этапы работ, наряды, платежи, складские отчёты, пикер отчётов, прогноз сборки, поиск, бирка печати. Везде номер карточки (`RMZ451`) — запасной: он называет двигатель только когда нет документного и внутреннего.

**Веб-админка осталась без номера вовсе.** Причина техническая, а не забывчивость: `web-admin` читает двигатели REST-ом (`web-admin/src/api/masterdata.ts`), а не клиентской репликой `erp_engine_numbers`. Клиентской подстановкой там номер не появить — админка не получает реплику.

## Что нужно

1. Серверный ответ списка/карточки двигателя (`backend-api`) — поле с номером карточки: `erp_engine_numbers` уже лежит в PG, join по `entities.id` двигателя.
2. В `web-admin/src/ui/EnginesPage.tsx` — колонка «РМЗ» третьей подряд (как в клиенте), в карточке двигателя — поле только для чтения.
3. Правило подстановки — то же: РМЗ не вытесняет документный номер, а стоит рядом/подставляется при его отсутствии.

## Почему не в этой серии

Серверный REST-ответ — отдельная граница (контракт API + права), и мешать её с клиентским периметром значило бы делать в одном PR две несвязанные вещи. Планшет, в отличие от админки, покрыт сам: он рендерит общий `renderer`, а `ANDROID_TABS` включает `engines`.
