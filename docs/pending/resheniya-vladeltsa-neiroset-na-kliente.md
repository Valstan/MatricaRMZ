**Откуда пункт.** Промт КАРМАНА **#176** («Нейросеть на клиенте: аккаунты из Кармана по надобности и
действия по данным») отдал владельцу шесть развилок. Все шесть **закрыты по умолчанию** 27.11.2026
(делегировано) — по правилу промтов КАРМАНА «развилки, которые промт отдал владельцу, закрыть по

План нитки — [`../plans/local-agent-accounts-on-demand-2026-11.md`](../plans/local-agent-accounts-on-demand-2026-11.md).

## 1. Подтверждать ли запись перед действием

**Развилка.** Агент получил данные (список номеров, Excel, Word), проверил, что уже есть, и зовёт
действие приложения. Нужен ли вопрос «добавить 12 двигателей?» перед записью — или доверять агенту?

**По умолчанию (27.11.2026):** **подтверждать.** Пока в чате нет явной команды оператора («добавь 12»),
агент готовит список и спрашивает: сколько добавить, что отклонено и почему. При явной команде —
добавляет без лишнего вопроса.

**От владельца:** всегда спрашивать / спрашивать только без явной команды / не спрашивать никогда.

## 2. Кто выполняет действие агента и расширять ли мост к реплике

**Развилка.** Мост «реплика → локальный агент» отдаёт агенту только чтение — писать в реплику он не
может, и это сделано намеренно (база завода под защитой). Значит, действовать агент должен через
приложение. Расширять ли мост?

**По умолчанию (27.11.2026):** **мост не расширяем.** Агент читает сам, действие зовёт через приложение
(реестр действий программы), запись идёт существующими дверями программы с проверкой прав. Агент не
пишет в реплику мимо моста.

**От владельца:** оставить как есть / расширить мост на запись (меняет модель безопасности, а не
деталь реализации).

## 3. Сколько аккаунтов держать и что при двух заданиях сразу

**Развилка.** Аккаунт пула — конечный ресурс. Живёт ли взятый аккаунт до конца задания или
возвращается сразу? Нужен ли второй аккаунт, если заданий два?

**По умолчанию (27.11.2026):** **до конца задания**; при простое запросов к пулу нет вовсе (так уже в
коде: единственный путь к пулу — из `aiChat:create`); **два задания — один аккаунт по очереди**, второй
не берём.

**От владельца:** держать до конца задания / отпускать сразу после ответа; один аккаунт по очереди /
по аккаунту на задание.

## 4. Что уходит в облако вместе с вопросом

**Развилка.** Агент читает локальную реплику, а запрос в нейросеть уходит наружу: номера двигателей,
названия заказчиков, детали. Что можно отправлять?

**По умолчанию (27.11.2026):** **только то, что оператор и так отправил в чат** — текст вопроса и
файлы, которые он приложил сам. Ничего дополнительно из базы в запрос не подмешиваем. База завода
наружу не уходит: агент читает локальную реплику через read-only мост.

**От владельца:** подтвердить ограничение или назвать состав, который можно отправлять целиком.

## 5. Клиентский агент не видит данные других машин

**Развилка.** Клиентский агент видит только свою реплику; серверные инструменты ИИваныча ему
недоступны. Часть задач (сводка по другим машинам) на клиенте не закроется.

**По умолчанию (27.11.2026):** **принимаем ограничение.** Сводки по другим машинам считает серверный
контур. Отдельный путь не заводим, пока владелец не попросит.

**От владельца:** принять ограничение / описать отдельный путь (правка прав и отдельная нитка).

## 6. Порядок внедрения кнопок нейросети по разделам

**Развилка.** «Кнопка нейросети в каждом разделе» — много работы, и в каждом разделе своя проверка
данных. Какой раздел первым?

**По умолчанию (27.11.2026):** **производственная программа** (добавление двигателей списком — там
проверка дублей уже есть и однозначна) → **двигатели** → **дефектовка** → **склад и номенклатура** →
**заказы и контрагенты** → **наряды и производство**.

**От владельца:** утвердить порядок или назвать другой.
