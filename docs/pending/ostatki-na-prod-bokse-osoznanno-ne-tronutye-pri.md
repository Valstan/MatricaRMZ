Техобслуживание по мандату владельца выполнено (см. [письмо brain'у](../mailbox/to-brain/2026-08-30-box-maintenance-done-updater-was-blind-since-may.md)). Три вещи найдены и **оставлены намеренно**:

1. **19 базовых 32-битных библиотек** и сама foreign-архитектура. После сноса Wine они ни от чего не зависят, но `apt` требует для них `--allow-remove-essential` — на живом проде ради ~60 МБ такой флаг не оправдан. Снимать только вместе с плановым окном.
2. **Пакеты samba** (7 штук, службы не запущены, поставлены при первичной настройке). Мало места, ненулевой риск — трогать без нужды не стоит.
3. **Ретенция обновлений — механизмов оказалось три** (решение владельца 01.09: одна работа — один механизм, живёт тот, что в git). Политики сравнены 03.09: из внерепозиторного `matricarmz-updates-prune` (ежедневно, `KEEP_COUNT=1`, файл от февраля) в репозиторный `cleanup-updates.sh` перенесено полезное — удаление `.blockmap` вместе с установщиком и подбор осиротевших карт. **Осталось на проде, ждёт OK владельца (#025):** `sudo systemctl disable --now matricarmz-updates-prune.timer && sudo rm /etc/systemd/system/matricarmz-updates-prune.{timer,service} /usr/local/bin/matricarmz-updates-prune && sudo systemctl daemon-reload`, затем `bash deploy/systemd/install.sh` для свежего `cleanup-updates.sh`. Третий двойник того же класса (#200) — `matricarmz-nightly-backup.timer`: скрипт в git, **юнит вне git**; не трогать, пока не заработает репозиторный шифрованный бэкап (см. 🔴 выше), потом решить, нужен ли второй pg_dump за ночь.
4. **PostgreSQL сидит на зоне `Host`** (найдено 05.09 по мандату brain'а про tzdata, [письмо](../mailbox/to-brain/2026-09-05-apt-is-clean-zone-is-moscow-on-disk-and-in-debconf-but-postgres-still-points-at-host.md)): в `postgresql.conf` `timezone = Host` и `log_timezone = Host`, файл `/usr/share/zoneinfo/Host` положен хостером (2024-02-18), не пакетом. Система при этом на `Europe/Moscow` и на диске, и в debconf — `apt`/`dpkg-reconfigure tzdata` ничего не сдвинут. **Файл `Host` не удалять** — PG перестанет стартовать. Перевод на `Europe/Moscow` — отдельная работа в окно: сверить содержимое `Host` с `Europe/Moscow` (`diff`), `SHOW timezone` до, `ALTER SYSTEM SET timezone/log_timezone` + `pg_reload_conf()`, `SHOW` после; вывод `timestamptz` и логи не должны сдвинуться.
