# ⏳ Прод-бэкфилл цехов программ: ждёт решения владельца (рантайм не пускает к прод-БД) 🗓 since:2026-11-24

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «⏳ Ждёт внешнего окна / события»

Связь цеха программы со справочником (`workshop_id`) введена в коде (**PR #1983**, релиз **v3.145.0**),
миграции `0140` (сервер) и `0042` (клиентская реплика) накатаны на прод. Осталась одна запись,
которую по правилу нельзя делать без слова владельца: **проставить связь старым программам,
у которых цех записан текстом** («Цех № 1»).

**Скрипт готов и лежит в репозитории** (`backend-api/src/scripts/backfillProductionProgramWorkshop.ts`,
команда `production-programs:backfill-workshop`):

```
# на проде, в ~/MatricaRMZ:
corepack pnpm -F @matricarmz/backend-api production-programs:backfill-workshop            # сухой прогон — список
corepack pnpm -F @matricarmz/backend-api production-programs:backfill-workshop -- --apply # запись: только однозначные
```

**Правило (уже в коде, D-238 / G659 / G660):** связь ставится **только** при однозначном совпадении
имени со справочником (регистр, «ё», «№», лишние пробелы не важны). Неоднозначные (два живых цеха
с одинаковым именем) и несовпавшие — не угадываются, они попадают в отчёт и ждут решения владельца:
завести в справочник новый цех, переименовать или привязать вручную. Снимок имени (`shop`) при этом
не трогается — печать и выгрузка идут по нему, образец «Цех № 1» должен уйти как раньше.

**Почему не сделано в этой сессии:** рантайм агента режет **любой** доступ к прод-БД — и `psql`,
и скрипт бэкфилла, и любой прогон по прод-базе, даже «на чтение». Это ограничение инструмента,
а не решение по существу: правило однозначного совпадения соблюсти можно, нужно лишь место,
где команда разрешена. Поэтому и сухого списка по продовым цехам у нас нет — приложить нечего.

**Как закрыть:** прогнать сухой прогон на проде, показать владельцу список (однозначные / неоднозначные /
несовпавшие) и применить однозначные. Отчёт владельцу — письмом в `mailbox/to-brain/`
(заказ от 24.11.2026, нитка «ПП: наложение полей, цех из базы, перетаскивание»).

**Проверено:** на дев-БД скрипт отработал — 1 программа, 1 однозначное совпадение («Цех № 1» → «Цех №1»),
связь `workshop_id` проставлена, снимок имени сохранён. На проде не гоняли (см. выше).
