# 🟡 Журнал релизов не пополняется с 3.54.0: токен публикации протух 🗓 since:2026-10-28

**Статус:** 🟡 техдолг. Шаг 9 релиза (`corepack pnpm release:ledger-publish X.Y.Z`) не работает, но выкат не блокирует.

## Что происходит

На проде `release:ledger-publish 3.91.0` падает:

```
Ledger publish failed 401: {"ok":false,"code":"token_invalid","error":"invalid token"}
```

`MATRICA_LEDGER_RELEASE_TOKEN` в `/etc/matricarmz/matricarmz.env` — **не вечный ключ, а обычный access-token** (`signAccessTokenWithTtl` в `backend-api/src/routes/auth.ts`, TTL по умолчанию 168 часов, максимум 720). Он выдаётся в web-admin (Admin → Release token) и протухает молча.

**Последняя запись в `release_registry` — 3.54.0.** Значит шаг падает не первый раз: с 3.55 по 3.91 журнал пуст, 37 выпусков.

## Почему это не заметили

Шаг стоит **после** выката (`deploy-backend.sh` уже разложил `dist`, сервисы поднялись). Падение публикации не мешает клиентам: обновление работает через `latest.json` от `updateTorrentService`, а `release_registry` в парке **никто не читает** — ни `electron-app`, ни `shared`, ни `web-admin` (проверено грепом; таблица отдаётся только эндпоинтом `ledger/state`). То есть это бухгалтерия релизов, и её отсутствие никого не будит.

## Что нужно решить

1. **Держим журнал?** Если да — токен с длинным TTL (720 ч) и **дата в календаре `PENDING_FOLLOWUPS`** на его перевыпуск: иначе он снова протухнет молча. Либо отдельный долгоживущий ключ публикации вместо access-token — тогда `auth/release-token` перестаёт быть источником.
2. **Догонять пропущенное?** Нет: `release_registry` — история, а не состояние. Записи 3.55–3.91 задним числом ничего не восстановят.
3. **Или снять шаг из релизного чеклиста**, если журнал не нужен: шаг, который умеет падать в тишину, хуже отсутствующего (brain #125 — «зелёный гейт маскирует красный»).
