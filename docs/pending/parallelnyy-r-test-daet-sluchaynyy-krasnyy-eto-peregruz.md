# Параллельный `-r test` даёт случайный красный — это перегруз, а не три бага 🗓 since:2026-08-22

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «🟡 Техдолг»

За 22.08 полный `corepack pnpm -r test` покраснел трижды, и каждый раз **в другом тесте другого пакета**:

| Тест | Пакет | Одиночный прогон |
|---|---|---|
| ~~`boot.test.ts` → «без логина SyncManager честно отказывает»~~ | ~~android-app~~ | **закрыто 14.09 — был настоящий баг** |
| `workOrderNumberImmutable.test.ts` → «first save materializes the row» | electron-app | 11 из 11 зелёных |
| `diagnosticsAutohealService.test.ts` → «skips when server snapshot is unknown» | backend-api | 7 из 7 зелёных (сам тест идёт 4.7 с) |
| `clientOpsArchive.test.ts` → «читает и архив с именами в UTF-8» (21.10) | electron-app | 7 из 7 зелёных за 0.8 с; в пакете падает по таймауту ~10 с — тест зовёт `7za` синхронно и под нагрузкой не укладывается |
| `engineStrictView.test.ts` → «первый сейв виден сразу, без синк-круга» (21.10) | electron-app | 6 из 6 зелёных за 1.5 с; в пакете — таймаут 5 с |

**Один из трёх оказался не перегрузом** (14.09, GOTCHAS **M128**): у android-теста было общее состояние — файл сессии. Посылка «у android sidecar шимится в no-op» была неверной: шим стоял только на браузерном таргете, в vitest работал настоящий `sessionSidecarStore` на `node:fs`, а фиктивный `app.getPath` сводил всех параллельных воркеров в один файл `<диск>:\android\appData\MatricaRMZ\auth-session.json` (искали его в `%APPDATA%` — потому и «не тронут»). Лечится шимом в vitest; сторож — `authOverShims.test.ts`.

Оставшиеся два по-прежнему выглядят перегрузом: общего состояния у них не видно (у electron БД `:memory:` на каждый вызов, у backend свои моки), зато общее есть у прогона — `pnpm -r` запускает четыре пакета разом, каждый со своим пулом потоков vitest, на **четырёхъядерной** машине. Но урок android-случая в силе: **сначала искать общий ресурс, и только потом списывать на тайминг**.

**Проверено:** `corepack pnpm -r --workspace-concurrency=1 test` — зелёный целиком, 9 мин 21 с против ~2 мин у параллельного. CI (машина крупнее) зелёный на всех трёх PR этой сессии.

Что это значит: пере‑разбирать каждый тест по отдельности, скорее всего, бесполезно — искать надо не «баг в тесте», а тайминг-зависимости, которые перегруз проявляет. Кандидаты первого ряда: тесты, чья длительность измеряется секундами (backend-овский — 4.7 с).

Файл действительно был не тронут — потому что тесты писали **другой** файл, по фиктивному пути шима, и искать надо было не в `%APPDATA%`. Подозрение на `memorySession` + незаawait'енный `flushPendingEngineReservationReleases` (`syncManager.ts:107`) не подтвердилось.
