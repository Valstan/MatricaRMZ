# Ложные «Возвраты» в этапах ремонта на проде — пересчёт скриптом, нужно ОК владельца 🗓 since:2026-10-22

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «⏳ Ждёт внешнего окна / события»

Слово владельца 22.10.2026: при создании этапа «задним числом» программа сама помечала
«Возврат, проход № 2», если в тот же день уже стояли этапы выше по линейке. Внутри суток
порядок канонический (по приоритету линейки) — очерёдность ввода его не меняет, поэтому
пометка была ложной. **Код починен** (#1454): свидетельством возврата теперь считается только
этап верхнего ранга, стоящий строго раньше по дням.

**Что осталось на проде.** Уже накопленные ложные пометки (`meta.repeat.pass ≥ 2` без
`reason`, поставленные системно) в базе лежат — правка кода их не трогает. Снимает их
существующий серверный скрипт `stages:recount-passes` (тот же предикат, что и при записи):

```bash
corepack pnpm -F @matricarmz/backend-api stages:recount-passes            # dry-run: список строк
corepack pnpm -F @matricarmz/backend-api stages:recount-passes -- --apply # запись
```

⚠️ **`--apply` — запись в прод-данные: только после того, как владелец увидел конкретный
список из dry-run** (гейт #025). Скрипт снимает только системные пометки (без `reason`);
операторские подтверждения не трогает, ничего не добавляет, идемпотентен (повторный прогон
обязан показать 0). Фильтр по одному двигателю: `-- --engine <uuid>`.
