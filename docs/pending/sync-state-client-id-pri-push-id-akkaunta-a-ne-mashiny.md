# 🟡 `sync_state.client_id` при push — id аккаунта, а не машины (GOTCHAS M102) 🗓 since:2026-09-04

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «🟡 Техдолг»

`syncWriteService.ts` отдаёт в `applyPushBatch` `client_id: actor.id`, pull пишет настоящий `clientId`. Итог: у машин `last_pushed_at` всегда `NULL` (колонка «Последняя отправка» в отчётах пуста), а «аккаунты» выглядят как машины-призраки, которые только пушат (7 таких за неделю на 04.09). ✅ Закрыто кодом (ветка fix/push-client-id). Уточнение к посылке: клиент `client_id` НЕ слал — в теле `/ledger/tx/submit` его не было вовсе; добавлен опционально (Android наследует общий `runSync`), сервер тянет его через `applyLedgerTxs → writeSyncChanges → applyPushBatch` с откатом на id (старые сборки и серверные писатели — как раньше). Миграция `sync:merge-account-rows` (dry-run по умолчанию, идемпотентна): однозначные (ровно одна машина с логином аккаунта) — перенос max(`lastPushedAt`) + удаление, остальные (нет машин / несколько / ничейный uuid) — удаление, машины и служебные (`system`, `ledger-replay`, …) — нетронуты. Замер прода 11.10: 162 строки, 28 uuid-only (27 в `users`, 1 ничейный); из них 8 однозначных. Потребители проверены чтением: ключуются generic-id, правок не требуют (`logSkip` — только громкость лога). Тесты: `pushClientId.test.ts` (plumbing + откат) и `mergeSyncStateAccountRows.test.ts` (7, план слияния) + `client_id` в android-смоуке (сквозное доказательство отправки); подрывы пройдены. Dry-run скрипта прогнан на dev-БД (exit 0). Остаток — прогнать dry-run и `--apply` на проде окном владельца (строки вернутся, пока парк на старых сборках; после обновления парка — повтор до пустого плана).

**Смежное, закрыто в коде 04.09 (ждёт релиза 3.20.0):** PC19 неделю пушил 8 нарядов на 4 двигателя, которых нет на сервере (`f85e51fd…`, `8841e8c5…`, `bb8efc66…`, `274c5d87…`), каждые 22 с, без ошибки на экране: пропущенные как `missing_dependency` строки оставались `pending`. Клиент теперь возвращает зависимость в очередь, если она есть локально, иначе помечает строку `error` (`sync/dependencyRequeue.ts`, 5 тестов). **После обновления PC19 проверить:** в журнале сервера пропала серия `dependency rows skipped … user: mubvera`; на сервере появились эти 4 двигателя (тогда это был M52) — либо у mubvera в диагностике 8 нарядов в `error` (тогда двигатели существовали только в старом профиле и их надо завести заново).
