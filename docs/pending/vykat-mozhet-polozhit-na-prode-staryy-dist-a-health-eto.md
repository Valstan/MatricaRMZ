# 🔴 Выкат может положить на проде старый dist, а `/health` это замаскирует 🗓 since:2026-09-30

Случилось на релизе 3.53.0: `deploy-backend.sh` без аргумента берёт «последний успешный прогон `backend-dist`», и запрос `gh run list` на боксе вернул прогон **29.09** — на сервер лёг код 3.52.0. Признак был один, и скрипт его напечатал: `ВНИМАНИЕ: собранное и исходники в клоне — с разных коммитов`. Ни `/health`, ни `/updates/status`, ни раздача инсталлятора, ни диспетчер этого не показали: `backendVersion` читает `package.json` **из клона**, а не из артефакта, поэтому `/health` отвечал `3.53.0` при отсутствующем коде. Перевыкат по run-id исправил, приёмка прошла. Подробности — GOTCHAS **M148**.

Два укрепления (обе — правки кода, а не разовая ручная привычка):

1. **`deploy-backend.sh` должен отказывать при расхождении коммитов**, а не только предупреждать: сделать «выкатываем предыдущую сборку намеренно» явным флагом (`--allow-older`), иначе `exit 1` до замены `dist`. `deploy-backend.test.sh` гоняется локально (16 проверок) — дописать случай с расхождением.
2. **`/health` должен отвечать версией исполняемого кода**, а не клона: `backendVersion` читает `require('../package.json')` рядом с `dist/`, то есть попадает в git-клон. Нужно вшивать версию и sha в артефакт (шаг сборки `backend-dist.yml` + чтение из `process.env`, клоновое значение — запасным) и отдавать `buildSha` в ответе: тогда расхождение видно прямо в приёмке.

Пока не сделано — **в выкате передавать run-id явно** и читать строку «с разных коммитов» как стоп.

**Рецидив 05.10 (релиз 3.65.0, мандат D-111):** тот же класс, другой путь — выкат 11:01 шёл с **явным старым run-id** (`37187430570`, v3.61.0), а не со stale-выдачей `gh run list`. Доказательства: md5 живого `dist/index.js` побайтово равен снепшоту 09:48, ctime 11:01:23, файлов моста в dist не было вовсе, после рестарта 11:01 — ни одной bridge-строки, `/health` — 3.65.0 из исходников. Вылечено перевыкатом 12:56 прогоном `37280935779` (#1175) + `ledger-publish 3.65.0`; dry-прогон моста после этого зелёный. Вывод для укреплений: сверка headSha прогона с HEAD клона обязана работать и при явном run-id — иначе явный id остаётся легальным обходом будущего гейта.
