# 🟡 Сеть VPS рвётся круглосуточно: Telegram, клиенты и ssh — один и тот же путь 🗓 since:2026-09-09

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «🟡 Техдолг и отложенное»

Замер 09.09: отказы опроса Telegram (`telegram unreachable after 2 attempts: TimeoutError`) идут **1–7 в час непрерывно двое суток** (07.09 17:00 → 09.09), клиенты парка ловят `ERR_CONNECTION_TIMED_OUT` пачками по 3–4 машины в одну минуту (12:03, 15:59, 16:22), в те же часы отваливается по таймауту собственный `ssh` на прод. Сервер при этом чист: рестартов нет, ошибок нет, `load average 0.05`, оба сервиса живы с 00:37.

То есть **это хронический фон канала (~60–70 отказов в сутки), а не происшествие**, и «21 сбой за 12 часов» в ночной тревоге — обычная норма этого бокса, а не симптом сбоя конвейера. Продолжение линии M101 (потеря половины TCP-SYN на сети хостера, закрытая ретраями 04.09): ретраи лечат Telegram, но клиентам парка их никто не выдал. Следующий ход — хостер, не код; кодом можно только смягчить (ретрай/бэкофф на стороне клиента).

**Замер 31.10.2026 (тот же симптом, с конкретикой):** после успешного выката 3.98.0 путь на прод лёг — 10+ попыток подряд, `ssh matricrmz` → «Could not resolve hostname matricarmz», по прямому IP `195.161.41.30` TCP на 22 **открыт** (`Test-NetConnection` → True), но SSH-сессия не устанавливается (зависает, обрывается по keepalive). То есть падает не handshake, а payload — картина того же «полпути». Побочно вскрылось: **алиас `matricarmz` в `~/.ssh/config` не имеет `HostName`** (`hostname matricrmz`, user `valstan`), то есть он ждёт DNS-имя, которого **нет в hosts-файле** (там одна непустая строка, про `matricarmz` — ни одной). Пока DNS отдаёт это имя — ssh работает; когда не отдаёт — падает. **Дешёвое облегчение на своей стороне:** вписать `195.161.41.30 a6fd55b8e0ae.vps.myjino.ru matricrmz` в hosts (нужны права администратора) — тогда алиас перестанет зависеть от DNS. Хостера это не лечит, но убирает половину симптома.
