# 🟡 Форс-килл клиента в установщике — сделать безусловным 🗓 since:2026-08-04

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «⏳ Ждёт внешнего окна / события»

Следствие M59. Сейчас `KillClientProcesses` (`electron-app/installer/installer.nsh`) пробует мягкий `taskkill /IM`, а `/F` применяет только после `MessageBox`, у которого автоответ `/SD IDYES` работает **лишь в silent-режиме**. Проверено на PC40: мягкий kill Electron не берёт вовсе (5 процессов пережили его). Итог — при ручной установке диалог ждёт человека, а если его не дождаться, оператор остаётся на прежней версии при формально успешной установке.

Правка на вид однострочная, но это `installer.nsh` — не ловится ни линтером, ни тестами, и уже дважды прятала блокеры (`writeShortcutLink('replace')`, затирание кода возврата в `CheckClientRunning`). Поэтому отдельным PR со своей живой приёмкой, не «заодно». Сборка тестового установщика без публикации: `gh workflow run release-electron-windows.yml --ref <ветка>` (рецепт — в [`machines/PC40.md`](machines/PC40.md)).

Что проверить на первой машине после обновления:
- `schtasks /Query /TN "MatricaRMZ\Watchdog Periodic" /V` — путь `/TR` указывает на `Programs\MatricaRMZ-Watchdog`, задача существует (на rmz4val исторически была только Periodic — проверить и Logon);
- бинарь лежит в `%LOCALAPPDATA%\Programs\MatricaRMZ-Watchdog\`, из `%APPDATA%\MatricaRMZ\` исчез (данные сторожа — handshake/лог/состояние — остаются там же);
- кэш обновлений создан в `%LOCALAPPDATA%\Programs\MatricaRMZ-Updates`, старый каталог в «Загрузках» удалён клиентом при первом запуске;
- `%APPDATA%\MatricaRMZ\watchdog.log` без `falling back to reinstall` и без повторяющихся переустановок;
- **отдельно проверить починку ярлыков:** удалить оба `.lnk` при закрытом клиенте → дождаться прохода сторожа (≤15 мин) → ярлыки вернулись **без** переустановки. Это ветка, где ревью нашло блокер (`writeShortcutLink('replace')` не создаёт отсутствующий ярлык — исправлено на `'create'`, проверено эмпирически, но на живой машине не гонялось).
