# Пересадить 3 живых legacy-`user` на роль «Кладовщик» — после релиза с ней и обновления парка 🗓 since:2026-08-28

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «⏳ Ждёт внешнего окна / события»

28.08 на проде снова оказалось 4 живых аккаунта с легаси-ролью `user` (полный доступ) — все четыре свежие регистрации 22–27.07, одобренные админом в один клик: дефолт approve-flow ставил `user`, а подходящей роли для кладовщиков в каталоге не было вовсе (право `erp.documents.edit` не входило ни в одну операторскую роль). Один аккаунт (зам директора) пересажен на «Наблюдателя» сразу; **три складских ждут роль `storekeeper`** (выпущена в **v3.15.0**, 2026-08-29; дефолты одобрения теперь `viewer`, `user` из выпадашек убран).

- **Когда:** после **обновления парка до ≥ v3.15.0** (следить в админке по `lastVersion`) — старые клиенты не знают `storekeeper` и уронят её в fail-closed «без доступа» в оффлайн-гейтах.
- **Кого:** живой worklist даёт `security:role-report -- --worklist 10` (логины в репо не пишем, D-041).
- **Как:** по образцу PR #200 — одноразовый скрипт с логином через CLI-аргумент (`reassignRoleOneoff`, применён 28.08 для зам директора; логины НЕ хардкодить), роль + `section_access` (`warehouse/supply:editor`, остальное viewer — существующий посекционный доступ у двух из трёх уже такой) + отзыв refresh-токенов. Верификация: `role-report` → live `user` = 0.
- После пересадки — R1 этапа B3 выводит `user` из каталога совсем (план `matrica-v4-kickoff-2026-08.md`).
