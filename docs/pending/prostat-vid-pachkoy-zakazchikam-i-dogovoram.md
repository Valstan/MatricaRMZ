# 🟡 Вид «ГОЗ / гражданка»: проставить его пачкой — на проде вида нет ни у одного заказчика 🗓 since:2026-11-26

**Статус:** открыто (26.11.2026). Заведено ниткой промта КАРМАНА **#163** («Вид — полноценный
признак: фильтр, сортировка, группировка»).

## Что сделано в нитке #163

Вид стал полноценным признаком в списках: ступень фильтра «Вид» везде, где вид выводим;
сортировка по колонке «Вид» по заданному порядку (ГОЗ → гражданский → вид не задан); раздел
«Вид» в группировке; короткие подписи в кнопках и ступенях; быстрый доступ к отбору по виду
кнопкой `ГОЗ / Гражд.` в тулбаре. Правило — в `AGENTS.md` §«Списки, фильтры и признаки»,
перечень списков — в [`docs/ENGINE_KIND_INVENTORY.md`](../ENGINE_KIND_INVENTORY.md).

## Что осталось открытым (это отдельная работа, не эта нитка)

**Замер на проде 26.11.2026 (read-only SELECT):**

| Срез | ГОЗ | Гражданский | Вид не задан | Всего |
|---|---|---|---|---|
| Заказчики | 0 | 0 | 61 | 61 |
| Договоры | 73 (20 явно + 53 по умолчанию) | 5 | 0 | 78 |
| Двигатели | 1 660 | 3 | 910 | 2 573 |

Вид заполнен у единиц: у **всех 61 заказчика вида нет**, у двигателей вид известен только у
тех, у кого есть договор (1 663 из 2 573). Фильтры и группировки работают и показывают это
честно (значение «Вид не задан» с числом строк), но выдача «Гражд.» почти пустая.

**Что нужно сделать (когда владелец решит):**

1. **Проставить вид пачкой** — заказчикам (префикс вида в строгой таблице
   `erp_counterparties.engine_kind`) и договорам (`contract_sections.primary.kind`). Без этого
   отбор по виду в заказчиках бессмысленен: там вида нет ни у кого.
2. **Решить, чей это вид по умолчанию** — сейчас умолчание договора «ГОЗ», а у двигателя без
   договора вида нет вовсе (двигатель без договора — 910 штук). Пакетное проставление должно
   решить и это: иначе «вид не задан» останется у четверти двигателей.
3. **Учесть обратную связь оператора**: вид — признак заказа, а не только двигателя; проставлять
   его пачкой по списку заказчиков (как в «Колонках списка») оператору, вероятно, удобнее, чем
   по одному.

## Чего делать нельзя

- **Вид не хранить в двигателе отдельным новым полем** — владелец прямо сказал: «в двигателе
  вид добавлять не надо, он определяется по договору». Вид двигателя считается по общему
  правилу `resolveEngineKind` (договор → карточка → карточка заказчика); ручное значение в
  карточке двигателя — только запасной путь, пока нет договора.
- **Не брать вид из легаси-EAV** — вида там нет вовсе, источник один (строгая таблица).
