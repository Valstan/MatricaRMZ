## Что сделано (23.11.2026)

### Кит и верхний уровень (ветка `feat/unified-list-rules`, PR #1923)

- **Кит:** модель объявления действий (`ListActionDeclaration`) + переработка `buildListContextMenuItems` — недоступного пункта в меню **нет**, «удалить» только там, где список умеет удалять и есть право; одно объявление обслуживает строку и пачку.
- **Слои:** перетаскивание с подсветкой и линией места вставки (`useListDrag`), клавиатурное перемещение по ручке (`useListKeyboardMove` + `ListRowHandle`), выделение контуром (`useListLasso` + `ListLassoLayer`).
- **Настройка:** группа `listBehavior` в глобальных дефолтах; личные настройки её не перекрывают (D-248). Пункт суперадмина — «Настройки → Интерфейс → Правила списков».
- **Верхний уровень:** двигатели, договоры, сотрудники, наряды, контрагенты, свойства инструмента.

### Карточки — шаг 3 (ветка `feat/unified-list-rules-cards`, PR #1934, 23.11.2026)

- **Кнопки ↑/↓ заменены единой ручкой «⠿»** из кита: перетаскивание мышью + перемещение стрелками по клику (клик по ручке → красная рамка → ↑/↓) + блок из нескольких строк (Ctrl/Shift по ручкам). Списки: марки и детали договора, детали исполнения договора, бригада/подписи/виды работ наряда, свойства инструмента, строки складского документа, позиции и поставки заявки на снабжение, строки табеля, переводы сотрудника. Рукописная копия ↑/↓ в заявке — тоже на кит.
- **Общий кит перестановки** (одна точка, а не копия в каждой карточке): `hooks/useListReorder.ts` (сборка), `utils/listReorder.ts` (мост «новый порядок → массив строк»), `components/ListReorderHandle.tsx` (ручка).
- **Два решения, которых не было в ките верхнего уровня:** ключ строки — её **номер** (у строк карточек своего id нет, а выдуманный id пришлось бы хранить и передёргивать при каждой правке — это вторая механика рядом с китом), и **пересчёт номеров блока после сдвига** — иначе второе нажатие стрелки двигает уже другую строку. Плюс **граница списка** (`scopeRef`): на карточке наряда списков три, и без границы перетаскивание целилось бы в строки соседних.
- **Сторож кита** (`ui/listKit.guard.test.ts`) расширен на карточки: перестановка только через кит, кнопок ↑/↓ в карточках нет, у строк есть маркеры, у каждого списка своя граница, ручка одна на программу.
- **CDP-смоук написан** (`cdp-card-reorder-handle.mjs`), но на этой машине **не прогнан**: клиент стенда не достаёт до сервера (очередь «не отправлено на сервер: 7»), его всплывающие окна перекрывают кнопку МЕНЮ, а нативный confirm из окна «Отбросить» блокирует рендерер (лечится `Page.handleJavaScriptDialog`). Прогнать на живой машине.

### Диалоги-редакторы — на ките (PR #1938, ветка `feat/unified-list-rules-editors`, 23.11.2026)

- **Четыре диалога переведены на общий кит:** `WorkSheetTypeEditorDialog` (колонки вида работ), `WorkOrderTemplateEditorDialog` (слоты подписей), `RepairStageTemplateDialog` (этапы ремонта), `NomenclatureTemplateCompositionEditor` (свойства шаблона номенклатуры). Кнопки ↑/↓ (`RowReorderButtons`) и их хелпер `moveArrayItem` **удалены из программы** — вторая механика закрыта целиком.
- **Два решения, которые потребовались именно здесь:** у шаблона наряда блоков подписей несколько ⇒ блок вынесен в отдельный компонент (`WorkOrderTemplateSignatureSlots`) — у каждого блока своя граница списка, а хук кита вызывается по одному разу на список; у номенклатуры порядок — это поле `sortOrder` ⇒ после перестановки оно пересобирается по новому порядку (`renumberTemplateProperties`), иначе сохранённый JSON разошёлся бы с экраном.
- **Порядок этапов по-прежнему хранится на сервере:** кит считает механику перемещения (мышь, стрелки, линия места вставки), а сохраняет его `commitOrder` → `templates.reorder`. Своего drag-and-drop у диалога больше нет.
- **Кит: активна одна ручка.** На странице списков их несколько (у шаблона наряда — блоки подписей), и клик по ручке второго списка **не снимал** режим первого: одна стрелка двигала строки обоих списков сразу. Теперь активный список один — ручка другого списка снимает прежний режим (`utils/listKeyboardMove.ts`: `claimMoveOwner` / `currentMoveOwner` / `releaseMoveOwner`), покрыто тестом. Правило оказалось нужным и карточкам (там списков три).
- **Сторож кита** (`ui/listKit.guard.test.ts`) расширен на диалоги: перестановка только через кит, кнопок ↑/↓ нет, у строк маркеры, у каждого списка своя граница, сам компонент кнопок удалён из программы. Гард шаблона этапов (`pages/WorkSheetsPage.guard.test.ts`) больше не требует `RowReorderButtons` — требует кита.

## Приёмка (осталось проверить руками)

- Перетаскивание: видно перетаскиваемую строку и место вставки.
- Клик по ручке → красная рамка; ↑/↓ двигают; повторный клик снимает; блок из нескольких строк двигается целиком.
- Ctrl + рамка → выделение контуром, с выделенными — перетаскивание блоком, копирование, удаление.
- Клик мимо снимает выделение — везде.
- В меню списка, где удаление запрещено, пункта «Удалить» нет.
- Настройка одна — меняется в одном месте и действует во всех списках.
