# Списки вне общей панели кнопок — без переполнения 🗓 since:2026-11-13

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «🟡 Техдолг»

**Суть.** Панель кнопок над списком живёт на общем `PageToolbar` (`ui/components/PageToolbar.tsx`): ряд в одну строку, лишнее уезжает в меню «⋯», закреплённое (поиск, «≈ Похожие») остаётся в строке. **11 экранов с поиском этот ряд не используют** — у них своя строка, а значит нет ни переполнения, ни меню «⋯»: кнопки в узком окне уезжают за край.

**Список экранов** (найдено обходом дерева — ищут `SearchModeToggle`, но не `PageToolbar`):

`AdminPage`, `ChangesPage`, `EngineBrandDetailsPage`, `EngineBrandGroupsPage`, `EngineBrandsPage`, `ServicesByBrandPage`, `StockBalancesPage`, `StockInventoryPage`, `ToolPropertiesPage`, `WorkOrderTemplatesPage`, `GlobalSearchOverlay` (общий поиск Ctrl+K — он не «панель над списком», но правило строгого поиска к нему относится).

**Почему не в этой работе.** Задача «панель кнопок над списком» (промты КАРМАНА #9 + #13) касалась списков, уже собранных на общей панели: правило переносить «в компонент, а не в каждый экран» — иначе разъедется по спискам. Перевод остальных 11 экранов — отдельная работа: у каждого своя раскладка (заголовок + поиск + фильтры + свои кнопки), и решать, что уходит в меню «⋯», а что закрепляется, нужно по месту.

**Что уже сделано и не переделывается:** общий `PageToolbar` с переполнением и общий компонент поля поиска (`ToolbarSearchField`) — новые экраны берут их сразу, минуя самодельные ряды. Сторож `ListChrome.guard.test.ts` держит список экранов на общей панели; новые списки в этот перечень обязаны попадать (список из 14 страниц — не выкидывать).
