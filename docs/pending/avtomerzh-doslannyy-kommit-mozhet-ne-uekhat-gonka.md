# 🟡 Автомерж: досланный коммит может не уехать — гонка, пойманная на первом применении 🗓 since:2026-09-04

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «🟡 Техдолг»

Автомерж включён 04.09 (`allow_auto_merge=true`), обязательных проверок стало восемь. **На первом же PR он показал зубы.**

**Что произошло.** PR [#773](https://github.com/Valstan/MatricaRMZ/pull/773) поставлен на автомерж с одним коммитом. Пока шли проверки, в ту же ветку дослан второй коммит. Проверки первого позеленели раньше, GitHub слил PR по **первому** коммиту и удалил ветку. `git push` второго коммита при этом **прошёл успешно** и молча **воссоздал удалённую ветку** на origin. В `main` уехала половина работы; вторая половина осталась на ветке-призраке, которую уже никто не ждал. Заметил только потому, что после мержа проверил содержимое `main` грепом, а не поверил слову «MERGED».

**Правило.** Ставить на автомерж — **последним действием** по ветке. Если после этого нужно что-то дописать:

```bash
gh pr merge <N> --disable-auto      # сначала снять
git push                            # потом дописывать
gh pr merge <N> --squash --auto     # и снова вооружить
```

**Проверка после автомержа — по содержимому, а не по статусу.** `gh pr view --json state` скажет `MERGED`, даже если уехал не весь ваш труд. Смотреть надо так:

```bash
git fetch origin && git checkout main && git pull --ff-only
grep -c "<строка из вашей правки>" <файл>    # 0 = не уехало
```

**Если уже случилось**, ничего не потеряно: коммит жив локально и на воссозданной ветке. Лечится `git checkout -B <новая-ветка> <sha> && git rebase origin/main` и обычным PR.

Тот же класс, что «пустой вывод неотличим от несостоявшейся проверки» ниже: **успешный статус операции не означает, что уехало то, что вы имели в виду.**
