1. 🟡 **R3 — планшетный хвост: КОД ОТГРУЖЕН в `main` ([#516](https://github.com/Valstan/MatricaRMZ/pull/516), 09.08), открыта только живая приёмка на DIGMA.** Режим «данные на весь экран» был мёртв с 07.08; починены оба дефекта, мёртвая панель снесена. В цех поедет со следующим релизом. Ниже — что именно чинили (для истории) и чем упирается приёмка:
   - **I:** `REQUIRED_ANCHORS` (`shell/ChromeVisibilityContext.tsx`) требует `.mx-chrome-slot--header` — класс жил в `layout/Page.tsx` и снесён вместе с синей шапкой в [#494](https://github.com/Valstan/MatricaRMZ/pull/494). Через 2 с после монтирования fail-open ставит `broken=true` без права сброса → режим мёртв с 07.08. Замена: `['.v3-tab-strip', '.mx-chrome-rail']` + контрактный тест с жёстким `toEqual` (пустой список прошёл бы «зелёным» и навсегда выключил fail-open).
   - **J:** `DATA_SCROLL_CLASSES` (`shell/chromeScrollTargets.ts`) содержит снесённый `v3-split-list` и никогда не проставленный `mx-data-scroll`; живой из трёх — только `v3-card-body`. То есть прокрутка ЛЮБОГО списка не считается «данными» и хром не убирает. Добавить `v3-tab-content` (не `v3-tab-content-menu` — токены сравниваются целиком), убрать мёртвые.
   - **Мёртвая выдвижная панель:** `ChromeDrawer.tsx` не рендерится нигде с #494, но язычок ☰ и скрим в `ChromeHandleRail` остались. Починка одного лишь якоря выпустит в цех тап ☰ → пустое полноэкранное затемнение поверх данных, снимаемое только вторым тапом. Сносить вместе с I; координату язычка 🔍 (`top: calc(42% + 108px)`) пересчитать на `top: 42%`.
   - Приёмка (пять сценариев на DIGMA): листание списка ≥48 px убирает хром; возврат к началу — возвращает; 20 с бездействия — убирает; язычок ▾ возвращает и попадается пальцем в перчатке; 🔍 возвращает тулбар и стоит на новой координате.
   - **Код готов и проверен без планшета** (ветка `fix/r3-tablet-chrome-anchors`): браузерный спайк `android-app` (`pnpm -F @matricarmz/android-app dev` + `?spikeLogin=1`) поднимает renderer с `__MATRICA_PLATFORM__='android'`, то есть с НАСТОЯЩИМ планшетным режимом. Проба `.verifier-electron/_r3-tablet-chrome.mjs` — 13/13 PASS; с откаченными правками честно краснеет и воспроизводит цеховую картину (`data-mx-chrome` пропадает, в консоли «выключен: не найдены якоря разметки», рейла нет). **Осталось на DIGMA только тач-эргономика:** краевые свайпы, палец в перчатке, системный жест «назад», 20 с бездействия на живом экране.
   - ✅ **Артефакт CI для планшета починен** (workflow [`android-apk-build.yml`](../.github/workflows/android-apk-build.yml)). Было: на прогоне PR [#516](https://github.com/Valstan/MatricaRMZ/pull/516) из workflow выходил `app-release-unsigned.apk` (24 МБ) — блоков подписи нет ни v1 (`META-INF/*.RSA`), ни v2/v3 (`APK Sig Block 42`), потому что секрет `ANDROID_KEYSTORE_BASE64` не заведён; по логу это было не видно (шаг «Decode keystore» отрабатывал без ошибки, job зелёный). Стало: НЕ-тег сборки идут через `assembleDebug` → артефакт **`matricarmz-android-apk-debug`**, подписанный штатным debug-ключом Android, ставится на DIGMA sideload'ом без секретов; отдельный шаг «Verify APK signature» (`apksigner verify`) краснеет, если подписи нет, — молча зелёного неустанавливаемого артефакта больше не будет. Тег-сборки не изменились: release + подпись ключом владельца, без ключа падают намеренно (4 секрета — см. §Keystore выше). ⚠️ **applicationId тот же** (`ru.matricarmz.tablet`), а ключ у CI-debug свой — поверх ранее поставленного APK (локальный debug с PC40) он не встанет, приложение надо сначала удалить с планшета.
2. 🟢 **Хвосты R3, отложенные осознанно** (каждый трогает либо dirty-guard, либо необратимо стирает данные парка — поэтому не в чистку):

   - слои `appHeader`/`sections` в ядре хрома (`chromeVisibility.ts`) — ~17 ассертов теста; туда же осиротевший `ChromeApi.route()` и ветка `'route'` редьюсера: **не зовётся ниоткуда** (найдено 09.08 при сносе выдвижной панели), а `sections` после её сноса не читает ни один селектор — атрибут корня так и стоит `data-mx-chrome-hidden="sections"` вхолостую;
