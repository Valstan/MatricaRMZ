# Пул соединений PG — понаблюдать после подъёма 🗓 since:2026-08-12 🟡

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «⏳ Ждёт внешнего окна / события»

Россыпь `Failed query` по несвязанным подсистемам (peer cleanup, `card_drafts`, statistics-audit, тик ИИваныча; 8 штук 11–12.08) оказалась **исчерпанием пула**, а не сбоем БД: `PGPOOL_MAX` не был задан → дефолт 10 слотов на инстанс при ожидании 5 с, а тул-цикл ИИваныча делает 20+ SQL подряд. Postgres здоров (аптайм 41 день, 1 коннект из 100, лог чист).

Сделано 12.08: в `/etc/matricarmz/matricarmz.env` добавлены `PGPOOL_MAX=25` и `PGPOOL_CONN_TIMEOUT_MS=10000` (бэкап env рядом), сервисы перезапущены; три «немых» места логирования переведены на уже существовавший `describeError` (cause + SQLSTATE) — [#552](https://github.com/Valstan/MatricaRMZ/pull/552).

Осталось: **посмотреть через неделю, повторяется ли**. Если да — в журнале теперь видна настоящая причина; тогда смотреть, кто держит соединения (кандидат — тяжёлые `execute_safe_sql` движка), и либо резать их таймаутом, либо давать ИИванычу отдельный пул.
