_Приёмка ветки «пропавшие ярлыки» ✅ 2026-07-25 на rmz4val — нашла дефект (тихий NSIS не возвращает удалённые `.lnk`, GOTCHAS **M44**), починено #341 и перепроверено собранным CI-бинарём. **Приёмка backoff ✅ 2026-07-26** (30м → 1ч → 2ч на CI-бинаре в песочнице) — см. COMPLETED._

**Живая приёмка hardening-пакета (--repair + mutual heal, ветка feat/watchdog-self-heal-hardening) — на первой машине после релиза** (ADR-0002 §Порядок выката: installer.nsh и Go не ловятся ни линтером, ни тестами). Порядок и чек-лист:

1. **Backend деплоится ДО клиентского релиза** — строгий zod на `POST /client/watchdog/report` отвечает 400 на неизвестный kind `app_missing` (сторож шлёт fire-and-forget, но событие потеряется).
2. После установки: на рабочем столе появился ярлык «Восстановить Матрицу РМЗ» → `matricarmz-watchdog.exe --repair` (иконка клиента).
3. Клик по ярлыку на здоровой машине: в `%APPDATA%\MatricaRMZ\watchdog.log` строка `healthy, exiting … repair=true`, переустановки нет, `watchdog-pass.lock` удалён.
4. Переименовать/убрать `resources\app.asar` при закрытом клиенте → клик по ярлыку → сторож считает установку битой (`clearly broken` в логе), тихая переустановка, в «Критических событиях» появилось `client.watchdog.app_missing` и затем `recovered`.
5. Mutual heal: удалить `%LOCALAPPDATA%\Programs\MatricaRMZ-Watchdog\matricarmz-watchdog.exe` и снести обе задачи (`schtasks /Delete`) → запустить клиент → в `matricarmz.log` строки `watchdog heal:`, exe вернулся, `schtasks /Query /TN "MatricaRMZ\Watchdog Logon"` и `…Periodic` существуют (заодно закрывается историческое отсутствие задачи Logon на rmz4val/PC40).
6. Dev-гигиена (на dev-машине): убедиться, что dev/CDP-запуск клиента больше не переписывает `%APPDATA%\MatricaRMZ\watchdog.json` на electron.exe/localhost.

**Сторож качает заглушку, а не установщик** (найдено по коду 2026-09-10 при сборе файлов для Kaspersky Allowlist, D-084; на машине не наблюдалось). `watchdog/main.go` спрашивает `/updates/latest-meta` **без** `current`, а сервер на такой запрос навсегда отдаёт заглушку `MatricaRMZ-Setup-2026.1231.2359.exe` — мост для клиентов старше 3.1.0 (`backend-api/src/routes/updates.ts`). Итог при восстановлении: сторож молча (`/S`, скрытое окно) запускает заглушку, та качает и запускает настоящий установщик — два тихих загрузчика подряд, ровно поведенческий паттерн `PDM:`. Лечение — передавать `current`, как уже делают клиент (`updateService.ts`) и аварийное обновление (`emergencyUpdate.ts`). Правка Go ловится только живой приёмкой (см. выше), так что проверять на первой машине после релиза.

**Исправлено в коде 12.09:** `fetchLatestMeta` сторожа передаёт `current=<версия клиента из handshake>`. Побочно вскрылось второе следствие прежнего запроса: сторож сверял кэшированные установщики с версией **заглушки** (`2026.1231.2359`), поэтому ни один настоящий кэшированный `.exe` не проходил проверку «совпадает с последней версией» и сторож всегда качал заглушку. **Живая приёмка — на первой машине после релиза:** в `watchdog.log` при `--repair` на сломанной установке должно быть скачивание `MatricaRMZ-Setup-<версия>.exe`, а не `…2026.1231.2359.exe`. Go локально не собирается (нет тулчейна на PC79) — компилирует только CI релиза.

**Мелочь того же захода:** в пакет уходят два `test_extension.node` (тестовые артефакты `better-sqlite3*` в `app.asar.unpacked`) — приложению не нужны, а каждый исполняемый файл — лишняя строка в партии для Касперского. Исключить через `files`/`asarUnpack` в `electron-app/package.json`. Там же: сторож в CI собирается побитово невоспроизводимо (3.24.0 и 3.25.0 — один размер, разные хэши при неизменном коде), `.node` пересобираются из исходников каждый релиз — оба пункта раздувают ежерелизную партию хэшей с 3–4 файлов до 9.
