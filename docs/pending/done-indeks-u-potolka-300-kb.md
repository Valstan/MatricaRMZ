# 🟡 Done-индекс у потолка 300 КБ: новая строка не влезает 🗓 since:2026-11-06

**Раздел:** [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md) → «🟡 Техдолг и отложенное»

`docs/COMPLETED.md` — живой done-индекс поколения 3.x — упёрся в потолок сторожа `docsMemoryLayout.guard.test.ts` (**300 КБ**, `COMPLETED_LIMIT_BYTES`). Файл занимал 307 034 байта из 307 200: **запас 22 байта**; после #1601 — 306 710 (запас 490), после релизной строки 3.107.0 — **302 083 (запас ~5 КБ)**. Потолок не поднимаем — это решение владельца от 31.10.2026 (авто-поджатие строк по «; » однажды портило старые записи, откачено).

**Что делать при добавлении строки** (проверено 06.11.2026, PR с handoff; повторено 07.11.2026 в #1601 — сжатие форм ссылок в трёх секциях освободило 324 байта):

1. Строка влезает только после освобождения места. Способ, который не портит записи: **сжать форму ссылок в той же секции** — `([#700](https://github.com/Valstan/MatricaRMZ/pull/700)–[#702](…))` → `(#700–#702)`. Номера PR сохраняются, тексты записей не трогаются, форма совпадает с уже принятой в файле (`#694`, `#912`, `#1574`). В секции «Обновления / установка / версии» это освободило ~500 байт на 10 ссылках.
2. **Чего не делать:** не резать текст «Итога» автоматически (режет предложения посреди — портит старые записи), не поднимать потолок, не двигать записи в `docs/_archive/COMPLETED-2026H1.md` (архив прошлых поколений — только чтение).
3. Перед коммитом — прогнать сторож: `corepack pnpm -F @matricarmz/electron-app exec vitest run src/main/services/docsMemoryLayout.guard.test.ts`.

**Что решить владельцу (не срочно):** формат ссылок в индексе единообразно сжать по всему файлу (≈170 ссылок, освободит ~9 КБ — хватит на десятки строк), либо оставить как есть и сжимать по секциям. Нынешний подход — «сжимаем форму в своей секции» — работает, но в следующий раз упрётся снова.
