## Контекст

- **Экран «Номера РМЗ» читает реплику, а не сервер** (`engineRmzNumbersHistory.ts`): список обязан открываться офлайн. Опознание карточки берётся из `erp_engine_cards`, недостающее — из `snapshot_json`; снимок строится только для неактивных строк (у живой «что было» открывается самой карточкой), ключи читаются и `camelCase`, и `snake_case`, битый JSON не роняет экран.
- **Ключ реестра — `entities.id` двигателя:** `erp_engine_numbers.id` равен id карточки, поэтому список читает реплику одним `inArray`, а отчёты — одной выборкой на весь отчёт (`Snapshot.rmzByEngineId` из `loadSnapshot`, терпимо к отсутствию реплики), без join.
- **Номер РМЗ — запасной, а не третий в подписи:** в пикерах, гейте дубля, шапке наряда, актах и отчётах он подставляется **только когда документного и внутреннего нет**. Где номер уже показан отдельной колонкой (список, карточка), он стоит третьим рядом с двумя прежними.
- **Инвариант, который нельзя ломать:** номер РМЗ **не** подставляется в `stamped_number` строк деталей (решение 15.07.2026, PR #216). Там личный номер экземпляра детали; одинаковый номер схлопнул бы 6 поршней в один.
- **Имена полей:** удаление карточки живёт в `card_deleted_at`/`card_deleted_by`, а не в базовом `deleted_at` контракта (базовое означает удаление строки синка, а строки реестра не удаляются — иначе история уехала бы из pull и номер выдали бы второй раз).
- **Причина удаления — существующим каналом:** `audit_log` (`action='engine.delete'`, `payload.reason`), актор создания/удаления — из `ledger_tx_index`. Отдельного поля в контракте не завели: второй канал однажды разошёлся бы с первым. На клиенте причина обязательна (`engine:delete` отбивает пустую, карточка спрашивает через `promptText`).
- **Карточка, удалённая до первой сверки, номера не получает:** номера не было — расходовать нечего. Окно практически отсутствует: сверка идёт после каждого push-батча.
- **Сверка не рекурсирует:** собственные записи идут с `skipEngineNumberReconcile` — журнал и pull штатные, но поводом для нового прохода они не служат.
- **Попутно закрыт разрыв (в #1493):** `erp_engine_cards` был в контракте с E3, но отсутствовал в обеих PG-картах pull — холодный снапшот отдавал по двигателям пустоту. Сторож `mirrorTables` его не видел: карточки не входят в `SERVER_MIRROR_TABLES`.
- **Прод-замеры 27.10:** живых двигателей 2570, дата прихода есть у ~1903, пустых заброшенных карточек нет по конструкции (deferred create).
- **Прод-доступ:** `ssh -o ConnectTimeout=15 matricarmz`; psql — `cd ~/MatricaRMZ/backend-api && set -a && . ./.env && set +a && psql -X -f …`; кириллицу читать из файла (`scp`).
