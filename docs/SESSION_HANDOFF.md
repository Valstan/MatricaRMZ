## Что не сработало (и почему это стоит помнить)

- **Код с обратными кавычками через `node -e "…"` в Bash ломается молча:** bash исполнил `` `OAuth ${token}` `` как подстановку команды, в файл легло `Authorization:  }`, а скрипт отчитался «updated». Правило: код вставлять только через Write/Edit или через `node script.js` с heredoc в одинарных кавычках; после любой текстовой вставки — `typecheck`.
- **Неэкранированная обратная кавычка внутри template-literal рвёт скрипт workflow молча:** в блоке фактов было `` `[[ ! -s ]]` ``, литерал оборвался на первой кавычке, `-s` уехал в код, и запуск умер с `ReferenceError: s is not defined` до старта агентов (токены целы, но проход потерян). В строках workflow обратные кавычки не использовать вовсе — кавычить кодовые фрагменты обычными.
- **Цифра из лога — не измерение текущего кода.** Весь первый вывод («места не хватит, сначала переносить фото») стоял на `db.dump: 1.5G` из `backup.log`, но это лог **старого** скрипта с `--compress=0`; новый дампит с `--compress=zstd:3` и даёт 70,8 МБ — в 22 раза меньше. Прежде чем строить план на числе из лога, проверять, тем ли кодом оно получено (`git show <прод-HEAD>:<файл>`).
- **Workflow наследует cwd Bash-инструмента:** после `cd backend-api && …` ревью стартовало из подкаталога, и пути `scripts/prod-ops/…` у агентов не резолвились. Перед запуском workflow — `cd` в корень репо (или абсолютные пути в командах).
- **`grep -c "Backup failed"` в логе — не признак отсутствия алертов:** текст алерта уходит в Telegram, в лог пишется `ERROR:`. Проверять по обеим строкам.
- **Переменная окружения не перебивает env-файл, который скрипт сорсит сам:** два негативных кейса смоук-теста передавали `MATRICA_LEDGER_DIR` через окружение, `set -a; . "$ENV_FILE"` его затирал, и оба кейса молча гоняли happy-path (зелёные по неверной причине — тот же класс, что сторожа 31.08). Поймал сам тест на первом же прогоне в CI. Для таких кейсов — отдельный env-файл.
- **Смоук-тест бэкапа на PC79 не идёт** (нет `zstd` и `flock`) — печатает `SKIP`. Судить о правках `backup-encrypted.sh` только по CI-джобу `prod-ops-backup`.
- **Рабочая копия на PC79 в CRLF, и это ломает многострочные якоря** в скриптах правки (`node -e … replace('…\n…')` не совпадает, а `cat -A` `^M` не показывает — по глазам не отличить). Потерял на этом проход по тест-файлу. Многострочные правки — инструментом Edit; деталь в профиле машины.
- **`n_live_tup` из `pg_stat_user_tables` на проде сильно устарел** (показывал 489 строк там, где реально 45 116, и ноль у живых `directory_parts`/`change_log`). Судить о «мёртвых» таблицах только по настоящему `count(*)` — иначе вывод «таблица пуста» о живой таблице. Годный однострочник — `query_to_xml` по всем таблицам разом (есть в истории сессии).
- **Опровергатели правы не всегда, но и находки — не всегда.** Из 16 находок аудита три опровергнуты, а у двух пришлось смягчить формулировку по прод-данным («отчёт всегда пуст» → «печатает 1,4 % данных»; «флаг всегда ложен» → «потерял одно слагаемое из трёх»). Сверка находки с данными обязательна до записи в PENDING.
