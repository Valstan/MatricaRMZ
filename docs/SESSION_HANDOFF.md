## Контекст

- Разбор раздела договора — **одно доменное правило** `planContractSectionToken` (`shared/src/domain/contract.ts`); оба серверных скрипта переноса зовут его, сторож `contractSectionTokens.guard.test.ts` не даёт правилам разойтись. Проверено на стенде: EAV → зеркало `erp_engine_cards` → журнал `ledger_tx_index` (парк тянет журнал; строгая реплика побеждает EAV по свежести).
- ⚠️ Строка `attribute_values` в журнал при переносе **не** попадает (серверная строка уже равна payload'у — путь записи считает изменение пустым). Это не потеря: парк получает значение строгой карточкой.
- На экране у 8 перенесённых двигателей ничего не меняется (клиент и так читал мусор как `primary`) — CDP-смоук по этому не гонялся, экрана правка не касается.
- Гейты перед релизом: `pnpm -r typecheck` ✔, `typecheck:test` ✔, `lint` ✔, `pnpm -r --workspace-concurrency=1 test` ✔ (electron 2287, shared 1792, backend 1391, android 85), CI 10/10 на PR #1716 ✔.
- Локальные ветки: `feat/production-program-module`, `feat/scrap-highlight-everywhere`, `wip/contracts-followup-2026-11` — **в других воркаутах**, их работа уже в `main` (сверка: файлов, которых нет в `main`, нет ни у одной).
- Грабли сессии: стенд может остаться поднятым с прошлой сессии (бэкенд на 3011, версия 3.119.0) — `start-stack.ps1` падает с `EADDRINUSE`; ABI `better-sqlite3` живёт на двух ABI — перед смоуком `swap-sqlite-abi.ps1 -Target electron`, перед тестами `-Target node`; **стенд живёт между прогонами** — проверяемые факты возвращать как было.

## Что не сработало

- **Правка EAV напрямую в SQL не годится:** «миграция» владельца исполнена переносом через серверную дверь — SQL обновил бы только сервер, а парк увидел бы старое значение («3» вместо «ДС 3») ещё годами.
- **Два скрипта резали одно поле по-разному** (`backfill-section-tokens` и `canonicalize-section-keys`): первый понимал голое число как номер ДС, второй — как основной договор (и сдвинул бы 55 движков с их ДС). Правило сведено в `shared`, сторож держит.
- **Patch-id не годится для сквош-мержей:** коммит, влитый сквошем, не совпадает по patch-id с исходным — сверка чужих веток делается по наличию файлов в `main`, а не по patch-id.
