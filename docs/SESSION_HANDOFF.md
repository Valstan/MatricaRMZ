## Что не сработало

- **Патчи через `node -e` в PowerShell — снесли кусок кода.** В replacement-строке
  `'$1\n$2'` PowerShell интерполировал `$1`/`$2` как пустые переменные, и regex-замена удалила
  не только свой кусок, но и строки properties + закрывающие скобки (`otkConflicts` в
  `engineBulkIntakeService.ts` исчезли, осталась одинокая запятая). Чинили скриптом-файлом.
  **Вывод:** любые regex-патчи по исходникам писать отдельным `.cjs` (или через edit-инструмент),
  не через `node -e` в PowerShell.
- **Правка логики ломает чужие guard-тесты, потому что те завязаны на строковые литералы.**
  `canClose: t.kind !== 'menu',` и `{tab.canClose && (` — строковые проверки в
  `railBuiltinCards.guard.test.ts` и `shellTabsAndVersion.guard.test.ts`. Исключение для черновиков
  пришлось вынести **рядом** с литералом, а не переписывать строку.
  **Вывод:** литерал, на который завязан чужой guard-тест, — это контракт; менять поведение,
  сохраняя литерал.
- **`App.tsx` — 356 КБ; читать его целиком нельзя.** Хватит `grep` по символам + чтение
  участков по 30–80 строк. Полное чтение съедает контекст и ничего не даёт.
- **ABI `better-sqlite3`:** electron-тесты гоняются на Node-ABI, стенд — на Electron-ABI. Забыли
  поменять перед прогоном → 20+ файлов упали с `NODE_MODULE_VERSION 148 vs 137`. Менять **до**
  тестов, возвращать Electron-ABI **после** (стенду нужен Electron-ABI). Переключение —
  `.verifier-electron/swap-sqlite-abi.ps1 -Target node|electron|status` (бэкапы
  `abi-node-20261019/`, `abi-electron-20261021/`). **Пока клиент запущен, бинарь
  `better-sqlite3-multiple-ciphers` залочен** — сначала закрыть Electron, потом менять.
- **Смоук шёл «по кнопкам» глазами драйвера, а не по продукту.** Три из четырёх «FAIL» были
  ошибками драйвера, не продукта: номера искали по префиксу вместо `includes(stamp)`, поле даты
  считали за `<input type=date>` (в UI это текстовое `дд.мм.гггг`), а «дополняем его карточку»
  искали в первых 900 знаках окна — оно ниже таблицы. **Вывод:** прежде чем звать дефект, проверить,
  что драйвер смотрит туда, где значение реально живёт (поле карточки / атрибут / текст целиком).
