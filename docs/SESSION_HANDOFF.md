## Что не сработало

- **PostgreSQL на PC79 падал сам — и это была не «нехватка памяти».** Прежняя запись в профиле машины («похоже на антивирус либо нехватку памяти — лечится на стороне машины, не агентом») **неверна**: след в логах (`процесс сервера (PID N) был прерван исключением 0xC0000142` → «система БД выключена») и состав софта на машине (Kaspersky + Defender + Happ) дают причину — инъекция в пользовательской сессии. Лечится **агентом**: служба Windows + права NetworkService.
- **Скилловский `start-backend.ps1 -Stand laneN` не переключает БД backend'а:** скрипт ставит `PG_VERIFY_DB`, а backend читает `PGDATABASE` (`backend-api/src/database/db.ts`), и `Import-DotEnv` перетирает его из `.env.dev` ⇒ именованный стенд молча ходил в общую БД. Рабочий путь на PC79 — свой лаунчер `.verifier-electron/start-lane1-backend.ps1` (ASCII-only: PS 5.1 ломает кириллицу в `.ps1` без BOM).
- **Гвард карточки в программе называется «Не сохранять», а не «Не сохранить»** ⇒ поиск по точному тексту молча не находил кнопку, и смоук застревал на прошлой вкладке. Искать по вхождению `/не\s+сохра/i` и снимать в цикле ожидания.
- **Неактивная панель вкладки прячется через `visibility:hidden`, а не `display:none`** ⇒ фильтр «по размеру» её не отсекает (геометрия сохраняется). Строки — только из `.v3-tab-pane[data-pane-active="1"]`.
- **МЕНЮ — аккордеон:** свёрнутая секция не рендерит свои пункты ⇒ пункт не находится в DOM, пока секция не раскрыта; подпись брать из `.v2-menu-btn-label`.
- **Пустой список нечем проверять:** «Группы марок» на свежей стендовой БД пусты ⇒ фикстуру заводить путём записи продукта (`admin.entities.create` + `setAttr`), и ждать обновления страницы (20 с).
- **Сторож `globalModules.guard.test.ts` (escapeHtml) красный под нагрузкой:** сканирование репозитория занимает 2.9 с одиночно, а лимит теста — 5 с ⇒ в полном прогоне таймаут. Одиночный прогон — 10/10 PASS, и **тот же красный воспроизводится на чистом дереве** ⇒ не регресс.
- **Ответы смоука читать через `node -e`, не `Get-Content`**: PowerShell 5.1 портит UTF-8 без BOM.
- **Permission gate хоста** режет цепочки команд: мутирующие `gh` (`merge`, `edit`, `create`) — **отдельной командой**, без `;`; `rm -- <файл>` — **отдельной верхнеуровневой командой** с абсолютным путём (после `cd` блокируется политикой).
- **`git commit -m` с кириллицей из PowerShell** → манжит текст ⇒ писать сообщение в UTF-8 файл и `git commit -F`.
- **Слиять PR с кириллическим сообщением — через `gh pr merge --squash --body-file <файл>`:** REST-путь `gh api -X POST …/pulls/N/merge` вернул **404 Not Found**, а `gh api graphql` режет гейт ⇒ остаётся каноническая команда, тело — из UTF-8 файла, заголовок — из самого PR.
- **PowerShell интерполирует `$` внутри `node -e "…"`** ⇒ GraphQL-запрос с `$pr`/`$title` молча превратился в `mutation(:ID!,…)` и упал с `Expected VAR_SIGN, actual: BANG`. Запрос — в файл, переменные — через JSON (`node` читает файл и пишет payload).
- **`git worktree add` с путём вне рабочего дерева** (например, `D:\valstan\REPO\_rmz-…`) блокируется гейтом ⇒ worktree создавать **внутри репо**: `.claude/worktrees/<имя>` (папка в `.gitignore`).
- **Подписка на состояние встала на другой ключ, чем запись (промт #151).** `subscribeFacetPanel` считал ключ от уже посчитанного (`…:facetPanel:facetPanel`), а запись — от сырого `usageKey` (`…:facetPanel`) ⇒ уведомление уходило в пустоту: кнопка сворачивала панель (стор это писал), а панель оставалась на экране. **Видно это только живым прогоном** — сторож по исходнику такой класс не ловит. Правило: ключ состояния считается **в одном месте**, из сырого `usageKey`; инвариант закреплён сторожем `FacetFilter.guard.test.ts`.
- **Смоук врал трижды — и врал про продукт:** (1) ховер без движения мыши (курсор уже стоял над ячейкой ⇒ Chromium не шлёт `mouseenter` ⇒ «меню не открывается»); (2) второй клик по **уже выбранному** значению снимает его ⇒ отбор пустел, плашек не было ⇒ «плашек нет»; (3) `data-list-root` — это колонка страницы, а не таблица ⇒ «список не вырос». Все три — грабли драйвера, а не продукта; выводы в [`machines/parts/PC79/cdp-drivers.md`](machines/parts/PC79/cdp-drivers.md).
- **В worktree `pnpm install` не качает бинарь electron** (postinstall не отрабатывает на linked-зависимостях) ⇒ клиент падает с «Electron uninstall»: распакованный `dist` копируется из основного дерева. Рецепт стенда в worktree — [`machines/parts/PC79/stand.md`](machines/parts/PC79/stand.md).
- **`git worktree remove --force` на Windows падает с «Filename too long»** (пути в `node_modules/.pnpm`) ⇒ `git config core.longpaths true` + `git worktree prune`, остаток каталога — node `fs.rmSync('\\\\?\\' + path, { recursive: true })`.
