## Что не сработало

- **Разведочные агенты дают точные факты и промахиваются номерами строк.** Из проверенных вручную ссылок неверными оказались `userUiProfile.ts:158-159` (на деле `368-369`) и `ReportsCatalogPage.tsx:379-386` (на деле проп передаётся в `App.tsx:5497`). Числа тоже плывут: «30 кодов операций» → фактически 27, «42 определения отчётов» → 34. Вывод для следующей сессии: **утверждение агента годится как указатель, но перед записью в план или PR его номер строки надо открыть глазами.**
- **Два агента, независимо проектировавшие одну задачу, дали два несовместимых решения** с одинаковыми именами функций в одном файле (`humanLabel` с разными сигнатурами → `TS2300`), тремя разными механизмами исключений и четырьмя копиями детектора UUID — ровно тем дефектом, ради устранения которого затевались. Параллельное проектирование одной задачи требует сквозного критика; без него результат не складывается.
- **Первый заход на значок был мимо:** нарисовал три схематичных варианта, владелец ответил «возьми с интернета подходящий рисунок». Картинку из интернета брать нельзя (право + офлайн-программа), но и схема его не устроила — договорились на собственный детальный SVG, запасной вариант — иконка закрепа.
