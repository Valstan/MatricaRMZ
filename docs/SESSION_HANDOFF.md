## Активная нитка: первый сейв новой карточки не теряется

Слово владельца 20.10: заполняешь новую карточку двигателя, сохраняешь — через полминуты она пуста; заполняешь второй раз — держится. То же с «Принять двигатели списком»: строки легли заполненными, а после синка все пустые.

**Корень (воспроизведён вживую на PG, GOTCHAS M163):** клиент отправляет сущность и карточку одним батчем; ветка `entities` применяется раньше ветки карточек, и её `INSERT` зажигает `trg_mirror_engine_card_entity` → `rebuild_erp_engine_card` заводит **пустую** строку карточки (EAV ещё пуст) со своим `updated_at` = `clock_timestamp()`. Строка клиента проигрывает ей по LWW и отбрасывается молча; издатель публикует пустую строку, pull затирает локальные значения.

**Фикс (в работе, зелёный):**

- миграция `0112_engine_cards_first_save_guard.sql` — зеркало не заводит строку, когда зеркалить нечего (нет строки И нет живых EAV-атрибутов);
- `applyPushBatch` — строка без номера журнала (`last_server_seq IS NULL`) не считается автором по LWW; отказ LWW в ветке карточек больше не молчит (`addSkipMetric` + `logSkip`);
- приёмка `engines:first-save-check` (живой PG, в CI — джоба `migrations-check`): до фикса 7 красных из 7, после — PASS, включая «устаревший сейв отклоняется» (LWW жив);
- смоук `cdp-engine-bulk-intake.mjs` шаг `[9]`: push → издатель (75 с) → pull — марка/контрагент/договор и внутренний номер пережили круг.
