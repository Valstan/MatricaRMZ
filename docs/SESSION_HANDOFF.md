## Текущая нитка

Серия «Этапы движения» закрыта, v3.66.0 на проде. Владелец 06.10 дал таблицу
«Рефакторинг этапов движения двигателя по заводу» (docx) — остаток серии. Аудит прода
(только чтение) нашёл настоящую причину «копий»: перенос 29.09 создал новые строки

**Этот PR — унификация ввода + скрипт чистки:**

  («Добавить этап» — прежде отдавал виды работ: «Укладка вала в картер», «Приёмка ОТК»;
  «Приёмка ОТК» сервер отвергал вовсе). Смоук `cdp-stage-unified-picker` — **14/14**.
- Скрипт `stages:cleanup-duplicates` (dry-run по умолчанию): класс A — 134 старые копии
  «этап работ» → мягкое удаление с переносом автора/примечания; класс C — 15 «Приёмка ОТК»
  переписываются в «Выходной контроль ОТК»; класс B — 60 пар «Приемка» (живой остаётся
  строка с датой карточки).
- Решения владельца: имена — длинные канон-имена; дата приёмки — карточки; ввод — все
  этапы реестра; «Промежуточный этап» оставить для комментариев.

**Не сделано:** dry-run чистки на проде → список владельцу → `--apply` по его слову

  06.10). Только подписи; ключ `work_sheets`, права и IPC-контракт не тронуты. Старое имя

  их из переименования; переименовать = одна правка `permissions.ts` + строка в стороже.

  а не инструментом.
- Смоук-скрипты на Windows: правка многострочных блоков через `Edit` не берёт (CRLF в
  файлах `.mjs`), а вставка строки с обратными кавычками внутрь инъектируемого JS ломает
  парсинг. Рабочий путь: правка через node-скрипт по `lines.splice` и `//`-комментарии
  без обратных кавычек в инъектируемой строке.
