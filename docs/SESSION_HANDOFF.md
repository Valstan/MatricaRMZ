- **Что было на самом деле.** «10 076 пропущенных строк за сутки» — это **8 строк, отвергнутых ~800 раз** одним клиентом (`mubvera`, PC19, на 3.21.0). - **Дефект 1 (клиент, чинится этим PR).** Лечение «безнадёжная строка уходит в `error`» (написано 04.09) отменяется `recoverErroredRows` в том же файле: она воскрешает `error`-строку, если та **валидна по схеме**, а сломано отсутствие родителя. Вечный цикл push→skip→error→recover. Класс — **M116**.

- **Дефект 3 (НЕ в этом PR, отдельным шагом после релиза).** Журнал пишется **до** применения (`syncWriteService`: `signAndAppendDetailed` → `applyPushBatch`), поэтому каждая отвергнутая попытка ложится в журнал: 29 таких строк дали **65 069 записей — 5,6% журнала** (861 МБ), +6 000 в сутки от одного клиента. Трогает контракт журнала — отдельный разговор.
- **Чем лечится машина `mubvera`.** Правка стоит цикл и впервые делает застревание видимым (`client.sync.blocked_rows` + причина отказа схемы полем, а не счётчиком). Своя ступень из подсчёта исключена, иначе выбранное значение схлопывает свой же список. Одна кнопка «Сбросить фильтр». Старое значение `customerFilter` переезжает в ступень автоматически.

## Что не сработало

- **Автомерж снова съел коммит, досланный после вооружения.** Это второй раз, запись из прошлого handoff'а не спасла. PR показывал «слит», а мой второй `git push` молча воссоздал ветку с коммитом, которого в `main` нет. Ловится только сверкой по **содержимому** `main` (`git show origin/main:<файл> | grep …`), не по статусу PR. Вооружать автомерж последним действием.
- **Ожидание «процесса нет» вместо «работа закончена».** Ждал ночной бэкап проверкой «нет процесса», а запускал её до времени его старта по cron — условие было истинным сразу и ожидание завершилось бы за пять минут до начала бэкапа. Ждать надо появления записи о **завершении сегодняшним числом**, а не отсутствия процесса.
- **Длинный текст с кавычками через `git commit -m` и `gh pr create --body`.** Двойные кавычки внутри сообщения рвут строку в Git Bash, и `git add` получает куски текста как пути. Сообщения коммитов и тела PR — только через файл (`-F`, `--body-file`).
- **«Парк не заходил ни разу за сутки» чуть не стало симптомом.** Ноль heartbeat'ов за 24 часа выглядит как отказ синхронизации ровно до того момента, как посмотришь на день недели: 06.09 — воскресенье. Прежде чем разбирать тишину, проверить, ожидалась ли она по календарю.
- **Вывод «значит, снаружи» из тишины в собственном логе.** Записал в доки «второй потребитель вне бокса» на основании того, что у secondary нет строк про опрос, — при том что логирование там гейтится по streak. - **Цифры из AI-отчёта принял за замер.** «~200 конфликтов за 12 часов» из отчёта в чате — артефакт выборки (`limit: 200` за двое суток, поданный в промпт как «за окно»), а мой исходный счёт по журналу (~30/сутки) был верным. Успел сказать владельцу, что мой замер занижен, — не был. Числа из `logAnalysisAgentService` цитировать нельзя, пока не починен `:190/:200`.
