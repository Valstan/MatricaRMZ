## Контекст

- **Точный поиск двигателя пришлось делать новым каналом** (`engine:findExactByNumber`): наружу выведен был только `engine:findDuplicateCandidates`, а он отдаёт `similar` и отключается при длине ключа < 3 — «похожее» в переносе данных = запись не туда.
- **Пути к файлам — машинно-локально, не в профиле.** Профиль (`ui_profile_json`) роумится на сервер, а путь на другой машине невалиден: роум списка файлов приносил бы только недоступные файлы. Прецедент — `files.downloadDir`.
- **Ссылки (`customer_id`/`contract_id`/`engine_brand_id`) в переносе не участвуют:** в файле лежит название, карточке нужен id справочника — точного соответствия полей нет, значит и переноса нет.
- **Собиратели (exceljs/docx/jszip) живут в main** — сторож `FileSearchPage.guard.test.ts` это фиксирует (как и `ListChrome.guard.test.ts` для выгрузок).
- **Машина PC79:** `pnpm -r --workspace-concurrency=1 test` обрывается на границе пакетов (процесс умирает после android-app) — гонять по пакетам отдельно; CDP-смоук требует Electron-ABI у `better-sqlite3` (копия из `.verifier-electron/abi-electron-20261022/`), после смоука — вернуть Node-ABI (`.verifier-electron/abi-backup/`).
