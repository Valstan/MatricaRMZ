## Текущая нитка

**Пакет владельца 2026-08-19(б)** — план [`plans/owner-batch-2026-08-19b.md`](plans/owner-batch-2026-08-19b.md), 7 этапов. **Этап 1 (P0) отгружен релизом v3.5.0** (PR [#632](https://github.com/Valstan/MatricaRMZ/pull/632)–[#637](https://github.com/Valstan/MatricaRMZ/pull/637)):

- **Баг «выкидывает из программы при синхронизации»** — шесть путей разлогина, закрыты все. Главный: расхождение серверного схема-хеша давало `rebuild` — клиент сносил свою SQLite (вместе с несинканными строками и сессией) и **пересоздавал ровно ту же схему**, то есть ничего не чинил; любая backend-миграция стирала парк за ≤6ч. Плюс: экспорт/реплей pending перед любым reset, sidecar сессии вне БД, single-flight refresh + серверное grace-окно ротации, 503 вместо 401 на инфраструктурных сбоях, «сессию чистит только дефинитивный 401», guard pending в repair, full-pull не чистит локалку с незапушенным, админ-синки через SyncManager.

## Что не сработало / грабли сессии

- **Стенд-бэкенд держит старую сборку**: после правок backend/shared серверная фича молча не работает, проба краснеет «как будто клиент не пишет». Ловилось дважды. `stop.ps1` убивает только electron. Записано в `docs/machines/rmz4val.md`.
- **Bridge-логин через CDP не обновляет React-стейт** — окно остаётся на экране входа до 60-сек поллинга; в пробе нужен `Page.reload`.
- **ABI-качель better-sqlite3** между vitest (Node) и стендом (Electron; версия Electron теперь 43.0.0).
- Тест sidecar падал на Linux CI из-за захардкоженного Windows-разделителя в моке fs; android-бандл не собирался, пока не зашимили `sessionSidecarStore` и не добавили `readdir`/`rm` в fs-шим.
