| Что | Как сделано |

| Вёрстка находок | список «подпись — значение» вместо таблицы со столбцами |
| Вместо id — названия | ссылки карточки расшифровываются из локальной реплики (контракт → номер, заказчик → название, марка → марка) |

| `.xls` | `@e965/xlsx` (SheetJS 0.20.3): файлы оператора («Дела ремонтов», «шт.21.10.2026») читаются, шапка ищется под титулом |

## Что не сработало

- **Клиент стенда не открывал окно вовсе** (в CDP живой endpoint, но ни одной вкладки): Node-ABI у `better-sqlite3` **и** у `better-sqlite3-multiple-ciphers` — про первый пакет знали, про второй нет; без его подмены окно не создаётся. Лечится свопом ABI в обеих сборках (`.verifier-electron/abi-electron-20261022/` содержит оба файла). Подробности — в [`docs/machines/PC79.md`](machines/PC79.md).
- **Проверка «находки не в таблице» в смоуке сначала ловила чужую таблицу** на странице (значение двигателя есть и в таблице «Поля карточки») — проверку сузили до «сама строка находки не внутри `<table>`».
- **`.xls` — решение по библиотеке принято без ответа владельца.** Вопрос «зависимость или свой парсер BIFF8» был задан 16.11, ответа не было — сделано по рекомендованному варианту (`@e965/xlsx`, SheetJS 0.20.3). Если владелец против новой зависимости в клиенте — замена на свой парсер, читать всё равно придётся.
- **Выкат: первый перенос артефактов пропал — снесла авто-чистка каталога.** `rm` прежнего `latest.yml` запустил path-юнит `matricarmz-updates-prune` до переноса, и чистка снесла только что прилетевшие файлы. Порядок «сначала новое, потом старое» это устранил. Записано граблей **[M208](gotchas/M208.md)** и в профиль машины.
- **Саб-агенты недоступны** (`insufficient balance`) — разведку по контракту синка и клиентскому слою делал сам; на будущее: не закладывать в нить делегирование.
- **Диагностика клиента по сети:** логи клиента на машине оператора недоступны с чужого компа; серверный снимок (`diagnostics_snapshots`, scope=`client`) дал pending/error по таблицам — этого хватило, чтобы найти 617 зависших строк.
