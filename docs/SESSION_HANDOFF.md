**Решение по контуру данных (отклонение от плана #5):** новые таблицы — **вне sync-контракта, клиент ходит по REST** (прецедент — «Приказ о ценах на услуги»; так же устроены и уже работающие шаблоны печати СИЗ: `ppe:printTemplates:list` → REST). План #5 предлагал sync-контракт — это ~15 файлов контура доставки ради копии, которую печать не читает. Чем платим: печать по шаблону требует связи с сервером; офлайн печать деградирует до «без шаблона» (все блоки печатаются) — как сегодня при недоступном сервере. Офлайн-шаблоны — отдельный пункт в `PENDING_FOLLOWUPS` с готовым рецептом.

**Ключевая находка (проверено по коду):** шаблоны печати уже сегодня читаются по сети в момент печати (`PpeCardDetailsPage.tsx:660` → IPC → REST), а локальная реплика `ppe_print_templates` формой не используется. Отсюда и решение выше.

**Что не трогаем:** `ppe_print_templates` (имя живёт в sync-контракте) — не переименовываем и не удаляем; 4 формы наряда и печать списков не ломаем; `permissions.ts` / `signatureAccess.ts` — узкие права не расширяем; прод-контур не трогаем.

**Заводская линза:** участок — печатные формы (сквозной слой документов: наряды, акты, СИЗ, склад, ПП); главный затор (начало сборки) не кормим, снимаем вторичную боль (бумажная передача между операторами, ручная перенабивка форм); поток ремонта не меняется, версионирование снимка печати сохраняется; подписи по должности/цеху — персональные данные, доступ только через существующие `signatureAccess.ts`/`permissions.ts`.
