Заказ владельца (08.11): «после закрытия документа оператор возвращается туда, откуда его открывал, а не в случайную вкладку». Прежнее правило было «вкладка слева» — памяти «откуда открыли» в модели не было.

| Что | Где | Состояние |
|---|---|---|
| Память об источнике | `shared/src/domain/tabsModel.ts` — `CardTab.originTabId` (+ `CardRef`, акшен `OPEN_CARD`) | ✅ |
| Возврат по источнику | `focusAfterClose` → в источник; нет источника — прежнее «сосед слева»; редьюсер `CLOSE` спрашивает ту же функцию | ✅ 7 кейсов |
| Источник не может быть самой карточкой | иначе закрытие вернуло бы фокус на закрытую вкладку | ✅ |
| Кто считает источник | `App.tsx` `cardOriginTabId` — список раздела (`CARD_PARENT_TAB`) либо активная вкладка (открыли по ссылке) | ✅ |
| Источник переживает перезапуск | `V2SessionCard.originTabId` + санитайзер + `sessionTabs` + восстановление | ✅ |
| Стража | `electron-app/src/renderer/src/ui/tabOrigin.guard.test.ts` — 5 проверок | ✅ |

Смоук `.claude/skills/verifier-electron/scripts/cdp-tab-return-origin.mjs` — **11/11 PASS** на живом клиенте: карточка открылась отдельной вкладкой **справа** от «Двигатели»; после закрытия активна вкладка **списка** — та, откуда открывали.

Честно о разнице: в V3 карточка встаёт справа от активной вкладки, а активной в момент открытия обычно и есть тот список, из которого кликнули, — поэтому в самом частом сценарии старое правило давало тот же ответ. Расхождение проявляется там, где сосед слева ≠ источник (открыли по ссылке из другой карточки; вкладку переставили; источник закрыли раньше; после перезапуска). Теперь правило выполняется буквально.

**Рядом в этом же заходе сделаны (все смержены):** «СИЗ: сквозной переход СИЗ ↔ сотрудник и правка его данных прямо из карточки СИЗ» (PR #1801), «Скрипты обслуживания: плитка на Верстаке сразу открывает окно скрипта, инструкция при старте не лезет» (PR #1803), «СИЗ: график отпусков» (PR #1805), «Вид двигателя: одно правило на всю программу» (PR #1807, параллельная сессия), «Аларм застрявшей очереди: кнопка «сообщить администратору», автоотправка в чат и канал МАКС» (PR #1810/#1813, параллельная сессия), «Кладовщик правит размеры сотрудника прямо в карточке СИЗ; связь работает в обе стороны» (PR #1809), «Вид двигателя: обязателен при создании карточки» (PR #1814).
