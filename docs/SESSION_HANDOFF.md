## Что не сработало

- **Имя прода и базы — `matricarmz`; ошибка в одну букву даёт два разных «прод сломался».** `ssh matricrmz` → «Could not resolve hostname» (это не сеть и не fail2ban — просто не найден блок `Host`), `psql -d matricrmz` → `FATAL: database "matricrmz" does not exist` (это не поломка: в списке баз только `matricarmz` + шаблоны, данные на месте — 95 строк в `client_settings`, живой бэкенд держит 5 соединений с `matricarmz` в `pg_stat_activity`). Живое имя БД — дефолт в коде (`backend-api/src/database/db.ts`); канон (`AGENTS.md` §Prod server) пишет верно. В дереве на боксе (`~/MatricaRMZ/backend-api/.env`) встречается устаревшая строка `PGDATABASE=matricrmz` — не путать с живым именем. Сверка: `ssh -G matricarmz` (без сети) и `sudo -u postgres psql -lqt`.
- **SQL через пайп из PowerShell** (`Get-Content | ssh`) — psql спотыкается о BOM. Рабочая форма: запрос **одной командой** в `ssh '… -c ''…$$литерал$$…'''` (литералы — долларовые, `$` в PowerShell не интерполируется внутри одинарных кавычек).
- **`gh api graphql` режет permission-гейт**, `gh api -X POST …/merge` → 404. Слияние — только `gh pr merge <n> --squash --body-file <UTF-8 файл>` (заголовок брать из самого PR).
- **Живая приёмка кнопок строки ленты не проверялась на живом клиенте:** заведённая ручная запись **не доезжает до ленты** (в `operations.list` строка есть, в панели «История ремонта» — нет). Воспроизводится и на **неизменённом** коде (A/B через `git stash`: штатный `cdp-manual-entry-undo.mjs` падает теми же 6 шагами) ⇒ это **не регресс** промта #141; причина не исследована (вне границ задачи) ⇒ инвариант «кнопки строки в левой ячейке» держит сторож по исходнику, а не живой смоук.
- **Sync-гейт закрытия красный после squash-merge** («branch has no upstream — never pushed»), хотя всё в `main` ⇒ локальная ветка удаляется принудительно, линия переводится на базу от `origin/main`; грабля [M231](gotchas/M231.md).
