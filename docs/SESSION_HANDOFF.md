Главный блокер — прежний ранбук мигрировал на живой системе, и старый файловый счётчик цепочки продолжал раздавать номера в ту же таблицу с первичным ключом по номеру. ## Что не сработало

- **Автомерж снова съел коммит, досланный после вооружения.** Это второй раз, запись из прошлого handoff'а не спасла. PR показывал «слит», а мой второй `git push` молча воссоздал ветку с коммитом, которого в `main` нет. Ловится только сверкой по **содержимому** `main` (`git show origin/main:<файл> | grep …`), не по статусу PR. Вооружать автомерж последним действием.
- **Ожидание «процесса нет» вместо «работа закончена».** Ждал ночной бэкап проверкой «нет процесса», а запускал её до времени его старта по cron — условие было истинным сразу и ожидание завершилось бы за пять минут до начала бэкапа. Ждать надо появления записи о **завершении сегодняшним числом**, а не отсутствия процесса.
- **Длинный текст с кавычками через `git commit -m` и `gh pr create --body`.** Двойные кавычки внутри сообщения рвут строку в Git Bash, и `git add` получает куски текста как пути. Сообщения коммитов и тела PR — только через файл (`-F`, `--body-file`).
- **«Парк не заходил ни разу за сутки» чуть не стало симптомом.** Ноль heartbeat'ов за 24 часа выглядит как отказ синхронизации ровно до того момента, как посмотришь на день недели: 06.09 — воскресенье. Прежде чем разбирать тишину, проверить, ожидалась ли она по календарю.
- Грабли вынесены в [`GOTCHAS.md`](GOTCHAS.md), а не сюда: **M105** (предел строки V8 у файла состояния), **M106** (`pgrep -f` через ssh находит саму ssh-команду), **M107** (два генератора номеров против одного первичного ключа), **M108** (409 у `getUpdates` — второй потребитель токена, а не потеря пакетов).
