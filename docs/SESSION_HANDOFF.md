## Текущая нить

**«Вид двигателя: военный (ГОЗ) или гражданский — источники, приоритет и отображение» (промты КАРМАНА #34 + #35) — сделана.**

Задание владельца (18.11): вид двигателя должен быть **одним и тем же** в списке, в фильтрах, в отчётах и в карточках; по нему — отбор (отдельно военка, отдельно гражданка); приоритет один: **контракт → карточка двигателя → контрагент**.

| Что | Где | Состояние |
|---|---|---|
| Единое правило | `shared/src/domain/engineKind.ts` — `resolveEngineKind` (+ источник значения) | ✅ 9 тестов |
| Ступень фильтра «Вид» + колонка в списке | `shared/src/domain/engineListFacets.ts` (`kind`), `pages/EnginesPage.tsx` | ✅ 3 теста |
| Вид в строке списка | `listEngines` (`services/engineService.ts`): карта вида договора + вида заказчика | ✅ |
| Карточка двигателя | Поле «Вид двигателя»: договор — «из договора», без договора — выбор руками | ✅ |
| Карточка контрагента | «Вид двигателя (по умолчанию)» — значение по умолчанию для его двигателей | ✅ |
| Хранение | Строгие колонки `engine_kind` в `erp_engine_cards` и `erp_counterparties` (миграция `0133`), **EAV-атрибут не заводим** (заморозка) | ✅ |
| Отчёты-списки | «Вид» колонкой в отчёте «Двигатели»; отбор тот же, что в списке | ✅ |

Ключевые находки: **вид вычисляемый** — ручное значение при появлении договора НЕ переписывается, договор просто перебивает его (иначе ломается история); **нет источников — вида нет (`null`), а не «ГОЗ по умолчанию»** (умолчание есть только у договора); пустая строка в колонке — «вид снят», NULL — «поля не было в пуше» (COALESCE на сервере защищает вид от затирания клиентом старой версии).

**«СИЗ: сквозной переход на карточку сотрудника и правка его данных прямо из карточки СИЗ» (промты КАРМАНА #40 + #41) — сделана.**

Задание владельца (18.11): из карточки СИЗ — в карточку сотрудника и обратно; данные, которые карточка СИЗ подтягивает из карточки сотрудника (структурное подразделение, размеры), должны редактироваться прямо в карточке СИЗ.

| Что | Где | Состояние |
|---|---|---|
| Связь «карточка СИЗ ↔ карточка сотрудника» | `shared/src/domain/ppeEmployeeLink.ts` — индекс по **табельному номеру** | ✅ 6 тестов |
| Переход СИЗ → сотрудник | кнопка «Открыть карточку сотрудника» → `openEmployee` (штатный вход) | ✅ смоук |
| Переход сотрудник → СИЗ | кнопка «Карточка СИЗ» → `openPpeCardEmployee` | ✅ смоук |
| Правка подразделения и размеров из карточки СИЗ | блок «Данные сотрудника» → **в карточку сотрудника** (`employees:setAttr`), то же право | ✅ смоук |
| Определения атрибутов размеров | до-регистрация при записи (иначе «Неизвестный атрибут») | ✅ нашёл смоук |

Ключевые находки: **id у карточек разные** (карточка СИЗ — строгая `erp_employee_cards`, карточка сотрудника — EAV), а серверный `erp_employee_cards.entity_id` **в зеркальный DTO не входит** — общий ключ один, табельный номер. Свой копии значений в карточке СИЗ не заводим (одна правда).
