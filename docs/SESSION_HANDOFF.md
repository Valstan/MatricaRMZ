## Текущая нитка

**Нет активной нитки.** Сессия закрыла жалобу владельца «двигатель, заведённый под суперадмином, не виден никому; в наряде двигатель откатывается» — оказалась не проблемой доступов, а **мёртвым push'ем машины**. Детали — [`COMPLETED.md`](COMPLETED.md) §Инфра, грабля — [`GOTCHAS.md`](GOTCHAS.md) **M49**, эффект для завода — [`zavod/PROGRAM_EFFECTS.md`](zavod/PROGRAM_EFFECTS.md).

Коротко: `entityReferenceGuard` кидал `throw` → одна строка со ссылкой на цех (цеха мигрировали в `directory_workshops`, резолвер искал в `entities`) валила весь submit в 400, и с PC40 **неделями не уезжало ничего**. `force_full_pull` прошлой сессии не мог помочь — сломан был не приём, а отправка. Гард переведён на построчный отказ + критсобытие `server.sync.reference_denied`. Попутно #388: гард authz читал `entity_type_id` вместо `type_id` → гейты Ф2/Ф3 молча не применялись к строкам сущностей, **а тесты кодировали то же неверное поле**.

## Что не сработало

- **Диагностика «от прав» — тупик, стоивший прошлой сессии впустую.** Симптом «не виден у других» инстинктивно читается как проблема видимости/доступов, и прошлая сессия разослала `force_full_pull` трём клиентам. Правильный первый шаг — **клиентский лог на `pushed=0` при непустом `push pending`**: диагноз за минуту вместо дня. Записано рефлексом в M49.
- **Прод-probe `psql` с `payload_json` в выборке падает** `invalid byte sequence for encoding "UTF8": 0xd0` (битая кодировка в старой записи аудита). Не лечил — просто не тянуть `payload_json`/`details_json` в `select`; фильтровать по нему через `like` можно.
- **`gh pr checks` разово отвалился** `Post "https://api.github.com/graphql"` — тот же сетевой флап, что вчера с `gh pr list`. Ретрай проходит; не диагностировать авторизацию.
