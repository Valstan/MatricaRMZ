- **SQL через пайп из PowerShell** (`Get-Content | ssh`) — psql спотыкается о BOM. Рабочая форма: запрос **одной командой** в `ssh '… -c ''…$$литерал$$…'''` (литералы — долларовые, `$` в PowerShell не интерполируется внутри одинарных кавычек).
- **«Нет проверок» ≠ «проверки зелёные».** `gh pr checks` на PR в конфликте с `main` отвечает «no checks reported» — Actions-сьютов не создаётся, workflow не триггерится; это выглядело как «GitHub не реагирует на форс-пуш». Причина — конфликт, снимается ребейзом на свежий `origin/main` (после него проверки идут сразу). Разбор — грабля [M234](gotchas/M234.md). Второе следствие оттуда же: локальный прогон гейта относится к состоянию кода на момент прогона — правка после прогона его обесценивает (так уехала тип-ошибка, которую поймал только CI).
- **`gh api graphql` режет permission-гейт**, `gh api -X POST …/merge` → 404. Слияние — только `gh pr merge <n> --squash --body-file <UTF-8 файл>` (заголовок брать из самого PR).
- **Живая приёмка кнопок строки ленты не проверялась на живом клиенте:** заведённая ручная запись **не доезжает до ленты** (в `operations.list` строка есть, в панели «История ремонта» — нет). Воспроизводится и на **неизменённом** коде (A/B через `git stash`: штатный `cdp-manual-entry-undo.mjs` падает теми же 6 шагами) ⇒ это **не регресс** промта #141; причина не исследована (вне границ задачи) ⇒ инвариант «кнопки строки в левой ячейке» держит сторож по исходнику, а не живой смоук.
- **Sync-гейт закрытия красный после squash-merge** («branch has no upstream — never pushed»), хотя всё в `main` ⇒ локальная ветка удаляется принудительно, линия переводится на базу от `origin/main`; грабля [M232](gotchas/M232.md).
