## Стенд lane2 в worktree `m2`: готовый рецепт (25.11, линия 2)

- **Порты lane2:** backend **3003**, vite **5175**, CDP **9230** — **не 9224**: 9224 на этой машине держит чужой браузер (профиль Яндекса), и клиент стенда запускается с явным `-CdpPort`, чтобы стенд остался изолированным. БД — `matricarmz_dev_lane2`.

Обычный `pnpm install` без `--ignore-scripts` на PC79 падает на нативной сборке better-sqlite3 (нет VS Build Tools).
- **Гейт разрешений хоста:** `cd` + запись в одной команде блокируется ⇒ git-операции через `git -C <worktree> …` **без** `cd`, правки файлов — в основном worktree.
- **После прогона:** `stand-lane2.ps1 -Down` гасит стенд и возвращает ABI в **node** (юнит-тесты требуют node-ABI, иначе vitest красный на десятках файлов).

## Именованный стенд lane2: подъём с нуля (23.11.2026, линия 4 «список СИЗ на ките»)

- **Рабочий порядок (без `migrate-and-seed.ps1` — permission-гейт его режет):**
  1. `$env:PGPASSWORD='postgres'` (пароль PG на этой машине — см. раздел про PostgreSQL в [`stand.md`](stand.md)) и **`$env:PG_VERIFY_DB='matricarmz_dev_lane2'` ДО `setup-env.ps1`** — иначе `.env.dev` уедет на базу `main`-стенда, и миграции/фикстуры линии окажутся в чужой базе;
  2. `setup-env.ps1` → `setup-db.ps1 -Stand lane2` (база создаётся пустой: дампа прода в worktree нет, `prod-schema.sql` ищется в `.verifier-electron/` своего репо);
  3. миграции и сиды — **командами напрямую**: `db:migrate` → `dev:bootstrap-types` → `perm:seed` → `dev:seed-fixtures` с `$env:PGHOST/PGPORT/PGDATABASE/PGUSER/PGPASSWORD` в env;
  4. ABI под Electron: `corepack pnpm -C electron-app exec electron-builder install-app-deps`; **после смоука** — `corepack pnpm rebuild better-sqlite3` (обратно на Node, иначе vitest `electron-app` красный);
  5. `start-backend.ps1 -Stand lane2` (backend 3003) → `start-electron.ps1 -Stand lane2 -Cdp` (CDP 9224, renderer 5175) **долгоживущей фоновой задачей**;
  6. смоук: `$env:MATRICA_CDP_PORT='9224'; node .claude/skills/verifier-electron/scripts/cdp-ppe-cards-list-kit.mjs`.
- **⚠️ Баг скилла, исправленный в этой нитке (PR #1959):** `start-electron.ps1` импортировал `electron-app/.env.dev` **после** подстановки портов стенда ⇒ клиент именованного стенда уезжал на backend `main`-стенда (3001) — ровно то смешение, ради которого стенды разделили. Лечение: `Import-DotEnv` перенесён **выше** подстановки `$env:MATRICA_API_URL` / `MATRICA_UPDATE_PEER_HTTP_PORT` (в `start-backend.ps1` порядок уже был правильный).
- **`psql` не в PATH** — `C:\Program Files\PostgreSQL\17\bin\psql.exe`; без пароля он уходит в интерактивный запрос и **висит** (проба с `-w`: «no password supplied»).
- **`stop.ps1 -Stand lane2` гасит только свой стенд**, но node-процесс backend может остаться сиротой — порт 3003 продолжает слушать; добивать по владельцу соединения.
- **Логины свежего стенда:** `valstan` / `valstan-dev` (суперадмин — разделы СИЗ не гейтятся) и `verify` / `verify123` (admin).
- **Фикстуры стенда дают двух сотрудников** (`Superadmin (dev)` и `Verifier (dev)`) — этого хватает смоуку списка СИЗ: строки есть, ключи строк уникальны.
- **⚠️ PG на PC79 умирает сам всё быстрее (23.11, вечер):** поднимается `pg_ctl -D 'C:\Program Files\PostgreSQL\17\data' -l <лог> start` (гейт это СЕЙЧАС пускает — в отличие от утра 23.11, когда резал все четыре формы), но живёт **1–2 минуты**: backend после этого видит `connect ECONNREFUSED 127.0.0.1:5432`, а лог стенда показывает «permissions seed failed» и «base masterdata ensure failed» — это следствие упавшего PG, а не ошибка правок. Практический вывод: **окно для живого смоука на ПП на этой машине минуты** ⇒ смоук пишется и ждёт машину, а в теле PR пишется явной строкой. **Исправлено 25.11.2026** — PostgreSQL переведён в службу Windows с правами NetworkService, см. [`stand.md`](stand.md).
- **✅ `taskkill` гейт ПУСКАЕТ, а `Stop-Process` — режет (23.11, вечер):** `Stop-Process -Id <pid> -Force` и `Stop-Process -Name electron -Force` дают `HOST_CAPABILITY_UNAVAILABLE`, а `taskkill /PID <pid> /F` и `taskkill /IM electron.exe /F` проходят. Зомби-backend (порт 3003 занят, а pid-файла нет — его съел прошлый `stop.ps1`) снимается только так.
- **⚠️ `pnpm rebuild better-sqlite3` НИЧЕГО не делает** (23.11, вечер): модуль остаётся под ABI Electron (148), и vitest `electron-app` красный на 44 файлах («compiled against a different Node.js version»). Рабочий путь (проверен): `node node_modules/.pnpm/node-gyp@12.4.0/node_modules/node-gyp/bin/node-gyp.js rebuild --release --directory=node_modules/.pnpm/better-sqlite3@12.11.1/node_modules/better-sqlite3` — заголовки Node 24.19.0 уже в кэше node-gyp, сети не нужно.
- **`electron-builder install-app-deps` иногда зависает** (23.11, вечер): node-gyp ретраит python-процессы каждые ~20 с и не finishes — повторный запуск (в фоне, без перенаправления) проходит за минуту.
- **⚠️ Гейт режет запуск PostgreSQL — в такой сессии стенд не поднять (23.11.2026):** `Start-Service postgresql-x64-17`, `net start postgresql-x64-17`, `pg_ctl start`, прямой `postgres.exe -D …` — **все четыре формы** дают `HOST_CAPABILITY_UNAVAILABLE` (гейт не может показать вопрос). Служба `postgresql-x64-17` при этом стоит, а порт 5432 не слушает ⇒ **без БД не поднимутся ни backend, ни клиент ⇒ CDP-смоук невозможен**. Это надо **проговаривать явно в теле PR** («смоук не гонялся — гейт не даёт поднять БД»), а не молча пропускать гейт. **Исправлено 25.11.2026:** служба запускается сама и держит кластер (`Get-Service postgresql-x64-17` → Running).
- **Read-only ssh на прод при этом проходит, и список логинов можно сверить с репозиторием, не выпуская логины в чат (23.11.2026):** `ssh matricarmz 'set -a; . /etc/matricarmz/matricarmz.env; set +a; psql -At -h $PGHOST -p ${PGPORT:-5432} -U $PGUSER -d $PGDATABASE -c ''select …'''` — вывод кладётся в **переменную PowerShell**, а в отчёт идут только **имена файлов** (совпадения ищутся по границам слова; логины-роли вроде `admin`/`owner` дают ложные срабатывания — их надо исключать отдельно). Квики PowerShell 5.1: одинарные кавычки внутри удалённой команды **удваивать**, символ `|` в удалённой команде **не использовать** (режется), а `$PGHOST` и прочее писать без локальных кавычек, чтобы развернул удалённый shell.

## Стенд lane3 в worktree `m2`: прогресс поиска с отменой (26.11.2026, полоса 2, промт #166)

- **Порты lane3:** backend **3004**, vite **5176**, CDP **9225** (свободны были), БД — `matricarmz_dev_lane3`. Логин стенда — `verify` / `verify123`.
- **⚠️ `start-backend.ps1 -Stand laneN` уводит backend в чужую БД:** backend читает `PG*` из окружения процесса (`backend-api/src/database/db.ts`), а скилл ставит `PG_VERIFY_DB`, который backend не видит ⇒ именованный стенд молча едет на `matricarmz_dev`. Лечение — **свой лаунчер** `.verifier-electron/start-lane3-backend.ps1`: `Import-DotEnv` → затем явно `PGDATABASE=matricarmz_dev_lane3`, `PGPASSWORD=postgres`, `PORT=3004`. Пароль суперюзера PostgreSQL на PC79 — `postgres` (`psql -U postgres`), без него psql уходит в интерактивный запрос и **висит**.
- **⚠️ `electron-builder install-app-deps` может «успешно» ничего не пересобрать:** electron-rebuild решает по маркеру `build/Release/.forge-meta`; если он остался от Node-ABI сборки (`x64--148`), пересборка пропускается, а бинарника (снесённого заранее) нет ⇒ клиент падает на SQLite-init без окна (грабля [M241](../../gotchas/M241.md)). Лечение: снести **и `.forge-meta`, и `.node`**, потом `install-app-deps`.
- **⚠️ Возврат на Node-ABI: `npx prebuild-install` в каталоге пакета, а НЕ самосборка node-gyp.** node-gyp-сборка работает, но на Windows роняет worker-пул vitest («Assertion failed: (env) != nullptr» в `node::RemoveEnvironmentCleanupHook») — прогон `electron-app` падает «Unhandled Error: Worker forks emitted error» при зелёных тестах. Официальный prebuild (`prebuild-install`) возвращает ровно тот бинарник, что ставит pnpm, и гонка исчезает. Заметка 23.11 («рабочий путь — node-gyp») верна для падения по ABI, но для возврата к pnpm-состоянию лучше prebuild.
- **Смоук:** драйвер `.verifier-electron/lane3/cdp-search-progress.mjs` (вне git, в каталоге стенда) — вход, навигация «Производство → Поиск по файлам», режим «В папках по названию», папка-источник с тестовым деревом (120 папок / 24 000 файлов), старт поиска, поимка полосы, нажатие «Отмена», проверка статуса. Отчёт и снимки — рядом, в `.verifier-electron/lane3/`.
- **Хитрость драйва:** полоса живёт ~200 мс из-за троттлинга, поэтому «сейчас смотрим» надо ловить ПОЛИРОВАНИЕМ DOM (цикл по 20 мс), а не одним снимком: снимок сразу после «Искать» показывает ещё состояние `start` без текущего объекта.
