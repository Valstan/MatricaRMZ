> Вырезано из [`../../PC79.md`](../../PC79.md) 24.11.2026: профиль разложен на части (индекс и что где — в `../../PC79.md`). Пиши сюда по мере изучения, в свою часть.

### Прогон смоука 2026-09-12 (пакет владельца): что сработало

Полная последовательность заняла ~4 минуты и прошла с первого раза после ABI-танца:

1. Сохранить Node-ABI-бинари в скретчпад (они понадобятся обратно), снести `build` у обоих `better-sqlite3*`, собрать Electron-ABI (`electron-builder install-app-deps`). Проверять фактом: `node -e "process.dlopen(...)"` под Electron-ABI обязан **упасть** с «NODE_MODULE_VERSION 148 … requires 137».
2. `start-backend.ps1` откреплённо → ждать `/health` на 3011 (поднимается ~25 с).
3. Снести профиль `%APPDATA%\@matricarmz\electron-app-cdp-9222`, запустить `start-electron.ps1 -Cdp` откреплённо → ждать непустой `/json/list` на 9222 (~15 с).
4. Прогнать драйвер, затем `stop.ps1` **и** добить порт 3011 по владельцу соединения (осиротевший backend — известная грабля выше).
5. Вернуть Node-ABI копированием сохранённых бинарей поверх собранных и проверить тестом `electron-app`: без этого 35 красных.

Пароль стенда для прод-подобных сценариев — `valstan` / `valstan-dev` (у `verify` урезан доступ по разделам). Читающий SQL к базе стенда: `PGPASSWORD=<из backend-api/.env.dev> "/c/Program Files/PostgreSQL/17/bin/psql.exe" -h 127.0.0.1 -p 5432 -U postgres -d matricarmz_dev -c "…"`. Таблица файлов называется `file_assets` (не `files`), и на свежем стенде она пуста — фикстуру файла заводить через REST.

### Замер кадров: GPU vs программный рендеринг (2026-10-18)

- **Как получить «машину без видеокарты»:** `MATRICA_FORCE_SOFTWARE_GPU=1` в окружении перед `start-electron.ps1 -Cdp` (свитч читается в `index.ts` до `ready`, в упакованной сборке игнорируется). Запуск одной строкой:
  ```powershell
  Start-Process powershell -WindowStyle Hidden -ArgumentList '-NoProfile','-ExecutionPolicy','Bypass','-Command',"`$env:MATRICA_FORCE_SOFTWARE_GPU='1'; & '.claude\skills\verifier-electron\scripts\start-electron.ps1' -Cdp"
  ```
- **Драйвер:** `.verifier-electron/cdp-frame-timing.mjs <tag>` — закрывает лишние вкладки, открывает Склад → Номенклатуру, разворачивает самую большую группу и прокручивает список 330 кадров (первый кадр чанка отбрасывается — это пауза на круг CDP, а не работа интерфейса). Требует реально прокручиваемый контейнер (`scrollHeight > clientHeight + 100`), иначе падает, а не меряет пустоту. Отчёт — `.verifier-electron/cdp-frame-timing-<tag>.json`.

Холостой кадр на этом мониторе ~10 мс (100 Гц), то есть 18 мс — это работа, а не vsync.
- **Длинный список на стенде:** `dev:seed-nomenclature-verify` пишет в PG напрямую, без журнала, — клиент этих строк не видит, пока они не проштампованы: `corepack pnpm -F @matricarmz/backend-api sync:restamp:apply -- --tables erp_nomenclature` (dry-run — `sync:restamp`), затем `window.matrica.sync.run()` и перезагрузка страницы. Группа, чьей сущности нет в реплике, рисуется как «Без группы62».

### Прогон смоука 2026-09-18 (гейт дублей этапов работ): что добавилось

- **⚠️ Пикеры (`SuggestInput`/`SearchSelect`) больше НЕ открываются установкой значения.** Подсказка рисуется `createPortal` и только при `dropdown.open`; сеттер свойства (`setVal`) меняет текст в поле, но список не открывает — опций `div[data-idx]` нет вовсе, а форма потом честно отказывает «Выберите двигатель». Старый рецепт `setVal(engInput, …)` в `cdp-work-sheets.mjs` (16.09) **устарел** — вероятно, вместе с переездом всплывающих слоёв в портал (M140, v3.41.0). Рабочий способ — печатать по-настоящему: сфокусировать поле из `Runtime.evaluate`, затем `Input.insertText` доменом CDP, дождаться `div[data-idx]` и кликнуть опцию **нативным** `opt.click()`.
  ```js
  await evaluate(ws, `const i = vis('input', vis('[data-work-sheet-editor-engine]', PAGE())[0])[0]; i.focus(); i.click(); return {ok:true};`);
  await send(ws, 'Input.insertText', { text: 'ДВ-1003' });      // настоящий ввод, не сеттер
  await waitVal(ws, `vis('div[data-idx]').length > 0`, 'подсказка');
  ```
- **Грабля «цикл ожидания внутри одного `Runtime.evaluate`» сработала снова** (она уже описана ниже по файлу — подтверждение, что это не разовость). Симптом коварнее, чем кажется: драйвер получает `timeout Runtime.evaluate`, **а страница при этом живёт и действие продолжается** — в первом прогоне 18.09 это дало противоречивое доказательство (драйвер «упал», а строка возврата в базе появилась). Любой опрос состояния — короткими повторными `evaluate` со стороны драйвера.
- **Скриншот диалога — единственный способ проверить текст для оператора**: `Page.captureScreenshot` после `waitVal` по `#pick-choice-title`. У диалога `pickChoice` из `ConfirmContext` есть свои id — `#pick-choice-title` и `#pick-choice-detail`, позиционного угадывания не нужно.
- **⚠️ Бинарь `better-sqlite3-multiple-ciphers` в скретчпаде мог остаться Electron-ABI** от прошлой сессии: «сохранить перед танцем» не гарантирует, что сохраняешь Node-ABI. Юнит-тесты `electron-app` используют обычный `better-sqlite3` — его вернуть обязательно, а расхождение по второму на тесты не влияет. Проверять — `dlopen`-фактом по каждому отдельно, а не «оба скопировались».
- Драйвер: `.verifier-electron/cdp-work-sheet-duplicate-gate.mjs` (17 шагов: гейт поднимается, «Отмена» строку не создаёт, подтверждение создаёт её проходом № 2, список подписывает «· проход 2», правка возврата не переспрашивает).
