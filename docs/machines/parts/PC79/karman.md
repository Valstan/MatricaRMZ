### ⚠️ Комната КАРМАНА доступна с этой машины (2026-11-07)

Пишущий токен комнаты лежит на машине владельца: `%USERPROFILE%\.matricarmz-keys\karman-token`.
Комната `matricarmz`, права токена — `canWrite: true`, `identity: null` (статический).
Адрес и устройство API — в `brain_matrica/docs/KARMAN_ROOM.md` (в публичный репо не пишем).

```powershell
$env:HTTP_PROXY=''; $env:HTTPS_PROXY=''; $env:ALL_PROXY=''; $env:NO_PROXY='*'
# Адрес хранилища — в локальном файле рядом с токеном: в репозиторий (репо публичный)
# адрес не пишем. Правило и устройство API — brain_matrica/docs/KARMAN_ROOM.md.
$VAULT = (Get-Content "$env:USERPROFILE\.matricarmz-keys\vault-url" -Raw).Trim()
$TOKEN = (Get-Content "$env:USERPROFILE\.matricarmz-keys\karman-token" -Raw).Trim()
# имена ключей — без значений
(Invoke-WebRequest "$VAULT/api/secrets" -Headers @{Authorization = "Bearer $TOKEN"} -UseBasicParsing).Content
```

Значение ключа наружу не печатать: сверять с продом по `sha256` (сравнение делается на боксе,
наружу уходят только хэш и длина). Ключ `DEEPSEEK_API_KEY` в комнате на 07.11.2026 совпал с
живым `MATRICA_AI_DEEPSEEK_API_KEY` на боксе — зеркало свежее. В репозиторий ключ не кладём:
замеры читают его из комнаты на лету.

### Промты проекта из КАРМАНА (2026-11-08)

- **Токен раздела `PROMPTS_TOKEN_MATRICARMZ` лежит на машине** в `%USERPROFILE%\.matricarmz-keys\prompts-token` (вне репо, рядом с `karman-token` и `vault-url`). Выпущен 08.11.2026: 48 случайных байт → base64url, 64 символа; значение положено в комнату `matricarmz` (read-back 200).
- **Грант — в комнату `karman-hotline`, а не `karman`:** грант 22 (в `karman`) отозван, грант 23 (в `karman-hotline`) принят 08.11 токеном комнаты-получателя на боксе KARMANa → раздел читается (200, 26 промтов). **Проверка факта:** `GET /api/secrets/self` на боксе сервиса → `{"slug":"karman-hotline","projectId":19}`; комната `karman` (projectId 10) пуста — 0 ключей — и сервис её не читает, поэтому грант туда принимается, а канал остаётся `503`.
- **Читать раздел:**
  ```powershell
  $env:PROMPTS_TOKEN_MATRICARMZ = (Get-Content "$env:USERPROFILE\.matricarmz-keys\prompts-token" -Raw).Trim()
  $env:KARMAN_URL = (Get-Content "$env:USERPROFILE\.matricarmz-keys\vault-url" -Raw).Trim()
  node scripts/karman/prompts-section.mjs list
  ```
  Адрес сервиса в репозитории не хранится — берётся из локального файла.
- **Прокси-обвязка агента мешает:** `HTTP(S)_PROXY=127.0.0.1:10809` (Happ VPN выключен) → перед вызовом обнулять переменные (см. выше), иначе `fetch` падает на прокси.
- **`503` = канал не настроен** (токен раздела не выдан комнате, из которой сервис читает) — **не** повод архивировать промт. `403` = токен не от этого раздела.
- **Границы комнаты работают:** наш токен читает только свою комнату — чужие секреты отдают `404` (проверено 08.11 на трёх именах соседних проектов).
- **Смоук меню ПП (20.11.2026):** `.claude/skills/verifier-electron/scripts/cdp-production-program-menu.mjs` — **21/21 PASS** (панель кнопок; «В Word»/«В Excel» — файлы на диске; в файле те же строки, что на экране; буфер; письмо с вложением; печать). Рецепт стенда — как у смоуков ПП (миграции → backend на свежем коде → ABI-свап на electron → `pnpm dev` долгоживущей фоновой задачей с `MATRICA_CDP_PORT=9222` → смоук → снос → ABI-свап обратно на node). **Грабли этого смоука:**
  - `jszip`/`exceljs` надо брать **из `electron-app`**: `createRequire(new URL('../../../../electron-app/package.json', import.meta.url))` — в корне монорепо в pnpm их нет, `import('jszip')` из смоук-скрипта падает;
  - **имя файла-вложения в письме появляется не сразу** (файл собирается в main) — проверять надо «дождались `.docx` в окне», а не «открылось окно»;
  - **тема письма лежит в поле ввода**, а не в тексте окна: `innerText` её не содержит, читать `input.value`;
  - **двигатели сверять с ЭКРАНОМ**, а не с фикстурой: у стендового движка `RMZ61` нет ни марки, ни номера, и в ячейке плана он пуст — как и в файле.
- **Стенд после этого прогона снят полностью (20.11):** клиент закрыт (CDP `Browser.close`), backend отработал лимит часа фоновой задачи и ушёл, **порты 3001/3002/5173/9222 свободны**, **ABI better-sqlite3 возвращён на Node** (проверено тестом `preloadContract.guard.test.ts`). Перед следующим прогоном стенд поднимается с нуля; если порт 3001 занят — значит, backend кто-то не снял (в этом рантайме kill-процессов может не спросить подтверждение и будет отказан).
- **ABI-свап без записи сквозь hard-link** (грабля [M209](../gotchas/M209.md)): файл `better_sqlite3.node` в `node_modules/.pnpm` — hard link на store; `Copy-Item -Force` пишет сквозь него и портит store для всех воркаутов. Рабочий порядок: **сначала снести файл** (`rm -- <путь>`, в корзину), **потом положить бинарь** из `.verifier-electron/abi-backup/`. Пока клиент жив, файл занят и не удаляется — сначала закрыть клиент.
- **Закрыть клиент стенда, не имея прав на kill:** CDP-команда `Browser.close` по таргету `127.0.0.1:5173` закрывает приложение (ответ приходит таймаутом — это норма, процесс всё равно уходит), после чего `.node`-файлы освобождаются.
- **Смоук вкладки «История заездов» (20.11.2026):** `.claude/skills/verifier-electron/scripts/cdp-engine-arrivals-tab.mjs` — **14/14 PASS** (вкладка открывается; лента заездов с приходом/отправкой/дефектом; у заезда по рекламации свой договор и свой контрагент; в очереди рекламаций поля «Договор заезда» и «Контрагент (заказчик)»; фикстура убрана). Рецепт стенда — тот же (миграция → backend на свежем коде → ABI-свап на electron → `pnpm dev` долгоживущей фоновой задачей с `MATRICA_CDP_PORT=9222` → смоук → снос → ABI-свап обратно на node). **Грабли этого смоука (переносимые на любой смоук карточек):**
  - **вкладку карточки нельзя искать по тексту**: в шапке карточки есть одноимённая кнопка **печати** («Рекламация») — клик открывает печать, а не вкладку, и смоук «открыл вкладку», не заметив. Надёжно: искать **соседей по общей полосе вкладок** (`CardTabs`) — нашёл вкладку-эталон, нашёл её родителя, нашёл в нём нужную;
  - **поле поиска искать по подсказке, а не по слову «поиск»**: в DOM есть «Поиск беседы…» (чат) и «Поиск по всем данным двигателя…» (список) — фильтр по подстроке «поиск» выбирал чат, и смоук писал номер двигателя в переписку;
  - **раздел открывать верхней полосой** (`button.v3-tab-label` с точным текстом), а не пунктом меню: пункт меню может вести в другое место (у нас «Двигатели» есть и в списке, и в справочнике);
  - **строки списка — по таблице с нужной шапкой**, а не «первой строке с номером»: стенд держит открытыми экраны прошлых прогонов (keep-alive), и строка из чужой таблицы подходит под ту же подстроку.

- **⚠️ Правку файлов репо через PowerShell-конвейер не делать (23.11.2026):** `Get-Content -Raw … | Set-Content -Encoding utf8` **испортил** файл теста: PS 5.1 прочитал UTF-8 как ANSI (кракозябры в кириллице) и записал обратно с BOM ⇒ файл пришлось переписывать целиком. Тот же класс, что заметка про передачу скриптов на бокс байтами (17.11) и про `psql` из PowerShell (16.11): **файл на этой машине содержит не то, что кажется при чтении через PowerShell.**
