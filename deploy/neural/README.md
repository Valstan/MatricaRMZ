# Сторож эгресса движка (контур A)

Что здесь лежит и зачем. Установка — `sudo bash deploy/neural/install.sh`,
посмотреть без изменений — `sudo bash deploy/neural/install.sh --dry-run`.

## Задача

Трафик серверного opencode-движка (`opencode-web.service`, пользователь `opencode`) обязан идти
через ВПН: free-тир провайдера считает сообщения на **сеть**, а не на процесс, поэтому прямой выход
бокса = общая квота с чужим трафиком. Директива — brain `2026-10-22-engine-egress-via-vpn-and-rate-measurement`.

Редирект делает `neural-egress-redirect` (nft-правило по uid движка), он **не наш** — приходит вместе
с установкой ВПН. Грабли: правило, нацеленное на чужой uid, выглядит включённым и молчит (GOTCHAS **M168**).

## Что делает сторож

`tunnel-watchdog.sh`:

| Режим | Что делает | Тратит квоту провайдера? |
|---|---|---|
| `--check` (таймер, каждые 2 мин) | живость туннеля по exit-IP (`api.ipify.org`); последний **реальный** запрос Ииваныча в `ai_chat_requests` — если его обслужил не движок, запускает холодную ротацию | **нет** (пока не сработала ротация) |
| `--cold-rotate` | гасит движок → меняет сервер ВПН → поднимает движок → спрашивает его **текстом того вопроса, который оператор уже задал**; до 3 серверов | да, но это уже заданный вопрос |
| `--find-exit` | перебор всех серверов подписки (`ATTEMPTS`, по умолчанию 21) | да — только для диагностики, руками |
| `--force-rotate` | переключение при живом туннеле (проверка механизма) | да |
| `--dry-rotate` | собрать и проверить конфиг следующего сервера, ничего не применяя | нет |
| `--test-alert` | тестовое сообщение в Telegram | нет |
| без аргументов | только живость туннеля, при отказе — следующий сервер | нет |

Правила, которые сторож держит:

- **Никаких синтетических проб.** Каждая проба = одно сообщение квоты free-тира; единственный
  законный пробный запрос — тот, который оператор уже задал (GOTCHAS **M169**).
- **Fail-closed не нарушается:** прямого пути в конфиге нет, упавший туннель = нет выхода.
- **Смена сервера — лечение мёртвого туннеля, не «сброс квоты».** Перебор 21 сервера подписки
  возвращает 429 на каждом; ротация полезна, когда сел сам сервер.

`engine-probe.py` — проба ответа движка через session-API: различает «сеть мертва», «провайдер ответил
429/402» и «ответ пришёл». Модель можно задать (`ENGINE_PROBE_MODEL`), ожидание — `ENGINE_PROBE_WAIT_MS`.

## Таймеры

- `tunnel-watchdog.timer` — `--check` каждые 2 минуты. Провайдера не трогает, стоит копейки.
- `neural-subscription-refresh.timer` — раз в неделю обновляет список серверов подписки
  (`refresh-subscription.sh` приходит из установки ВПН, не из этого репозитория).

## Журнал

`/var/log/neural/tunnel-watchdog.log`. Именно файл: `logger -t tunnel-watchdog` на боксе не доходит
ни до journald, ни до syslog — записи теряются молча (GOTCHAS **M170**).

## Секреты

В самих скриптах секретов нет: токен движка, пароль PG и параметры Telegram сторож читает во время
работы из `/etc/matricarmz/matricarmz.env`. Алерт включается значением `MATRICA_TELEGRAM_ENABLED`
в формах `1|true|yes|on` (GOTCHAS **M171** — проверка `= "1"` молча выключала все уведомления).
