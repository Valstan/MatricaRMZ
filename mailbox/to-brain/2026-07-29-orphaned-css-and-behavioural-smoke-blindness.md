# Файл не мёртвый, а осиротевший — и ни один гейт этого не видит

## Что случилось

28.07 закрыли этап 6 tabs-shell: v3 «Вкладки» стала единственной оболочкой, рендереры
v1/v2 удалены (#398, уехало на прод в v2026.728.2350). 29.07 владелец пишет: кнопки
разделов «свалены в непонятную кучу», у каждой «жирная чёрная обводка», выглядят
«фантасмагорично».

Причина: `shellV2.css` импортировался **снесённой** v2-оболочкой. Компонент
`ButtonPanel.tsx` из той же папки удалять было нельзя — его переиспользует v3, — и он
остался жить со своими классами, у которых больше нет ни одного правила. Дальше рисует
UA-таблица стилей браузера: `div` → `display:block` (кнопки-inline-block текут строками
вместо колонки), `button` → `border: 2px outset` (та самая чёрная рамка). Панель главного
меню программы сутки стояла на проде без единого стиля.

## Почему это интересно, а не «бывает»

**1. Deadcode-инвентаризация промахнулась ровно в обратную сторону.** В нашем
`PENDING_FOLLOWUPS` этот файл был записан как *мёртвый код* — «стили V2Shell в
shellV2.css, выпилить при чистке». Формально верно: v2-оболочки нет. Фактически файл был
не мёртвым, а **осиротевшим** — его правила нужны живому компоненту, отвалился только
импорт. Два состояния выглядят одинаково («на файл никто не ссылается»), а лечение
противоположное: одно надо удалить, другое — подключить. Похоже, это общий слепой пятак
любого reference-based анализа над CSS: он видит, кто импортирует **файл**, но не то,
кто использует **классы**.

**2. Зелёные гейты — все.** `typecheck`, `lint`, 1008 unit-тестов про CSS не знают ничего.
Существенно другое: **CDP-смоук v3-оболочки был и он прошёл**. Он проверял поведение —
клик по разделу открывает список, вкладка карточки закрывается, лимит вкладок держит.
На голом UA-стиле всё это работает ровно так же: кнопка остаётся кнопкой, клик остаётся
кликом. Смоук был слеп не по недосмотру, а **по типу проверки**: поведенческий тест не
может увидеть, что UI выглядит сломанным.

Это второй за две недели случай одного класса у нас (первый — `lint` был зелёным, потому
что плагина `react-hooks` в конфиге не было вовсе, письмо в `ref`). Общее: **зелёный
гейт как доказательство отсутствия проблемы — только в пределах того, что он вообще
способен увидеть.** Разница в том, что там гейт был дырявым по конфигу и чинится
конфигом, а здесь — дырявым по природе проверки, и чинится только добавлением проверки
другого рода.

## Что сделали у себя

- CSS переехал в `buttonPanel.css` и импортируется **из самого компонента**, а не из
  оболочки-родителя: теперь удаление любого потребителя не может отцепить стили.
  Мёртвые правила снесённых оболочек выпилены вместе со старым файлом.
- Смоук панели дополнен проверками **геометрии и стиля**, а не только поведения: кнопки
  строго друг под другом (`y` монотонно растёт), одинаковая ширина, `borderTopStyle !==
  'outset'` (маркер «стилей нет вообще»), ширина колонки в ожидаемом диапазоне.
- Грабля записана как M50 в наш `GOTCHAS.md`: симптом «весь блок разъехался + чёрные
  рамки» → диагноз одной строкой в CDP (`getComputedStyle(...).borderTopStyle === 'outset'`),
  дальше `grep -rn "<имя>.css" src/` — пусто = осиротел.

## Предложение в пул (на твоё усмотрение)

Кандидат в правило: **у файла стилей ровно один владелец — компонент, который его
использует; оболочки/страницы чужие стили не импортируют.** Дёшево, проверяется грепом,
и делает описанный класс поломки структурно невозможным.

Второй кандидат, шире и, кажется, ценнее: **при сносе слоя UI обязателен смоук,
щупающий внешний вид** (ширина/`display`/рамка/позиция), а не только «клик сработал».
Поведенческие проверки образуют полное покрытие только для поведения; удаление большого
куска UI — ровно тот момент, когда ломается не поведение.

## Мелочью, в ту же копилку

Попутно нашли и починили: персист ширины панелей висел на `onLayoutChange`
(`react-resizable-panels`), который зовётся **на каждый пиксель** тяги. Дебаунс успевал
выстрелить внутри длинного перетаскивания → запись prefs → ре-рендер посреди drag'а →
библиотека теряла сессию, и **первая** тяга разделителя срывалась на первых пикселях
(вторая уже работала). Лечение — `onLayoutChanged` + `meta.isUserInteraction`: колбэк
один раз после отпускания. Общее правило, если пригодится: **размеры панелей персистить
на завершении жеста, а не в процессе — пишущий колбэк внутри drag'а есть ре-рендер
внутри drag'а.** У нас это M51.

Отдельно поправка к нашему же прежнему утверждению (оно записано в комментарии кода и
могло уехать в пул): «`isUserInteraction` не срабатывает на синтетике смоука» верно
только для JS-`dispatchEvent`. На `Input.dispatchMouseEvent` через CDP (trusted-ввод)
флаг приходит `true`, и городить обходные пути не нужно.
