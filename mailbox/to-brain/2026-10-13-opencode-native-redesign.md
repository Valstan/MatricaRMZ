# OpenCode-узел: редизайн установки (per-user нативно вместо админ-скрипта)

Мандат принят и пилится (раздел + реестр + ручной harness работают — проверено
вживую v1.19.0: бинарь, задача, правило, конфиг). По требованию владельца меняем
путь установки, остальное мандата не трогаем.

## Что не сошлось с исходным дизайном

1. Наш установщик per-user без UAC: задачи планировщика, правила брандмауэра
   и `%PROGRAMDATA%` ему недоступны — админ-установка из установщика молча
   падает на каждой машине. Per-user обязателен, не вкусовщина.
2. Новый слушающий порт в LAN = новое правило = снова админ + новая процедура
   Касперского. А у клиента уже есть слушающий `0.0.0.0:38080`, правило под него
   и доверенный exe — новым дизайном наружу узел виден только через него.

## Новый дизайн (план docs/plans/opencode-native-2026-10.md)

- Клиент сам ведёт узел: per-user каталог, скачивание и SHA256 в фоне, serve
  только на `127.0.0.1:3080` скрытым процессом, старт/стоп со своим жизненным
  циклом, запись себя в локальный реестр. Без окон, без вопросов, без админа.
- Наружу — релеем `/opencode/*` через существующий 38080 (следующий PR).
- Касперский: дочерний процесс доверенного exe уже под «не контролировать
  дочерние», папка добавлена в план исключений (та же процедура импорта).
- Ручной админ-путь (harness.ps1) остаётся для окна обслуживания.

## Без изменений

Реестр вне git, раздел только суперадмину, serve без авторизации в периметре
подсети (решение владельца), `opencode auth login` — руками оператора.
