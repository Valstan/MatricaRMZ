# Тест на функции не доказывает существование двери: путь — часть контракта

## TL;DR

В MatricaRMZ четыре дня не сохранялись договоры: оператор видел «ошибку», клиентские логи
молчали, `journalctl` молчал, тесты зелёные. Корень — роутер смонтирован дважды:
`app.use('/contracts', contractsRouter)` снаружи и `contractsRouter.post('/contracts', …)`
внутри → фактический путь `/contracts/contracts`. Сервис `contractStrictService` был жив,
покрыт тестами (функции вызывались напрямую, импортом), а дверь по пути клиента отвечала
404. Класс: **«контракт — это не только имя функции, но и путь, по которому её зовут»**.

## Как устроено у нас

1. Клиент (`electron-app/.../register/contracts.ts`) зовёт `POST /contracts`.
2. Сервер: `app.use('/contracts', contractsRouter)` + внутри `post('/contracts')` — путь
   удваивается; Express молча монтирует оба, `/contracts/contracts` отвечает 200, `/contracts` — 404.
3. `contractStrict.test.ts` тестировал `createContractStrict`/`patchContractStrict` — прямой
   импорт функций, **через HTTP не ходил вовсе**. Тест на поведение сервиса зелёный при мёртвом пути.
4. 404 Express **не логируется приложением** (до обработчиков дело не доходит) — и клиентские
   логи, и `journalctl` чисты. Улика нашлась только в nginx access-log (`POST /contracts → 404`,
   десятки строк), а живое воспроизведение (локально: `/contracts` → 404, `/contracts/contracts` → 200)
   дало корень за минуты.
5. Фикс: пути внутри роутеров — без префикса (`post('/')`, `get('/:id')`) + сторож
   `routes.test.ts` «двери смонтированы по путям клиента» (падает на старом коде подрывом;
   вторая половина — фантомный `/contracts/contracts` должен отвечать 404).

## Почему переносимо

Везде, где сервер и клиент знакомы по строке — HTTP-путь, gRPC-метод, WebSocket-канал,
queue-топик — `app.use`-префикс и внутренний путь живут в **двух местах**, и рассогласование
между ними не пересекает ни компилятор, ни юнит-тесты функций. Два дешёвых правила:

- **тест на путь** (суpertest/httpx): живая дверь отвечает не-404, фантомный двойной префикс — 404;
- **404 на живую кнопку ищется в access-log**, не в логах приложения (приложение 404 не пишет).

Родня: существующий G184 (связка по строковому имени через границу процессов — там
исчезновение хендлера, здесь рассогласование путей) и идея #347 (переименование пути —
изменение контракта). Класс тот же — строковая граница, невидимая компилятору; эта запись —
третья грань: **путь собран неправильно при живом сервисе**.
