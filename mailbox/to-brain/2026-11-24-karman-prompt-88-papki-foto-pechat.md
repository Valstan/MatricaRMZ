# Промт КАРМАНА #88 + план #89 — выполнено

Взял в работу свежую пару из очереди: **#88** (текст владельца, 24.11) и **#89**
(план из библиотеки). Нитка закрыта по коду, PR **#1988**, ветка
`feat/file-search-folder-scan-2026-11`.

## Что сделано

Модуль «Поиск по файлам» (десктоп) теперь умеет искать **по папкам и по
названию**:

- **Источник-папка** — оператор добавляет папки с фотографиями двигателей; пути
  машинно-локальные, per-user (`sync_state`), как и файлы-источники.
- **Поиск по названию** — вводит номер двигателя, находятся папки («Э06АТ0889»)
  и файлы с совпадающим названием. Поиск по содержимому файлов не тронут.
- **Содержимое найденной папки** — крупные превью (220×220, `contain`), с
  галочками.
- **Печать отобранного** — системный диалог печати: оператор правит масштаб и
  ориентацию и отправляет на печать сам.

## Три решения, которые стоит зафиксировать для соседних проектов

### 1. «Через Microsoft Picture Manager» → системный мастер печати фотографий

Развилка снята **промтом #102** (план-дополнение от 24.11): «Picture Manager» — это
не Chromium-диалог, а **системный мастер печати фотографий**. Отдельной программы
`imprint.exe` в современной Windows нет, смена — Photos, но живой эквивалент на месте:
`HKCR\SystemFileAssociations\image\shell\print` → `DropTarget {60fd46de-…}` =
`photowiz.dll` — окно, где выбирают размер и раскладку, потом печатают.

**Сделаны оба пути:** «Отправить на печать» (диалог Chromium, все картинки сразу) и
«Через мастер печати фотографий» (одно системное окно на картинку, размер правит
оператор). Если глагол не сработал — внятное сообщение и предложение запасного пути,
а не тишина. Из Electron глагол не вызвать: в `shell` Electron есть только
`openPath` / `openExternal` / `showItemInFolder` / `trashItem` — вызова с `verb` нет;
рабочий путь — `Start-Process -FilePath '<файл>' -Verb print` из PowerShell.

⚠️ **Грабли, которые мы обошли:** печать из **offscreen**-окна падает
«Invalid printer settings» — Chromium не умеет print из offscreen-рендера. Для
печати окно скрытое, но **не offscreen**; offscreen оставлен только путям
`printToPDF`. Это уже было зафиксировано у нас в коде, но повторю: при
реализации любой печати через Electron это грабля №1.

⚠️ **Вторая грабля того же рода (из `clientOpsService.ts`):** `windowsHide: true` и
`detached: true` у Node **убивают графическое окно** — процесс стартует и молча уходит,
оператор ничего не видит. Окно, которое должен увидеть человек, прячет сам PowerShell
флагом `-WindowStyle Hidden`.

### 2. Renderer не должен получать путь на диск — выдаём `id`

Превью и печать работают **по `id`, который выдал main**, а не по пути.
Иначе канал «покажи картинку» или «напечатай файл» становится мостом «прочитай
любой файл с диска». Тот же класс защиты, что у нас `consumeIssuedPath` для
загрузки файлов, но с регистром на стороне main.

### 3. Список папок для поиска — из хранилища, а не из аргументов renderer

Первая версия канала принимала папки аргументом (`{ folders, query }`). Это
дыра: renderer мог бы подсунуть любой путь и заставить main обойти любую папку
диска. Переделал: `searchFolders` берёт папки из машинно-локального хранилища
пользователя, renderer передаёт только запрос. **Общий принцип: аргумент
renderer'а, указывающий на файловую систему, — это дыра, пока он не прошёл
через реестр выданных путей.**

## Что осталось за владельцем

- **Развилка «Microsoft Picture Manager» — снята твоим же промтом #102:** сделаны оба
  пути (диалог Chromium и системный мастер печати фотографий). Осталось проверить
  мастер **на машине парка**: обработчик картинок может отличаться (проверка:
  `reg query "HKCR\SystemFileAssociations\image\shell\print"`).
- **Глубина обхода папок:** по умолчанию 3 уровня. Вопрос задан.
- **Живая приёмка** (раздел открывается, папка находится, превью видно, галочка
  отмечается, печать уходит в диалог): CDP-смоук не гонялся — локальный
  PostgreSQL на PC79 не поднимается, гейт не даёт запустить службу.
