# Отметка «спрятать колонку один раз» должна быть по колонке, а не по пользователю

**Одна строка:** `механизм разового умолчания в списках (спрятать колонку один раз у тех, у кого она уже видна) помечал факт применения на пользователя и на список колонок; из-за этого колонка, добавленная в умолчание позже, у всего парка не спряталась бы никогда — нашли на живом смоуке, починили`.

## Что было

Механизм `HIDE_ONCE` в `electron-app/src/renderer/src/ui/hooks/columnLayoutStore.ts` решает задачу «колонка была видимой по умолчанию, а теперь владелец хочет её выключить — но чтобы у того, кто её включил руками, она не исчезала». Отметка о применении лежала в `localStorage` как ключ `<user>:<list>` со значением «1»:

```ts
if (window.localStorage.getItem(key)) return null;   // «это умолчание уже применялось»
```

Пока в списке умолчаний была одна колонка, этого хватало. Стоило добавить вторую — и у всех, кто отметку уже получил, механизм видел «уже применяли» и выходил, ничего не пряча.

## Почему это переносимо

Паттерн «применить новое умолчание один раз, но уважить выбор оператора» — общий для любых настроек, у которых есть **сохранённое состояние пользователя** и **новое значение по умолчанию**. Метка «применялось» должна относиться к **конкретному значению**, а не к «списку умолчаний вообще»: иначе второе изменение умолчания приходит слишком поздно.

Починка (у нас): значение отметки — список id применённых колонок через запятую, старое значение «1» читается как «единственная колонка, что тогда была». Новая колонка прячется один раз у всех, а включил оператор — больше не трогаем. Тест на это — в `columnLayoutStore.test.ts` (4 новых случая).

## Где это пригодится ещё

- настройки колонок списков (у нас — 14+ списков);
- «новый фильтр по умолчанию», «новая сортировка по умолчанию» — тот же приём: сохранённая у пользователя раскладка знает старое значение, а новое умолчание должно примениться один раз;
- любые «новые поля в карточке», которые раньше были видны всем, а теперь по умолчанию скрыты.

**Дешёвая проверка на будущее:** механизм, который «помнит, что уже применял», должен хранить **что именно применял**, иначе следующий канал сломается так же тихо, как этот.

## Пара промтов КАРМАНА взята в работу

Промты **#8** (текст владельца) и **#12** (план из библиотеки) — «Колонка „Привязка“: три цифры договора вместо слова „договор“, номер ДС, и колонка выключена по умолчанию» — прочитаны 12.11.2026 и взяты в работу: в ячейке теперь рабочий номер договора и номер ДС («125/2»), у непривязанного — только красный кружок, колонка выключена по умолчанию (в том числе у тех, у кого она была видна). План уточнён под наш код, смоук на стенде — 12/12. **В архив уйдут после выкатки** (правило D-190: архив = «сделано»).

Отдельно нашлась **находка по данным**: у 55 двигателей раздел ДС лежит в старом формате («3» без слова «ДС»), ещё у 8 в поле раздела — номер договора. Приложение такие значения ДС-ами не считает, поэтому подпись «/N» даётся только по канону; решение по этим строкам — за владельцем (запись в PENDING).
