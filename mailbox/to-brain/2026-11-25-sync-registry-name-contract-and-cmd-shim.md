# Реестр sync: имя поля — это контракт, и молчаливый вылет Node на .cmd

Нитка по промтам КАРМАНА **#59**/**#62** (локальный MiniMax на клиенте). Код модуля был выпущен
23.11 (PR #1917) **без живого прогона**. Смоук на стенде 25.11 показал, что запись ответа не
работала вовсе. Три поломки — две из них переносимые классы.

## 1. Общий реестр sync берёт поле из строки ПО ИМЕНИ ⇒ расхождение имён = молчаливая потеря

Клиент и сервер читают одну таблицу (`ai_chat_requests`) через **общий** реестр
`shared/src/sync/registry.ts`: DTO-строка собирается из полей реплики по маппингу
`{ db: 'answerSource', dto: 'answer_source' }`. У клиента поле называлось `serverAnswerSource`.

Что получилось: `toSyncRow` **молча выбросил** поле (`undefined` ⇒ ключ не попал в payload),
сервер получил вопрос без `answer_source`, отверг ответ как «не processing» и оставил вопрос
висеть до `reclaimStale`. Юнит-тесты были зелёные: политика push проверялась на готовых
DTO-строках, а сборка DTO из реплики — нет.

**Класс:** контракт, заданный реестром, проверяется только на той стороне, где поле названо
одинаково. Сторож «имена полей реестра есть в колонках реплики» (`aiChatAnswerSourcePush.test.ts`)
ловит это за секунды — а раньше ловил только живой прогон.

**Что переносимо:** если у портфельных проектов общий реестр DTO ↔ реплика — сверяйте имена
полей **обеих** сторон тестом, а не глазами. Имя поля в реплике — такой же контракт, как имя
таблицы.

## 2. Node не исполняет `.cmd` без `shell` ⇒ npm-шимб мёртв на Windows-клиенте

Клиентский модуль запускал `mcode.cmd` (то, что npm кладёт рядом на Windows). Node даёт на этом
`EINVAL` (запрет запуска `.bat`/`.cmd` без `shell` — защита от аргумент-инъекции), а `shell: true`
открыл бы окно консоли — то есть «молчание» (план #62 п. 9, грабля M214) было бы нарушено.

Решение: клиент находит **настоящий JS-вход** (сначала одноимённый файл рядом, потом путь внутри
shim npm — `"%~dp0\..\@minimax-ai\code\bin\mcode.js"`) и запускает его **рантайм-node, который едет
с модулем**. Окна нет, `detached` по-прежнему выключен.

**Класс:** «запусти бинарь из node_modules» на Windows — это не `spawn(path/to/bin.cmd)`, а
`node.exe <настоящий JS-вход>`. Клиентская машина без системного Node — норма, значит рантайм
должен ехать с модулем и быть указан явно.

## 3. Относительные пути bundle надо разрешать от каталога самой конфигурации

Конфиг рантайма читался из трёх кандидатов (resources, dev-сборка), а относительные пути внутри
всегда разрешались от resources-каталога ⇒ в dev-режиме модуль объявлялся «не настроенным», и
никто этого не замечал: на боевой машине раскладка другая.

**Класс:** если конфиг ищется в нескольких местах, то и база относительных путей — это каталог
**найденного** файла, а не «каталог сборки».
