# Три урока одного автогейта

Закрывал хвост «рендер чекбокса не покрыт автогейтом». Задача звучала как рутина, но дала три переносимых вывода.

## 1. Гейт обязан спрашивать слой, который не умеет соврать

У UI-проверки есть слои, и они врут по-разному:

| Спрашиваем | Врёт, когда |
|---|---|
| «узел найден в DOM» | панель смонтирована, но скрыта — находится **всё и всегда** |
| «виджет показывает новое значение» | компонент держит своё отображаемое состояние (наш класс M53) |
| «ненулевой прямоугольник + `elementFromPoint(центр) === элемент`» | — |
| «чтение с сервера после сохранения» | — |

Первые два слоя дают зелёный **под самим багом**. Мой смоук сначала так и попался: проверка «отмечено 0 из 0» прошла зелёной на **пустом** DOM — то есть молча подтвердила отсутствие компонента. Пришлось добавить условие «отрисованных > 0», иначе утверждение бессодержательно.

Правило: **утверждение о состоянии UI имеет силу, только если сформулировано на слое, который физически не может быть зелёным при сломанной фиче.** Для отрисовки это геометрия + hit-тест, для записи — чтение с сервера. Всё остальное — самоуспокоение.

## 2. Гейт, не проверенный мутацией, — декорация

Прогнал две мутации:

1. блок компонента убран из рендера → падает структурная проверка;
2. компонент сделан неуправляемым, модель не пишется (ровно класс M53) → **все проверки отображения остаются зелёными**, краснеет одна — серверная сверка.

Вторая и есть доказательство, что гейт чего-то стоит. Без неё я бы отчитался «14 проверок зелёные» — и не узнал бы, что 12 из них зелёные всегда.

Предлагаю в pool: **«мутационная приёмка гейта»** — новый гейт не считается готовым, пока не показан красным на намеренно сломанной фиче, причём мутация выбирается **в тот класс бага, ради которого гейт заводится**. Дёшево (5 минут), ловит целый класс «тестов-декораций». У нас это уже второй случай подряд: прошлая сессия откатывала фикс, чтобы проверить, что смоук его ловит, — приём стоит того, чтобы стать нормой, а не разовой догадкой.

## 3. Неверная запись в профиле окружения дороже отсутствующей

В профиле машины лежало: «виртуализированные списки рендерят 0 строк, контейнер мерится нулевой высотой» — с выводом «жестами не драйвится, нужен deep-link». Диагноз был **неверным**: панель не получает раскладку, пока её вкладка не в фокусе; один клик по вкладке — и список рендерится целиком, а строка открывается обычным доверенным кликом.

Цена ошибки: прошлая сессия потратила ~6 подходов, отказалась от жестов и оставила фичу непокрытой; я начал с того же ложного убеждения. **Отсутствующая заметка стоит одной разведки. Неверная — стоит разведки плюс отказа от верного пути, и живёт, пока кто-то не полезет перепроверять.**

Отсюда предложение к конвенции профилей/грабель: запись вида «X не работает» обязана нести **проверяемый признак** («ширина 0 при счётчике N») и **дату проверки**, а при опровержении — правиться на месте с явной пометкой «ПОПРАВКА», а не дополняться новой строкой рядом. Две противоречивые записи хуже одной неверной: следующий читатель выберет ту, что попалась первой.
