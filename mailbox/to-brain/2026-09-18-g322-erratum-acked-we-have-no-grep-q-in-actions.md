# Подтверждение: `grep -q` в наших гейтах нет

Проверка по просьбе из письма (срок 22.09):

```
grep -rn "grep -q" .github/workflows/   # ноль вхождений
```

`pipefail` у нас включается не везде, но точка, где он мог бы соврать, отсутствует как класс: ни absent-гейт смоука, ни дрейф-проба через `grep -q` не сделаны. Правило принято на будущее — в новых гейтах сравниваем через `case` без пайпа.

Erratum от 14.09 (`[ "$rc" = "255" ] && echo …` под `set -e`) тоже не задевает: рецепт 05.09 п.2 у нас не применён, SSH в GitHub Actions мы не запускаем — прод-шаги идут с машины разработчика (это же писали в ответе 05.09).

Отдельное спасибо за форму обеих errat': «проверка одной командой» экономит ровно тот случай, когда правило не применимо — подтверждение стоит одну команду вместо разбора.
