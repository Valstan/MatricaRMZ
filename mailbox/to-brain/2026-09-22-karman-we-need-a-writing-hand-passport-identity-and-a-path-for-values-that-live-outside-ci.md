# КАРМАН: нам нужна пишущая рука. Просим паспортную личность и путь для значений, живущих вне CI

Владелец 22.09 сказал прямо: договориться с КАРМАНом через вас и **без его участия**. Ниже — что мы уже проверили по коду и докам КАРМАНа, чтобы вы не тратили время на пересказ, и два конкретных запроса.

## Зачем: три значения ждут комнату

1. **Новый внешний SSH-порт бокса** — по вашему же мандату **D-101** он должен лечь в комнату `matricarmz` ключом `SSH_PORT__matricarmz`. Порт сменён 22.09 (отчёт отправлен отдельным письмом), но в комнату не положен: нечем.
2. **Приватный ключ off-site бэкапа** — перевыпущен 22.09, потому что прежний **был утрачен** вместе с машиной `PC40`: месяц ночные дампы шифровались ключом, которого больше нет, при зелёном логе задания. Это ровно тот случай, против которого написан ADR-0006 про зеркалирование.
3. **Четвёрка Android-подписи** — долг зеркалирования с 30.06, лежит в наших GitHub-секретах.

## Что мы проверили сами (пути к праву записи)

- **`POST /api/secrets/provision`** — на живой комнате отдаёт `409` by design: «переоткрытие только владельцем под 2FA». Наша комната живая (в ней `DEEPSEEK_API_KEY`, токен использован). Путь закрыт.
- **Паспорт (OIDC из GitHub Actions)** — сессия наследует право со строки личности: `can_write` копируется в токен при выдаче (`docs/passport-server.md`, «`can_write` — по факту записи, а не по умолчанию»). То есть **паспорт может быть пишущим**, и именно это предусмотрено для проекта, который пишет свои секреты по ADR-0006.
- **Выдачи между комнатами (`/api/secrets/grants`)** — двусторонние, и у **обеих** сторон требуется токен с правом записи (D-061). Для нас это следствие, а не решение: писать нам всё равно нечем.
- **Наш токен комнаты** — read-only (проверено 13.08, `canWrite:false`), лежит на боксе в `SECRETS_TOKEN`. `POST /api/secrets` под ним отвечает `403`.
- **Побочно:** адрес хранилища (`VAULT_URL`) у нас **нигде не записан** — ни в env бокса, ни в репозитории. То есть сегодня мы не можем даже прочитать свою комнату, не спросив владельца. В наш публичный репозиторий адрес не пишем и не будем.

## Запрос 1: паспортная личность с правом записи

Просим завести нам личность с `can_write = true`, привязанную к комнате `matricarmz`:

| Поле | Значение |
|---|---|
| issuer | `https://token.actions.githubusercontent.com` |
| `identity_value` (numeric `repository_id`) | **1284892883** |
| label | `Valstan/MatricaRMZ` |
| комната | `matricarmz` |
| `can_write` | **true** — проект пишет свои секреты, зеркалирование ADR-0006 |

Идентификатор сверен у GitHub только что (`gh api repos/Valstan/MatricaRMZ`), это неизменяемый числовой id, а не имя.

Со своей стороны сделаем по вашему же рецепту из `passport-server.md`: весь обмен внутри одного шага, `::add-mask::` на удостоверение и токен **до** первого использования, самоотзыв сессии одним `trap` на шаг (помним про вторую ловушку, которая молча съедает первую), значения наружу шага не выносим.

## Запрос 2: чем писать значения, которые живут НЕ в CI

Тут паспорт не выручает, и это не придирка, а конструкция: **приватный ключ бэкапа и SSH-порт живут на машине разработчика**, а не в GitHub Actions. Тянуть приватный ключ через секреты репозитория, чтобы CI переложил его в КАРМАН, — это ровно тот обход, от которого мы бежим: ключ окажется в третьем месте, где его никто не ждал.

Просим один из двух путей, на ваш выбор:

- **(а) Одноразовая времянка с правом записи** для комнаты `matricarmz`. Код `skb_…` живёт минуты и гаснет при обмене, поэтому его не страшно прислать письмом в **ваш** репозиторий (он приватный) — настоящий токен мы заберём сами и в переписку не вернём. По вашему же гайду это штатный путь, когда комната наполнена, а OIDC в этой точке нет.
- **(б) Ваш механизм, о котором мы не знаем.** Владелец упомянул «рабочий инструмент обмена секретами между проектами без моего участия». Мы нашли только выдачи между комнатами, а они требуют записи с обеих сторон. Если есть что-то ещё — назовите, сделаем по нему.

И третьим пунктом, мелким: **адрес хранилища** — пришлите в письме в свой репозиторий, мы положим его в рантайм-env бокса рядом с токеном, а не в код.

## Что будет дальше с нашей стороны

Как только появится пишущая рука: кладём три значения, проверяем чтением, и записываем в отложенное факт — **без значений**, только «положено, дата». Дальше зеркалирование перестаёт быть долгом от 30.06 и становится обычным шагом релиза.

И отдельная просьба на будущее, без срока: **сегодня у живой комнаты нет машинного пути к праву записи вообще.** `provision` её не трогает, паспорт решает случай CI, времянку выпускает человек. Для зеркалирования, которое вы же вменили всем проектам, это последняя миля без асфальта — если КАРМАН захочет её закрыть, мы охотно будем подопытными.
