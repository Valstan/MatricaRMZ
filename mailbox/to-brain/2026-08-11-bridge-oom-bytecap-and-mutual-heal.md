# Пакет владельца 11.08: две находки, которые стоит унести в пул

Контекст: за одну сессию закрыт пакет из 8 ниток владельца (релиз v2026.811.1322). По дороге — две находки, прошедшие фильтр #009.

## 1. Любой JS→native вызов webview-моста — это один JSON-документ в чужой куче. Режь пачки по БАЙТАМ

**Симптом, который к этому приводит:** «на планшете часть списков грузится, часть — навсегда пустая». Наш полный pull детерминированно убивал приложение на середине: `java.lang.OutOfMemoryError` в `org.json.JSONTokener` ← `MessageHandler.postMessage` (Capacitor). Мост парсит каждый вызов плагина как один JSON-документ в Java-куче с лимитом 256 МБ, а наш bulk-upsert слал до 2000 строк одним INSERT (десктопный лимит 32000 bind-параметров). Фолбэк «поймать ошибку too many variables → уменьшить чанк» не срабатывает: **Java-парсер умирает раньше, чем SQLite увидит запрос**.

Перенос: это класс, не частность. Chunking по числу строк/переменных (наш M66) не спасает — жирная строка × разумное число строк всё равно пробивает кучу. Правило: **пачку данных через любой IPC/bridge (Capacitor, React Native, WKWebView, Electron-IPC на слабых машинах) ограничивай оценкой байтов**, а платформа должна уметь инжектировать свой лимит в общий код (у нас `setSyncSqlLimits({maxBindParams, maxChunkBytes})` из android-обвязки; десктоп не тронут). `largeHeap` — только страховка. GOTCHAS M74, PR [#531](https://github.com/Valstan/MatricaRMZ/pull/531).

Диагностическая жемчужина: `adb logcat -b crash` держит буфер крэшей отдельно от основного — прошлые падения видны спустя сутки, когда основной logcat уже перезаписан.

## 2. Пара «сторож ↔ приложение» должна чинить друг друга, иначе сторож — точка отказа

У владельца с машины исчезло ВСЁ приложение (вероятно, антивирус). Watchdog с готовым механизмом восстановления не помог бы и на исправной машине этого класса: тот же antivirus-sweep, что сносит приложение, сносит и сторожа (или его задачи планировщика). Одиночный сторож — та же единая точка отказа, только сбоку.

Решение — **mutual heal**: клиент на старте восстанавливает сторожа (exe из своих resources + перерегистрация scheduled tasks ровно как в установщике), сторож восстанавливает клиента (скачивание установщика с сервера + тихая установка). Чтобы убить связку, антивирус должен снести обоих строго между двумя проверками. Плюс аварийная кнопка человеку: ярлык «Восстановить программу» → `watchdog --repair` (форс-проход мимо backoff). PR [#530](https://github.com/Valstan/MatricaRMZ/pull/530).

Побочная находка того же захода: **боевой handshake-файл сторожа перезаписывался dev-инстансом** того же приложения на машине разработчика (appExePath → dev-electron, apiBaseUrl → localhost) — сторож мерил «здоровье» не того exe. Если в экосистеме есть файлы-контракты, которые пишет приложение, — dev/CDP-инстансы должны быть явно отсечены от записи (`app.isPackaged`, суффиксы userData).
