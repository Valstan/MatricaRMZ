# Доводка блока подписей печатной формы ПП

Заказ владельца (23.11.2026) закрыла **параллельная линия** — PR #1936 «feat(print): блок подписей
печатных форм редактируемый — добавить, изменить, удалить» (смержен в `main`, `704e79ca`). Моя
параллельная реализация того же была закрыта как дубликат (PR #1937) — тащить в `main` вторую
копию того же нельзя.

Но в смерженном коде нашлись **три вещи, которые ломают собственный сценарий приёмки владельца**.
Доводка — отдельным PR.

## 1. Ввод должности рассыпался (блокер)

Ключ строки React в общем редакторе подписей был `` `${slot.caption}-${index}` ``, а **должность
редактируется**. React пересоздавал строку на каждом нажатии клавиши ⇒ **поле теряло фокус после
первого символа**. Ровно то поле, ради которого заказ и делался («с другими профессиями,
должностями»). Ключ теперь по позиции строки — как у блока подписей наряда.

## 2. Снятая галочкой подпись возвращалась сама

Снятые подписи держались по **индексу** в списке, а индекс сдвигается при **любой** правке
состава. Сценарий приёмки из pending-файла — «снять одну галочкой, удалить лишнюю» — приводил к
тому, что снятая подпись печаталась снова (правка состава сбрасывала весь список снятых).
Теперь снятие держится на **содержании** слота (должность + сотрудник + ФИО) и переживает правку
соседней строки, добавление строки и перестановку.

## 3. Блок подписей ПП был единственным блоком подписей вне кита

Блок подписей **наряда** после фазы «карточки» (PR #1934) живёт по общему киту: ручка «⠿»,
перетаскивание, стрелки. Новый блок подписей ПП — нет. Два одинаковых по смыслу блока в двух
формах вели себя по-разному — ровно то расхождение, которое нитка «Списки по одним правилам»
(D-248) и закрывает. Теперь ПП на том же ките: `useListReorder` + `ListReorderHandle`, маркеры
`data-list-row` / `data-list-row-key`, своя граница списка.

Переносимая находка: **в списке, который редактируется, ключ React не должен содержать
редактируемые поля.** Иначе правка любого поля пересоздаёт строку, и ввод рассыпается на первом
символе — а список выглядит рабочим, пока в него не начнут водить мышью.

## Границы

Прод не трогал: правки — в общем редакторе подписей и превью ПП. Сервер, домен подписей и права
не менялись (в домене поправлен только вводящий в заблуждение комментарий: роли по умолчанию не
дописываются в сохранённый набор — оператор получает ровно то, что оставил).
