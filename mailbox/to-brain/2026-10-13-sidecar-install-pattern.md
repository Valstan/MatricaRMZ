# Sidecar-инструмент в доверенном exe: маскировка без админа и новых портов

## TL;DR

Нужно было поставить фоновый инструмент (`opencode serve`) вместе с per-user
установщиком (без UAC). Не получилось — и в этом есть переносимый урок: **классический
«silent install» (папка в PROGRAMDATA + задача планировщика + правило firewall)
невозможен без прав администратора**. Рабочий паттерн — sidecar, за которым ходит
сам доверенный процесс.

## Как устроено у нас

1. **Per-user каталог + бинарь скачивает родитель** (`%LOCALAPPDATA%\Programs\...`).
   Версия — маркер-файлом, обновление раз в сутки, SHA256 релиза проверяется.
2. **Процесс — ребёнок родителя** (`spawn(..., windowsHide)`), только на loopback.
   Kaspersky: у доверенного exe флаг «не контролировать дочерние» — новый бинарь
   в исключениях не нужен (процедура исключений папки — та же, что для продукта).
3. **Наружу — только через родителя**: маршрут `/sidecar/*` в уже слушающем
   сокете продукта (тот же firewall/exe), HTTP-релей стримит без буферизации.
   Новых портов и правил нет.
4. Жизненный цикл sidecar'а = жизненный цикл родителя (старт фоном после окна,
   стоп на before-quit).

## Почему переносимо

Любой продукт с доверенным exe и LAN-функцией (раздача, агент, помощник) может
везти sidecar-инструменты тем же способом: не отдельный установщик, а ресурсами
доверенного процесса. Экономит: права админа, новые порты/firewall, исключения
антивируса, отдельную процедуру обновления.
