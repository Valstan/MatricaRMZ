# Артефакт релиза проверяется по хэшу, а не по длине

**Как нашлось.** Релиз v3.125.0 в Матрице РМЗ: тег нажали дважды (две сессии
выкатывали параллельно). Второй прогон перезаписал ассеты релиза («overwrite
published file … reason=already exists on GitHub»), и дальше получилось три разных
факта, каждый из которых выглядел невинно:

1. **API и манифест говорили одно, скачивание отдавало другое.** `gh api` показывал
   ассет 142 390 888 Б, а скачанный файл был 142 385 952 Б. Кто-то (включая меня)
   решит, что «сеть режет», и начнёт докачивать.
2. **Докачка склеила два блоба.** `curl -C -` поверх обрыва дописал остаток от
   ДРУГОГО блоба: длина стала правильной (142 385 952), содержимое — мусор.
   Проверка «размер сошёлся» даёт зелёный свет на битый файл.
3. **CDN отдавал смесь.** По URL-пути `/releases/download/<tag>/<file>` кэш живёт
   отдельно от ассетов: после перезаписи он какое-то время отдаёт ПРЕДЫДУЩИЙ блоб.
   То есть в репозитории лежит новая сборка, а по ссылке отдаётся старая — и если
   манифест и файл приехали из разных эпох кэша, пара несовместима.

**Что это значит для любого проекта с выкатой по тегам.** Проверка «размер файла
совпал с манифестом» — недостаточная: она зелёная и для склейки, и для старого
блоба правильной длины. Единственная проверка, которая ловит всё, — **хеш того
файла, который описывает манифест**.

**Правило, которое предлагаю забрать (переносимо):**

- **Манifest всегда описывает конкретную сборку.** Перед переносом артефакта на место
  сверяй хэш файла с манифестом (`sha512`/`sha256`), а не длину. Расхождение →
  файл сносится и качается заново.
- **Докачка поверх неизвестного обрыва — это не починка.** `-C -` продолжает файл
  тем, что лежит на диске; если этот кусок из другого блоба, получится файл
  правильной длины с мусором внутри. Обрыв → удалить → качать заново.
- **Манифест и его «мелочи» (blockmap, checksum-файл) — одна сборка.** Качать их
  заново каждый раз: «уже полный» файл при `-C -` не перезаписывается (сервер
  отдаёт 416 на Range за концом файла) и молча остаётся прежней версии.
- **Один тег — одна сборка.** Если сборка запускается дважды (повторный прогон,
  две сессии), вторая перезаписывает ассеты — и репозиторий получает смесь,
  которую видно только на месте, после выкатки.

**Что уже сделано у нас:** грабля записана в проекте (`docs/gotchas/M206.md`), рецепт
выкатки в `.claude/commands/reliz.md` переписан: качать артефакты **на прод**
(с бокса CDN отдаёт нормально — правило «с прода TLS-таймауты» было устаревшим),
но с гейтом по `sha512` до переноса.

**Про «качать на прод или в офис» (решение владельца 13.11.2026).** Мысль «зачем
тащить 142 МБ через свою машину, если бокс сам ходит в GitHub» — правильная, и
проверка её подтвердила: с бокса CDN отдаёт 206 за 0.76 с. Но она ломает другую
схему: если артефакт качает прод, агент на своей машине **не может его проверить**
— сверка хэшей требует, чтобы эталон и файл были в одном месте. Отсюда практическое
правило: качать на прод — да, но тогда гейт по хэшу делает **прод** (скачать, сверить,
перенести), а агент на своей машине сверяет уже то, что лежит на проде.
