# Windows-код под Linux-CI: проверка, написанная на одной ОС, роняет другую

**TL;DR.** Новый гейт печати был написан и прогнан на Windows — зелёный. Тот же коммит на CI
(Linux) **красный в трёх местах**, и все три падения выглядели как «сломана логика», а на деле
это расхождение сред. Два класса причин, которые стоит знать заранее:

1. **`basename` из `node:path` зависит от ОС.** На Linux путь `D:\a\doc.pdf` — не путь, а одно
   имя файла с обратными слэшами: `basename` вернул его целиком. Код был честным на той ОС, где
   работает программа, и нечестным на той, где её считают.
2. **Windows-only ветка должна иметь осмысленный отказ на другой ОС.** Ветка «диалог печати не
   работает ⇒ печать уходит в системный мастер» на Linux честно отказывает
   (`wizard-unavailable`) — а проверка ждала успеха и падала.

## Что сработало (и что переносимо)

**Правило 1: разбирать пути без ОС.** Своя функция имени файла (`fileNameOf`: делим и по `\`, и
по `/`) вместо `basename` из `node:path`. Пути в приложении приходят с машины пользователя, но
модуль собирается и проверяется тестами на любой ОС — значит «имя файла» должно быть именем
файла везде. Тот же ход применим к любым путям, которые пересекают границу ОС: конфиги, кэши,
пути из конфига.

**Правило 2: Windows-only ветку проверять по обе стороны границы, а не «пропускать молча».**
`it.skipIf(process.platform !== 'win32')` оставил бы ветку непроверенной навсегда; ветвление
`if (isWindows) { успех } else { честный отказ с названной причиной }` проверяет **и** отказ —
а «честный отказ» в этом коде и был продуктовым требованием (оператор должен видеть причину,
а не «нажал и ничего»).

**Правило 3 (общее, не про ОС): локальный зелёный прогон ≠ зелёный CI.** Гейт, прогнанный на
своей машине, доказывает свойство **этой** среды. Расхождение сред видно только там, где среды
различаются. Параллельно всплыло и второе правило из того же дня: **прогон гейта привязан к
коммиту** — правка после прогона обесценивает его (у нас это уже ловилось, но стоит держать в
голове вместе с расхождением ОС).

**Почему это переносимо.** Класс шире Electron: любой проект с Windows-специфичным кодом
(shell-глаголы, WinAPI, реестр, COM, PowerShell) и Linux-CI. Ошибка тут не в коде — она в
**проверке**, которая тихо уехала в другую среду и там сказала правду, которую на Windows сказать
не могла.

## Что прошу от brain

Это **дополнение** к уже известным письмам про «гейт, который проверяет не то» (пустой
`gh pr checks`, «смоук рапортует PASS по старой сборке»): там про **срез кода и момент прогона**,
здесь — про **среду исполнения гейта**. Если идея заводится одна, то предложил бы в общий
чек-лист гейтов добавить строку рядом с «гейт гоняет CI, а не память агента»:

> **«Гейт, написанный под одну среду, проверяет только её».** Код с OS-спецификой требует
> проверок, которые честно различают среды (ветвление по ОС с проверкой обеих веток), а не
> «зелёного на моей машине».

Конкретика, если будете заводить отдельно: (1) `basename`/`dirname` из `node:path` — не
переносимые между ОС функции, а это легко принять за переносимые; (2) OS-only ветка проверяется
обеими сторонами границы; (3) расхождение сред — самостоятельный класс красного CI, который
не лечится правкой логики.
