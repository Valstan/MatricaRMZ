# Подписи печатных форм: блок подписей редактируется, а сохранённое больше не отбрасывается

Заказ владельца (23.11.2026): «В печатной форме блок подписей нужно сделать редактируемым, чтобы
можно было добавлять другие подписи, с другими людьми, с другими профессиями, должностями. Добавлять
и удалять подписи. А то сейчас вот производственную программу открыли на печать, и там надо добавить
ещё одну подпись, а мы не можем, никак».

**Корень оказался не в интерфейсе, а в правиле:** домен собирал подписи для печати **только** из
списка ролей по умолчанию, а сохранённые слоты, которых в этом списке нет, **отбрасывались**. То есть
даже будь интерфейс с кнопкой «добавить подпись», добавленная подпись всё равно исчезла бы из печати.
Интерфейс был лишь местом, где это заметили.

## Что сделано

- **Общий слой подписей** (`shared/src/domain/printSignatures.ts`): слот = должность + человек
  (сотрудник из базы **или** ФИО, вписанное от руки); сохранённый набор — **как есть**, роли по
  умолчанию — только если оператор не правил блок; правки «добавить/изменить/удалить»; разбор и
  запись JSON в документ (мусор не роняет разбор, пустая подпись сохраняется — под неё подписывают
  от руки).
- **Общий редактор** (`components/PrintSignatureBlockEditor.tsx`) — по образцу наряда.
- ПП подключает общий слой; правка состава **уходит в программу**, поэтому подпись печатается и на
  бумаге (лист ПП), а не только в превью.

**Ответ на вопрос задания:** мимо шаблона печатаются **две** формы — производственная программа
(теперь редактируемая) и наряд (уже редактируемый, свой механизм, зона другой линии — не трогал).
Формы по шаблонам (`signature_role`) не затронуты: свой механизм, работает.

## Переносимая находка (pool #009)

**1. Правило по умолчанию не должно вытеснять то, что сделал человек.** Список «как должно быть по
умолчанию» и список «что operator сделал» — это **два разных списка**: дефолты нужны, пока человек не
трогал (чтобы старая форма не осиротела), и не нужны после (иначе удалённое возвращается, а
добавленное — тем более). Правило, которое проверяет «есть ли моя строка в списке дефолтов», —
это тихий способ выкинуть работу человека; у нас оно и выкидывало.

**2. Фильтровать надо по идентичности, а не по значению.** Печать отбирала подписи по названию
должности. Как только должность стали менять, две подписи могли получить одинаковую должность — и
фильтр по названию печатал бы не то. Правило переносимо: **у элемента, который пользователь может
править, нужен устойчивый ключ**; значение для отбора годится только пока оно неизменно.

**3. Правка печати и правка документа — разные вещи, и их нельзя смешивать.** Снятая галочка «не
печатать» — это про **эту** печать (в окне), а удалённая подпись — про документ (навсегда). Если
смешать, «снял на этот раз» станет «удалил из программы».
