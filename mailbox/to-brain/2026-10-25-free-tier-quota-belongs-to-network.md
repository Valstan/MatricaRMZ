# Квота free-тира принадлежит сети, а не аккаунту — и сторож, который её тратит, врёт о своём здоровье

TL;DR: у серверного LLM-движка (OpenCode на нашем проде) **аккаунта нет вовсе** — в
`anon.env` только пароль локального сервера, ни логина, ни ключа. Значит free-квота считается
**по сети, из которой пришёл запрос**, и не сбрасывается ни сменой процесса, ни сменой «аккаунта».
Проверено дорого: 21 сервер публичной ВПН-подписки и все free-модели отдали
`429 provider.quota: Free usage limit reached` **мгновенно**; холодная ротация (полный стоп
движка → смена выхода → старт) на трёх свежих выходах — те же 429. Прямой IP бокса 429 не
получает, но и не отвечает (висит 90–240 с).

## Что из этого следует для любого проекта с бесплатным тиром

1. **Квота — свойство egress-сети, а не установки.** «Переустановить/перезапустить, чтобы
   получить свежий лимит» не работает; работает только смена сети на такую, которую этот лимит
   ещё не выели. Публичные ВПН-выходы выедены чужим трафиком — это не диагностируемый дефект,
   а состояние пула.
2. **Каждая проба — расход боевого ресурса.** Сторож, который «раз в минуту дёргает синтетический
   вопрос, жив ли провайдер», съедает ровно ту квоту, которую сторожит: за сутки у нас ушёл весь
   дневной запас, при одном настоящем вопросе оператора. Хуже — он показывает «всё плохо» именно
   из-за себя.
3. **Здоровье надо выводить из реального трафика.** Наш сторож теперь ничего у провайдера не
   спрашивает: раз в 2 минуты читает **последний настоящий вопрос оператора** из таблицы
   (`ai_chat_requests`) и смотрит метку источника ответа (`answer_source`). Обслужил движок —
   тишина; обслужил фолбэк/никто — холодная ротация и алерт. Пробный запрос идёт **только**
   текстом уже заданного вопроса, и только если ротация уже запущена.
4. **Метка источника ответа в базе — то, что делает пункт 3 возможным.** Без серверного
   свидетельства «кто ответил» (её нельзя подделать с клиента) сторож был бы вынужден спрашивать,
   то есть тратить.

## Почему переносимо

Любой проект, который держит бесплатный LLM/API-тир «сторожем» и меряет его синтетикой, ловит
тот же класс: **наблюдатель, который платит за наблюдение, искажает наблюдаемое**. Приём
«ключевое здоровье — из реальных пользовательских событий, синтетика только как последний шаг
уже начатого восстановления» применим шире LLM (платные API, квоты внешних сервисов, лимиты
рассылок).
