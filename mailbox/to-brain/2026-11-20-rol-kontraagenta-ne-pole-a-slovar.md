# Два правила из нити «история заездов» (промты КАРМАНА #42 + #43, 19–20.11.2026)

## 1. Не плодить поля под синонимы ролей

Владелец сформулировал: «в каждом заезде могут быть разные договоры, разные поставщики и заказчики». На первый взгляд — три стороны: договор, поставщик, заказчик. Проверка по данным программы показала: **поставщик деталей и заказчик ремонта — одна и та же сторона** (`customer_id`; импорт двигателей из ведомости комплектности кладёт `supplierName` в `customer_id`, договор и карточка называют это поле «Контрагент»).

Дальше владелец снял вопрос сам: «может просто контрагент везде, а там мы сами в голове решаем уже кто это заказчик или поставщик, **главное чтобы учет был и концы можно было найти, а не название**».

**Правило (переносимое):** если бизнес различает роли одной стороны **в голове**, в учёте живёт **одна ссылка**, а не по полю на роль. Два поля «заказчик» и «поставщик» — это две правды об одном человеке: они разъедутся (заказчика сменили — поставщик остался), и найти «концы» по одному из них уже нельзя. Роль — справочник/словарь, а не колонка.

**Где применять:** любой учёт с «ролями» контрагента (подрядчик, поставщик, получатель, грузоотправитель), любой ERP-домен, где одна и та же организация играет разные роли. Симптом, по которому узнать: в задаче перечислены три термина, а в данных они указывают на один id.

**Что сделали:** у заезда — договор + **контрагент** (запасной путь, если договора нет); поле называется «Контрагент», без уточнения роли. Отдельной колонки «поставщик» не заводили.

## 2. Счёт по «проходу» — из слота объекта в договоре этого прохода

У заезда (прохода двигателя по заводу) свой договор. Деньги по договору лежат **слотами**: слот = (договор, марка/двигатель, цена по договору) + платежи. Слот — по двигателю, платёж — по слоту.

Правило счёта: **оплачено по заезду = платежи слота этого двигателя в договоре этого заезда** (`slotTotals` по слоту). Не «все платежи договора» (тогда в заезд попадают деньги за другой движок) и не «платежи карточки» (тогда у заезда с чужим договором покажется оплата не по тому договору).

**Переносимость:** любой объект, у которого есть повторные проходы (двигатель, оборудование, наряд, ремонт) и у каждого прохода свои условия оплаты. Счёт «по проходу» собирается из слота объекта в договоре прохода — тем же кодом, что и вкладка оплаты объекта (одна правда на две точки).

**Что показали:** деньги по договору основного цикла в заезде по рекламации **не показываются** — договор другой, слот другой.

## Что не отправили

Стоило отметить, что «история объекта по проходам» — общий класс задач для сервисного учёта, но это уже следствие пункта 2, а не отдельная находка.
