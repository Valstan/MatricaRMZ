# Два класса из приёмки v3.45.0, тем же вечером 22.09

Релиз v3.45.0 перевёл отсчёт срока ремонта двигателя с даты стартового аванса на дату поступления на завод. Владелец попросил проверить прод на живом потоке. Проверка дала два класса — оба про разрыв между тем, что видно в коде, и тем, что есть в данных.

## 1. Предупреждение, выведенное из кода, а не из данных, бывает неверным по направлению

Выкатывая правку, я честно предупредил владельца: число «горящих» двигателей изменится, потому что у двигателей без заполненной даты поступления отсчёта теперь нет вовсе. Рассуждение было чистым и неправильным: я смотрел на то, что правка **отнимает**, потому что именно это видно в диффе.

Замер на проде:

| | |
|---|---|
| Двигателей в работе с отсчётом по ПРЕЖНЕМУ правилу | **0** |
| Двигателей с датированным авансом вообще | 12, и все уже отремонтированы |
| Двигателей в работе с отсчётом по НОВОМУ правилу | **457** |

То есть прежний индикатор на живых данных не работал ни для одного двигателя, а правка не отняла, а дала. Владелец, получив моё предупреждение, искал бы падение там, где произошёл рост в четыреста пятьдесят семь раз от нуля.

**Класс:** при смене источника величины дифф показывает, какие входы перестают приниматься, и ничего не говорит о том, сколько их было заполнено. Предупреждение о последствиях для пользователя выводится из **данных**, а не из кода; если замера нет, формулировать надо как вопрос («сколько таких?»), а не как прогноз («станет меньше»). Я сформулировал как прогноз и ошибся знаком.

Побочно — второй случай вашего правила про отрицательный результат (письмо про непустой контроль). Ноль двигателей с прежним отсчётом мог означать и «функция не используется», и «мой запрос неверен». Контроль развёл: тот же запрос нашёл 31 контракт с платежами, 1722 слота, 100 датированных авансов и 12 двигателей. Без контроля я бы отчитался цифрой, не зная, что она значит.

## 2. Индикатор, срабатывающий на заброшенных записях, измеряет не то, что обещает

Новый отсчёт зажёг красным 335 двигателей. Разбивка:

| | |
|---|---|
| Красных всего | 335 |
| Из них без единой работы за 2 месяца | 198 |
| Из них стоят дольше года | 142 |
| Максимум | 854 дня |

Индикатор называется «срок ремонта вышел», но на этих данных он измерял другое: **сколько карточек не закрыли**. Настоящие просрочки (137 двигателей, по которым работа идёт) тонули среди забытых — ровно та беда, на которую владелец жаловался про поиск, подмешивавший похожее: выдача формально верна и практически бесполезна.

Лечение по решению владельца: порог живости. Гореть может только двигатель, по которому была хоть одна работа за 60 дней. Две детали, которые считаю содержательными:

- **Забытые карточки не гасим, а называем.** Отдельное состояние «без движения» вместо «ничего не показывать»: 198 неразобранных карточек — это работа, которую надо сделать, и спрятать её значило бы заменить один неверный сигнал другим. Индикатор при этом перестаёт врать, а список дел появляется.
- **Порог гасит только тревожные состояния.** «В сроке» в «без движения» не превращается. Иначе подпись утверждала бы, что по двигателю идёт работа, хотя про это мы ничего не знаем.

**Класс:** любой индикатор вида «прошло больше N времени с события X» на реальной базе сработает и на живых случаях, и на брошенных записях, а брошенных со временем становится больше. Без признака живости он сползает в отчёт о гигиене данных, продолжая носить прежнее имя. Проверять это надо не логикой, а разбивкой по признаку активности — до выката, если данные есть.

## Чего в письме нет

Самого пакета из девяти задач владельца (v3.45.0) — он проектный. Из него вам ушло отдельное письмо с тремя классами сегодня днём.
