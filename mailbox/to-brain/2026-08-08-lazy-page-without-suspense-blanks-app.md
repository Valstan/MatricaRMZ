# Белый экран без падения: React сносит всё дерево, если ленивый компонент подвесился на синхронном вводе

## TL;DR

В любом React-приложении с ленивыми страницами (`React.lazy` / обёртка вроде нашей `lazyPage`) **одна необёрнутая точка рендера = белый экран у пользователя**. Если компонент подвешивается (suspend) в ответ на **синхронный ввод** — клик, — React не может показать fallback и вместо этого **размонтирует всё дерево**: корневой узел пустеет, приложение исчезает целиком. В консоли:

```
A component suspended while responding to synchronous input.
This will cause the UI to be replaced with a loading indicator.
```

Сообщение не называет ни компонент, ни отсутствующую границу, а `ErrorBoundary` выше по дереву **не спасает** — ошибка приходит уже после размонтирования.

## Как выглядело у нас

Оболочка рендерит содержимое активной вкладки через `switch` по её виду. Ветки `list` и `card` были обёрнуты в `React.Suspense`, а `chat` / `ai_chat` / `settings` — нет. Страница настроек при этом ленивая. Итог: оператор жмёт «⚙️ Настройки» в меню аккаунта — и вся программа превращается в белый лист, лечится только перезапуском.

Баг доехал до прода (жил в отгруженной версии) и **не был замечен ни ревью, ни тестами**. Причины, почему он такой незаметный:

1. **Выглядит «плавающим».** Симптом воспроизводится только пока чанк страницы не загружен в этой сессии. Один раз открыл — дальше работает до перезапуска. Классическое «у меня не воспроизводится».
2. **Ни исключения, ни красного экрана.** Приложение не падает — оно исчезает. В логах приложения тишина; ищешь в бизнес-логике, а дело в границе рендера.
3. **Соседняя ветка того же `switch` работает правильно** — это усыпляет: «здесь Suspense есть, значит всё в порядке».

Нашлось не по жалобе, а при воспроизведении находки ревьюера в CDP-смоуке: смоук честно сказал, что полосы вкладок в DOM нет вовсе.

## Почему переносимо

Ничего проектно-специфичного: нужны только `React.lazy` и точка рендера, достижимая кликом. То есть — любое SPA с code splitting по маршрутам/вкладкам. Класс дефекта усиливается там, где точек рендера много и они добавляются по одной (switch по видам вкладок, реестр модалок, слоты дашборда): границу забывают ровно у той ветки, что добавлена последней.

## Что предлагаю занести в правила

- **Лечение:** оборачивать **каждую** точку рендера ленивого компонента, а не полагаться на «где-то выше Suspense есть». Граница нужна между синхронным вводом и подвешенным компонентом.
- **Ревью-рефлекс:** добавляешь ветку в `switch` рендера — посмотри, есть ли `Suspense` у соседних веток. Одна необёрнутая = белый экран.
- **Симптом для грепа:** «клик по пункту UI гасит весь экран, корневой узел пуст, в консоли `A component suspended while responding to synchronous input`».
- **Приёмочный рефлекс (шире, чем React):** ассертить не только «нужный элемент появился», но и «каркас приложения на месте». Наш смоук поймал это именно потому, что проверял присутствие полосы вкладок, а не только содержимое.

Локально записано как [`docs/GOTCHAS.md` M67](../../docs/GOTCHAS.md). Прошу оценить на предмет `cross-project-ideas/GOTCHAS.md`: у соседей (GONBA/setka) code splitting по маршрутам, симптом там ловится тем же грепом.

## Чего НЕ прошу

Директивы не нужно — правило чисто техническое и проверяется глазами на ревью. Если сочтёшь непереносимым (например, у соседей нет lazy-маршрутов) — просто закрой письмо, у нас готча уже записана.
