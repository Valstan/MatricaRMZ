# kaspersky-matrica — настройка Касперского под «Матрица РМЗ»

Инструмент + **модуль сопровождения**: программа Матрицы меняется (пути, адрес сервера,
новые компоненты), и список исключений обязан меняться вместе с ней. Здесь — и утилита,
и правила её поддержки.

**Запуск:** `Запустить.cmd` · для кнопок «Сохранить/Применить эталон» —
`Запустить-от-администратора.cmd`.

## Что он делает

1. **Находит сам** на текущем компьютере: Касперского (редакция, версия, `avp.com`),
   клиент Матрицы, сторож, папки данных/обновлений, адрес прод-сервера и его IP.
2. **Показывает готовые строки** для внесения в Касперский — каждая с кнопкой
   «Копировать» (и «Копировать всё»).
3. **Складывает оба списка в файлы импорта** → `%LOCALAPPDATA%\kaspersky-matrica\`
   (`Касперский-1-исключения.csv` и `Касперский-2-доверенные-программы.xml`) и печатает
   пути к ним: у обеих кнопок списков в Касперском рядом есть **Импорт**, путь вставляется
   прямо в строку имени файла. Вбивать строки по одной больше не нужно.
4. **Рендерит инструкцию** под реальные пути → туда же.
5. **Экспорт/импорт эталона настроек** Касперского (`avp.com EXPORT/IMPORT`) — штатный
   способ перенести **всю** конфигурацию на другие компьютеры.
6. **Проверяет состояние** (`-Verify`): цел ли клиент, цел ли сторож, на месте ли
   плановые задачи, свежо ли рукопожатие, отвечает ли сервер.

## Режимы

| Команда | Что |
|---|---|
| `kaspersky-matrica.ps1` | окно с готовыми строками (основной режим) |
| `-Quiet` | то же в консоль |
| `-Json` | машинный вывод — для встраивания в Матрицу/сторож; файлы импорта тоже пишутся, их пути лежат в `importFiles` |
| `-Verify` | проверка состояния; **ничего не пишет** — её дёргают часто |
| `-Export <файл.cfg>` | сохранить эталон настроек Касперского (нужен админ) |
| `-Import <файл.cfg>` | применить эталон (нужен админ) |
| `-SettingsPassword <пароль>` | если в Касперском стоит пароль на управление настройками |
| `-Report <путь.md>` | куда положить отрендеренную инструкцию |
| `-ImportDir <папка>` | куда положить файлы импорта (по умолчанию `%LOCALAPPDATA%\kaspersky-matrica`) |
| `-MergeExclusions <файл.csv>` | влить в наш файл строки твоего прежнего экспорта исключений |
| `-MergeTrusted <файл.xml>` | то же для списка доверенных программ |

### Формат файлов импорта

Снят **побайтово с живого экспорта** Kaspersky Standard 21.26 (2026-08-27) — документации
на него нет. Оба файла, несмотря на разные расширения, — один и тот же текстовый формат:
**UTF-16LE с BOM, переводы строк CRLF**, поля через точку с запятой, в конце файла — CRLF.

```
исключения (.csv):            1;<путь>;<вердикт>;<область>;1;0;1;<комментарий>;1
доверенные программы (.xml):  1;<путь>;
```

Грабли, каждая из которых стоит молчаливого отказа импорта или, хуже, правила-пустышки:

- **папка обязана заканчиваться `\`**, файл — нет. Без косой черты правило читается как
  файл без расширения и на содержимом папки не срабатывает;
- **UTF-8 не подходит.** Файл примут, но кириллические пути станут кракозябрами — правило
  будет в списке и не совпадёт ни с чем;
- `*` в полях «вердикт» и «область» = «любая угроза, любой компонент защиты» — так
  Касперский пишет исключение, добавленное вручную без уточнений;
- **шести галочек доверенной программы в формате обмена нет вовсе.** Строка несёт только
  путь — проверено на выгрузке руками настроенного списка: ни одного флага. Значит импорт
  вносит программы с галочками по умолчанию, и «полный набор» из пункта A ставится
  вручную. Дописывать в строку своё поле нельзя: это ровно тот молчаливый мис-парс,
  ради защиты от которого формат и снимали побайтово;
- **импорт вносит содержимое файла в список.** Прежде чем импортировать — выгрузи
  текущий список кнопкой «Экспорт» рядом: это точка возврата и файл для `-Merge*`.
  С ними наш файл гарантированно **содержит** прежние строки (дословно, со всеми их
  настройками), и вопрос «заменит ли импорт список целиком» перестаёт иметь значение.
  Переносится и строка **без пути** — в Касперском можно исключить угрозу по имени
  вердикта, не указывая файла (`1;;PDM:Trojan.Win32.Generic;*;…`); дедупликация её
  просто не касается. Отбрасываются только строки, где нет ни одной точки с запятой:
  это значит, что подсунут не тот файл.

## Граница возможного — читать до того, как просить «сделай полностью автоматически»

Проверено замером (Kaspersky Standard 21.26) и по документации Касперского:

- **Команды «добавить исключение» у потребительского Касперского НЕТ.** `avp.com HELP`
  даёт: HELP, SCAN, UPDATE, ROLLBACK, RENEW, FEATUREFLAGS, START, STOP, STATUS,
  STATISTICS, **EXPORT**, **IMPORT**, AcceptEULA, REPORT, SHOWTM, PROXYAUTH, EXIT, TRACES.
  Ни EXCLUSION, ни TRUSTED, ни ADD. Исключения создаются только в окне программы.
- **Подсунуть файл настроек в папку Касперского нельзя.** Конфиг непрозрачный, а
  **Самозащита** — отдельный механизм: она **не выключается** вместе с защитой в реальном
  времени и блокирует правку файлов/реестра/процессов Касперского извне в любом состоянии
  защиты. Идея «программа настроит Касперского, пока он спит» не реализуема в принципе —
  это не обход лени, это защищённая граница продукта.
- **Что автоматизируемо:** определение путей, генерация строк, инструкция,
  **EXPORT/IMPORT всей конфигурации** и — с 2026-08-27 — **готовые файлы для кнопки
  «Импорт» у каждого из двух списков** (см. «Формат файлов импорта» выше). Последнее
  снимает ручной ввод по строке, но нажатие «Импорт» всё равно делает человек в окне
  Касперского: команды у `avp.com` для этого нет.
- **Импорт списка ≠ импорт эталона.** Эталон (`-Export`/`-Import`, `avp.com`) заменяет
  **все** настройки Касперского и требует совпадения версий. Файлы списков трогают только
  свой список и от версии почти не зависят — это разные инструменты под разные задачи.
- **Прочитать список действующих исключений программно тоже нельзя** — поэтому `-Verify`
  честно отвечает «всё ли цело и работает», а не «внесены ли исключения». Не завышать
  это в отчётах.

Если когда-нибудь потребуется настоящая централизованная раскатка — это Kaspersky
Endpoint Security + Security Center (бизнес-линейка): там исключения задаются политикой
на группу машин и разъезжаются сами, плюс есть импорт/экспорт доверенной зоны в XML.
На потребительской линейке такого нет by design.

## Что именно вносится (и почему каждый пункт)

| Что | Зачем |
|---|---|
| `MatricaRMZ.exe` → доверенная программа | снимает поведенческий контроль и контроль сети с клиента |
| `matricarmz-watchdog.exe` → доверенная программа | **самый уязвимый** файл: неподписанный Go-бинарь по расписанию — типовой ложный вердикт эвристики |
| папка приложения | файлы клиента не сканируются на каждом открытии |
| папка сторожа | то же + не даёт «свипу» унести бинарь |
| `%APPDATA%\MatricaRMZ` | рукопожатие, состояние и локи сторожа |
| `%APPDATA%\@matricarmz` | **рабочие данные клиента: база SQLite, логи, файл ключа** — самая пишущая папка; без неё исключения выглядят полными, а тормоза остаются |
| папка обновлений | туда качается установщик (`MatricaRMZ-Setup-*.exe`) — свежий неподписанный установщик антивирусы трогают чаще всего |
| кэш автообновления (`%LOCALAPPDATA%\@matricarmz…-updater`) | то же, но именно отсюда обновлятор запускает скачанный установщик; имя папки собирается из **имени пакета**, а не из отображаемого имени программы, поэтому ищется по образцу `*matricarmz*-updater`, а не угадывается |
| ярлыки (рабочий стол, автозагрузка, меню «Пуск») | Касперский проверяет `.lnk` отдельно от файла, на который тот ведёт. Ищутся по двум образцам — латинскому и кириллическому: аварийный ярлык называется «Восстановить Матрицу РМЗ.lnk» и по одному латинскому не находится |
| папка вложений `<Загрузки>\MatricaRMZ_Files` | туда клиент кладёт **каждый** скачанный файл и фото — по нагрузке соперничает с базой. Путь «Загрузок» берётся из реестра: их часто переносят (на этой машине — `D:\Скачано с интернета`). Базовую папку оператор может сменить в настройках клиента, они лежат в его зашифрованной SQLite и снаружи не читаются — перенесённую папку придётся внести руками |
| хвосты прежних раскладок | `Programs\@matricarmzelectron-app` (старая папка установки) и четыре исторических кэша обновлений. Вносятся, **только если существуют** — на машине, пережившей переезд версий, в них остаются неподписанные установщики |
| установщики в `%TEMP%` (два образца имён) | когда обычная папка обновлений недоступна, установщик качается и запускается оттуда. Папку целиком исключать нельзя — там исполняется половина всего, что происходит на компьютере; берутся только `matricarmz-*.exe` и `MatricaRMZ-Setup-*.exe`, и не из `%TEMP%` (она зависит от того, чем запустили помощник), а из штатного `%LOCALAPPDATA%\Temp` |
| папка с репозиториями | сборка гоняет тысячи файлов в `node_modules`/`dist` и рождает свежие неподписанные `.exe`. Основной способ — **от расположения самого скрипта**: он лежит внутри клона, значит соседи клона и есть экосистема. Это работает при любом имени папки, на любом диске, и искать ничего не надо. Папка-родитель предлагается, **только если кроме нашего клона в ней есть хотя бы ещё один** — иначе предлагается сам клон: клон, брошенный в «Загрузки», не делает «Загрузки» папкой с репозиториями |
| папка Яндекс-диска | постоянная синхронизация = постоянная проверка. Берётся **только из реестра** (`HKCU\Software\Yandex\Yandex.Disk.2\RootFolder`, запасной ключ — `Yandex.Disk\DownloadsPath`, у него берётся родитель — и только с меткой `.sync`: папку загрузок можно перенести куда угодно, и родителем оказалась бы посторонняя). Перебор известных путей на диске сознательно не делается: `.sync` есть и у рабочей папки, и у брошенной от прежней установки — отличить их по содержимому нельзя (даже `~uid2` внутри байт в байт одинаков), а молча исключить не ту хуже, чем не найти вовсе. Ключ живёт только в `HKCU`, поэтому запускать помощник надо **под тем пользователем, который работает в Матрице**, а не от имени системы; при мультилогине в реестре лежит корень активной учётной записи |
| IP прод-сервера : 443 | чтобы проверка трафика не рвала обмен с сервером |

**Запасной поиск папки с репозиториями** — для копии скрипта, унесённой от клонов (на
машине парка её обычно и нет, тогда строки просто не будет). Два прохода по фиксированным
дискам и профилю: сначала известные имена (`PROGRAMMING`, `GitHubReps`, `Projects`, …),
затем **все папки первого уровня** — именно второй проход находит папку с нетиповым
именем на другом диске. Годится папка с **двумя и более** клонами внутри; если подходящих
несколько, берётся самая населённая (первая зависела бы от буквы диска). Сетевые и съёмные
диски не трогаются вовсе — обход шары вешает инструмент на минуты, а исключение на сетевой
путь бессмысленно; системные каталоги пропускаются по списку. Цена на живой машине —
**около полутора секунд** (`C:\` 0,9 с + `D:\` 0,35 с + профиль 0,16 с), и платится она
только когда скрипт лежит вне клона.

Папка с репозиториями и Яндекс-диск к Матрице отношения не имеют и показываются
отдельным разделом: инструмент их **находит и предлагает**, а решение вносить принимает
владелец компьютера.

**Гейт `Test-CanBeExcludedWholesale`** отсекает пути, которые нельзя отдавать под
исключение целиком: корень диска, профиль пользователя, `AppData`, системные каталоги и
**папки общего назначения** — Рабочий стол, Документы, Загрузки, Изображения, Видео,
Музыка (пути спрашиваются у Windows: их часто переносят на другой диск). Исключение вида
`D:\` выглядит в окне Касперского такой же безобидной строкой, как папка с репозиториями,
а снимает защиту с половины компьютера. Через этот же гейт проходит и корень
Яндекс-диска из реестра: пользователь волен назначить корнем синхронизации хоть диск
целиком, и реестр это честно вернёт.

## Что будет на машине, где чего-то нет

Машины парка разные, и инструмент обязан отработать на любой. Проверено запуском
имитаций (2026-08-27, PS 5.1):

| Чего нет | Что делает инструмент |
|---|---|
| нет репозиториев (разработка не ведётся) | раздел «рабочие папки» просто не показывается, файлы импорта пишутся как обычно |
| репозитории есть, но в папке с другим именем / на другом диске | находит — от расположения скрипта, а если скрипт унесён, вторым проходом по дискам |
| нет Яндекс-диска | строки нет вовсе. Ключа в реестре нет — угадывать по диску запрещено (см. таблицу выше) |
| нет Касперского | всё считает и пишет; в шапке окна честно «НЕ НАЙДЕН», кнопки эталона недоступны |
| Матрица не установлена вовсе | не падает: списки пустые, файл доверенных программ **не создаётся** (пустой список импортировать нечего), в файле исключений остаются только рабочие папки |
| Матрица установлена, но ни разу не запускалась | работает: рукопожатия нет, пути берутся из реестра и стандартных мест; папка обновлений появится после первого запуска |
| папку импорта нельзя создать (нет прав, диск полон) | окно и строки для ручного ввода остаются, в окне отдельный раздел с причиной |

Общее правило внутри: **пустое значение никогда не попадает в список**, а путь, который
нельзя исключать целиком, отсекается гейтом. Поэтому «не нашлось» всегда означает
пропущенную строку, а не строку-пустышку и не падение.

## Модуль сопровождения: когда обновлять инструмент

Инструмент читает пути **из самого приложения** (рукопожатие
`%APPDATA%\MatricaRMZ\watchdog.json`: `appExePath`, `userDataDir`, `updatesRootDir`,
`apiBaseUrl`), поэтому переезд путей и смена адреса сервера подхватываются **сами**.
Править инструмент нужно, когда:

1. **Появился новый исполняемый компонент** (ещё один агент, служба, CLI) → добавить его
   в `Get-ExclusionPlan` (`TrustedApps`).
2. **Появилась новая папка, куда приложение активно пишет** → добавить в `$folders` там же.
3. **Изменилась схема рукопожатия** (переименовали поля) → поправить `Get-MatricaInfo`.
4. **Сменился прод-адрес по умолчанию** → `$DefaultApiBaseUrl` / `$KnownProdIps` в шапке
   (это лишь запасной путь: обычно адрес приходит из рукопожатия).
5. **Обновился Касперский до новой мажорной версии** → перепроверить `avp.com HELP`
   (не появилось ли управление исключениями) и перевыпустить эталонный `.cfg` — старый
   в новую версию импортируется с потерями.

После правки — прогнать: `-Quiet` (пути), `-Verify` (состояние), `-Json` (контракт),
и обязательно проверить синтаксис скрипта парсером (см. ниже).

## Технические грабли этого инструмента (пойманы при сборке)

- **`.ps1` обязан быть с BOM.** Windows PowerShell 5.1 читает UTF-8 без BOM как cp1251 —
  кириллица в строках ломает **парсер**, скрипт не запускается вовсе. `.cmd` наоборот —
  **без BOM** и только ASCII (cmd.exe давится BOM в первой строке).
- **`"$target:443"` в PowerShell — не то, что кажется:** двоеточие после имени переменной
  разбирается как указание области видимости, и подстановка молча даёт пустоту. Правильно
  `"$($target):443"`. Поймано на живом выводе (`Связь с сервером ():`).
- **Приложение отдаёт `userData` с прямым слэшем** (`...\Roaming\@matricarmz/electron-app`
  — слэш приходит из имени npm-пакета). Windows такой путь откроет, а Касперский сверяет
  строку исключения **текстом** — правило молча не совпало бы. Инструмент нормализует
  слэши и схлопывает путь к папке-вендору `@matricarmz`, чтобы одно исключение накрыло и
  `electron-app`, и его CDP-двойники от смоука.
- **Маски вместо путей для эталона.** Путь содержит имя пользователя; на другом компе он
  не совпадёт. Для эталонного `.cfg` вносятся маски `C:\Users\*\...`.
- **🔴 Касперский удаляет сам этот скрипт при запуске — пока на его папку нет исключения.**
  Поймано на `rmz4val` 2026-08-26 при переносе в этот репозиторий: первые три запуска
  (`-Quiet`, `-Verify`, `-Json`) прошли нормально, дальше `powershell` стал завершаться с

## Встраивание в клиент / сторож

Режим `-Json` — готовый контракт: `{ kaspersky, matrica, plan, canAutoApply:false,
autoApplyReason }`. Клиент может вызвать его при старте (или пунктом «Диагностика») и,
если Касперский найден, показать своё модальное окно с теми же строками и кнопкой
копирования.

Три границы, которые нельзя переступать в реализации:

- **не менять настройки Касперского из кода** — Самозащита это заблокирует, а попытка
  выглядит как атака на антивирус;
- **не писать «исключения настроены/проверены»** — прочитать действующий список
  программно нельзя, честная формулировка: «файлы на месте, задачи есть, сервер отвечает»;
- `canAutoApply` в контракте **всегда false** — это не заглушка на будущее, а вывод из
  устройства продукта.

Ещё одна деталь на будущее: `-SettingsPassword` передаётся в `avp.com` обычным аргументом
командной строки, а значит виден в списке процессов любому локальному пользователю.
Для домашней машины это приемлемо; если инструмент когда-нибудь поедет в среду с
несколькими пользователями — читать пароль из защищённого ввода, а не из параметра.
